# 第一部分 · 用户 2026-09-21 新增的 5 条决定

## 决定 1 · 夹取顺序改成「按行扫描」

```
第一键：Y 从大到小      —— 从「靠近 Y 正方向」那一排开始，逐行往里
第二键：同一行内 X 从小到大 —— 从最靠 HOME/内角那件开始，向 +X 依次抓
```

* **取代**当前的"离托盘无壁边最近"规则（`pick_strategy/selector.py`）。
* 当前实链里接的是 `pick_strategy` 的**选择器**（`--pick-strategy order`，
  实现见 `电控/src/electrical_control/pick_strategy/chain_adapter.py`）。
* ✅ **这条不需要改协议、不需要改固件**，只改排序键。
* ✅ 用户补充：**同一排不会出现并排** ⇒ **不需要"就近"次键**。

## 决定 2 · 按类别选张开脉宽，只留 3 个值

* 顺序：**识别类别 → 设脉宽 → 再移动/夹取**；
* **目的**：不同形状/尺寸的件用不同开度，**避免把旁边的件蹦飞**；
* ✅ 用户明确：**先台架实测这 3 个值，测准了再决定改固件；不要先改固件再试。**
* 已知硬约束：`EC_AXIS_GRIPPER_OPEN_US` 是**编译期常量**，**同时**是 `[0]`/`[7]` 两处的开度，
  且是**单舵机联动**（一个舵机同时决定"升降"与"夹合"）
  ⇒ **"按类别给不同张开脉宽"必然要动固件（或动协议 = L4）。**

## 决定 3 · 🔴 **Y 优先**（用户强调，确定性结论）

> 用户原话：「**肯定是 Y 优先**……先走靠近 Y 轴正方向那一排，然后再直接往 Y 轴正方向移动，
> 这样子它可以出去；**要不然它会刮到其他的件**。如果 X 优先……它会把外面那个一起刮飞掉。」

**⇒ 固件里有现成的编译期开关：**

```c
// 电控/firmware/stm32f407_m144z/App/Inc/ec_motion_plan.h:201-203
#ifndef EC_MOTION_XY_ORDER_X_FIRST
#define EC_MOTION_XY_ORDER_X_FIRST 1     // ← 现在：每个路径点【先 X 后 Y】= 会刮飞
#endif

// 使用处：App/Src/ec_motion_plan.c:56-75  append_ordered_xy()
```

**⇒ 改成 `0` = 每个路径点【先 Y 后 X】= 用户要的"先出托盘再横移"。**
⚠️ **它是全局的**：也会改变 `HOME → 取料点` 那一段的轨迹 ⇒ **改之前要先把两条腿的轨迹画出来对比。**

## 决定 4 · 目标格不在前 3 个固定点 ⇒ **转盘翻 180°**

* 只有 **3 个固定落点**（A 侧）；B 侧 3 格靠**转盘翻 180°** 转到同样 3 个位置；
* ⇒ **转盘只需 2 个角度位置**。
* **可行性推论**：把两组分界装夹在舵机正中心 **1500 µs**，两组各占 **±90°**
  （对应 **845 / 2155 µs**）⇒ **正好 180° 分离，且两端都在 500–2500 µs 行程内**
  ⇒ **现有这只 270° 位置舵机直接可用，不需要换舵机、不需要 2:1 增速。**

## 决定 5 · **货格：1 类 1 格**

> 用户原话：「这次只有 6 个物块，6 个物块分别放一个货格。」

⇒ **6 个类别 → 6 个货格，一一对应**，不共用、不分组。
（"只用 3 个脉宽"是**另一件事**：把 6 类按大小/形状归成 3 组、共用 3 个张开开度。）

# 第三部分 · 🔴 「15 秒失活窗」的固件 vs 赛规（**最容易被误解的一条**）

| | 口径 |
|---|---|
| **赛规** | 「**15 秒没有动作** 或 没有显示本次分拣信息，本轮比赛结束」⇒ **中间一直在动 ⇒ 不失活** |
| **固件实现** | 窗口在 **运动开始** 时打开（`App/Src/ec_app.c:197-198 / :312-313`），**只有 `DISPLAY_ACK` 关窗**（`:218-220 / :532`）；"动作进度续命"的功能**编译期关着**（`App/Inc/ec_app.h:16-17` `EC_APP_PROGRESS_SOURCE_ENABLED = 0`，且运行时开关默认 `false`，`ec_app.c:582`）|

**⇒ 固件是"从开始运动到上屏必须 < 15 秒"，比赛规严。**
**⇒ 实测单件 14.1~14.3 s，余量只剩 0.7~0.9 s ⇒ 任何"加路径"的决定都会立刻超窗。**

要让固件回到赛规口径，得打开 `EC_APP_PROGRESS_SOURCE_ENABLED=1`
⇒ **这是改安全语义，属 L4**，且注释明确要求先做 **`HIL-PROGRESS-001`** 台架验证。**赛前不建议动。**

**⇒ 推荐路线**：先做"Y 优先 + 屏幕提速"，把单件压到 13 秒上下，**窗口就够了**，不必碰安全语义。
