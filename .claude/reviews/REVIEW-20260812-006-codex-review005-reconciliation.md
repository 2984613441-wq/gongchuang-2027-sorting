# REVIEW-20260812-006：Codex 对 Claude REVIEW-005 的技术对账

> 日期：2026-08-12  
> 范围：协议冻结子集及其对状态机/驱动骨架的影响  
> 独立性：Claude 原审查来自外部节点；本文件为 Codex 技术复核，不覆盖原审查  
> 裁决：采纳P0阻塞，允许无电机主机侧开发继续

## 1. 采纳

- P0-001：`DISPLAY_ACK` 的内容CRC需要 `image_id` 与 `success_count` 期望值，而V0.3没有完整定义STM32如何获得两者；因此真实显示闭环仍阻塞。
- P1-001：采用独立逐位CRC-32/ISO-HDLC参考实现复算 `01 02 03 04 05 → 0x470B99F4`，与生产实现及文档向量一致。
- P1-002：继续保留长度、字段范围、方向反例；未冻结的 `target_seq=0` 语义不自行补写。
- P2-002：把旧轮次、重复任务和事件次序纳入状态机测试。

## 2. 暂缓/驳回

- P2-001命名调整暂缓：当前codec与上下文验证职责已经分离，单纯改名不能解除P0，且会扩大本轮变更面。
- 不直接采用“只给ITEM_TASK增加image_id”作为完整方案A：这仍没有单独解决期望 `success_count` 的来源和同步规则。

## 3. 待用户确认

建议将Claude方案A补全为“增强A”：

1. V0.4在 `ITEM_TASK` 冻结 `image_id`；
2. STM32与树莓派以相同初值，仅在同一成功 `ITEM_RESULT` 后更新本轮成功数；
3. 冻结计数范围、溢出、复位和失败件规则；
4. 用跨语言测试向量验证树莓派Python与STM32 C的规范摘要和CRC一致。

用户裁决前，不修改V0.3、不缩减CRC范围、不声称真实显示闭环可用。

## 4. 当前允许继续的范围

- 纯状态机与fake HAL；
- 通用STEP/DIR骨架与fake pulse；
- 主机侧单元/集成测试；
- 不接线、不上电、不烧录、不绑定A4988或任何真实电机参数。
