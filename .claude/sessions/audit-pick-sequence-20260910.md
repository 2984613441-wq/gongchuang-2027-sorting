### 1. 协议兼容性（执行官主审）

**关键检查点**：
- [ ] ObjectRisk.position单位与ItemTaskPayload一致？（0.1mm）
- [ ] VisionTarget.confidence转换正确？（0-100 → 0.0-1.0）
- [ ] target_seq/class_id/image_id映射完整？
- [ ] 冻结字段约束遵守？（grip_angle=0xFF）

**潜在问题**：

- drop_point_for_box未集成，坐标如何获取？

### 2. 架构设计（建制官主审）

**关键检查点**：
- [ ] 模块耦合度评估
- [ ] 接口清晰度
- [ ] 可测试性
- [ ] 演化路径

**潜在问题**：
- SchedulerBridge直接依赖VisionTarget结构，耦合较紧
- 未来drop table集成需要修改bridge.py

### 3. 时间估算准确性（求是官主审）

**关键检查点**：
- [ ] `_MOTION_SPEED_MM_PER_S = 50.0` 是否实测标定？
- [ ] `_PICK_ACTION_TIME_S = 2.0` 是否包含Z轴时间？
- [ ] 三阶段时间阈值（7s/12s）依据是什么？
- [ ] Phase3的1.5s阈值是否过严？

**潜在问题**：
- 运动速度未实测，可能偏差50%+
- 未考虑Z轴上下运动时间
- 阶段切换时间可能不适配实际速度

### 4. 风险控制（监察官主审）

**关键检查点**：
- [ ] 15秒判罚防护是否充分？
- [ ] 失败重试逻辑是否符合赛规？
- [ ] 贝叶斯更新是否可能过度惩罚？
- [ ] 数据丢失/重启场景处理？

**潜在问题**：
- Phase3可能过早终止（保守策略）
- 成功率更新无持久化，重启丢失
- should_abort()的3s边界可能不足

### 5. 测试覆盖（执行官+复盘官）

**关键检查点**：
- [ ] 36个测试是否覆盖关键场景？
- [ ] 缺少集成测试
- [ ] 缺少边界条件测试（12件vs1件）
- [ ] 缺少性能测试

**潜在问题**：

- 缺少协议兼容性集成测试

## 📊 审查流程

### 阶段1：并行深度分析（3个Agent）

- **求是官**：验证时间估算假设
- **建制官**：分析架构设计
- **执行官**：检查协议兼容性

### 阶段2：风险复核（1个Agent）

- **监察官**：基于前3个官员的发现，进行红线检查

### 阶段3：经验提炼（1个Agent）

- **复盘官**：总结可复用模式、识别技术债务

### 阶段4：汇总报告

整合5个Agent的分析，输出：
- ✅ 通过项（无需修改）
- ⚠️ 建议改进（非阻塞）
- 🔴 必须修正（阻塞集成）
