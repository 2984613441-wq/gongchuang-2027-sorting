## 3. 事实、推断与未知

### 事实

- V0.3 的 CRC32 规范输入为 `target_seq + class_id + image_id + success_count + result_code`。
- REVIEW-005 已证明原协议代码在显式注入上下文时可工作，但真实 STM32 缺少 `image_id` 与完整计数来源。
- 用户已明确选择方案 A；REVIEW-006 指出仅增加 `image_id` 不足以解决计数同步。

### 推断

- `ITEM_TASK.image_id` 加上双端同规则计数，可以让 STM32 重建本件显示期望内容。
- 该推断只有在协议和跨层测试通过后才可升格为主机侧已验证结论；仍不代表真实 STM32 C 固件或显示器已验证。

### 未知

- 完整 `ITEM_TASK` wire codec（包括 X/Y/角度的最终单位、有效值表达、端序与完整载荷长度）；
- 帧头、外层 CRC16、最大帧长、波特率、超时、重传和心跳参数；
- 单节点掉电后的持久化/恢复实现；当前规则只冻结“上下文不能证明一致则禁止续跑”；
- 电机、驱动、电源、保险、线束和引脚参数。

## 4. V0.4 冻结规则

1. `ITEM_TASK` 的逻辑上下文显式包含 `target_seq, class_id, image_id`，且 `image_id` 位于类别字段之后、运动字段之前；本任务不据此猜写 X/Y/角度编码、完整载荷长度或外层帧编码。
2. `success_count` 为 `u8`，每轮初值 0，合法范围 0..255。
3. 当前件首次有效的成功 `ITEM_RESULT` 后，两端各自恰好加一；失败结果和所有重复/重传事件不更新。
4. 显示 CRC 使用更新后的计数；失败件使用未改变的计数。
5. 达到 255 后禁止接受可能产生下一成功计数的新件；绝不回绕。异常溢出进入协议/轮次故障并等待人工复位。
6. 只有经验证的新轮次初始化同时清零；重连、重传、超时、通信恢复和同轮单节点重启不得自行清零。
7. 无法证明两端 `(task_id, success_count, current item)` 一致时不得继续接件。

- `COUNT-RESET-001`：仅新轮次清零；重连、重传、超时和同轮恢复不清零。
- `COUNT-DESYNC-001`：上下文无法证明一致时禁止继续接件。
