# TASK-20260816-001：G1 PCB 与固件引脚交接沉淀

## 原始需求

将当前已讨论、已测试的 STM32F407/M144Z-M4 引脚分配与 PCB 阶段状态沉淀下来，供下一段对话直接开始编写固件。

## 真实问题

GPIO 功能测试、候选排针位置、EDA 网络、PCB 布线与 Gerber 导出发生在多轮操作中。若不区分“已实测 GPIO 功能”“文档静态一致”“真实 PCB/物理针序待验”，下一段固件对话容易把候选条件误写成已冻结事实。

## 必须目标

- 形成可复制到下一段对话的 GPIO、定时器、UART、输入极性和安全默认态基线。
- 记录当前 G1 PCB 的实际边界、最新已观察 DRC 状态及 Gerber 导出限制。
- 将本轮可复用判断作为经验候选，标明来源、适用条件、反例、验证时间和状态。

## 非目标

- 不修改 GPIO/定时器映射、原理图、PCB、Gerber 或 EDA 工程。
- 不宣称 ERC/DRC、Gerber、BOM、坐标、投板或硬件系统验证已通过。
- 不接线、上电、烧录、采购、投板或执行实机运动。

## 事实、推断与未知

| 分类 | 内容 |
|---|---|
| 事实 | `TASK-20260814-004` 与 `stm32f407-pin-timer-allocation.md` 记录了 29 个候选功能网络及 GPIO/定时器分配；记录中包含 GPIO 功能测试通过证据。 |
| 事实 | 当前会话中观察到的 Gerber ZIP 仅含制造输出；其 `FlyingProbeTesting.json` 显示旧的元件位号/显示名称，且当时 EDA 报告原理图与 PCB 网表不一致。 |
| 推断 | 下一段固件工作可安全采用已测试 GPIO 功能分配作为代码基线，但必须保持上电安全态并以当前 CubeMX 时钟树重新计算定时器参数。 |
| 未知 | M144Z-M4 官方针序与排针连续性、真实 EDA 的最终网表/DRC、板框/安装孔、供电能力、A4988 与执行器实物参数仍未冻结。 |

## 最小验收

1. 交接记录覆盖 29 个功能网络、默认安全态、输入极性、UART 角色和禁止占用引脚。
2. 交接记录明确代码基线不等于 PCB/实物放行。
3. 经验条目符合五字段模板，状态为“待验证（新）”。
4. 文档中的核心 GPIO 映射与 `docs/design/stm32f407-pin-timer-allocation.md` 静态一致。
