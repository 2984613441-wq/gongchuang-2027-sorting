## 4. 目标行为与建议模块边界

### 4.1 离线 fake 任务源

- 提供确定性、可重复的任务序列，只构造已冻结的逻辑字段；运动字段可使用不进入 wire 编码的测试对象或显式占位，不猜 X/Y/角度单位和端序。
- 支持合法顺序、重复本件、同身份异载荷、旧轮次、乱序和计数边界等场景。
- fake 源只喂入高层事件，不打开串口、不读取 GPIO、不调用任何执行器接口。

### 4.2 调度器

- 同一时刻最多存在一个未结本件。上一件尚未完成“接受 `ITEM_RESULT` → 实际渲染完成 → 生成首个有效 `DISPLAY_ACK` 意图”时，不取出或发送下一件。
- `MOTION_DONE` 不能计数、不能开始渲染最终结果、不能放行下一件；最终显示由匹配当前件的 `ITEM_RESULT` 驱动。
- 相同本件的重复消息返回一致结果，不重复计数、不重复推进队列；同一身份出现不同载荷或不同结果进入协议/轮次故障。
- 计数为 255 时拒绝开始任何可能产生第 256 个成功结果的新件，保持计数并锁定等待人工恢复。

### 4.3 显示模型

显示模型的规范字段固定为：

```text
target_seq + class_id + image_id + success_count + result_code
```

- 五字段均为 `u8`，模型必须来自已经锁定的本件 `ITEM_TASK`、首次有效 `ITEM_RESULT` 和按 V0.4 更新后的 `success_count`。
- 成功件使用递增后的计数；失败件使用未改变的计数，并且失败件同样必须渲染和确认。
- 模型可包含仅供界面使用的派生文字，但 CRC32 只以以上五个规范字节为输入，不能把字体、窗口大小、时间戳或本地化文本混入协议摘要。

### 4.4 渲染完成凭据与 `DISPLAY_ACK` 意图

- 渲染端接收不可变显示模型，只有在其后端报告本帧已经完成提交/呈现的明确凭据后，才返回 `RenderReceipt`；“写入内存”“调用 render 方法”“开始刷新”均不算完成。
- 调度器只能用匹配当前显示模型版本的 `RenderReceipt` 生成 `DisplayAckIntent`。意图至少保留当前任务上下文、`target_seq`、`RENDERED` 和五字段 CRC32，供未来通信适配层编码。
- 本任务只生成发送意图，不实现或猜测统一外层帧、串口发送、超时、重发次数或波特率。
- 渲染失败、异常、取消、凭据错件或旧模型完成回调均不得生成成功意图，不得推进队列。
- 同一显示模型的重复完成通知最多产生一个可消费的首个有效意图；通信层未来可以重发同一已缓存意图，但不能重新计数或重新完成本件。

### 4.5 掉电和进程重启

- 采用用户批准的安全策略：树莓派进程启动、崩溃重启或节点掉电恢复后，默认进入 `RECOVERY_LOCK`，不得恢复旧队列、旧当前件、旧计数并继续原轮次。
- 即使磁盘残留旧状态，也只能用于诊断记录，不能作为自动续跑授权；本任务不开发跨节点持久化续跑。
- 解除锁定只允许走“人工确认 → STM32 完成安全自检/重新回零 → 两端验证新轮次初始化 → `success_count=0` → 注入新轮 fake 任务”的新轮流程。树莓派不能自行把旧轮标成新轮。
- 普通重连、重复消息、显示重试和同轮通信恢复均不能解除锁定或清零。

## 5. 明确不实现与不得猜写

- 不需要也不接受触摸、鼠标按钮或屏幕手势作为运行、复位、跳件或安全控制输入。
- 不冻结真实串口设备名、USB 枚举、帧头、外层 CRC16、最大帧长、波特率、心跳、超时或重发次数。
- 不冻结显示分辨率、刷新率、显示驱动、窗口系统、字体、全屏方式或 HDMI 热插拔策略。
- 不冻结 `ITEM_TASK` 的 X/Y/角度单位、有效值、端序和完整载荷长度。
- 不控制步进脉冲、PWM、GPIO、急停或回零；STM32 仍是唯一底层运动与安全控制器。
- 不声称 fake 渲染通过等于屏幕已自动亮屏、已全屏、可读或实机 `DISPLAY_ACK` 闭环通过。

| 测试 ID | 期望行为 |
|---|---|
| `RPI-COUNT-INIT-001` | 经验证的新轮从 0 开始。 |

| `RPI-COUNT-DUP-001` | 重复成功结果不二次计数、不创建第二个本件。 |
| `RPI-COUNT-BOUNDARY-001` | `254 → 首次成功 → 255` 合法，计数不回绕。 |
| `RPI-COUNT-OVERFLOW-001` | 255 时拒绝可能成功的新件；异常成功条件锁定且保持 255。 |

| 测试 ID | 期望行为 |
|---|---|
| `RPI-DISPLAY-001` | 显示模型精确包含五个规范字段，成功与失败计数规则正确。 |
| `RPI-RENDER-RED-001` | 仅调用/开始渲染时没有 `RenderReceipt`，不得产生 `DisplayAckIntent`。 |
| `RPI-RENDER-001` | 匹配模型的真实 fake 后端完成凭据出现后，才生成首个意图。 |
| `RPI-RENDER-FAIL-001` | 渲染失败、取消或异常不生成成功意图、不放行下一件。 |
