## 3. 已确认总体电控方案

### 3.1 硬件角色

| 模块 | 已确认选型 | 固定职责 | 状态 |
|---|---|---|---|
| 视觉端 | MaixCAM Pro | 拍照、YOLO 推理、类别判断、置信度过滤、机械坐标和抓取角度计算、可选诊断二次核验 | `已确认` |
| 界面与调度端 | 树莓派 4B 2GB | 顶部屏界面、日志、统计；方案 B 阶段额外保存任务队列并安排顺序 | `已确认` |
| 运动与安全端 | 正点原子探索者 STM32F407ZGT6 | 单件运动、限位、急停、超时、故障锁定、看门狗和补光灯控制 | `已确认` |
| 显示端 | 已购非触摸 HDMI 屏；其具体到货规格以实物铭牌/资料为准 | 比赛信息显示，不承担任何控制输入 | `已确认类型，待到货实测` |

工作流程PDF中“树莓派负责视觉运算”的旧描述已被当前方案替代。视觉识别以 MaixCAM Pro 跑 YOLO 为准。

### 3.2 开发阶段：方案 B

```text
MaixCAM Pro ◄──结构化视觉数据、请求、ACK、心跳──► 树莓派 4B 2GB
树莓派 4B 2GB ◄──单件任务、状态、结果、ACK、心跳──► STM32F407ZGT6
树莓派 4B 2GB ──Micro-HDMI──► 顶部显示屏
```

- MaixCAM Pro 完成 YOLO 和坐标计算，不把原始视频交给树莓派再次运行 YOLO。
- MaixCAM Pro 首次识别整批物料；每件抓取前再次运行 YOLO 复核当前目标位置，位置变化时更新本件坐标。
- 树莓派保存整批目标队列并决定抓取顺序，但只向 STM32 发送单件高层任务。
- STM32 独立完成移动、下降、夹取、抬升、投放、复位和结果反馈。
- STM32 完成本件运动后等待；树莓派完成本地名称与图片映射并实际刷新界面后返回 `DISPLAY_ACK`，STM32才接受下一件任务。本件内容保持到下一件完成。

建议台架接线：

```text
MaixCAM UART ◄──► CP2102（3.3V）◄──USB──► 树莓派
树莓派 USB ◄──► 探索者板载 USB 串口 ◄──► STM32F407
树莓派 Micro-HDMI ──► 7英寸 HDMI 屏
ST-Link SWD ──► STM32F407
STM32 控制信号 ──► 待选外购负载开关模块 ──► 待定补光负载
```

### 3.3 校赛后候选：方案 A

```text
MaixCAM Pro ◄──UART──► STM32F407ZGT6 ◄──UART──► 树莓派 4B 2GB ──HDMI──► 顶部显示屏
```

- 最终把整批任务队列、抓取顺序和自动启动下一件的逻辑从树莓派迁移到 STM32。
- MaixCAM Pro 的视觉算法、STM32 的单件运动状态机和树莓派显示界面不重写。
- 树莓派最终只负责显示、日志和统计，不参与正式运动调度。

方案 A 属于校赛后候选升级。校赛前只实施方案 B 并完成必要接口预留，不开发任务调度迁移逻辑；校赛结束并完成稳定性复盘后，再判断迁移收益是否大于新增开发和验证成本。

### 3.4 总体取舍原则

- 设计取舍按安全合规、准确性、稳定性、性能、预算与复杂度的顺序评估。
- 使用简单主链与必要补强相结合的方式，不为“功能更多”堆叠没有验证收益的模块。
- 新增功能必须明确改善准确性、稳定性或性能；引入新故障路径时必须能够关闭或退回已验证方案。
- 性能优化必须通过实物对比测试，不能取消校验、显示确认或安全保护换取速度。

## 4. 功能流程与电气接口输入

本节来自工作流程PDF，属于`设计输入`，机械形式和执行器参数仍需机械组确认。

1. **入料归集**：上方投入物料，四周挡板将物料引导到中间区域。
2. **视觉识别**：顶部相机一次俯拍全部物料，输出类别、位置和抓取信息。
3. **挡板避让**：识别后挡板翻折，给夹爪让出空间。
4. **分拣执行**：XYZ 机构和夹爪逐件抓取并投放至六个储物盒。
5. **结果核验**：全部分拣结束后进行二次视觉核验。
6. **数据输出**：顶部屏显示单件进度、分类统计和最终核验结果。

当前电控接口输入：

| 机构 | 当前功能输入 | 仍需机械组提供 |
|---|---|---|
| X/Y滑台与机械手 | X轴、Y轴各1台 **17HS4401** 步进电机（NEMA17，1.8°，1.7A/相，40N·cm 保持扭矩）；Z 轴（机械手升降）为舵机。**X/Y 运行范围 27cm**（2026-08-24 确认）。X/Y 载板各预留1个可插拔 A4988 候选模块位；A4988 适配需验证 1.7A 电流能力与散热 | 传动方式、速度、负载、安装尺寸（行程已确认 27cm）；Z 轴舵机型号及重力轴断电防坠方案 |
| 夹爪 | **DS3120MG 数字舵机**（金属齿轮，20kg·cm @ 6.0V，PWM 开合控制）；旋转能力默认不启用 | 供应商资料（精确电压范围、PWM 参数、堵转电流）、夹持行程、断电自然状态、安装孔位 |
| 四周挡板 | 4个舵机、4路独立PWM控制；允许在同一阶段同时动作，实现归集和避让 | 舵机型号、工作电压、单个与同时动作峰值电流、PWM范围和极限位置 |
| 固定储物盒 | 六个独立储物盒固定安装，仅承担储物功能 | 不需要旋转电机、驱动器、零位传感器或运动控制接口 |
| 限位与原点 | STM32负责回零、限位和故障保护 | 每轴限位数量、常开/常闭类型、安装位置、电平、是否带编码器或零位传感器 |

机械组以 [机械图.png](./机械图.png) 为总结版。已确认的机构数量只作为电控通道、供电和接口设计输入，不把夹爪、储物盒、滑台等机械零件纳入电控采购责任。后续仍由机械组提供执行器电气参数、回零与限位位置、断电自然状态、相机与补光安装视野、电控与电池安装空间，以及已经购买的执行器或传感器。具体电流、力矩、线径和保险值不属于本轮机械接口确认内容。

模块化落地采用“探索者 STM32F407 开发板 + 自制载板/接口板 + 外购成熟功能模块”。用户提供的淘宝链接是 A4988 驱动模块链接，不是电机型号证明；因此 A4988 当前只作为 X/Y 两个可插拔候选模块位。电源变换、舵机/夹爪动力、补光功率开关、急停危险动力切断和第三运动驱动器优先外购成熟模块，自制载板只负责低能量连接、信号调理、默认态、保护器件位和测试点。详见 `docs/design/modular-pcb-design.md`。

## 5. 通信与控制要求

### 5.1 接口预留

| 链路 | 方案 B | 方案 A |
|---|---|---|
| MaixCAM Pro ↔ 树莓派 | 正式传输整批视觉结果 | 保留为调试接口，不进入正式控制链 |
| MaixCAM Pro ↔ STM32 | 完成基础收发测试 | 正式传输目标列表与二次核验数据 |
| 树莓派 ↔ STM32 | 单件任务、状态、显示确认 | 显示数据、日志状态和 `DISPLAY_ACK` |
| ST-Link ↔ STM32 | 下载、断点调试 | 固件维护和现场诊断 |
| STM32 调试串口 | 错误码和状态日志 | 现场排错 |

方案 B 的逐件主链方向固定为：树莓派→STM32 的 `ITEM_TASK`；STM32→树莓派的 `MOTION_DONE` 与 `ITEM_RESULT`；树莓派完成本件界面实际渲染后，再以树莓派→STM32 发送 `DISPLAY_ACK`。普通协议 ACK、成功 `ITEM_RESULT` 或重复刷新均不能替代首次有效 `DISPLAY_ACK`。

### 5.2 数据协议

- 三台设备从开发第一版开始使用相同的二进制外层帧结构，不在方案 B 使用临时 JSON 后再为方案 A 重写。
- 正式数据帧包含：帧头、协议版本、发送方与接收方、任务号、消息序号、命令字、数据长度、数据区和 CRC。基础消息至少区分挡板就绪、单件任务、`MOTION_DONE`、`ITEM_RESULT`、显示数据和`DISPLAY_ACK`。
- 关键指令必须应答；超时后只允许有限次数重发。
- 接收端依据任务号和消息序号拒绝旧帧，重复帧可以重发应答，但不得重复执行运动。
- MaixCAM Pro 输出机械坐标；STM32仍须检查工作空间边界。
- 同一识别结果不得同时由树莓派和 STM32 两个调度端执行。
- 树莓派只能发送高层任务，禁止直接控制步进脉冲或逐关节实时运动量。
- 抓取角度预留数值和有效标志；夹爪不需要旋转时接收端忽略该字段。
- `BARRIER_READY`、`MOTION_DONE`、`ITEM_RESULT`和`DISPLAY_ACK`是四个不同事件，分别表示挡板允许通行、运动序列结束、单件结果和界面完成显示。运动结束不等于结果成功，结果成功不等于界面已经显示；累计成功数量只能由成功`ITEM_RESULT`更新。
- 货物名称和图片预存在树莓派 TF 卡中，控制链只传类别 ID、图片 ID、序号、结果和累计数量，不通过 UART 传输图片文件。
- 比赛运行时，ST-Link、调试串口、USB调试链路和外部电脑只能用于事前维护或只读日志，不得接受或转发运动命令；不需要的无线服务关闭。

## 6. 安全、故障与补光要求

### 6.1 安全与故障

- 物理启动按钮接入STM32；只有急停释放、限位正常、无锁定故障、回零完成且MaixCAM和树莓派均就绪并协议兼容时，STM32才接受一键启动。
- 故障仍分为三级：数据扰动、任务异常和安全故障。任务异常再按严格白名单分为可恢复任务异常和不可恢复任务异常。
- 数据扰动包括CRC错误、偶发丢帧和应答丢失，只允许在原状态内有限重传；重复帧可以重发应答，但不得重复执行运动。
- 三个恢复闸口固定为：运动开始前可有限次数重新请求同一目标的视觉结果；运动执行中只允许通信重传，不允许运动重放；运动完成后可重新刷新同一件界面或重发同一`DISPLAY_ACK`，不得重复投放。
- 所有恢复都禁止自动跳件、自动回零、自动重抓、重复运动和提前启动下一件。恢复次数耗尽、坐标越界、任务号冲突、白名单外异常或`DISPLAY_ACK`最终超时，均进入任务停止并结束本轮。
- 急停通过独立硬件回路切断电机、舵机和挡板等危险执行机构动力支路，同时向STM32报告状态。重力轴不得依赖软件或持续通电保持安全；急停回路定稿前必须确认断电自锁、常闭制动器、配重或其他经验证的防坠措施。
- 限位异常、运动超时、驱动故障和看门狗复位等安全故障由STM32立即停止脉冲并关闭相关驱动使能后锁定；是否进一步切断整个动力支路由后续安全回路设计确定，不在总体方案中提前锁定。
- STM32、MaixCAM、树莓派和显示屏在任务停止、安全锁定或急停后保持逻辑供电，用于显示故障和记录日志。
- MaixCAM或树莓派失联、重启或程序卡死时，有限通信恢复失败后，STM32停止新任务并受控停止当前运动；比赛版本不自动执行撤回、回零或继续旧任务。
- 人工复位只能在本轮已经结束后执行。复位后必须重新自检和回零，旧任务号、旧队列和未完成运动不得恢复。
- STM32始终是唯一的底层运动、安全控制器和赛规15秒活动/显示边界监控端。只有经台架验证对应可观察动作的执行器输出进展，以及本件界面完成渲染后的首次`DISPLAY_ACK`可以更新时间基准；心跳、日志、重复应答、通信重传、重新请求视觉结果和同一界面重复刷新均不得重置监控。
- 系统只预留默认关闭的抓取、投放和其他传感器恢复扩展接口；具体传感器、检测点和恢复动作必须单独验证后才能启用。

### 6.2 整机顶层状态流

校赛方案 B 采用“简单主链 + 三个恢复闸口 + 默认关闭的扩展接口”。主状态机固定为：

```text
上电 → 自检 → 回零 → 待机
  → 物理按钮一键启动 → 自动运行
  → 完成

完成 → 可选诊断二次核验（默认关闭，不改变比赛完成判定）
```

自动运行子状态机为：

```text
整批识别
  → 挡板避让并等待 BARRIER_READY
  → [抓取前目标复核 → 单件运动 → ITEM_RESULT
     → 显示刷新与 DISPLAY_ACK] × N
```

| 状态 | 进入与退出规则 |
|---|---|
| 上电 | STM32、MaixCAM、树莓派和显示屏上电，执行机构动力支路保持禁止自动动作；随后进入自检。 |
| 自检 | 检查急停与限位状态、三端通信、协议版本和关键配置。自检通过后进入回零；失败时按故障等级处理。 |
| 回零 | 由STM32独立完成受控回零，并使4块挡板进入归集位。回零及挡板初始状态建立后进入待机；失败或触发安全保护时进入安全故障锁定。 |
| 待机 | 保持就绪并等待物理启动按钮，4块挡板保持归集位。只有急停释放、限位状态正常、无锁定故障、回零完成、MaixCAM和树莓派双向通信就绪且协议兼容时，STM32才接受一键启动。 |
| 自动运行 | MaixCAM完成整批识别，树莓派建立队列；随后STM32命令4块挡板在同一阶段进入避让位，并等待`BARRIER_READY`。到位判据不得只是发出PWM命令，可由经过台架验证的最坏动作时间与安全余量、位置反馈或视觉净空确认产生；未就绪或超时立即停止本轮。每件抓取前重新复核位置，树莓派只发送一条单件高层任务；STM32完成运动后先产生`MOTION_DONE`，再生成`ITEM_RESULT`。基础链只有完整运动序列结束且无可检测故障时才给出控制层成功，并记录依据`CONTROL_SEQUENCE`；启用已验证结果确认后改记`CONFIRMED`。树莓派只在成功结果后更新累计数量并刷新显示，随后发送`DISPLAY_ACK`；收到确认且仍有剩余目标时才进入下一件。 |
| 完成 | 最后一件成功`ITEM_RESULT`完成规定信息显示并收到`DISPLAY_ACK`后进入完成状态，保持最终统计，不自动开始新一轮。本轮结束后人工复位或重新上电，必须重新自检和回零。 |
| 可选诊断二次核验 | 默认不进入校赛比赛主链。启用后只在完成状态之后，由MaixCAM在已验证可视范围内检查托盘残留及可见储物区；不得隐藏最后一件规定显示、改变累计成功数量、触发自动返工或发出运动命令。 |

恢复闸口与异常转移统一如下：

| 闸口或故障 | 允许动作 | 禁止动作或退出条件 |
|---|---|---|
| 运动开始前 | 通信有限重传；在STM32尚未接受本件运动任务时，有限次数重新请求同一目标视觉结果 | 不得跳件或启动下一件；恢复耗尽进入任务停止 |
| 运动执行中 | 通信有限重传；重复数据只重发应答 | 不得自动重放、回零或重抓；安全异常立即受控停止并锁定 |
| 运动完成后 | 重新刷新同一件显示内容或重发同一`DISPLAY_ACK` | 不得重复投放或提前进入下一件；最终超时进入任务停止 |
| 默认关闭的扩展接口 | 后续可接入经过独立验证的抓取、投放确认能力 | 未验证功能不得进入校赛比赛版本，不得改变已验证主链 |

- 坐标越界、任务号冲突、白名单外异常或恢复次数耗尽，均为不可恢复任务异常，受控停止整轮流程。
- 急停从任意状态进入安全锁定并通过独立硬件回路切断执行机构动力；其他安全故障由STM32停止脉冲并关闭相关驱动使能，是否切断整个动力支路留待详细安全回路设计。
- 任务停止和安全锁定都不允许在同一轮人工恢复。只能在本轮结束后人工复位，并重新经过自检、回零和待机；旧任务不得恢复。
- STM32使用独立单调计时监控赛规15秒无动作或未显示边界。只有经台架验证对应可观察动作的执行器输出进展，以及本件界面完成渲染后的首次`DISPLAY_ACK`可以更新时间基准；心跳、日志、重复应答、通信重传、重新请求视觉结果和同一界面重复刷新均占用原阶段预算，不得重置监控。预算耗尽时进入任务停止并结束本轮。

### 6.3 补光灯

- 补光颜色、形状、工作电压、功率和安装方向由视觉对比测试与机械空间共同确定，不在当前阶段锁定。

- 分拣及核验期间保持稳定亮度，任务结束、故障或急停时关闭。

## 9. 供电方案的确定规则

1. 最终整机必须只有一个内置电池，所有电压由该电池分路转换。
2. 先取得所有负载的持续电流和峰值电流，再选择电池与降压模块，不能反向猜型号。
3. STM32与传感器、树莓派、顶部屏、MaixCAM、补光灯、舵机和电机按负载性质分别核算支路余量；实测证明互不干扰且容量充足时可以共用转换模块。
4. 树莓派与舵机不得共用容量不足的转换模块，防止舵机启动造成树莓派掉电。
5. 动力回路和逻辑回路分路布线，但必须按接口要求建立可靠公共参考地。
6. 总电源入口需要总开关、急停切断方案、防反接和总保险；各大功率支路需要独立保护。
7. 电池、降压模块、保险和线束也必须计入整机尺寸、重量、散热和固定空间。
8. 急停只切危险动力正极，不切公共参考地；解除急停后动力不得自动恢复。重力轴必须由断电自锁、常闭制动器、配重或其他经验证措施防坠；机械组确认断电自然状态前，不冻结急停动力切断回路。

### 9.1 安装与布线框架

- 电控主体在固定区域集中安装，并划分逻辑控制区、电源与驱动区、电池区。
- 相机、补光灯、显示屏、按钮、限位和传感器按功能位置分布，通过固定线束接回电控主体。
- 驱动器原则上位于固定驱动区；确需靠近电机时只能安装在固定机架，不得安装在运动部件上。
- 动力线与UART、限位、相机等信号线分开走线；电池尽量低位固定；调试口、TF卡和主要接插件装机后仍可访问。
- 具体安装尺寸、出线方向、散热空间和线束固定点由机械组确认。

### 9.2 配置、日志与版本框架

- MaixCAM保存模型、类别与相机标定配置，STM32保存运动边界和后续执行参数，树莓派保存名称、图片映射与界面配置。
- 三端使用统一协议版本，协议不兼容时禁止启动；树莓派不得自动覆盖STM32安全参数。
- 树莓派集中记录启动、任务、结果、显示、故障码和关键阶段时间，限制日志容量，不保存无必要的连续原始视频。
- 校赛前冻结包含MaixCAM程序与模型、STM32固件、树莓派程序、图片和配置的完整发布包，并准备经过验证的树莓派恢复镜像。

## 10. 验收与测试要求

### 10.1 方案 B 台架验收

1. MaixCAM Pro稳定输出带任务号的目标列表。
2. 树莓派保存队列并逐件向STM32发送高层任务。
3. STM32在收到一条单件任务后独立完成抓取和投放。
4. `MOTION_DONE`、`ITEM_RESULT`和`DISPLAY_ACK`分别记录；运动结束不得直接增加累计成功数量，只有成功`ITEM_RESULT`可以更新统计。
5. 挡板未产生`BARRIER_READY`或等待超时时，XYZ和机械手不得开始运动；不得仅凭发送PWM命令判定挡板到位。
6. 拔掉视觉或树莓派通信链路，STM32不会继续执行旧任务。
7. 顶部屏显示本件完整信息后返回`DISPLAY_ACK`，之后才允许下一件。
8. 连续完成不少于100次单件循环，不出现重复执行、任务串号或无保护失控。
9. 按单设备、两两通信、空载运动、单件闭环、多件随机分拣、故障注入和连续运行的顺序完成测试。
10. 记录关键阶段耗时，确认不会触发赛规15秒判罚并保留合理余量。
11. 分别注入运动前视觉请求失败、运动中通信丢帧和运动后界面刷新失败，确认系统只在对应恢复闸口执行白名单动作。
12. 白名单恢复次数耗尽后停止整轮；重传、重复帧和重复`DISPLAY_ACK`均不得导致重复运动或重复投放。
13. 比赛运行中不接受人工复位继续旧任务；本轮结束后复位必须重新自检、回零并生成新任务号。
14. 急停测试必须验证独立硬件切断危险执行机构动力且重力轴保持安全；限位、运动超时和驱动故障测试必须验证STM32停止脉冲、关闭相关驱动使能并锁定。
15. 心跳、日志、重复应答、重传、重新识别和同一界面重复刷新不得重置15秒监控；阶段预算耗尽后必须停止本轮。
16. 默认关闭的抓取、投放、诊断二次核验和传感器恢复扩展接口不得进入校赛比赛版本的活动路径。

### 10.2 校赛后方案 A 验收（当前不执行）

1. MaixCAM Pro正式控制数据绕过树莓派直达STM32。
2. 关闭树莓派任务调度模块后，完整分拣流程仍能运行。
3. 树莓派重启或界面崩溃时，STM32超时后安全停止。
4. STM32能够管理整批目标、逐件运动、单件结果和显示确认；诊断二次核验仍为完成后的可选功能。
5. 通过丢帧、重复帧、错序帧、坐标越界、限位和急停测试。

### 10.3 到货与整机检查

- 显示屏：通电自动亮屏、断电恢复、正面和斜侧可读、规定信息完整显示。
- 树莓派：精简系统、程序开机自启、日志限额、镜像备份、散热稳定。
- 补光灯：无明显频闪，不导致过曝或欠曝，拍摄延时经测试确定。
- 电源：峰值负载下不掉压、不重启；急停和保险动作正确；接线无异常发热。
- 尺寸：每次新增或更换硬件后复核整机不超过`350×350×450 mm`。
- 比赛流程：随机摆放不少于12件、至少6类物料，逐件分拣和显示顺序符合赛规。
