## 1. 方案结论

校赛前正式实施方案B：

```text
MaixCAM Pro ◄──结构化视觉数据、请求、ACK、心跳──► 树莓派4B 2GB
树莓派4B 2GB ◄──单件任务、状态、结果、ACK、心跳──► STM32F407
树莓派4B 2GB ──Micro-HDMI──► 顶部显示屏
STM32F407 ──控制──► 运动驱动、夹爪、4块挡板、补光与安全接口
```

三台核心设备分工如下：

| 模块 | 主要职责 |
|---|---|
| MaixCAM Pro | YOLO识别、类别判断、目标坐标计算、抓取前位置复核和可选诊断二次核验 |
| 树莓派4B 2GB | 保存目标队列、安排抓取顺序、显示界面、统计和日志 |
| STM32F407 | 唯一底层运动与安全控制器，负责一键启动授权、单件运动、限位、急停、超时、故障锁定和15秒边界监控 |
| 顶部显示屏 | 显示序号、货物名称、图片、累计成功数量、故障和最终结果，不承担控制输入 |

方案A只预留接口，校赛前不开发调度迁移逻辑。校赛结束并复盘后，再判断是否将任务队列和抓取顺序从树莓派迁移到STM32。

## 2. 设计边界与原则

当前只确定总体架构，不提前确定电机电流、力矩、驱动器型号、电池容量、降压功率、保险值、STM32引脚、线径、接插件和传感器型号。

设计优先级固定为：

```text
安全合规 → 准确性 → 稳定性 → 性能 → 预算与复杂度
```

总体采用“简单主链 + 三个恢复闸口 + 默认关闭的扩展接口”。新增功能必须能够明确改善准确性、稳定性或性能；增加故障路径时，必须可以关闭或退回已验证方案。

## 3. 赛规关键约束

- 整个装置只能使用一个安装在装置内部的电源。
- 控制系统必须安装在装置内部，比赛中禁止任何形式的遥控。
- 调试结束前设备应提前上电、自检、回零并进入待机。
- 裁判下达开始指令后，通过一个物理按钮启动并自主运行。
- 每件货物必须先完成存放，再显示本件序号、名称、图片和累计成功数量，随后才能处理下一件。
- 超过15秒没有动作或没有显示本次分拣信息，本轮比赛结束；内部恢复不得重置该边界。
- 顶部屏优先选择非触摸高亮HDMI屏。触摸版只有取得赛事方书面确认后才进入候选，且比赛版本不得连接或使用触摸输入。

## 4. 已确认电控接口

机械组提供的机构数量只作为电控设计输入，不代表机械零件由电控组采购。

| 对象 | 电控接口结论 | 采购责任边界 |
|---|---|---|
| X轴 | 1个电机，预留1路独立运动控制接口 | 电机本体及机械结构不计入电控采购 |
| Y轴 | 1个电机，预留1路独立运动控制接口 | 电机本体及机械结构不计入电控采购 |
| 机械手 | 1个步进电机，预留1路独立运动控制接口 | 步进电机本体及机械结构不计入电控采购 |
| 4块挡板 | 4路独立PWM，允许在同一阶段同时动作 | 舵机本体由机械组确定；电控负责接口和供电核算 |
| 夹爪 | 预留开合控制和可选方向字段；旋转默认关闭 | 结构与执行器由机械组确定，未确认前不采购专用旋转电控器件 |
| 六个储物盒 | 固定部件，无旋转驱动 | 不配置电机、驱动器、零位传感器或运动接口 |

## 5. 顶层运行流程

```text
上电 → 自检 → 回零并建立挡板归集位 → 待机
→ 物理按钮一键启动 → 自动运行
→ 完成

完成 → 可选诊断二次核验（默认关闭，不改变比赛完成判定）
```

自动运行子流程：

```text
整批识别
→ 4块挡板进入避让位并等待 BARRIER_READY
→ [抓取前目标复核 → 单件运动 → ITEM_RESULT
   → 显示刷新与 DISPLAY_ACK] × N
```

关键顺序：

1. MaixCAM首次识别整批物料，树莓派生成目标队列。
2. STM32命令4块挡板在同一阶段进入避让位，只有`BARRIER_READY`成立后才允许XYZ和机械手运动。到位判据不得只是发出PWM命令。
3. 每件抓取前，MaixCAM重新确认当前目标位置。
4. 树莓派每次只向STM32发送一条单件高层任务。
5. STM32独立完成本件运动并记录`MOTION_DONE`，再生成独立的`ITEM_RESULT`。运动结束不得直接增加成功数量。
6. 基础链只有完整运动序列结束且无可检测故障时才给出控制层成功，并记录依据`CONTROL_SEQUENCE`；以后启用已验证结果确认时改记`CONFIRMED`。
7. 树莓派只依据成功`ITEM_RESULT`更新累计数量，完成图片加载和界面实际刷新后发送`DISPLAY_ACK`。
8. STM32收到`DISPLAY_ACK`后才允许下一件任务；最后一件显示完成后进入完成状态。
9. 二次核验默认移出比赛主链，只可在完成后执行诊断，不改变成功数量、不触发运动，也不得隐藏最后一件规定显示。

## 6. 故障与安全策略

| 层级 | 典型情况 | 处理方式 |
|---|---|---|
| 数据扰动 | CRC错误、偶发丢帧、应答丢失 | 原状态内有限重传；重复帧只重发应答，禁止重复运动 |
| 可恢复任务异常 | 运动前视觉请求失败、运动后界面刷新失败 | 只在对应闸口执行白名单恢复，次数耗尽即停止本轮 |
| 不可恢复任务异常 | 坐标越界、任务号冲突、白名单外异常、`DISPLAY_ACK`最终超时 | 受控停止整轮，保持控制和显示供电 |
| 安全故障 | 急停、异常限位、运动超时、驱动故障、看门狗复位 | 立即停止运动并锁定；急停通过独立硬件回路切断危险动力，重力轴必须有经验证的断电防坠措施 |

三条恢复闸口：

- 运动前：允许有限重传和重新请求同一目标视觉结果。
- 运动中：只允许通信重传，禁止运动重放、自动回零和自动重抓。
- 运动后：允许重新刷新同一件界面或重发同一`DISPLAY_ACK`，禁止重复投放。

统一红线：不自动跳件、不自动恢复运动、不在同一轮人工复位后继续。人工复位只能在本轮结束后执行，随后必须重新自检、回零并使用新任务号。

## 7. 通信与显示

三台设备从第一版开始使用相同的二进制外层帧，包含帧头、协议版本、发送方、接收方、任务号、消息序号、命令字、数据长度、数据区和CRC。

关键事件必须区分`BARRIER_READY`、`MOTION_DONE`、`ITEM_RESULT`和`DISPLAY_ACK`，分别表示挡板允许通行、运动序列结束、单件结果和界面完成显示。

关键要求：

- 关键命令必须应答，超时只允许有限重传。
- 接收端通过任务号和消息序号拒绝旧帧与重复执行。
- 树莓派只发送单件高层任务，不发送步进脉冲或逐关节实时控制量。
- 图片和货物名称预存在树莓派，只传类别ID、图片ID、序号、结果和累计数量，不通过UART传图片。
- 比赛期间调试串口、ST-Link、USB调试链路和外部电脑不得发送运动命令；关闭不需要的无线服务。

## 8. 供电与安装原则

整机使用一个内置电源，经总开关、防反接和总保护后，按以下负载组分路核算：

```text
STM32与传感器逻辑
树莓派计算
MaixCAM视觉
HDMI显示
补光
舵机
电机动力
```

- 急停切断电机、舵机和挡板等执行机构动力支路。
- STM32、MaixCAM、树莓派和显示屏在急停后保持逻辑供电，用于故障显示与日志。
- 树莓派不得与电机或舵机共用容量不足的转换模块。
- 4个挡板舵机按同时动作核算峰值电流。
- 重力轴不得依赖软件或持续通电保持安全；机械组未确认断电自锁、常闭制动器、配重或其他防坠措施前，不冻结急停动力切断回路。
- 动力线与UART、限位和相机等信号线分开走线，并建立可靠公共参考地。
- 电控主体划分逻辑控制区、电源与驱动区、电池区，驱动器不得安装在运动部件上。

## 11. 当前进度与下一步

方案B总体设计已经完成，当前可以开展核心主控和基础调试物料采购。下一阶段进入电控详细设计，顺序建议为：

1. 接收机械组执行器电气参数和限位布置。
2. 选择3路运动驱动器并核算4路挡板舵机供电。
3. 完成整机负载表，确定单一电池、降压和保护结构。
4. 取得重力轴断电安全结论，设计急停动力切断回路和人工复位逻辑。
5. 分配STM32引脚并形成正式接线图。
6. 确定通信超时、恢复次数和15秒阶段预算；只有可观察执行器输出进展与本件首次`DISPLAY_ACK`可以续时，心跳、重传和日志不得续时。
7. 完成单设备、通信、空载运动、单件闭环、多件随机分拣、故障注入和连续运行测试。
