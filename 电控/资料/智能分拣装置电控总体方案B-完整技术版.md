## 1. 目标、边界与取舍

### 1.1 目标

在满足赛规和安全要求的前提下，建立能够快速完成台架闭环、便于定位故障并可逐步提高稳定性的电控架构。校赛前只实施方案B，优先完成可验证的简单主链。

### 1.2 当前边界

本方案锁定以下内容：

- 三台核心控制设备及职责边界。
- 校赛方案B及校赛后方案A接口预留。
- 顶层状态机、运行子状态机和显示确认顺序。
- 通信外层帧、幂等和重传原则。
- 急停、故障分级、15秒监控和人工复位原则。
- 单一电源、负载分组、安装与布线框架。
- 当前可采购物料与后续电控采购类别。

当前不确定电机力矩与电流、驱动器型号、电池容量、降压功率、保险值、STM32最终引脚、线径、接插件和传感器型号。这些项目必须在机械接口和实测负载明确后进入详细设计。

### 1.3 取舍原则

```text
安全合规 → 准确性 → 稳定性 → 性能 → 预算与复杂度
```

系统采用“简单主链 + 必要补强 + 可测试回退”：新增功能必须明确改善准确性、稳定性或性能；新增故障路径时，必须能够通过配置关闭或退回已验证方案。

## 2. 赛规约束

与电控直接相关的硬约束包括：

1. 控制系统安装在比赛装置内部。
2. 比赛运行中禁止以任何方式遥控装置。
3. 整机只能使用一个安装在装置内部的电源，比赛过程中不得更换电源。
4. 调试结束前设备应上电并进入待机。
5. 裁判发出开始指令后，必须一键启动并自主运行。
6. 单件顺序必须为“完成存放 → 显示本件信息 → 处理下一件”。
7. 显示内容包括本件序号、具体货物名称、图片和累计分拣成功数量。
8. 超过15秒没有动作或没有显示本次分拣信息，本轮比赛结束。
9. 顶部屏应为仅承担显示功能的高亮显示屏。

由此形成三条红线：不自动跳件、不在同一轮通过人工复位继续、不允许内部恢复重置15秒边界。

## 3. 总体架构

### 3.1 校赛方案B

```text
MaixCAM Pro ◄──结构化视觉数据、请求、ACK、心跳──► 树莓派4B 2GB
树莓派4B 2GB ◄──单件任务、状态、结果、ACK、心跳──► STM32F407
树莓派4B 2GB ──Micro-HDMI──► 顶部显示屏
STM32F407 ──控制──► 运动驱动、夹爪、4块挡板、补光与安全接口
```

方案B中，MaixCAM完成视觉，树莓派负责队列与界面，STM32负责单件运动和安全。任何时候只有一个调度端能够驱动正式任务流程。

### 3.2 校赛后候选方案A

```text
MaixCAM Pro ◄──UART──► STM32F407 ◄──UART──► 树莓派4B 2GB ──HDMI──► 顶部显示屏
```

方案A只预留接口。校赛结束并完成稳定性复盘后，只有确认迁移收益大于新增开发与验证成本，才考虑把整批队列、抓取顺序和下一件调度迁移到STM32。MaixCAM视觉算法、STM32单件运动状态机和树莓派界面不重写。

## 4. 控制器职责

| 模块 | 固定职责 | 禁止或不承担的职责 |
|---|---|---|
| MaixCAM Pro | YOLO识别、类别与置信度过滤、目标机械坐标计算、可选抓取角度、抓取前复核和可选诊断二次核验 | 不向树莓派持续传输原始视频用于二次YOLO计算，不直接控制执行器 |
| 树莓派4B 2GB | 保存目标队列、安排顺序、名称与图片映射、界面实际刷新、统计和集中日志 | 不发送步进脉冲或逐关节实时控制量，不覆盖STM32安全参数 |
| STM32F407 | 一键启动授权、单件运动、回零、限位、急停、超时、看门狗、故障锁定、补光控制和15秒边界监控 | 不承担相机标定、图像坐标变换或YOLO计算 |
| 顶部显示屏 | 显示序号、名称、图片、累计数量、故障和最终结果 | 不参与启动、复位、调试或运动控制 |

## 7. 正常运行流程

### 7.1 主状态机

```text
上电 → 自检 → 回零并建立挡板归集位 → 待机
→ 物理按钮一键启动 → 自动运行
→ 完成

完成 → 可选诊断二次核验（默认关闭，不改变比赛完成判定）
```

### 7.2 自动运行子状态机

```text
整批识别
→ 4块挡板进入避让位并等待 BARRIER_READY
→ [抓取前目标复核 → 单件运动 → ITEM_RESULT
   → 显示刷新与 DISPLAY_ACK] × N
```

### 7.3 状态规则

| 状态 | 进入与退出规则 |
|---|---|
| 上电 | STM32、MaixCAM、树莓派和显示屏上电，禁止执行机构自动动作，随后进入自检 |
| 自检 | 检查急停与限位、三端通信、协议版本和关键配置；通过后进入回零 |
| 回零 | STM32完成受控回零并使4块挡板进入归集位；失败或触发保护时进入安全锁定 |
| 待机 | 挡板保持归集位；只有急停释放、限位正常、无锁定故障、回零完成、MaixCAM和树莓派双向通信就绪且协议兼容，才接受物理按钮 |
| 自动运行 | 整批识别后命令挡板进入避让位，只有`BARRIER_READY`成立后才允许其他运动；树莓派逐件发送高层任务，STM32独立执行，收到本件`DISPLAY_ACK`后才允许下一件 |
| 完成 | 保持最后一件规定显示和最终统计，不自动开始新一轮；可按配置执行默认关闭的诊断二次核验，但核验结果不改变比赛完成判定和成功数量，也不触发运动 |

## 8. 视觉、任务与显示数据流

1. MaixCAM首次识别整批物料，输出类别、机械坐标、置信度、任务号和可选抓取角度。
2. 树莓派校验目标数据，保存队列并确定抓取顺序。
3. STM32命令4块挡板在同一阶段进入避让位，只有`BARRIER_READY`成立后才允许X、Y和机械手运动；挡板到位判据不得只是已经发出PWM命令。
4. 每件抓取前，树莓派请求MaixCAM重新运行YOLO复核当前目标位置。
5. 位置变化时更新本件坐标；复核失败按运动前恢复闸口处理。
6. 树莓派向STM32发送一条单件高层任务。
7. STM32检查任务号、工作空间、安全条件和当前状态后，独立完成本件运动并记录`MOTION_DONE`，再生成独立的`ITEM_RESULT`；运动结束不得直接增加成功数量。
8. 校赛基础链未启用结果确认接口时，只有完整运动序列结束且未检测到安全故障、运动超时或驱动故障，才允许给出控制层成功，并在日志中将结果依据标记为`CONTROL_SEQUENCE`。后续启用经过验证的结果确认能力时，依据切换为`CONFIRMED`；确认失败或结果不明时停止本轮，不自动重抓或跳件。
9. 树莓派只依据同一任务号的成功`ITEM_RESULT`更新累计成功数量，完成类别映射、图片加载和界面实际刷新后发送`DISPLAY_ACK`。
10. STM32收到`DISPLAY_ACK`后才接受下一件任务；最后一件显示完成后进入完成状态。
11. 可选诊断二次核验只在完成后执行，不改变成功数量、不触发运动，也不得隐藏最后一件规定显示。

图片与货物名称预存在树莓派TF卡。控制链只传类别ID、图片ID、序号、结果和累计数量，不通过UART传输图片文件。

## 9. 通信协议原则

### 9.1 统一外层帧

三台设备从第一版开始采用相同二进制外层帧：

| 字段 | 用途 |
|---|---|
| 帧头 | 帧同步 |
| 协议版本 | 阻止不兼容设备进入正式运行 |
| 发送方与接收方 | 标识通信端点 |
| 任务号 | 隔离不同轮次和任务 |
| 消息序号 | 去重、排序和幂等控制 |
| 命令字 | 表示就绪、心跳、目标、任务、结果、显示确认、故障等消息 |
| 数据长度与数据区 | 承载结构化数据 |
| CRC | 检测传输错误 |

### 9.2 可靠性与幂等

- 关键指令必须应答，超时后只允许有限次数重发。
- 接收端依据任务号和消息序号拒绝旧帧。
- 重复帧可以重发上次应答，但不得重复执行运动或投放。
- 坐标由MaixCAM转换为机械坐标后发送，STM32仍须检查工作空间边界。
- 同一识别结果不得同时由树莓派和STM32两个调度端执行。
- 抓取角度保留数值和有效标志；旋转未启用时接收端忽略该字段。
- 二进制帧可同步转成人可读日志，正式控制链不使用临时文本协议。

基础消息类别包括：设备就绪、心跳、整批目标、抓取前复核、挡板就绪、单件任务、运动完成、单件结果、显示数据、显示确认、可选诊断核验、故障和通用应答。

`BARRIER_READY`、`MOTION_DONE`、`ITEM_RESULT`和`DISPLAY_ACK`必须是四个不同事件，分别表示挡板允许通行、运动序列结束、单件结果和界面完成显示。`MOTION_DONE`不等于结果成功，成功`ITEM_RESULT`也不等于界面已经显示；累计成功数量只能由成功`ITEM_RESULT`更新。

## 10. 故障分级与恢复闸口

### 10.1 故障分级

| 层级 | 范围 | 处理 |
|---|---|---|
| 数据扰动 | CRC错误、偶发丢帧、应答丢失 | 原状态有限重传，禁止重复运动 |
| 可恢复任务异常 | 严格白名单内的视觉重新请求或界面重新刷新 | 仅在对应阶段有限恢复，不跳件、不启动下一件 |
| 不可恢复任务异常 | 坐标越界、任务号冲突、白名单外异常、恢复耗尽、`DISPLAY_ACK`最终超时 | 受控停止整轮流程 |
| 安全故障 | 急停、异常限位、运动超时、驱动故障、看门狗复位 | 停止运动并锁定；按安全回路规则切断或禁止动力 |

### 10.2 三个恢复闸口

| 闸口 | 允许动作 | 禁止动作 |
|---|---|---|
| 运动开始前 | 通信有限重传；STM32接受任务前有限次数重新请求同一目标视觉结果 | 跳件、启动下一件 |
| 运动执行中 | 通信有限重传；重复数据只重发应答 | 运动重放、自动回零、自动重抓 |
| 运动完成后 | 重新刷新同一件界面或重发同一`DISPLAY_ACK` | 重复投放、提前进入下一件 |

系统只预留默认关闭的抓取、投放和其他传感器恢复扩展接口。未经过独立验证的接口不得进入校赛活动路径。

### 10.3 人工复位

人工复位只能在本轮已经结束后执行。复位后必须重新自检、回零并生成新任务号；旧任务、旧队列和未完成运动不得恢复。

## 11. 15秒边界监控

STM32是赛规15秒无动作或未显示边界的唯一监控端。使用独立单调计时源，内部恢复均占用当前阶段原有预算，不得通过软件内部活动规避外部边界。

只有经台架验证能够对应可观察动作的执行器输出进展，以及本件界面完成渲染后的首次有效`DISPLAY_ACK`，才允许更新时间基准。心跳、日志、重复应答、通信重传、重新请求视觉结果、同一界面重复刷新和重复`DISPLAY_ACK`均不得重置计时。具体阶段预算和内部告警阈值在联调后确定，但不得改变“预算耗尽即停止本轮”的外部行为。

## 12. 启动、急停与失联处理

### 12.1 一键启动

物理启动按钮接入STM32。只有以下条件全部成立时才接受启动：

- 急停已释放。
- 限位状态正常。
- 无锁定故障。
- 回零完成，挡板处于归集位。
- MaixCAM和树莓派均通过双向通信报告就绪。
- 三台设备协议版本兼容。

条件不满足时，按下按钮只报告错误，不执行运动。

### 12.2 急停

急停通过独立硬件回路切断电机、舵机和挡板等危险执行机构动力支路，同时向STM32报告状态。STM32、MaixCAM、树莓派和显示屏保持逻辑供电，用于故障显示和日志记录。

急停只切动力正极，不切公共参考地。解除急停后不得自动恢复动力或旧任务。本轮结束后必须人工复位、重新检查、自检和回零。

重力轴不得依赖软件或持续通电保持安全。急停动力切断回路定稿前，必须确认该机构具有经验证的断电自锁、常闭制动器、配重或其他防坠措施。

### 12.3 其他安全故障与失联

限位异常、运动超时、驱动故障和看门狗复位由STM32立即停止脉冲、关闭相关驱动使能并锁定。是否进一步切断整个动力支路由后续详细安全回路确定。

MaixCAM或树莓派失联、重启或程序卡死时，有限通信恢复失败后，STM32停止新任务并受控停止当前运动；比赛版本不自动撤回、回零或继续旧任务。

## 13. 单一电源与负载分组

整机只使用一个内置电源。总电源经总开关、防反接和总保护后，按负载性质分组：

| 负载组 | 主要负载 |
|---|---|
| 逻辑控制 | STM32和后续传感器 |
| 计算 | 树莓派4B |
| 视觉 | MaixCAM Pro |
| 显示 | HDMI显示屏 |
| 补光 | 5V补光灯与待选3.3V逻辑负载控制模块 |
| 舵机 | 4个挡板舵机及后续夹爪执行器 |
| 电机动力 | X、Y和机械手运动驱动 |

负载组分别核算、布线和保护，但不代表最终必须每组独占一个降压模块。只有实测证明容量充足且互不干扰时才允许合并转换模块。

设计规则：

- 先取得持续电流和峰值电流，再选择电池、降压和保险。
- 4个挡板舵机按同时动作核算峰值负载。
- 树莓派不得与电机或舵机共用容量不足的转换模块。
- 补光PWM干扰不得进入视觉供电。
- 动力与逻辑分路布线，并按接口要求建立可靠公共参考地。
- 总入口设置总开关、防反接和总保护，大功率支路独立保护。
- 电池、降压、保险和线束均计入尺寸、散热和固定空间。

## 14. 安装、布线与维护

采用“主体集中分区、功能设备必要分散”：

- 固定电控区域划分为逻辑控制区、电源与驱动区、电池区。
- 相机、补光灯、显示屏、按钮、限位和传感器按功能位置分布，以固定线束接回电控主体。
- 驱动器原则上集中在固定驱动区；确需靠近电机时只能装在固定机架，不得装在运动部件上。
- 动力线与UART、限位、相机等信号线分开走线。
- 电池尽量低位固定，驱动器与转换模块保留散热空间。
- ST-Link接口、调试串口、TF卡和主要接插件装机后仍应可访问。
- 正式装机使用可靠端子和接插件，不以杜邦线作为长期动力连接。

## 15. 软件、配置、日志与发布

| 设备 | 本地保存内容 |
|---|---|
| MaixCAM | 程序、YOLO模型、类别配置和相机标定配置 |
| 树莓派 | 界面程序、名称与图片映射、目标队列、统计和集中日志 |
| STM32 | 固件、运动边界、安全参数和后续执行参数 |

- 三台设备使用统一协议版本，不兼容时禁止启动。
- 树莓派不得自动覆盖STM32安全参数。
- 树莓派记录启动、任务、结果、显示、故障码和关键阶段时间，限制日志容量，不保存无必要的连续原始视频。
- 树莓派使用精简系统、开机自启和全屏界面，关闭无关后台、自动更新和比赛中不需要的无线服务。
- 校赛前冻结MaixCAM程序与模型、STM32固件、树莓派程序、图片和配置的完整发布包。
- 准备一张经过验证的树莓派恢复镜像TF卡。
- 不实施远程升级，也不允许外部调试设备在比赛中发送运动命令。

## 16. 显示与补光

### 16.1 显示屏

当前已购买非触摸 HDMI 屏。屏幕仅连接显示与供电，只承担规定信息显示，不参与启动、复位、调试或任何控制。具体尺寸、分辨率、供电条件和亮度以到货实物铭牌及供应商资料核对结果为准，不用旧候选规格替代实物证据。

到货后检查通电自动亮屏、断电恢复、正面与斜侧可读性，以及规定信息完整显示。

### 16.2 补光

5V环形补光灯暂缓采购，等待机械组确认直径、安装空间和遮挡关系。补光灯由独立5V支路供电，不得从STM32或MaixCAM GPIO直接取电；控制模块必须明确支持3.3V逻辑触发，避免IRF520模块。

拍摄前补光稳定等待时间初步按100～300 ms预留，最终通过曝光测试确定。分拣和核验期间保持稳定亮度，任务结束或故障时关闭。

## 19. 开发与测试顺序

1. 单设备通电和基础功能验证。
2. MaixCAM与树莓派、树莓派与STM32两两通信测试。
3. MaixCAM与STM32预留链路基础收发测试。
4. 空载单轴运动、回零、限位和急停测试。
5. 单件识别、抓取、投放、显示确认闭环。
6. 多件随机分拣与抓取前目标复核。
7. 三个恢复闸口的故障注入测试。
8. `BARRIER_READY`、`MOTION_DONE`、`ITEM_RESULT`和`DISPLAY_ACK`的事件分离与异常顺序测试。
9. 重力轴断电防坠、急停和人工复位测试。
10. 15秒有效进度、无效内部事件与阶段耗时测试。
11. 峰值负载、掉压、复位和干扰测试。
12. 连续稳定性测试和发布包冻结。

## 20. 方案B验收标准

1. MaixCAM稳定输出带任务号的结构化目标列表。
2. 树莓派保存队列并逐件发送高层任务。
3. STM32收到一条任务后能够独立完成单件运动。
4. 拔掉视觉或树莓派通信链路后，STM32不会继续执行旧任务。
5. 挡板只有满足实际可验证的就绪条件后才生成`BARRIER_READY`；仅发出PWM命令不能放行其他运动。
6. `MOTION_DONE`、`ITEM_RESULT`和`DISPLAY_ACK`严格分离，运动结束或界面确认不会被误计为单件成功。
7. 基础链成功结果记录为`CONTROL_SEQUENCE`；启用结果确认后记录为`CONFIRMED`，确认失败或不明时停止本轮。
8. 顶部屏完成本件显示后才发送首次有效`DISPLAY_ACK`，STM32收到后才允许下一件。
9. 重复帧、错序帧和重复`DISPLAY_ACK`不会导致重复运动、投放、计数或延长15秒边界。
10. 运动前视觉请求失败、运动中通信丢帧和运动后界面刷新失败只触发对应白名单动作。
11. 恢复次数耗尽后停止整轮，不自动跳件。
12. 急停通过独立硬件回路切断危险执行机构动力，控制与显示保持供电；重力轴断电后不会失控下坠。
13. 限位、运动超时和驱动故障使STM32停止脉冲、关闭相关驱动使能并锁定。
14. 本轮结束前不接受人工复位继续旧任务；复位后重新自检、回零并生成新任务号。
15. 只有可观察执行器输出进展和首次有效`DISPLAY_ACK`能够更新15秒时间基准；心跳、日志、重传和重复刷新不能续时，预算耗尽后停止本轮。
16. 默认关闭的抓取、投放、传感器恢复和诊断二次核验不进入校赛活动主链。
17. 连续完成不少于100次单件循环，不发生任务串号、重复执行或无保护失控。
18. 随机摆放不少于12件、至少6类物料时，逐件分拣与显示顺序符合赛规。

## 21. 后续详细设计输入

进入详细设计前，需要取得或实测：

- X、Y和机械手执行器型号、电压、电流、负载、速度和行程。
- 4个挡板舵机型号、PWM范围、单个与同时动作峰值电流。
- 夹爪执行器接口及是否确需旋转。
- 限位、原点和编码器的数量、位置与电气类型。
- 重力轴、夹爪和挡板的断电自然状态，以及重力轴经验证的防坠方案。
- 最大同时动作组合。
- MaixCAM、树莓派、显示屏、补光和所有执行器的实测电流。
- 相机可覆盖的可选诊断二次核验范围。
- 电控、电池、驱动器、传感器和线束安装空间。

取得上述输入后，依次完成驱动器选型、整机负载表、单一电池与降压设计、急停安全回路、限位输入电路、保险和线径、接插件、STM32引脚分配、通信参数及阶段时间预算。

## 22. 最终结论

方案B职责清晰、控制链简单，并通过任务号、消息序号、CRC、四类关键事件、三个恢复闸口、硬件急停、重力轴防坠和STM32统一安全监控补强稳定性。该方案符合当前赛规边界，适合作为校赛阶段唯一实施架构。

校赛前不实施方案A迁移，不启用未经验证的抓取、投放或旋转恢复能力，不采用自动跳件或同一轮人工复位继续。详细硬件参数必须依据机械组输入和实测负载确定。
