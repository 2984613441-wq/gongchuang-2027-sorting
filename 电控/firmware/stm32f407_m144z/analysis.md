# STM32F407 CubeMX 工程接入任务分析

> 日期：2026-08-17
> 等级：L2（固件工程接入与只编译验证）
> 当前授权：写入本 Git 工作区并执行主机/Keil 编译；禁止烧录、接线、上电和实机运动。

## 目标与真实问题

- 原始需求：在用户完成 CubeMX 配置后，开始接入已经写好的电控代码。
- 真正问题：把已静态验收的 CubeMX/HAL 工程、仓库现有 `App` 适配层和 `stm32_logic` 纯逻辑核心组合成可由 Keil 编译的目标工程，同时保持启动安全默认态。
- 必须目标：保留 CubeMX 生成结构；接入 `ec_app_init()`、`ec_app_poll()` 和 USART3 接收回调；向 Keil 加入所需源码、包含路径和 `EC_DIAGNOSTIC_BUILD=1`；完成主机回归与目标编译。
- 非必须目标：不调整真实运动速度、加速度、行程、回零时序和多级动作参数；不烧录、不上电、不驱动电机。

## 已确认事实

- 第三轮静态验收确认 16 个 GPIO 标签宏已经生成。
- `ENABLE_X/Y/Z` 在切换为输出前预装为高；`DIR_X/Y/Z` 和 `LIGHT_EN` 预装为低。
- 九路输入为 `GPIO_NOPULL`；USART3 NVIC 和 IRQ 转发存在。
- STEP 定时器 TIM4/8/9 为 10 Hz；PWM 定时器 TIM2/3/10/11 为 50 Hz；所有初始 Pulse 为 0；启动路径未自动开启 PWM。
- 仓库已有 `App/Src` 六个适配层源文件和 `stm32_logic/src` 三个纯逻辑源文件。

## 未知与边界

- 真实运动参数、多级动作和联调时机尚未实机确定，本轮不得把候选值写成最终参数。
- 主机测试只能证明纯逻辑；Keil 编译只能证明目标工程能够构建，均不代表硬件、串口、电机、限位或安全电路已经通过。
- 共享仓库存在无关未跟踪文件，本轮不清理、不暂存、不覆盖。

## 实施方案

1. 将用户刚生成并通过静态验收的 `Core`、`Drivers`、`MDK-ARM`、`.ioc` 和 `.mxproject` 复制到本目录。
2. 只在 CubeMX `USER CODE` 区接入应用初始化、轮询、头文件和 UART 回调，以保留后续重新生成能力。
3. 更新 Keil 工程：加入 `App/Src` 六个 C 文件和 `stm32_logic/src` 三个 C 文件；加入相对包含路径；定义诊断宏。
4. 先运行现有主机回归，再执行 Keil 目标编译；最后检查启动路径、安全初值、工程文件引用和 Git 差异。

## 最小验收

- `main.c` 的接入只出现在 `USER CODE` 区，且仍不存在启动时自动 PWM/Base Start。
- Keil 工程能解析九个新增 C 文件、两个新增包含目录和 `EC_DIAGNOSTIC_BUILD=1`。
- 现有 `stm32_logic` 与 `firmware/.../tests` 主机测试全部通过。
- Keil 构建退出码为 0，且无 error；warning 若存在必须逐项说明，不能宣称“无警告”通过。
- `git diff --check` 通过；只报告实际验证结果，不外推为烧录或实机结论。
