## 2. GPIO 映射变更

### 2.1 零位开关接入（PG7）

**当前定义**（`ec_inputs.h:6`）：
```c
#define EC_INPUT_X_HOME       (UINT16_C(1) << 0U)  // PG7
```

**方案B 新增**：
```c
#define EC_INPUT_TURNTABLE_ZERO (UINT16_C(1) << 10U)  // PG7，复用原 X_HOME 引脚
```

**⚠️ 硬件接线基线**：
- 型号：FC-SPX302（光电开关）
- 供电：5-24V（用系统 5V 或 12V）
- 输出：NPN，**低有效**（遮光 → 输出 LOW）
- MCU 侧：**板外 10k 上拉 + MCU NOPULL**（与当前 X_HOME 基线一致）

**级别**：🔴 **L4**（修改 GPIO 映射，影响多个子系统）

---

### 2.2 遮罩审计（🔴 关键）

**当前遮罩定义**（`ec_inputs.h:24`）：
```c
#define EC_INPUT_COUNT        UINT32_C(10)
#define EC_INPUT_ALL_MASK     UINT16_C(0x03FF)
```

**新增 bit 10 后**：
```c
#define EC_INPUT_COUNT        UINT32_C(11)          // 10 → 11
#define EC_INPUT_ALL_MASK     UINT16_C(0x07FF)      // 0x03FF → 0x07FF
```

**⚠️ 必须审计所有派生遮罩**（台账 B-03 教训：位不在遮罩内会被裁掉）：

| 遮罩/常量 | 位置 | 当前值 | 方案B 值 | 影响 |
|----------|------|--------|---------|------|
| `EC_INPUT_ALL_MASK` | `ec_inputs.h:24` | `0x03FF` | `0x07FF` | ✅ 已列 |
| `EC_INPUT_COUNT` | `ec_inputs.h:23` | `10` | `11` | ✅ 已列 |
| `EC_INPUT_SAMPLE_PERIOD_MS` | `ec_app.c:23` | `10` | 不变 | ✅ 无关 |
| `EC_INPUT_DEBOUNCE_MS` | `ec_inputs.c:3` | `20` | 不变 | ✅ 无关 |
| `candidate_since_ms[EC_INPUT_COUNT]` | `ec_inputs.h:36` | 数组长度随 `EC_INPUT_COUNT` | ✅ 自动适应 |

**审计结论**：
- ✅ **只需改 2 处**：`EC_INPUT_COUNT` 和 `EC_INPUT_ALL_MASK`
- ✅ **无派生遮罩硬编码 10 或 0x03FF**（已用 Grep 确认）
- ✅ **数组长度由 `EC_INPUT_COUNT` 控制**，自动适应

**级别**：🔴 **L4**（修改冻结遮罩，必须审计所有引用）

## 4. 落料后时序（方案B）

**当前时序**（方案A）：
```
1. 抓取完成（夹爪闭合）
2. 移动到 (x, y)（落料点）
3. 到位后释放（夹爪张开）
4. 回安全位
```

**方案B 时序**：
```
1. 抓取完成（夹爪闭合）
2. 移动到 (x, y)（固定落料点）
3. ★ 转盘旋转到目标角度（box_id → angle）
4. 转盘到位后释放（夹爪张开）
5. 回安全位
```

**新增步骤**：
- 在步骤 3 插入**转盘旋转等待**
- 等待条件：零位开关 + 角度换算 or 单纯的舵机延时
- **用户拍板**：暂无零位开关的闭环方案 → 先用**舵机延时**（预留零位开关接口）

**级别**：🔴 **L3**（修改运动规划时序，不涉及协议变更）

## 5. 协议变更评估（🔴 关键设计问题）

### 5.1 当前 ITEM_TASK 字段（8 字节）

```
offset  0     target_seq(1)
offset  1     class_id(1)
offset  2     image_id(1)
offset  3-4   x_mm10(2, int16 BE)        落料点 X
offset  5-6   y_mm10(2, int16 BE)        落料点 Y
offset  7     grip_angle(1) = 0xFF
```

### 5.2 方案A vs 方案B 的协议需求

| 方案 | 落料点 | 抓取点 | ITEM_TASK 需要带什么 |
|------|--------|--------|---------------------|
| **方案A** | 六盒坐标不同 | 随机 | 落料点 (x, y) + 抓取点 (pick_x, pick_y) = **12 字节** |
| **方案B** | 固定坐标 | 随机 | 只需抓取点 (pick_x, pick_y)，落料点可烧进固件 = **8 字节**（复用 3-6） |

### 5.3 两条路线对照

#### 路线 1：方案A 扩到 12 字节，方案B 复用前 8 字节

**方案A**：
```
offset  0     target_seq(1)
offset  1     class_id(1)
offset  2     image_id(1)
offset  3-4   x_mm10(2, int16 BE)        落料点 X
offset  5-6   y_mm10(2, int16 BE)        落料点 Y
offset  7     grip_angle(1) = 0xFF
offset  8-9   pick_x_mm10(2, int16 BE)   ★新增：抓取点 X
offset 10-11  pick_y_mm10(2, int16 BE)   ★新增：抓取点 Y
```

**方案B**：
```
offset  0     target_seq(1)
offset  1     class_id(1)
offset  2     image_id(1)
offset  3-4   pick_x_mm10(2, int16 BE)   ★改：抓取点 X（复用原落料点字段）
offset  5-6   pick_y_mm10(2, int16 BE)   ★改：抓取点 Y（复用原落料点字段）
offset  7     grip_angle(1) = 0xFF
```

**结论**：
- ✅ **方案B 保持 8 字节**（不扩字段）
- ⚠️ **方案A 必须扩到 12 字节**（否则抓取点没地方放）
- ⚠️ **两方案不兼容**：同一份固件不能同时支持 A/B（8 != 12）

#### 路线 2：统一用 12 字节，方案B 的落料点字段填固定值

**方案A**：同路线 1（12 字节）

**方案B**：
```
offset  0     target_seq(1)
offset  1     class_id(1)
offset  2     image_id(1)
offset  3-4   x_mm10(2, int16 BE)        落料点 X（固定值，由树莓派填）
offset  5-6   y_mm10(2, int16 BE)        落料点 Y（固定值，由树莓派填）
offset  7     grip_angle(1) = 0xFF
offset  8-9   pick_x_mm10(2, int16 BE)   抓取点 X
offset 10-11  pick_y_mm10(2, int16 BE)   抓取点 Y
```

**结论**：
- ✅ **方案A/B 统一 12 字节**（可用同一份固件）
- ✅ **方案B 浪费 4 字节**（offset 3-6 每次都填同样的固定值）
- ✅ **协议改动只需做一次**（见 `docs/staging/2026-09-16-P3-ITEM_TASK扩字段-完整diff.md`）

### 5.4 推荐方案与 P3 的关系

**推荐**：**路线 2（统一 12 字节）**

**理由**：
1. **方案A 必须扩字段**（抓取点 + 落料点都是随机的，8 字节装不下）
2. **方案B 可以不扩**（落料点固定 → 复用 offset 3-6 放抓取点）
3. **但统一 12 字节让固件更简单**（不需要运行时判断 A/B 用哪个协议）
4. **浪费 4 字节 vs 维护两套协议**：前者代价更低

**对 P3 的影响**：
- ✅ **P3 已经设计为 12 字节**（`docs/staging/2026-09-16-P3-ITEM_TASK扩字段-完整diff.md`）
- ✅ **方案B 直接复用 P3 的 12 字节协议**
- ✅ **树莓派侧填 offset 3-6 为固定落料点**（由 `TurntableStrategy.get_drop_point()` 返回）
- ✅ **固件侧不需要区分 A/B**（都按 12 字节解析，只是方案B的落料点每次都一样）

**级别**：🔴 **L4**（修改通信协议，见 P3 文档）
