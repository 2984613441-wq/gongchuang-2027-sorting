# 修复记录：TIM 中断缺失导致步进计数与加减速全部失效

**日期**：2026-09-18
**子系统**：电控 / STM32F407 固件
**严重级别**：🔴 致命（电机运动功能整体失效，且**编译零报错**、静态检查无法发现）
**状态**：✅ 已修复并经实机验证（代码层面闭环）

---

## 一、现象

台架上执行 `MOVE X DIR0 STEPS 800 HZ 200/500/1000`：

| 现象 | 表现 |
|---|---|
| 三档速度**结果完全一样** | 200 / 500 / 1000 Hz 三次测试回读逐字节相同 |
| `STEP_REMAIN` **永远冻结** | 命令 800 步 → 回读恒为 `800`，从不变化 |
| `STEP_RESULT` **永远为 0** | 既不是 1(DONE) 也不是 2(TIMEOUT) |
| `MODE` **永远为 4** | 一直停"运动中"，从不回 0(IDLE) |
| 物理位移**远小于命令值** | 命令 40mm，实际只走一小部分 |

---

## 二、根因

固件里负责**步数递减**与**梯形加减速 ARR 更新**的唯一执行体是
`ec_step_port_on_timer_period()`（`App/Src/ec_board_stm32.c`）。

它的调用链只有一条：

```
TIM4/TIM8 更新中断  →  TIMx_IRQHandler  →  HAL_TIM_IRQHandler
                    →  HAL_TIM_PeriodElapsedCallback (Core/Src/main.c:740)
                    →  ec_step_port_on_timer_period()
```

**这条链在运行时从未接通。** 三处证据：

### 1. NVIC 从未使能

全工程 `HAL_NVIC_EnableIRQ` 只出现在：

| 文件 | 行 | 对象 |
|---|---|---|
| `Core/Src/stm32f4xx_hal_msp.c` | 467 | `USART2_IRQn` |
| `Core/Src/stm32f4xx_hal_msp.c` | 492 | `USART3_IRQn` |

**`TIM4_IRQn` / `TIM8_UP_TIM13_IRQn` 一次都没有。**

### 2. 中断函数体不存在

`TIM4_IRQHandler` / `TIM8_UP_TIM13_IRQHandler` 在全工程只存在于：

- `MDK-ARM/startup_stm32f407xx.s` —— 作为 **`[WEAK]` 默认实现（`B .` 死循环）**
- `Drivers/CMSIS/.../stm32f407xx.h` —— 仅 IRQn 枚举定义

`Core/Src/stm32f4xx_it.c` 只定义了 `USART2_IRQHandler` / `USART3_IRQHandler`。

> **铁证**：`Core/Src/stm32f4xx_it.c:64-66` 残留着
> `extern TIM_HandleTypeDef htim4; htim8; htim9;`
> —— CubeMX 生成的声明还在，**函数体被删掉/从未生成**。

### 3. CubeMX 生成时漏勾"TIM 全局中断"

`Core/Src/main.c` 中 CubeMX 放 NVIC 使能的标准位置
（`USER CODE BEGIN TIM4_Init 2` / `TIM8_Init 2`）**两个块都是空的**。

## 三、为什么一个原因造成四种现象

| 现象 | 机理 |
|---|---|
| `STEP_REMAIN` 冻结 | 递减语句只在 `ec_board_stm32.c:385`，位于死中断内。`counted_steps_remaining` 在 `:233` 被写一次 800，此后**无人触碰** |
| 三档速度完全一样 | 改 ARR 的语句在同一死中断内（`:342-344`、`:391-394`）。定时器永远停在**梯形曲线首个 ARR = 200 Hz**。`frequency_hz` 参数**仅在 profile 规划失败时才作为兜底使用**（`:149-152`），正常路径下**被完全忽略** |
| `MODE` 恒 4 / `RESULT` 恒 0 | `ec_motion_test_on_counted_done()` 只在死中断内被调用，永不执行 |
| 位移远小于命令值 | 无计数器即无正常停止条件。唯一能停下的只有 `ec_step_test_poll` 的超时，而超时按**传入的 `hz`** 计算（`ec_step_test.c:150`）—— 传的 HZ 越大算出的截止越短，实际却恒以 200 Hz 行进，**故 HZ 越大走得越少** |

> **附带解释**：历史上的 `STEP_RESULT=2 (TIMEOUT)` 不是玄学丢步，而是这套机制下**唯一可能的结局**。

## 四、修复内容（3 处 / 2 文件，必须成对）

### `Core/Src/main.c` — 补 NVIC 使能

```c
/* USER CODE BEGIN TIM4_Init 2 */
HAL_NVIC_SetPriority(TIM4_IRQn, 1, 0);
HAL_NVIC_EnableIRQ(TIM4_IRQn);
/* USER CODE END TIM4_Init 2 */

/* USER CODE BEGIN TIM8_Init 2 */
HAL_NVIC_SetPriority(TIM8_UP_TIM13_IRQn, 1, 0);
HAL_NVIC_EnableIRQ(TIM8_UP_TIM13_IRQn);
/* USER CODE END TIM8_Init 2 */
```

### `Core/Src/stm32f4xx_it.c` — 补中断函数体

```c
void TIM4_IRQHandler(void)          { HAL_TIM_IRQHandler(&htim4); }
void TIM8_UP_TIM13_IRQHandler(void) { HAL_TIM_IRQHandler(&htim8); }
```

> ⚠️ **只加函数体不加 NVIC、或反过来，都不通。** 这是最容易"改了一半"的地方。
> ⚠️ F407 上 **TIM8 更新中断与 TIM13 共用 `TIM8_UP_TIM13_IRQn`** 这一条向量。

### 实机回读（树莓派 `/dev/serial0`，115200）

**修复前**（三档 HZ 均相同）：

```
MOVE X DIR0 STEPS 800 HZ <200|500|1000>
OK MOTION STARTING
MODE=4  STEP_TARGET=800  STEP_REMAIN=800  STEP_RESULT=0     ← 冻结
```

**修复后 — X 轴（TIM8）**：

```
MOVE X DIR0 STEPS 1600 HZ 500
OK MOTION STARTING
STATUS ... MODE=4  STEP_AXIS=1  STEP_TARGET=1600  STEP_REMAIN=618  STEP_RESULT=0
t=0.0s  REMAIN=12   MODE=4  RESULT=0
t=0.3s  REMAIN=0    MODE=0  RESULT=1                        ← DONE
```

**修复后 — Y 轴（TIM4）**：

```
MOVE Y DIR1 STEPS 800 HZ 500
OK MOTION STARTING
STATUS ... MODE=4  STEP_AXIS=2  STEP_TARGET=800  STEP_REMAIN=277  STEP_RESULT=0
结束: MODE=0  STEP_REMAIN=0  STEP_RESULT=1                  ← DONE
```

**两路中断向量均确认工作。** `STEP_AXIS` 取值：`NONE=0 X=1 Y=2 Z=3`。

**修复前/后对比**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `STEP_REMAIN` | 恒 800（冻死） | 1600 → 618 → 12 → **0** |
| `STEP_RESULT` | 恒 0 | **1 = DONE** |
| `MODE` | 恒 4 | 4 → **0** |
| `STEP_TARGET` | 0 | 正确回读 |
| 加减速曲线 | 失效（恒 200Hz） | 生效（≈200→2000Hz） |

## 七、待办 / 遗留

1. **物理距离仍未实测**：1600 步理论 20mm（按 80 步/mm）。**必须用尺子量一次**才能确认标定值。
2. **`frequency_hz` 参数在生产路径下被忽略**：`start_axis_counted` 在梯形规划成功时完全不用该参数，速度由 profile 固定为 200→2000 Hz。若后续需要变速，必须改 profile 参数或使其可配。
3. **双轴无调试入口**：`HELP` 中无 XY 双轴命令，`ec_motion_test_start_steps_xy` 只能从生产路径进入，台架上无法单独验证。
4. **CubeMX 重新生成代码有回归风险**：本修复写在 `USER CODE` 块内（NVIC 部分）可保留，但 `stm32f4xx_it.c` 的两个函数体位于 `USER CODE BEGIN 1` 块内，**重新生成时须复查是否仍在**。
5. **`ACTIVE=00A8`**（Y_END/PD5、Z_DOWN/PG14、START/PA4 读为低）：**已确认不抑制运动**（`ec_step_test.c:14` `EC_MOTION_SAFETY_MASK` 仅含 `EC_INPUT_ESTOP_FB`），但外部 10k 上拉仍建议补齐以免误报。

## 八、更正记录

2026-09-18 本轮曾据 `INPUTS ACTIVE=00A8` 与 PG14/PA4 实测 0.4V，**误判**为"悬空输入触发安全锁致电机使能被切断"。

**实为错误**：`App/Src/ec_step_test.c:14`

```c
#define EC_MOTION_SAFETY_MASK  (EC_INPUT_ESTOP_FB)
```

唯一抑制源是急停。且修复后 `SAFE_LOCK=1` **仍为 1 而电机正常走完全程**，直接反证该结论。**在此登记以免后续误用。**
