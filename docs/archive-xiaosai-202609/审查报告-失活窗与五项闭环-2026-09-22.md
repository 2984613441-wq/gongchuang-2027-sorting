## 【B1 ★失活窗新修法审查】

### 一、现状总结

**当前实现**（`ec_app.c:719-721`）：
```c
const ec_axis_state_t ax_now = ec_axis_driver_state();
if ((ax_now != EC_AXIS_STATE_MOVING) &&
    (ax_now != EC_AXIS_STATE_GRIPPING) &&
    ((uint32_t)(now_ms - last_observable_ms) >= UINT32_C(15000))) {
    // 触发 DEADLINE_EXPIRED
}
```

**语义**：轴处于 `MOVING` 或 `GRIPPING` 时，**直接跳过整个判据**。

**现场验证**：
- ✅ 6件派发/6件成功/FAULTS=0
- ✅ "运动期间误判失活15秒" 已解决

### 二、三条件验证

| 条件 | 判定 | 证据 |
|------|------|------|
| **(i) 不误判正常运动** | **✅ 满足** | `MOVING/GRIPPING` 期间完全免检 |

### 三、已知缺口：堵转永不判出

#### 失效路径追溯

**Step 1：续命触发点**（`ec_app.c:649-659`）
```c
#if EC_APP_PROGRESS_SOURCE_ENABLED
    uint32_t progress_before = ec_axis_driver_completed_move_count();
    (void)ec_axis_driver_poll(now_ms, active_inputs);
    
    if (ec_axis_driver_completed_move_count() > progress_before) {
        // 计数递增 → 调用续命
        ec_app_note_observable_progress(ec_axis_driver_completed_move_count());
    }
#endif
```

**Step 2：计数递增条件**（`ec_axis_driver.c:388-390`）
```c
if (ec_step_port_take_counted_completion(&completed_axis)) {
    (void)completed_axis;
    ++completed_move_count;  // ← 只要此函数返回true就递增
    ++step_index;
}
```

**Step 3：完成锁存设置**（`ec_step_test.h:116` 注释）
```c
/* ec_step_port_take_counted_completion(): 消费一次"计数移动自然完成"锁存。
 * 该锁存由 TIM 中断在【软件计数器递减到0时】置位。
 * 
 * ⚠️ 关键：这是【软件计数】，不是位置传感器闭环。
 * TIM 中断只管递减计数器，不管电机是否实际转动。
 */
```

**Step 4：堵转时的实际行为**
```
STM32发脉冲 → TIM中断每次递减计数器
     ↓
[正常] 电机转 → 皮带动 → 到达目标位置
[堵转] 电机卡死/联轴器脱落 → 皮带不动 → 位置不变
     ↓
     但计数器仍递减到0（TIM中断不知道电机卡住了）
     ↓
     ec_step_port_take_counted_completion() 返回 true
     ↓
     ++completed_move_count → 续命
     ↓
     15秒窗口被重置 → 永不触发 DEADLINE_EXPIRED ❌
```

**证据文件**：
- `ec_axis_driver.c:27`：`static uint32_t completed_move_count;`（基于软件计数）
- `ec_axis_driver.c:9-11`：注释明确写"X/Y 不装限位开关"（无传感器闭环）
- `台账-2026-09-10.md §2.2 E-05`：用户裁决"X/Y 限位开关 → 不设"

---

### 四、下一版构想的问题

**原构想**：
> "窗口在轴开始动时打开，**只认「计数移动完成」续命**；堵转时没有完成 → 照样15s判出"

#### ❌ 构想的前提假设不成立

**假设**：堵转时 `completed_move_count` 不递增
**实际**：堵转时该计数**仍会递增**（因基于软件计数，见上方Step 1-4）

**结论**：
- 即使改成"窗口在轴开始动时打开"，**堵转仍会续命**
- 构想**不解决**条件(ii)

### 六、推荐方案

#### 方案A：接受现状 + 依赖单步超时（最快）
**做法**：
1. 明确记录：当前失活窗口在运动期间不检测，**无法检测堵转**
2. 堵转保护依赖**单步超时**（`ec_axis_driver.c:399` 的 `move_timeout_ms`）
3. 确认单步超时已启用且数值合理（默认公式：`步数×1000/频率 + 余量`）

**优点**：0代码改动
**缺点**：不满足条件(ii)"15秒失活窗口检测堵转"（但单步超时<5s能检测）

#### 方案B：加速度传感器闭环（硬件）
**做法**：
1. X/Y运动部件各装MPU6050
2. STM32读加速度：
   - 发脉冲期间 `|a|>阈值` → 实际在动 → 续命
   - 发脉冲期间 `|a|≈0` → 堵转 → 不续命 → 15s触发
3. 修改 `ec_app.c:653` 续命条件：`if (completed_move_count递增 && 加速度>阈值)`

**优点**：真正满足(i)(ii)(iii)
**缺点**：硬件改造 + 标定（≥8h）

#### 方案C：收紧单步超时（折中）
**做法**：
1. 保持当前失活窗口逻辑
2. 将 `EC_AXIS_MOVE_TIMEOUT_MARGIN_MS` 收紧到3秒
3. 在超时分支记录"连续超时次数"，3次→判堵转

**优点**：纯软件，9秒内检测堵转
**缺点**：可能误判慢速正常运动

## 【B3 转盘settle_s加长的副作用】

### 现状
```python
# 电控/src/electrical_control/scheduler/turntable_guard.py
settle_s = 1.0  # 当前值
index_side = 'none'  # 无传感器
```

### 算式

**单件延长**：
```
Δt = settle_new - settle_old = 1.5 - 1.0 = 0.5秒/件
```

**N件累计**：
```
Δt_total = N × 0.5秒
例：6件 × 0.5 = +3秒
```

**对15秒红线的影响**：
- 赛规口径：「15秒装置**没有动作**」（失活超时，不是单件总时长限制）
- 转盘旋转期间：有动作 → 不计入失活
- settle延迟期间：**无动作** → 计入失活时长
- **每件settle增量 = 0.5秒失活预算消耗**

### 新风险

1. **转盘惯性过冲**：到位后因惯性继续转 → 物料掉落/误投
2. **转盘堵转**：实际未到位，软件按固定延时认为到位 → 投错位置
3. **累计失活时长**：6件×0.5s = +3s失活预算（若其他阶段已接近15秒则有风险）

### 建议

**短期**（校赛前）：
- ✅ **保持1.0s**（已验证值）
- ❌ 不加长到1.5s（引入未验证风险 + 3s失活预算消耗）

**长期**：
- 若需加长 → 台架测试转盘实际稳定时间
- 若需精确控制 → 加索引传感器（霍尔+磁铁）

## 【B5 一键启动接线与安全审查】

### 接线方案（已采纳的外部结论）

```
NO-A → GPIO23 (针16)
NO-B → GND (针14)
INPUT + 内部上拉
NO脚【不接电源】
```

**语义**：
- 按钮按下 → NO闭合 → GPIO23拉低 → 检测到下降沿
- 按钮松开 → NO断开 → 内部上拉 → GPIO23恢复高电平

### 五项失效模式分析

| # | 失效模式 | 后果 | 缓解 |
|---|----------|------|------|
| 1 | **灯额定电压未测即接电源** | 电压不匹配 → 烧灯/不亮 | ① 先查灯铭牌/供应商资料<br>② 用万用表测灯实际工作电压<br>③ 确认电源输出电压与灯额定电压一致后再接 |
| 2 | **NO脚误接电源** | GPIO23短路到电源 → 烧GPIO/MCU | ① 接线前三次确认：NO脚只接GPIO，不接电源<br>② 上电前用万用表蜂鸣档测GPIO23与电源正极是否导通（按钮按下时也不能导通） |
| 3 | **自锁按钮"上电即闭合"** | 上电瞬间触发启动 → 跳过自检/回零 | ① 使用**点动按钮**（松手即断开），不用自锁<br>② 软件在自检/回零未完成前，忽略GPIO23信号<br>③ 若必须用自锁 → 上电前确认按钮处于松开状态 |
| 4 | **急停与一键启动交互** | 按急停后按一键启动 → 是否允许？ | ① 软件在急停状态下，禁止响应一键启动<br>② 必须先释放急停（ESTOP_FB=0），再允许一键启动<br>③ 见 `ec_app.c` 的 `EC_INPUT_ESTOP_FB` 检查 |
| 5 | **systemd自启与"运行期不许依赖笔记本"冲突** | systemd启动后自动开始运动 → 无人监控 | ① systemd只启动**守护进程**（通信/显示/日志），不启动运动<br>② 运动**只能**通过一键启动按钮触发（GPIO23下降沿）<br>③ 确认 systemd service 文件不包含 `--auto-start` 参数 |
