## 0. 先把「遮挡」拆开，否则三个层会解错题

赛规 `省赛规则.txt:136-138` 只保证「方向和位置随机、放置方式由裁判长决定」，**并不保证互不接触、不堆叠、面朝上**。V3 的适用条件正好是这三条的反面（`stage1_contour_v3.py:3-5`）。这是赛规与算法前提冲突，不是实现 bug。

这三种现象不要当成一个问题：

| 现象 | 0° 正俯视下实际是什么 | 谁负责 |
|---|---|---|
| **接触合并** | 两件侧面贴住 → 二值图连通。V3 把所有颜色 OR 成一张 mask 再 `cv2.RETR_EXTERNAL`（`:92-99`）→ **一坨外轮廓** | 检测层 |
| **部分可见** | 倾倒/堆叠/污渍/夹爪入画，顶面不完整，形状判据失效，bbox 里混了邻件颜色 | 检测层给「可见性」；策略层决定抓不抓 |
| **完全看不见** | 在 0° 下，邻件「高挡矮」几乎不发生（见相机方案 §1）；真正看不见的是 **堆在下面的件**、以及 **停放位上的夹爪挡住的那一块托盘** | 策略层（先抓走挡着的）+ 安装层（让夹爪尽量不占画面） |

另外两条已知遮挡，来源不同：

1. **夹爪挡镜头**：已确认「夹爪停 (0,0) 会挡住光轴正下方」（`抓取时序:89-94`）。解法已经拍板：拍照时夹爪停 HOME，不去 (0,0)。
2. **机械臂抓一件时挡其他件**：时序已经要求每件抓完回 HOME 再拍（`抓取时序:64,79`）。W14 还要把「一帧 N 件排队」改成「永远只用最新帧的一个」——这与「抓走后世界会变」是同一件事。

**本方案的总原则（后面每条都从这里推）**：

1. **检测只报告「现在看得见、且 (颜色,形状) 过关」的件**；看不见的件不编造。
2. **抓取只从本帧过关集合里选一个**；抓完回 HOME，下一帧重新看。不维护过期队列，不做静态 TSP 巡游。
3. **判不出就跳过（漏分），不许猜盒**。赛规把「放错盒」定价成整盒归零，把「漏一件」定价成少 2 或 5 分。
4. **不加第二摄像头**。夹爪挡镜头与件互挡 **共享「把挡着的东西移出光路再看」**，不共享「加视角」。

## 1. 检测层：轮廓合并怎么破

### 1.1 V3 现在究竟会怎样死（对源码，不是抽象批评）

| 机制 | 行号 | 接触/遮挡时的后果 |
|---|---|---|
| 全色 OR 成一张前景 | `:92-95` | 青立方贴橙圆柱 → 一个连通域。颜色投票被两色稀释，`:122-123` 的 70% 门槛很容易让 **两件都变成 `unknown`** |
| `RETR_EXTERNAL` | `:99` | 只留最外圈。接触件 **不可能** 分成两个轮廓 |
| 面积门 `MAX_AREA_FRACTION=0.22` | `:18,103-104` | 三件以上黏成一坨时，整坨被当成过大噪声丢掉 → **画面上「什么都没有」**，比 CHECK 更糟 |
| 形状要求 `solidity≥0.90` | `:59-60` | 两凸包件的并集凹陷，solidity 掉下去 → `unknown`。连「这是两件」都不会说 |
| 贴黄框 → 形状作废 | `:106,125-126` | 挤在托盘边的件即 CHECK |
| 颜色在轮廓局部计票 | `:107-123` | 即便以后换成 YOLO 框，**框里若含邻件，HSV/MMCQ 一样脏** |

V3 在「分开放、面朝上、三物料」下橙色圆柱曾通过；青/蓝仍 CHECK（`00_先看这里.md:52-53`）。六物料约 **4 FPS**（同文件 `:54`；单物料曾约 7.8 FPS）。这是 **CPU 上 Python + `image2cv` + 逐轮廓 HSV + 送显** 的实测，**不是** NPU 跑 YOLO 的帧率。不能把 4 FPS 直接当成「检测模型也会 4 FPS」。YOLO 上机帧率 **未验证**。

第一赛段 `BIN_MAP`（`:34-38`）里 **每种颜色最多对应一种形状**。这是当前 6 类表的性质，**不是赛规保证**。省赛「种类不少于 6 种」（`:55-56`）允许同色不同形。任何「只看颜色就能定盒」的捷径，只能写在 6 类表仍然成立的前提下，见 §3.3。

### 1.2 三个方案（按「谁来把一件从一坨里拆开」分）

#### 方案 A — 按色连通域 + 同色内距离变换/分水岭（V3.1 传统 CV）

**做法**：

1. 不再把所有颜色 OR 成一张 mask。对每个颜色范围（现有 `COLOR_RANGES`）各自 `inRange`，各自 `RETR_EXTERNAL`。
2. **异色接触**：这一步已经拆开。青贴橙不再是一个轮廓。这是 V3 没吃到的免费午餐。
3. **同色接触**（两只橙圆柱贴在一起，5 分加成的典型情形）：对该色 mask 做 `distanceTransform` → 在距边足够远的峰点放种子 → `watershed` 或条件腐蚀。每个峰当成一件。
4. 形状仍走现有 `shape_from_contour`（或 W16 落地后不再走它，见 §1.4）。
5. 颜色取样只在 **腐蚀后的核** 上做（V3 已有 `erode`，`:110`），禁止用外接矩形。

| 维 | 评估 |
|---|---|
| 精度 | 异色贴紧：高（前提：灯光/红橙边界稳，V3 已记录橙 H=4..5、红 H=177，边界脆弱）。同色贴紧、尺寸接近、顶面凸：中。堆叠、倾倒成非凸剪影、污渍把两色连成桥：低 |
| 算力 | 320×320 上多几个 `inRange` + 一次 `distanceTransform`，相对 V3 是同量级 CPU。风险不是 NPU，是 Python 循环。生产路径关掉 `render`/逐件 `putText` 后，4 FPS 有机会回到单物料那种 ~8 FPS 量级。**未验证** |
| 实现难度 | 低。不换模型、不改协议。可在 PC 上用整合包 `05_离线验证/check_stage1_contours.py` 那套离线入口做合成图单测 |
| 与随机姿态 | **不解决**。侧放圆柱的剪影是矩形，三棱柱侧放更不是三角形。这是 W16 要换模型的原因，方案 A 单独上不够 |

#### 方案 B — 外轮廓凹点 / 曲率分割

**做法**：继续 V3 的并集外轮廓，找凸缺陷（`convexityDefects`）或曲率极大的凹点，连线切开。

| 维 | 评估 |
|---|---|
| 精度 | 两圆相切这种教材图可以。三棱柱顶面本身有尖角；倒角会「多一个小顶点」（V3 `:61-62` 已在躲这件事）。凹点既可能是「两件交界」，也可能是「一件的合法顶点」。侧放、堆叠、污渍缺口会再造假凹点 |
| 算力 | 比 A 更便宜（只处理轮廓点） |
| 实现难度 | 中。阈值（凹深度、夹角）必须按物料直径标定，换一批物料就漂 |
| 结论 | **不作为主方案**。它修的是「一个轮廓怎么切」，而真正该修的是「不要先把所有颜色并成一个轮廓」 |

#### 方案 C — 检测模型当实例分离器（与 W16 同路）

**做法**：形状不再从轮廓来。W16 的检测模型（YOLO-detect 家族，MaixCAM 转换页目前列的是 `yolov5u/yolov8/yolo11/yolo26` 的 **detect**，见 `docs/design/2026-08-23-maixcam-deployment-facts.md:54-56`）直接出每件的框。颜色仍在框内做 HSV/MMCQ（冻结口径：`参数冻结表` 第 8 条「颜色不进模型」）。

接触问题改写成三个工程问题，而不是「切轮廓」：

1. **训练分布必须含接触、倾倒、部分遮挡**。若数据集仍是「面朝上分开放」（W16 提示词已要求先看 `D:\AAAdesktop1\shijue\yolo_dataset`），重训也救不了随机摆放。这是 W16 的路线闸门，本方案不替它下结论。
2. **NMS 与「重复即失败」必须为多件改语义**。现有 `视觉/src/sorting_vision/postprocess.py:53-57`：同类 IoU>阈值就进 `suppressed`；`reject_duplicates=True`（`config.py:22`）时 **整帧抛 `DuplicateDetectionError`**。两只同色同形件贴紧（要拿 5 分加成的那对）正好触发这条。`视觉/README.md:92-94` 还写着「一帧多个互不重叠目标违反单目标约束」。这两条与「托盘里 ≥12 件」直接冲突。方案 C 落地时必须：**允许多目标；同类接触不当成协议级失败；NMS 只去真重复，不去掉贴紧的第二件**。
3. **颜色取样不得用裸 bbox**。框会吃到邻件。必须：框与「该色 mask」求交，再腐蚀；或只取框中心 r×r 核（r 取物料像素的 ~1/4，需实测）。MMCQ 已经比均值抗污渍（`color_quant.py` 文件头），但抗不了「半框都是邻居」。

| 维 | 评估 |
|---|---|
| 精度 | 上限最高：实例分离靠外观而不是连通域。下限取决于数据。现有训练记录 `val_acc=0.4241`、六棱柱 0.0529（`maixcam-deployment-facts.md:46-50`），**当前权重不能当接触场景的检测器** |
| 算力 | 走 NPU，与 V3 的 CPU 轮廓不是同一条预算。上机 FPS **未验证**。不能用「V3 已经 4 FPS 所以再加模型会更卡」来否决 C——也可能更快。也不能保证 448 输入的 detect 一定 >4 FPS |
| 实现难度 | 高，但 **W16 已经在付这笔钱**。本任务不要再训一个分割模型 |
| 分割模型？ | **本季不上实例分割**。转换页列出的是 detect；seg 的 `.mud` 链、解码器、算力都未验证。颜色用「框 ∩ 色 mask」就能吃到分割 80% 的好处 |

### 1.3 对比与推荐

| | 方案 A 按色+分水岭 | 方案 B 凹点 | 方案 C 检测框 |
|---|---|---|---|
| 异色接触 | 强 | 弱（先并集再切） | 强（若数据有） |
| 同色接触 | 中（靠距变换峰） | 弱 | 中–强（NMS 是坑） |
| 随机姿态 | 不解决 | 不解决 | 这才是换模型的理由 |
| 堆叠只见上件 | 上件可能检出，下件本就不该编造 | 同左 | 同左 |
| 算力（SG2002） | CPU，与 V3 同量级 | 更轻 | NPU，FPS 未验证 |
| 实现 | 低，可当 V3.1 | 中，阈值脆 | 高，W16 主责 |
| 推荐 | **C 未上线前的过渡；C 上线后降为色核取样 + 同色漏检补救** | 不上 | **主方案（骑 W16）** |

**推荐组合（不是三选一独占）**：

- **主路径 = C**（W16 的 detect + 框内颜色）。本任务对 C 的附加约束只有三条：多目标合法、`reject_duplicates` 不能再整帧失败、颜色从色核取。
- **过渡 / 补救 = A**。W16 数据不够或转换失败时，A 至少能把「异色黏连 → CHECK」变成「两件分开」。同色黏连用距变换；失败则交给策略层跳过，不走凹点。
- **B 明确不上。**

### 1.4 如果 W16 走了 X，本方案怎么改

W16 此刻还没有落地文档（本仓库 `docs/` 下 2026-09-16 未见 W16 设计稿）。下面按它**提示词里已经写死的方向**预留改接线，避免两套检测器抢主链。

| W16 实际路线 X | 检测层怎么改 | 不要做什么 |
|---|---|---|
| **X1 检测模型出框 + HSV/MMCQ 出颜色**（提示词的原计划） | 本方案的实例分离 **就是** 这个检测器。A 的按色 mask 只服务于「框内取色」和「检测漏掉的同色黏连补救」。抓取点用检测框中心（再映射到 mm），不用并集轮廓质心 | 不要在 detect 前面再跑一遍全图分水岭当主检测；不要上 seg |
| **X2 分类器吃 crop，没有检测头** | 提案器必须是 A：按色 CC + 同色距变换出 ROI，再把 ROI 送分类器。凹点仍不上 | 不要用 `RETR_EXTERNAL` 并集去切 crop，那会把两件送进同一个分类器 |
| **X3 数据不够、仍用 V3 轮廓形状** | 只上 A。形状继续 `shape_from_contour`，接受「侧放必 CHECK」。策略层用跳过消化 | 不要假装分水岭能认三维形状 |
| **X4 有人想上 YOLO-seg / SAM** | 本季否决。等 MaixHub 真能转 seg 且 FPS 有数再说。颜色问题用「框 ∩ 色 mask」挡着 | 不要为接触问题单独开一条分割训练 |

无论 X 是哪条：`BATCH_TARGETS` 仍按现契约发 **多个目标**（`interface-contract.md §5.1`），X/Y 仍是像素；树莓派仍每周期只取一个（W14）。检测层出 N 个过关件，策略层选 1 个。协议不用为接触改字段。

## 2. 抓取策略层

### 2.1 看不见的件怎么办

三选一里 **「先抓挡它的那件，回 HOME，再看」** 是唯一与现有时序、W14、0° 相机同时相容的。

| 选项 | 为什么不/为什么要 |
|---|---|
| 跳过它、永远不再看 | 下件被抓走后它可能露出来。永久跳过是把可恢复的 2/5 分扔掉 |
| 等它自己露出来（夹爪不动） | 赛规 `省赛规则.txt:144,284`：超过 15 秒没有动作或没有显示本次分拣信息，**本轮结束**。干等是自杀。3 分钟赛时（`:277-278`）救不了这 15 秒 |
| **先抓挡着的可见件** | 0° 下「挡着」= 堆在上面的、或检测框完整且不贴边的。抓走后世界改写，W14 的下一帧自然看到新集合 |

「被夹爪挡住的托盘角」不是邻件问题，见 §4.2，不能靠先抓邻件解决。

机械臂运动过程中画面被臂挡住：**不要在运动中取帧当决策**。时序已经禁止「边走边看」（`抓取时序:108-114`）。决策帧 = 夹爪在停放位、机构静止后的新图。

### 2.2 「最近」是不是最优？TSP 该不该接进主链？

**不是。而且在当前机构决策下，`greedy_tsp` 优化的根本不是真实路径。**

证据：

1. **它没接主链**。仓库里只有 `电控/src/electrical_control/scheduler/tsp_solver.py`、`phased_scheduler.py` 和对应测试；`run_chain.py` 不用它。接进去是新决策，不是「把写好的打开」。
2. **真实路径不是巡游。** 用户已定每件：`HOME → 新图 → 抓取点 → 落料 → HOME`（`抓取时序:68-80`）。件与件之间 **不存在** 从件 i 走到件 j 的边。`greedy_tsp` 的边是 `current_pos → nearest`，默认还从 `(0,0)` 起算（测试也这么写）——而 `(0,0)` 正是禁止停的挡镜点。
3. **校赛目标是转盘方案 B**（`02-机构方案A-vs-B.md` v2.0）：落料 XY **固定**，转盘选格。于是每件路径是 `HOME → pick_i → PLACE_固定 → HOME`。`d(PLACE, HOME)` 对所有件相同。TSP 巡游长度与这个代价几乎无关。
4. **W14 删掉 `_pending` 之后，根本没有「12 件的静态名单」可巡。** 抓完一件，接触件可能被拖走、堆叠可能塌。对过期坐标做 2-opt 是在优化一张不再为真的地图。
5. **`phased_scheduler.py` 把 15 秒切成 0–7 / 7–12 / 12–15 三阶段**，把 15 秒当成「整轮时限」。赛规里 15 秒是 **失动/无显示** 判负，整轮是 **3 分钟**。这套相位策略与赛规时钟不是同一件事。

**在「避免遮挡 + 每件回 HOME + 最新帧只取一个」下，排序目标是本帧的一个标量，不是全局路径：**

```
本帧候选 = 检测结果中同时满足：
  (颜色, 形状) 能查到 box_id
  可见性过关（框未贴 ROI 边、色核占比够、未与夹爪停放位像素重叠）
  置信度 ≥ CONF_TH（冻结 0.5）

在候选里选 argmax：
  1. 隔离度          —— 与其他框的最小间距；贴紧的降权，不直接删除
  2. 同类成组（转盘方案 B）—— 若转盘已停在某格，优先同 box_id，少转一次
  3. HOME 到该件的距离 —— 唯一还与「近」有关的项（缩短 HOME→pick）
  4. 禁止用「离上一件抓取点近」—— 上一件抓完已经回 HOME 了
```

`tsp_solver.greedy_tsp` **不要**接进主链。若以后要复用文件，最多把它的欧氏距离函数拿来算 `d(HOME, pick_i)`，不要拿巡游结果当顺序。`two_opt_improve` 同理。

隔离度优先的理由：贴紧件抓取时夹爪可能带走邻件或一次夹两件。赛规 `省赛规则.txt:267-268`「一次只能分拣一件货物」；掉落在装置内/外直接 **本轮结束**。错盒是丢分，掉落是清零。所以「近而黏」劣于「远而孤」。

### 2.3 抓走一件后其他件会不会动？视觉多久能反映？

**会动。必须按「会动」设计。反映时间 = 回 HOME 的运动时间 + 静止后 1～2 帧，不是检测算法的 FPS。**

会动的机制（均为物理推断，未验证幅度）：

- 接触件：夹爪闭合/提起时的剪切把邻件拖偏或带起
- 堆叠：上层被抓走，下层滚动
- 薄壁件 / 圆柱侧放：托盘振动
- 一次误夹两件，半路掉下一件（这是掉落判负，比坐标过期更严重）

W14 把 `_pending` 清掉，就是承认这件事。正确闭环：

```
HOME 到位且机构静止
  → 丢弃运动期间的所有帧
  → 取 ≥1 张新图（建议 2 张一致才用；不一致则再取，上限必须远小于 15 秒）
  → 只把「过关候选」交给 §2.2 的选择器
  → 选出 1 个 → 发 ITEM_TASK
  → 抓放显示完成后回到 HOME，坐标全部作废
```

V3 约 4 FPS → 两帧一致大约 0.5 s，相对一次 HOME→pick→place→HOME 的运动可忽略。**未验证** 的是：HOME 到位后画面还要多久才没有臂残影、曝光是否稳定。策略上「静止后再要新图」已经写在时序里（`抓取时序:70-72`）；缺的是「运动帧作废」这条纪律，不是更快的模型。

MaixCAM 可以继续在 `BATCH_TARGETS` 里带上本帧所有过关件（监控/屏幕/调试需要）。树莓派 **执行** 只取一个。检测层出多件与策略层用一件不冲突。

### 2.4 选择器遇到「本帧一个过关件都没有」

按下面顺序，**不要猜 box_id**：

1. 仍在 HOME，再要 1～2 帧（灯光闪、瞬时模糊）。
2. 仍无：若有「颜色过关、形状 CHECK」且当前 6 类 `BIN_MAP` 颜色唯一（§3.3），允许用表补形状——这不是猜。
3. 仍无：本周期不发 `ITEM_TASK`。固件只要还在做「可观察动作」（例如保持停放、心跳不够）—— **心跳不能续 15 秒**（`2026-08-30-motion-time-budget.md:78`）。所以必须有一个 **合法的小动作** 刷新「有动作」：例如夹爪在 HOME 做一次已标定的短 Z 点头，或 XY 在可达域内移几毫米再回来。具体动作属固件，本文件只要求：**不许为了续时去抓一个 CHECK 件。**
4. 连续多个周期全 CHECK：接受漏分，保住已经进盒的分。不要做「拨一下分开」——协议没有「只挪不放」的 `ITEM_TASK`，现场拨动还可能掉落判负。

## 3. 失败语义（引赛规）

### 3.1 条文（现场初赛 A3 计分，`:262-271`）

1. 储物盒中只有一个货物得 **2 分**；多个颜色和形状相同的货物放进同一储物盒，**每个货物得 5 分**；货物必须全部进入，没有全部进入的不计算数量（`:262-264`）。
2. 将不同颜色 **或者** 不同形状的货物放入同一储物盒（**只要货物部分进入**）为分拣错误，**不得分**（`:265-266`）。
3. 一次只能分拣一件；分拣掉落在装置范围内的货物或将货物掉落在装置外，**本轮比赛结束**（`:267-268`）。
4. 正确显示序号、货物名称、图片、成功总数量，**每条信息得 2 分**；**出现任何错误不得分**（`:269-271`）。一种读法是四项各 2 分 = 每件显示最多 8 分；另一种是把整屏当一条。无论哪一种，**名称/图片写错 → 该件显示分全丢**。显示分与货物分是两套账，猜错会两头都炸。
5. 本次分拣信息没有显示前而分拣下一件，不得分（`:275`）。

另：「必须将形状相同且颜色相同的货物分拣到同一个储物盒」（`:140-141`）。6 个独立储物盒（`:42-43`）。初赛不少于 12 件、种类不少于 6 种（`:55-56`）。

「不得分」在第 2 条没有写清是「该盒 0」还是「本轮 A3 全 0」。两种读法下，**猜盒的期望值都是负的或接近 0**，见下。设计按 **整盒归零** 算（较宽）；若现场按 **整轮归零** 执行，结论只会更硬。

### 3.2 算账：漏分 vs 猜

设某盒已有 2 件正确同类，已锁定 5+5=10 分。现在来了一件 CHECK。

| 动作 | 猜对（1/6，若 6 类均匀——这已经是对「瞎猜」的乐观假设） | 猜错 |
|---|---|---|
| 放进该盒 | 盒变为 15 | 该盒 0，10 分蒸发；该件也 0；屏幕名称错再丢显示分（`:271`） |
| 放进空盒 | 该盒 2 | 该盒 0；原 10 分还在（仅在「不得分=该盒」读法下） |
| 跳过 | 10 分保留；该件 0 | 同左 |

即便空盒瞎猜的「乐观期望」≈ 2/6 ≈ 0.33 分（货物分），一旦猜错且现场采用「分拣错误整轮不得分」，期望是 **-（本轮已有全部货物分+显示分）**。12 件全对且两两成组时，货物分上限 12×5=60；显示若按四项×2 计，上限另有 96。用一件 CHECK 去赌，是在用整轮打一件 2 或 5 分。

**结论：判不出 `(颜色,形状)` 时跳过。禁止为 CHECK 件填 `box_id`。** 这与 V3「CHECK 不分配货格」（`:6`）和冻结表「颜色+形状都匹配才分配」一致。

漏分的上限：一件 2 分（它本会独占一盒）或 5 分（它本会加入已有同类）。12 件里永久看不见的（压在最底、整场没露出来）本来就无法得分，不算策略失败。

### 3.3 唯一不算「猜」的补全

当前第一赛段 `BIN_MAP` 颜色唯一。若色核以高比例投出唯一表内颜色、形状因接触变成 `unknown`：用表补 `(形状, box_id)` 是在用已冻结映射，不是在 6 个盒里掷骰子。

**这条在下列任一成立时作废**（作废后回到纯跳过）：

- 省赛现场出现 **同色不同形**（赛规允许）
- 红橙/黑影导致色核本身不可信（V3 已有这个边界）
- W16 的类别表让同一颜色对应多个 `shape_id`

屏幕名称必须与送入的盒一致。用表补全时，显示的是表上的那个名字；若现场实物其实是同色异形，这会同时触发错盒与错显示——所以启用前必须确认「本轮词表颜色仍唯一」。**未验证现场词表。**

### 3.4 与 W14「box_id 缺失则拒识该件、链路继续」对齐

CHECK / 无 `box_id`：该件从本帧候选删除，**不发 `ITEM_TASK`**，不占 `target_seq`。不要发「去 (0,0) 抓」的占位（抓取点无缺省编码，`(0,0)` 就是去中心抓，见 `interface-contract.md:165`）。

## 4. 相机安装（不加第二摄像头）

### 4.1 夹爪挡镜头 与 件互遮挡 不是同一个硬件解

| | 夹爪挡镜头 | 件–件接触/堆叠 |
|---|---|---|
| 根源 | 夹爪与光轴争托盘中心 | 裁判随机放置；0° 下主要是连通域合并与堆叠，不是透视挡 |
| 已有解 | 停 HOME、不去 (0,0)（已拍板） | 检测分离 + 先抓可见件 + 每件重拍 |
| 把相机挪高 | 透视更接近正交，HOME 处夹爪在画面里变小；**不能**让夹爪离开托盘角（见 §4.2） | 正交化 **几乎不增加** 顶面可见性；接触合并与高度无关 |
| 斜视 / 第二视角 | 相机方案已否决斜视作主方案；用户否决第二摄像头 | 斜视会引入视差（40 mm 高、30° → 23 mm，相机方案 §2），换来的侧面信息救不了连通域，还要重训 |

**不要为接触问题改 0° 居中决定。** 那是为了视差=0 和「放错盒不得分」。接触是算法与策略问题。

### 4.2 一个现有停放方案自己的洞（对抗点，不是新相机）

托盘 ≥160×160、中心约 (0,0)（冻结表第 11 条）→ 托盘覆盖约 `[-80,80]²` mm。可达 ±82.5 mm。HOME 现在是 `(-80,-80)`（`抓取时序:69`；旧预算文档里还有 -145 的占位，以时序/冻结表为准）。

HOME 几乎就在托盘角上。夹爪有宽度（**张开尺寸空白**，冻结表 U-5 / `参数冻结表:163`）。**停在 HOME 拍照时，近 HOME 的那只角很可能长期被夹爪占着**——这不是「抓取过程挡一下」，是 **每一决策帧都挡同一块**。先抓「挡着的邻件」也救不了它，因为挡它的是停放中的夹爪自己。

不加第二摄像头的处置，按代价从低到高：

1. **ROI 仍覆盖整盘，但选择器把与夹爪模板重叠的检测作「不可见」**，本帧不抓它们。抓别处，盘面变空后，角上的件相对夹爪的像素关系会变，有机会露出来。若它就在夹爪正下方，可能整轮露不出 → 漏分，接受。
2. **在 ±82.5 里把 HOME 再往外挪 2.5 mm 到 (-82.5,-82.5)**。只能把夹爪中心移出托盘边，爪宽仍可能探入。需要机械确认爪宽。**未验证。**
3. **双停放位**（仍一个摄像头）：奇数件在 `(-82.5,-82.5)` 拍，偶数件在 `(+82.5,-82.5)` 拍，让被挡的角轮换。不改协议（抓取点仍在 `ITEM_TASK` 尾部），要改运动规划，属后续固件工作，本文件只提案、不改。
4. **相机在中心正上方升高**（机械净空允许的前提下，相机方案 U-1/U-2 仍空）。升高让夹爪在画面占比下降，并方便把 FOV 收到略大于 160、让 HOME 落在画面外。这是安装微调，不是第二视角。

### 4.3 本任务对安装的建议（可执行、不改文件以外的硬件直到机械组确认）

- **保持** `01-相机安装方案.md` 的决定 1–3：中心、0°、拍照时夹爪在停放位。
- **不要**为接触/遮挡加摄像头、不要改斜视。
- **要**机械组回答：夹爪在 HOME、Z 在最高时，俯视图里夹爪投影是否压住托盘。若压住，优先试 §4.2 的 1+2；净空不够再谈升高。
- 补光保持均匀。按色连通域和 HSV 在接触边界最怕阴影当「黑件」、高光当白底孔。这比换镜头更影响方案 A/C 的取色。

## 5. 每个方案什么时候会崩（对抗复核）

下面是作者对自己方案的攻击。能写进「何时会崩」的，都不算已解决。

### 5.1 方案 A（按色 + 分水岭）

1. **红贴橙、青贴蓝**：V3 自己的色边界就是试调的（`:23-24`）。两件在色空间相邻时，「按色拆开」退回并集。崩。
2. **同色两件 + 阴影桥**：黑圆柱的 `dark` 范围是 `(0,0,0)-(179,100,85)`（`:32,94`），阴影也进暗通道，距变换峰可能出现在阴影里，种子长在空地上。崩。
3. **污渍/二维码**（赛规 `:52-53`）：高饱和色块把异色 mask 连起来，或在一件内部造假峰，一件变两件。后一种会让策略去抓一个「不存在的中心」，空夹或撞邻件。
4. **尺寸差大**：40 mm 件贴薄壁件，距变换只看得到大件的峰，小件被当噪声。`MIN_AREA_FRACTION=0.0015` 也可能把薄件滤掉。
5. **堆叠**：上件核套在下件核上面，分水岭给不出「下面那件」。A 若硬输出两件，抓取点会落在上件里却配了下件的盒。必须：**一个峰只报一件，下面那件本帧不存在。**
6. **随机姿态**：拆开了也认错形状 → 若此时还用轮廓定 `box_id`，就是错盒。所以 A 在 X3（仍用轮廓形状）下必须保持高 CHECK 率，不能为了「拆开了」就放松 `solidity`。
7. **算力**：多色 mask + 分水岭 + 仍 `disp.show`，4 FPS 再掉。决策帧是静止后拍的，FPS 低不直接导致抓错，但「两帧一致」可能拖到秒级；再叠加回 HOME 的时间，15 秒失动窗口变紧。**未验证哪一段是 4 FPS 的主因。**

### 5.2 方案 B（凹点）—— 作为主方案时

1. 三棱柱合法顶点 ≈ 两件之间的凹点。切开等于把一件切成两件。
2. 并集轮廓在三件黏成串时凹点组合爆炸，切缝没有唯一解。
3. 与 W16 的检测框双重定义「什么是一件」，两套 ID 对不上。

这些就是不上 B 的原因。若有人把凹点塞进 A 的同色补救：只允许「同色、两峰、凹深相对物料直径过阈值」时切一刀，第三件及以上仍跳过。

### 5.3 方案 C（检测模型）

1. **数据全是分开放、面朝上**：接触场景 mAP 崩。W16 若没先回答训练集姿态，C 不能当主检测。
2. **`reject_duplicates=True` 原样上主链**：两只要拿 5 分的同类贴紧 → 整帧失败 → 一个候选都没有 → 走 §2.4 的空转 → 15 秒失动。这是 **现成代码级的崩点**，不是假想。
3. **NMS IoU=0.45 吃掉第二件**：不一定整帧失败，但少报一件。若再把「少报」当成「不存在」，策略永远不会去抓它，除非邻件被清走后 IoU 下降。部分可恢复。
4. **裸 bbox 取色**：分离成功、颜色失败 → CHECK 或更糟的 **颜色错、形状对 → 错盒**。C 的颜色污染比漏检更致命，因为漏检是漏分，颜色错是 §3.1 第 2 条。
5. **conf 0.5 在接触帧上偏高或偏低**：高则漏，低则假框。假框抓空或抓邻件边缘。
6. **词表 7 类 vs 现场 6 种、cuboid 已排除**：模型仍可能把接触变形的剪影认成 `cuboid`/`hexagonal_prism`。active 集过滤后该件消失（看起来像漏检）或若没过滤就进错误盒。
7. **NPU FPS 未验证**：若上机比 V3 还慢，且 W16 把检测和 MMCQ 都放 MaixCAM 一帧里，静止后「两帧一致」可能要 1 s+。不直接错盒，但会挤显示前的 15 秒。
8. **本方案骑 W16**：W16 若延期，C 不存在。必须能单独上 A，不能出现「等模型」的空窗把校赛拖死。

### 5.4 抓取策略 / W14 / TSP

1. **把 `greedy_tsp` 接进主链** 且仍从 `(0,0)` 起算：第一件就规划到中心附近，夹爪进画面，后续坐标全是挡镜帧。崩。
2. **在转盘方案 B 下按 XY 巡游优化、不按 `box_id` 成组**：转盘每件都转，时间浪费；不直接错盒，但 3 分钟内少抓几件。
3. **隔离度权过重**：永远先抓孤件，黏在一起的两只同类（5+5=10）留到最后，最后夹崩或超时。需要「隔离度不够但颜色形状都很干净」时仍允许抓，只是排在孤件之后，而不是删除。
4. **先抓「挡着的」若识别反了**：把下面那件的标签贴到上面那件上。0° 堆叠时只该相信 **最上面那块色核**。没有深度传感器（MaixCAM 事实：GC4653，无 IMU，深度也无）。
5. **空候选时用 CHECK 件续 15 秒**：直接违反 §3。
6. **W14 去重过狠**：静止托盘上同一件每帧都过关，若没有「上一件已抓的空间记忆」，会不会对空位再抓？W14 提示词自己问了这件事。策略层需要的不是 TSP，是 **刚完成的抓取点附近、短时间内不再选**（托盘已空）。记忆必须短：邻件可能滑进这个空位。记 1 个刚抓点 + 半径（约 30 mm，未验证）足够；记 12 件全局 ID 会与「世界已变」打架。
7. **一次夹两件**：检测层分离成功也不能保证夹爪物理分离。爪宽未知。两件同盒还好（都是 5 分），两件异类进同一盒 = 第 2 条不得分；中途掉一件 = 本轮结束。这是策略解不了的机械风险，只能靠「优先孤件」降概率。

### 5.5 失败语义

1. **把 `BIN_MAP` 颜色唯一推广到省赛**：同色异形出现之日，§3.3 从「表补全」变成「系统性错盒」。必须每轮确认词表，不能写死在代码里当物理定律。
2. **「不得分」若现场执行成整轮 A3=0**：任何一次错盒都是灭顶。更加禁止猜；连 §3.3 表补全都要更高的色核比例。
3. **部分进入也算错**（`:265-266`）：放料点偏了、件卡在盒沿，即使形状颜色都对，也可能被判「部分进入且看起来像另一件」——这是机械/转盘精度，不在本方案内，但策略不能用「再推一下」去补，因为可能掉落。
4. **显示错误不得分**（`:271`）：跳过 CHECK 件时 **不要** 往屏幕写一个编造名称。漏显示分优于错显示分。

### 5.6 相机 / HOME

1. **HOME 压住托盘角**（§4.2）：该角的件整轮不可见。方案在「接受漏分」上自洽，但若裁判把两只 5 分件都堆在那个角，损失是 10 分不是 2 分。
2. **升高相机却 FOV 仍罩住整个 350 装置**：夹爪还在画面里，只是小一点；色核更脏（背景进框）。升高必须配合 **FOV 收到托盘略外一圈**。
3. **把接触问题拿去重开斜视讨论**：视差 1 cm 级（相机方案 §2）会把抓取点系统性地推到邻件上。接触没修好，错盒先来了。

### 5.7 组合崩（多条同时发生才显现）

- W16 数据不够（C 崩）+ 仍用 V3 并集轮廓（A 没上）+ `_pending` 还在（W14 没上）= 一帧黏成一个 CHECK，再把过期坐标排成队。这是当前主链若「什么增强都不上」的默认结局。

- A 上了、C 没上、姿态随机 = 拆得开、认不对、若放松 CHECK 就错盒。对抗结论：**拆开之后仍然 CHECK 的，必须继续跳过。**

## 7. 验证方法（仍不改代码、不上电也可做的部分）

目的是以后谁实施时有可重复的判据，不是本任务去跑。

**离线检测（PC，合成或静物照片）**

- 用 6 色纸片或实物在 160 mm 见方白底上摆：分开放 / 异色对贴 / 同色对贴 / 三件串 / 两件叠 / 贴边 / 带阴影。
- 方案 A 成功标准：异色对贴必须出 2 个核；同色对贴允许出 2 个核或 1 个核+CHECK，**禁止出 3 个核**；叠放只许报上件。
- 方案 C 成功标准：同类对贴必须 2 个框（NMS 后），IoU>0.45 时不得整帧失败；每个框的色核颜色 = 该件颜色，不得吸邻居。
- 现有 V3 对照：同一组图上，并集 `RETR_EXTERNAL` 应能复现「两件变一个 CHECK 或超面积消失」，作为基线，不是作为验收。

**策略层（纯逻辑单测，不需要相机）**

- 输入一帧假检测：3 个过关孤件 + 2 个贴紧同类 + 1 个无 box_id。期望：选孤件；无 box_id 不出现在输出。
- 下一帧：刚才那件消失，贴紧对变成两个孤件。期望：能选其中一个，而不是报「已抓过的旧坐标」。
- 输入空候选。期望：不产生 `ITEM_TASK`，尤其不产生抓取点 (0,0)。

**安装**

- 夹爪停 HOME、Z 最高，看一张俯视照片：托盘四角各放一件，哪几件的顶面被夹爪挡住。这张照片就能决定要不要双停放位。本任务没有这张照片。

## 8. 一页结论（给拍板用）

1. **检测**：主路骑 W16 的检测框（方案 C）；V3.1 上按色连通域 + 同色距变换（方案 A）作过渡和取色核；**凹点分割不上**；**实例分割本季不上**。现成崩点：`postprocess.reject_duplicates` 与「单目标约束」注释。
2. **抓取**：看不见 = 本帧当它不存在；先抓可见且隔离的；每件回 HOME 用新帧；**不要把 `greedy_tsp` 接进主链**。「近」只作为 `d(HOME, pick)` 的并列项，排在隔离度和（转盘方案 B 下）同盒成组之后。世界会动，视觉反映 = 静止后 1～2 帧，不是模型 FPS。
3. **失败语义**：CHECK / 接触导致判不出 → **跳过漏分，禁止猜盒**。依据 `省赛规则.txt:262-266`（错盒不得分，且部分进入即算）和 `:269-271`（显示错也不得分）。仅当本轮词表仍「一色一形」时，允许用冻结 `BIN_MAP` 从高置信颜色补形状。
4. **相机**：不改 0° 居中，不加第二摄像头。夹爪挡镜头继续靠停放位；件互挡靠检测+重拍。真正要补的安装洞是 **HOME 可能压住托盘角**，先量爪宽和一张 HOME 俯视照片。
5. **会崩**：见 §5。最便宜也最致命的三发子弹是——并集轮廓还在、`reject_duplicates` 还在、把 CHECK 猜进已有分的盒子。
6. **没验证**：§6 全表。

本文件不进入实现。W16 路线一旦从 X1–X4 里钉死一条，按 §1.4 改接线即可，不必重做策略层与失败语义。
