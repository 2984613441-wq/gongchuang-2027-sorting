## 1. 第 0 步：上电前必须确认的 4 件事（闸门）

| # | 项目 | 怎么确认 | 合格判据 | 不合格怎么办 |
|---|---|---|---|---|
| 0-1 | **舵机型号** | 看舵机本体标签/包装/采购记录 | 明确写下 **MG996R（模拟，无位置反馈）** 或 **LDX-335MG（数字）** 之一 | 认不出来 → 按“**停 PWM 会掉**”的最坏情况处理，并记录“型号未验证” |
| 0-2 | **引脚 = PB10** | ① 目视追线；② 万用表通断档量 MCU PB10 ↔ 舵机信号线插头；③（最后做）不接舵机动力，发 P1500，用频率档量信号线应 ≈50 Hz | 信号线与 PB10 连通 | 若线其实在 PB11 → **本次停止**，不要改代码硬测，先报告 |
| 0-3 | **供电** | 独立稳压 5–6 V，≥3 A；舵机红/黑直接接电源；**GND 与 STM32 共地**；信号线只接信号 | 空载 5.0–6.0 V；舵机动作瞬间 ≥4.8 V | 从 STM32 取电 / 用 12 V / 不共地 → 一律停止 |
| 0-4 | **急停是否切动力电** | 万用表 DC 电压档量**舵机电源插头处红线对黑线**；拍下急停前后读数 | 急停前 5–6 V，急停后 **<0.5 V（应 0 V）** | 急停后仍有电压 → 不合格：在 5–6 V 正极串一个**手边能拍到的开关/插头**，把它当本次测试的急停 |

> 为什么 0-4 是一道闸门：固件里的 `EC_INPUT_ESTOP_FB` 只是**反馈输入**，`ec_safety_port_inhibit_power()` 的注释原文写明危险电源由外部硬件切断。**只拉 GPIO 不够**。

## 2. 安全前置清单（逐条覆盖 B 份指出的 7 条）

| # | B 份要求 | 本 SOP 的规定动作 | 判据 |
|---|---|---|---|
| 1 | 先手动居中再上电 | 断电状态下手动把 Z 升降与夹爪摆到中位（原点方案 A：上电位置即原点），并用垫块/扎带确认不会自行下滑，再上舵机动力 | 断电时机构能停在中位不自落 |

| 6 | 人员站位与隔离 | 见 §3 | 禁入半径已用胶带标出 |
| 7 | 首次最小脉宽步进 | 1500 起、≤100 µs；白名单做不到的限制与替代做法见 §4 | 第一条发值命令是 `SERVO PB10 P1500` |

补充项（B 份另行要求，同等强制）：

- **独立 5–6 V 供电 + 与板共地；禁止从 STM32 取动力电**（MG996R 堵转约 2.5 A）。

- **禁止把手伸进机构或运动包络**（要限制机构就用木块/泡沫垫/扎带）。

- **安全半径 ≥1.0 m**（机构尺寸未定，取保守值）；非操作人员退出该圈，测试期间不得进入。

## 4. 首次最小脉宽步进（硬规定 + 白名单限制 + 替代做法）

**顺序规定**

- 第一发：**1500 µs**（中位基线）。
- 之后：1500 → 1400 → 1300 → 1200 → 1100 → 1000（向下），或 1500 → 1600 → 1700 → 1800 → 1900（向上）。
- **每步 ≤100 µs**；接近极限后改 20–50 µs。
- **禁止** 1000/1900 首发；**禁止** 1500 直接跳 1100 或 1900；**禁止**在 1100 ↔ 1900 之间来回甩。

**白名单带来的限制（必须知情）**

白名单只有 7 档：1000 / 1100 / 1200 / 1300 / 1500 / 1700 / 1900。从 1500 出发，下一档只能是 **1300 或 1700 = 200 µs 步进**，达不到 ≤100 µs；1400 / 1600 / 1250 等都不在集合内。**所以：单纯用现有台架无法满足“≤100 µs 首测步进”这条安全要求。**

**三个替代做法（按推荐度排序）**

1. **【首选】外部舵机测试器**（现场若有一个）：可任意步进（20–50 µs），PWM 通常**持续保持**、不会 2 s 自动停。
   - 使用前必须**断开 STM32 → 舵机的信号线**（避免两个源同时驱动），只保留舵机电源与共地。
   - 用它做端点细探；STM32 台架只用于确认链路与粗方向。
2. **【零代码改动，次选】独立裸机最小台架** `docs/plans-2026-09-16/z_servo_bench.c`：接受 500–2500 µs 任意值。
   - 编译期必须选 **PB10**：在最小 Keil 工程的 Define 里写 `Z_SERVO_CH=3`（文件里默认 4 = PB11 是旧假设，必须覆盖）。
   - ⚠️ 它**没有** ARM / 白名单 / ESTOP 状态机，**唯一保护是物理断电**；2 s 自动停（模拟舵机会失力，必要时重发同值）。
   - 用完烧回生产固件。
3. **【建议，需 L4 批准；只写进建议，不擅自改】给测试白名单加 1400/1600**：需动 `ec_servo_test.c:21-30`、`ec_diag.c:52-60`、HELP `:325` 三处，属代码改动，测完必须还原，**不得就地长期保留**。

不管走哪条：**1500 是绝对第一发，且第一发前先拆舵盘。**

## 5. “憋死”识别（表笔位置 + 阈值 + 观察时长）

| # | 判据 | 怎么测（表笔/位置） | 阈值 | 观察多久 | 立即动作 |
|---|---|---|---|---|---|
| ① | 持续嗡鸣 | 耳朵离舵机 10–20 cm（脸不要进运动包络） | 与正常运转声不同即算 | 每次输出看满 2 s | 断电（§6） |
| ② | 电流显著上升 | 万用表 **10 A 档串在 5–6 V 电源正极 ↔ 舵机红线之间**（负极不动，绝不串信号线）；表笔用夹子固定，人不进运动区 | 空载正常 ≤0.3 A（规格推算，未实测）；持续 >1.0 A 或瞬间 >1.5 A = 疑似憋死；**≥2.0 A 立即断电** | 每次输出全程读表 | 断电（§6） |
| ③ | 外壳发热 | 手背快速轻触外壳，或红外测温 | >60 °C（烫得不能久放）= 立即断电 | 每档输出后立刻摸一次；**每档之间歇 ≥10 s**；连续探端点每 3 档休息 ≥1 分钟 | 断电（§6） |
| ④ | 异响 / 抖动 / 爬行 / 复位 | 目视 + 听；同时盯串口 | 任何咔哒、齿响、抖动、原地爬行、位置不随脉宽变化、STM32 复位（串口重新打印 BOOT） | 每次输出全程 | 断电（§6） |
| ⑤ | 电源欠压 | 万用表 DC 档常接舵机电源插头 | 动作瞬间 <4.8 V | 每次输出 | 停测，检查电源/线径 |

> ⚠️ 模拟舵机（MG996R）堵转嗡鸣**可能很小**，不能只靠听——②电流和⑤欠压是主要判据。
> ⚠️ 台架固定 2 s 自动停 PWM，**观察窗口只有 2 s**；2 s 后看到机构缓慢下落是模拟舵机的正常现象，但会造成夹手/砸件。

## 6. 超出行程时的立即处置（写死顺序）

1. **不要伸手**：垫块/泡沫垫/扎带应在**通电前**就预置在 Z 下方。
2. **拍物理开关**，切断舵机 5–6 V 动力电 —— 这是唯一可靠的“停”。
3. 随后（或同时）发 `SERVO STOP`、`STOP ALL`（软件停 PWM，是补充不是替代）。
4. 保持机构被垫住/绑住，直到确认不会回落；**只有断电且确认无动力后**才允许手接触。
5. 记录该脉宽为“超限点”并写明现象；从该值**回退 ≥50 µs**（细步进时 ≥20–30 µs）再试。
6. 若已撞机械/卡死：**不要反向硬顶**；断电后手动解除，检查舵机齿、摇臂、连杆是否变形，再决定是否继续。

**“停 PWM 后会不会掉”**

- **MG996R（模拟）**：通常会**失力、带载可能下落**（规格结论，本机未实测）。
- **LDX-335MG（数字）**：通常仍能保持（未实测）。
- **型号未定时按“会掉”处理** → 必须垫住/绑住 Z，每次发值前垫块已就位。

### 7.2 串口接线 —— 先解决"谁占用 USART2"（2026-09-16 补，原文漏写）

🔴 **`SERVO` 命令走的串口，和树莓派走的是同一条物理线。一条 UART 不能同时挂两个发送方。**

证据（2026-09-16 23:50 逐行复核）：
- 诊断输出 `ec_diag_port_write()` → `HAL_UART_Transmit(&huart2, ...)`（`App/Src/ec_board_stm32.c:660-669`）
- 主链路 `ec_board_uart_transmit()` → **同样是 `huart2`**（`:686-695`）
- USART2 = **PA2(TX) / PA3(RX)**（`Core/Src/stm32f4xx_hal_msp.c:451-459`），115200 8N1
- `USART3`(PD8/PD9) 虽被 `MX_USART3_UART_Init()` 初始化（`Core/Src/main.c:121`），
  但 **App 里没有任何代码使用 `huart3`** → 接到 USART3 收不到任何 SERVO 回显，**别走这条**

**接法 A（推荐，稳妥）— 把树莓派从 USART2 上摘下来，改用 USB-TTL 接 PC**

1. **先断电**。
2. 从 STM32 的 **PA2 / PA3** 上拔掉树莓派过来的线。
   ⚠️ 至少必须拔掉树莓派的 **TX**——两个输出（树莓派 TX + USB-TTL TX）接到同一个输入
   （PA3）会电气打架；建议 **TX/RX 一起拔**，并记下原位置以便复原。
3. USB-TTL 接线：**TX→PA3（STM32 的 RX）、RX→PA2（STM32 的 TX）、GND↔GND**。
   ⚠️ 先确认 USB-TTL 是 **3.3 V 电平**；5 V 电平会打坏 PA2/PA3。
4. PC 串口助手：**115200 8N1**，**命令必须以 CRLF（`\r\n`）结尾**，否则固件整行匹配不上。

**接法 B（不拔线）— 从树莓派上直接发 ASCII**

树莓派本就在 USART2 上。`App/Src/ec_app.c:576-578` 的入口分流是：
收到 `0xA5` → 走二进制协议；**否则 → 交给 ASCII 诊断**。
所以树莓派往串口直接写 `SERVO ARM\r\n`，效果等同从 PC 发：

```bash
python3 -c "import serial,time; s=serial.Serial('/dev/serial0',115200,timeout=1); s.write(b'SERVO ARM\r\n'); time.sleep(0.3); print(s.read(300))"
```

⚠️ 前提两条：
- **`run_chain.py` 绝不能同时在跑**（它会抢串口，且说的是二进制协议）；
- 串口设备名要自己确认：`ls -l /dev/serial*`，或
  `python3 -c "import serial.tools.list_ports as p;print(list(p.comports()))"`。

**接法选择建议**：树莓派侧还没跑通、或不想在半夜排查设备名 → **走 A**。
树莓派已在线且只想省事 → **走 B**，但务必确认 run_chain 没在跑。

### 7.3 串口链路自检（接线完成后）

- **USART2**：PA2 = TX、PA3 = RX，**115200 8N1**，ASCII，命令以 **CRLF** 结尾。
- 上电应看到：`BOOT SAFE HSI=16000000 SAFE_LOCK=1 ENABLES=DISABLED`。
- 之后**每秒自动一行** `STATUS ...`（`ec_diag.c:596-601`）。
- 看不到这两样 → 串口或固件不对，**不要继续**。

## 11. 🔴 会出人命 / 会烧东西的点（逐条读）

1. **舵机动力从 STM32 板取电**（5 V 排针/LDO）→ 堵转 2.5 A 烧稳压器、烧板、可能起火。必须独立 5–6 V。
2. **急停只进 MCU、不断动力** → 软件只能停 PWM，2 s 后还会自动停；一旦堵转持续，舵机与电源线发热冒烟。必须先做 §1-0-4 验证。
3. **带载探端点 / 超程** → 机构撞碎、夹手、舵机齿崩。必须先拆舵盘空载。
4. **首发 1000 或 1900**（或在 1100↔1900 之间跳）→ 一次几十度甩动，夹手、打坏连杆。必须 1500 起、≤100 µs。
5. **烧旧 hex**（servo-demo v1–v4）→ 旧串口 USART3 + 旧结构 + 旧舵机，结论全错，甚至按旧值带载运行。只烧当前源码重建的固件。
6. **开 GROUP / BARRIER** → XY 与舵机同时动 / 打到空脚或方案 B 转盘脚。全程保持 0。
7. **测完忘记把宏改回 0** → 生产固件带诊断与台架命令出厂，任何人都能发 SERVO/GROUP。必须走 §9.3。
8. **型号混判**（模拟 vs 数字）→ 以为停 PWM 会保持，实际掉下来砸手砸件。按最坏情况垫住。
9. **信号线与动力线接错**（5–6 V 灌进 MCU 引脚）→ 烧 MCU，可能连带整板。接线前断电、先量通断。
10. **不共地** → 舵机乱跳/抖动，被误判成代码 bug，越调越糟。
11. **手伸进机构“帮它到位”** → 夹/切/砸。用木块；手只在断电后进场。
12. **电源线/表笔线留在运动包络里** → 被带动拉断、短路。表笔用夹子固定，线走桌外。
