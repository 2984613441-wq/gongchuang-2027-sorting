## 问题 1：0° 倾角下单应矩阵是否退化成仿射？退化后 4 点够不够？

### 回答：是，退化成仿射；4 点够，但建议 6 点

### 证明

单应矩阵（Homography）是 3×3 矩阵，有 8 个自由度：

```
[h11 h12 h13]   [u]       [x']
[h21 h22 h23] × [v]   ~=  [y']
[h31 h32 h33]   [1]       [w']

x = x'/w', y = y'/w'
其中 w' = h31*u + h32*v + h33
```

**当相机与平面平行（0° 倾角）时**：
- 没有透视畸变（远近等比缩放）
- h31 = 0, h32 = 0, h33 = 1（归一化后）
- w' = 1（齐次坐标的尺度因子为常数）

**退化后的矩阵**：

```
[a11 a12 tx]   [u]       [x]
[a21 a22 ty] × [v]   =   [y]
[0   0   1 ]   [1]       [1]

即：
x = a11*u + a12*v + tx
y = a21*u + a22*v + ty
```

这正是 **仿射变换**，只有 **6 个自由度**：
- 缩放（2）：a11, a22
- 旋转（1）：a12, a21 的组合
- 剪切（1）：a12, a21 的另一维度
- 平移（2）：tx, ty

### 退化后 4 点够不够？

**理论最少**：3 对点
- 6 个未知数（a11, a12, tx, a21, a22, ty）
- 每对点提供 2 个方程（x 方程 + y 方程）
- 3 对点 = 6 个方程 → 刚好求解

**实践建议**：4-6 点
- **4 点**：有 2 个冗余约束（8 方程 - 6 未知数），可用最小二乘抑制测量误差
- **6 点**：有 6 个冗余约束（12 方程 - 6 未知数），覆盖工作区边界，鲁棒性最好
- **9 点**：过密集（人工摆放累积误差大，边际收益递减）

**结论**：
- ✅ 4 点够用（理论上）
- ✅ 6 点推荐（工程上）—— 4 角 + 2 中点，覆盖 ±82.5mm 工作区

## 问题 2：存单应矩阵 9 个分量还是仿射 6 个参数？

### 回答：仿射 6 个参数（a11, a12, tx, a21, a22, ty）

### 理由

#### 1. 符合物理约束

0° 倾角下，相机与托盘平行，**不存在透视畸变**：
- 单应矩阵的 h31, h32 理论为 0
- 存储 9 个分量会浪费 3 个自由度（h31, h32, h33）
- 仿射 6 参数完整描述了这个退化情况

#### 2. 避免过拟合

用 8 自由度（单应）去拟合 6 自由度（仿射）的问题：
- 多余的 2 个参数（h31, h32）会吸收测量噪声
- 产生"伪透视"效应（实际不存在）
- 降低泛化性能

#### 3. 数值稳定性

单应矩阵需要归一化除法：
```
x = (h11*u + h12*v + h13) / (h31*u + h32*v + h33)
```
当 h31, h32 接近 0 时（退化情况）：
- 分母 ≈ h33 ≈ 1，但浮点误差会放大
- 除法误差传播比线性变换大

仿射是纯线性变换：
```
x = a11*u + a12*v + tx
```
- 无除法，误差传播更可控
- 中间结果范围可预测

#### 4. 配置文件可读性

**仿射 6 参数**：
```ini
[CameraCalibration]
a11 = 0.26      # X 方向缩放
a12 = 0.0       # X-Y 耦合（旋转/剪切）
tx = -83.2      # X 平移
a21 = 0.0       # Y-X 耦合
a22 = -0.26     # Y 方向缩放
ty = 62.4       # Y 平移
```
- 每个参数有明确物理意义
- 便于人工检查（a11≈-a22 说明等比缩放 + 翻转）

**单应 9 分量**：
```ini
h11 = 0.26
h12 = 0.0
h13 = -83.2
h21 = 0.0
h22 = -0.26
h23 = 62.4
h31 = 0.0       # ⬅️ 理论为 0，但浮点误差可能不为 0
h32 = 0.0       # ⬅️ 同上
h33 = 1.0       # ⬅️ 归一化常数
```
- h31, h32 接近 0 但不精确为 0 → 引入困惑
- h33 需要手动归一化

### 实现方式

在 `pixel_to_device.py` 中，仿射参数存储为 3×3 矩阵（便于 NumPy 运算）：

```python
self.affine_matrix = np.array([
    [a11, a12, tx],
    [a21, a22, ty],
    [0.0, 0.0, 1.0]   # 第三行固定
], dtype=np.float64)
```

**优点**：
- 配置文件只需 6 个参数（人工可读）
- 代码中用 3×3 矩阵（向量化运算高效）
- 兼顾可读性和性能

## 问题 3：参数用整数还是浮点？

### 回答：浮点（float64）

### 理由

#### 1. 仿射参数必然是浮点

旋转、缩放、剪切分量无法用整数表示：
- `a11 ≈ 0.26`（mm/pixel）
- `a12 ≈ 0.001`（旋转耦合项）

#### 2. 相机高度和物体高度

- 相机高度：398.5mm（测量精度 ±0.5mm）
- 物体高度：34.8mm（游标卡尺精度 0.1mm）

#### 3. 工作区限制

- ±82.5mm（不是整数）
- 若用整数存储，需要改成 ±82 或 ±83 → 丢失精度

#### 4. 中间计算精度

视差补偿公式：
```
scale = camera_height / (camera_height - object_height)
      = 400.0 / (400.0 - 35.0)
      = 1.095890...
```
- 若用整数，scale 只能是 1 → 视差补偿失效

#### 5. 最终输出可以是整数

装置坐标最终转为 0.1mm 整数（协议要求）：
```python
x_mm10 = int(round(x_bottom * 10))
```
- 中间计算用 float64（IEEE 754 双精度，15 位有效数字）
- 最后一步舍入成整数

### 精度损失分析

| 阶段 | 类型 | 精度 |
|------|------|------|
| 配置文件存储 | 字符串 | 任意（如 "0.123456"） |
| 加载后 | float64 | 15-17 位有效数字 |
| 中间计算 | float64 | ±1e-15（相对误差） |
| 最终输出 | int | 0.1mm（协议单位） |

**结论**：float64 精度远超测量精度（±0.5mm），完全够用。

## 问题 4：超出 ±82.5mm 怎么办？

### 回答：拒识（返回 None），记日志，链路继续

### 三种选项对比

#### 选项 A：钳位到边界（不推荐）

```python
x_mm10 = max(-825, min(825, x_calc))  # 强制在 [-825, 825]
```

**问题**：
- 钳位后的坐标 ≠ 物体真实位置 → 抓空
- STM32 可能执行成功（坐标在可达域内），但夹爪到的是空位
- 误导调度算法（TSP 以为物体在边界，规划路径错误）

---

#### 选项 B：抛异常，停止链路（不推荐）

```python
if x_calc > 82.5 or x_calc < -82.5:
    raise ValueError("物体超出工作区")
```

**问题**：
- 一件物体超出 → 整条链路停止
- 其他可抓取的物体也无法处理
- 违反 fail-closed 原则（局部问题不应扩散成全局故障）

---

#### 选项 C：拒识该件，链路继续（✅ 推荐，已实现）

```python
if not (x_limits[0] <= x_bottom <= x_limits[1]):
    return None  # 拒识，不构造 payload
```

**优点**：
- fail-closed：不确定的数据不进入执行
- 局部化：只影响该物体，其他物体继续处理
- 可观测：记录 WARNING 日志，便于排查

**日志输出**：
```
WARNING: 物体超出工作区，拒识：target_seq=3, class_id=2, 
         像素(50,30) → 装置坐标超出 ±82.5mm
```

### 上游处理（vision_ingest.py）

```python
for target in batch.targets:
    grasp_point = coord_converter.pixel_to_device(u, v, class_id)
    if grasp_point is None:
        # 超出工作区，跳过该件
        _LOGGER.warning("物体超出工作区，跳过该件")
        continue  # 不构造 payload，不进入队列
    
    # 正常件继续处理
    payload = ItemTaskPayload(...)
    payloads.append(payload)
```

### 为什么超出 ±82.5mm 的物体不应抓取

- **可达域 < 协议域**：
  - 协议域：±145.0mm（±1450 单位 0.1mm）
  - 可达域：±82.5mm（硬件限制，见参数冻结表）
- **STM32 会拒绝**：
  - 固件有 `REACH_LIMIT_MM10 = 825` 检查
  - 超出 → 返回 `POSITION_UNREACHABLE`
- **记作失败件**：
  - 虽然最终也是失败，但提前拒识更高效
  - 避免 XY 轴做无效运动

## 问题 5：配置放哪个 .ini？要不要改 control_panel.py？

### 回答：新建 `电控/calibration_config.ini`，Phase 1 不改面板

### 理由

#### 1. 为什么不放 sorting_config.ini

**风险**：
- `sorting_config.ini` 已有 10+ 节，结构复杂
- 运维频繁修改（对应表、落点表、调度参数）
- 标定参数应保持稳定（一次标定，长期使用）

**解耦原则**：
- 标定参数 ≠ 运行参数
- 标定由专人负责，现场调参由操作员负责
- 分离后，调参不会误改标定参数

#### 2. 为什么不放 motion_config.json

**风险**：
- `motion_config.json` 当前有 `TypeError`（台账 E-14）
- JSON 格式不如 INI 人工可读（无注释、嵌套复杂）
- 运动参数与标定参数无直接关联

#### 3. 新建 calibration_config.ini 的优点

- **独立文件**：标定参数与其他配置解耦
- **INI 格式**：人工可读，支持注释（便于现场标定时填写说明）
- **专人维护**：标定文件由视觉/电控联合维护，不给操作员修改权限

#### 4. control_panel.py 改动评估

**Phase 1（本次交付）：不改面板**

**原因**：
- 标定是低频操作（一次标定，长期使用）
- 手动编辑 `calibration_config.ini` 可接受
- 面板当前只管理 4 个节（BoxMap / DropPoints / ColorThresholds / DisplayNames）
- 新增节需要改动 ≈50 行代码 + 测试

**Phase 2（联调后，可选）：新增标定管理 Tab**

**如果需要**（用户反馈"手动编辑不方便"），再改面板：

**改动量**：≈50 行
- 新增 `6 标定管理` Tab（与 `3 对应表` 平级）
- 显示：6 个仿射参数 + 相机高度 + 标定日期
- 编辑：6 个 QDoubleSpinBox + 1 个日期选择器
- 按钮：`重新标定`（启动九点标定流程）、`验证`（九宫格反向验证）

**改动位置**：

**判断标准**：
- 若现场需要频繁重新标定（更换相机/物料）→ 加面板

## 总结：设计决策一览表

| 问题 | 决策 | 理由 |
|------|------|------|
| 单应 vs 仿射 | **仿射（6 参数）** | 0° 倾角退化，避免过拟合，数值稳定 |
| 参数点数 | **4-6 点** | 理论最少 3 点，4 点有冗余，6 点覆盖边界 |
| 整数 vs 浮点 | **浮点（float64）** | 仿射参数、相机高度、视差补偿都需要浮点 |
| 超出工作区 | **拒识（返回 None）** | fail-closed，局部化，可观测 |
| 配置文件 | **新建 calibration_config.ini** | 解耦，独立维护，INI 人工可读 |
| 改面板 | **Phase 1 不改，Phase 2 可选** | 标定低频，手动编辑可接受，需求驱动 |
