class VisionTarget:
    target_seq: int
    class_id: int      # 形状ID
    box_id: int | None # 颜色+形状 → 盒号（视觉侧折叠）

    Y: int             # ⬅️ 像素坐标（bbox中心 v）

**当前 build_item_task_queue() 的逻辑**（简化）：

```python
def build_item_task_queue(
    batch: BatchTargets,
    image_id_for_class: Callable[[int], int],
    drop_point_for_box: Callable[[int], tuple[int, int] | None],
    grasp_point_for_target: Callable[[VisionTarget], tuple[int, int] | None] | None,
) -> tuple[ItemTaskPayload, ...]:
    """构造 ITEM_TASK 队列（当前只用落料点，抓取点未接入）"""
    
    payloads = []
    for target in batch.targets:
        # ⚠️ 当前逻辑：X/Y 是像素，但被直接忽略
        # 落料点从 drop_point_for_box(box_id) 查表
        # 抓取点未实现（grasp_point_for_target=None）
        
        drop_point = drop_point_for_box(target.box_id)
        if drop_point is None:
            continue  # 未知 box_id，跳过该件
        
        x_mm10, y_mm10 = drop_point  # 落料点（0.1mm）
        
        # ⚠️ 问题：抓取点（target.X, target.Y）没用上
        # 构造 payload（抓取点写死 None）
        payload = ItemTaskPayload(
            target_seq=target.target_seq,
            class_id=target.class_id,
            image_id=image_id_for_class(target.class_id),
            x_position=x_mm10,      # 落料点
            y_position=y_mm10,      # 落料点
            grip_angle=0xFF,
            pick_x_position=None,   # ⬅️ 抓取点缺失
            pick_y_position=None,   # ⬅️ 抓取点缺失
        )
        payloads.append(payload)
    
    return tuple(payloads)
```

## 4️⃣ 超出工作区的处理（关键决策）

### 选项 A：钳位到边界（不推荐）

```python
if grasp_point is None:
    # 超出 ±82.5mm，钳位到边界
    x_mm10 = max(-825, min(825, x_calc))
    y_mm10 = max(-825, min(825, y_calc))
    grasp_point = (x_mm10, y_mm10)
```

**问题**：
- 钳位后的坐标不是物体真实位置 → 抓空
- 误导调度算法（以为物体在边界）

---

### 选项 B：拒识该件（推荐，已在代码中实现）

```python
if grasp_point is None:
    # 超出工作区，拒识该件，记录日志，链路继续
    _LOGGER.warning("物体超出工作区，跳过该件")
    continue  # 不构造 payload
```

**优点**：
- fail-closed：超出工作区的物体不应被抓取
- 链路继续（不抛异常，不影响其他物体）
- 符合赛规（随机摆放可能有物体在边缘外）

**采用理由**：
- 超出 ±82.5mm 的物体 STM32 拒绝执行（协议域 ±145mm，但可达域 ±82.5mm）
- 抓取会失败 → 记作失败件 → 影响成功率
- 不如直接拒识，让用户重新摆放

## 5️⃣ 未标定时的行为

### 当前行为（未接入前）

- 抓取点字段为 `None`（`pick_x_position=None, pick_y_position=None`）
- STM32 固件忽略 `None`（协议未扩展时的兼容行为）
- 只用落料点，抓取点写死 (0,0) 或固定值

### 接入后（未标定）

- `coord_converter.is_calibrated == False`
- `grasp_point = None`（与当前行为一致）
- **不影响现有功能**：未标定时退化成原行为

### 接入后（已标定）

- `coord_converter.is_calibrated == True`
- `grasp_point = (x_mm10, y_mm10)` 或 `None`（超出工作区）
- **启用新功能**：抓取点使用视觉检测的真实坐标

## 6️⃣ 与 BATCH_TARGETS 字段语义的关系

### 红线遵守

**BATCH_TARGETS 的 X/Y 字段语义不变**：
- 协议定义（interface-contract.md §5.1）：X/Y 是像素坐标
- 本模块 **只读取** X/Y，不修改
- 转换结果写入 `ItemTaskPayload.pick_x_position/pick_y_position`（新字段）

### 数据流

```
MaixCAM: BATCH_TARGETS.X/Y (像素)
    ↓ (不变)
vision_ingest.py: target.X/target.Y (像素)
    ↓ 【转换】
pixel_to_device.py: pixel_to_device(u, v, class_id)
    ↓ (输出)
ItemTaskPayload.pick_x_position/pick_y_position (0.1mm)
    ↓ (协议字段)
STM32: ITEM_TASK payload[9:12] (抓取点，0.1mm)
```

**X/Y 字段全程保持像素语义，转换结果用新字段承载。**

## 7️⃣ 与 socket_vision_source.py 的 TSP 排序

### TSP 排序依赖的字段

**当前代码**（`socket_vision_source.py:195-209`）：

```python
def _order_payloads(self, payloads):
    """按贪心最近邻（TSP）排序"""
    # 用 payload.pick_x_position/pick_y_position 排序
    # 若缺失（None）→ 跳过排序，按原顺序
    
    if any(p.pick_x_position is None or p.pick_y_position is None 
           for p in payloads):
        _LOGGER.debug("抓取点缺失（像素→mm 未注入）：跳过 TSP 排序")
        return payloads
    
    # 按 (pick_x, pick_y) 排序
    ordered = greedy_tsp(
        list(payloads),
        self._current_position,
        position=lambda p: (p.pick_x_position, p.pick_y_position),
    )
    return tuple(ordered)
```

### 接入后的行为

- **未标定时**：`pick_x/y = None` → 跳过 TSP，按原顺序（与当前一致）
- **已标定时**：`pick_x/y = (x_mm10, y_mm10)` → TSP 排序生效

**兼容性**：接入后不影响未标定时的行为。
