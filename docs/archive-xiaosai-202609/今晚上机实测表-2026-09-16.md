### 🔍 怎么确认设备在 `WAIT_TASK`

**设备不在 `WAIT_TASK` 时，发帧是"静默无响应"——没有任何错误码。** 所以别靠"发一帧试试"来判断。

三种确认方式，任选：
1. **先只监听不发**：`link_check_stm32.py`（若已交付）或直接看有没有 `BARRIER_READY`(0x20) 帧
2. **看板子上的指示**（若有 LED / 调试输出）
3. **按启动按钮**：`ec_app_poll_start_button` 只在 `FAULT_LOCK` 下生效，
   如果按了有效果 → 说明之前在 FAULT；如果按了没用 → 可能已经在跑或卡在别处

> 启动序列：`POST → HOMING → （挡板已跳过）→ WAIT_TASK`，走完会发 `BARRIER_READY`。

## 🔧 故障速查（今晚最可能撞到的）

| # | 现象 | 最可能原因 | 怎么办 |
|---|---|---|---|
| **F1** | 第一帧动了，**后面怎么发都不动** | 设备停在等 `DISPLAY_ACK`（工具发不了）。**这是设计，不是坏** | **按启动按钮复位**，或重新上电 |
| **F2** | 发了帧，**完全没有回应**，也没报错 | ① **设备不在 `WAIT_TASK`** ② 波特率错 ③ TX/RX 接反 ④ 没共地 ⑤ DTR/RTS 复位了 STM32 | 先按 F2 的顺序排；用"只监听不发"确认设备是否活着 |
| **F3** | **每次运行都收不到，手动发却正常** | CH340 的 **DTR/RTS 接了 RESET/BOOT0** → 一开串口就复位 STM32 | 换不带自动下载的 USB-TTL，或断开 DTR/RTS |
| **F4** | 串口打不开 | 被树莓派程序 / `monitor_gui.py` 占用 | 关掉占用进程；工具会列出可用串口 |
| **F5** | 收到 `ITEM_RESULT` 里 `result_code=0x03` (`POSITION_UNREACHABLE`) | 坐标超了 **±825** | 把 \|x\|,\|y\| 降到 825 以内 |
| **F6** | 收到乱码 / 半截帧 | 波特率不是 115200，或线太长/干扰 | 检查 8N1、线长 |
| **F7** | 机构动了，但**方向或距离明显不对** | 行程/steps_per_mm 与实际不符 | 就是 A 表要量的东西 |
| **F8** | Z 舵机不动 | Z 在 PB10；若你接的是 PB11 → 固件打的是 PB10 | 确认舵机信号线接的是 **PB10** |
| **F9** | 舵机嗡鸣/发烫/憋死 | 脉宽超出新结构行程 | **立刻停**、断电、回到 1500 中位小步试探 |

### 今晚用的三条命令

```powershell
# 找串口
py -3 -m serial.tools.list_ports -v

# 只打印字节，不开串口（安全，随时可跑）
py -3 工具\pc_item_task.py --port COM__ --task-id 7 --x 0 --y 0 --class-id 2 --dry-run

# 真发一帧，监听 20 秒
py -3 工具\pc_item_task.py --port COM__ --task-id 7 --frame-seq 1 --target-seq 1 `
    --class-id 2 --x 0 --y 0 --listen-s 20
```

> ⚠️ **不要重复执行同一行** —— 契约规定：相同 `(task_id, target_seq)` 携带不同载荷
> 一律视为协议冲突并进入故障。要重试就换 `--target-seq`。
