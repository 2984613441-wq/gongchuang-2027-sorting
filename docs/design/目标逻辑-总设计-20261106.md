# 目标逻辑总设计（2026-11-06 版，供评审与后续修改）

> 用途：把**我们后面真正要跑的逻辑**从"视觉 → 协议 → 决策 → 排序 → 分格 → 转盘/滑台 → 落料 → 复看 → 记分/结束"一条条列清楚，
> 供你逐条看"有没有不对的地方"。**新对话里我们按编号改（L1、L2…），不用重述背景。**
> 标记约定：`[已实现]` 代码已有；`[要改]` 目标与原实现不同；`[待定]` 需你拍板；`【待标定】` 现场量。

## 0. 系统总览（一页）

```
                    ┌──────────── 树莓派（决策中心） ────────────┐
 MaixCAM 主相机 ───► │ ①收帧 ②滤波/稳定 ③code ④排序 ⑤分格      │
 (YOLO判形+HSV判色)  │ ⑥生成 ITEM_TASK ⑦显示/记分 ⑧复看纠正      │
        ▲            └───────┬──────────────────────┬───────────┘
        │ 8765 (TCP)          │ UART 115200          │ UART2 1Mbps
        │ BATCH_TARGETS       ▼                      ▼
        │              ┌────────────┐        ┌────────────────────┐
        │              │ STM32F407  │        │ STS3215 转盘(360°) │
        │              │ XY/Z/夹爪/ │        │ 6 格 / 单一落点     │
        │              │ 槽门/灯    │        └────────────────────┘
        │              └────────────┘
        │
   副相机 DF200（Pi USB）：只在落料位判"颜色"，做复看兜底
```

**三端分工（不变量）**
- L0 `[已实现]` 主相机只负责"看见并报码"；不做运动决策。
- L0 `[已实现]` 树莓派是唯一决策中心；STM32 只执行，不参与选件。
- L0 `[已实现]` 转盘是"执行器"，角度属于树莓派内部细节，**不上协议**。

## 1. 视觉逻辑（主相机）

- **L1** `[已实现]` 采集 1280×720，模型输入 448×448；只用于检测，不影响坐标。
- **L2** `[已实现]` 检测 6 类形状：`1=cube 2=cuboid 3=cylinder 4=pentagonal_prism 5=cone 6=tetrahedron`。
- **L3** `[已实现]` 颜色用 **HSV 在框内采样**判 5 色：`1=红 2=黄 3=绿 4=蓝 5=白`；输出 `color_id`。
- **L4** `[已实现·要启用]` **合成码**：`code = (shape_id-1)*5 + color_id`，范围 1..30；`code=0` 表示"判不出"。
- **L5** `[已实现]` 只发 6 类（越界 class 直接丢，避免整批被接收端拒绝）。
- **L6** `[要改]` **判不出就拒识该件**（`code=0` 不发或发 0，接收端不抓），绝不猜形状/颜色。
- **L7** `[已实现·待标定]` 置信度阈值：全局 `--conf`（现 0.40）；支持分类别阈值 `--min-conf-by-class`（如 penta/cuboid 0.55），**分类阈值必须 ≥ 全局**。
- **L8** `[已实现·默认关]` 多帧类别投票（Pi 侧）：默认 `unanimous`（3 帧全一致才采纳）+ 超时按"目标年龄"算 + 换轮清空 + 位置栅格键。
- **L9** `[待实现·可选]` **几何校验（特征点方案）**：只在设备端（MaixCAM）做——框内轮廓拟合，数**边数 4 vs 5** + **长宽比**；与模型结论不一致 ⇒ `code=0`。Pi 端**做不了**（只有中心点）。
- **L10** `【待标定】` 五色 HSV 阈值按现场灯光标定；灯带两路都要亮（CH0/CH1）。

## 2. 协议与数据语义（冻结，不改）

- **L11** `[已实现]` 主相机→Pi：TCP 8765，`BATCH_TARGETS` = `count(1) + task_id(2,BE)` + N×**7 字节**：`id_byte, conf, x(2,BE), y(2,BE), angle(0xFF)`。
- **L12** `[已实现·要启用]` `id_byte` 语义 = **code(1..30)**（`--id-mode code`；接收端 `BATCH_ID_BYTE_MODE=code`）。
- **L13** `[已实现]` Pi→STM32：统一外层帧（`0xA5 0x5A`+ver+src+dst+task_id+frame_seq+cmd+len+payload+CRC16/MODBUS），串口 115200 8N1。
- **L14** `[已实现]` `ITEM_TASK` = **12 字节**：`target_seq, class_id(=code), image_id(=class_id), x(2), y(2), angle(0xFF), pick_x(2), pick_y(2)`；坐标 0.1mm 有符号，|v|≤1450。
- **L15** `[已实现]` 抓取点缺失/角度≠0xFF/image_id≠class_id/越界 ⇒ **拒绝发帧**（fail-closed）。
- **L16** `[已实现]` 颜色不在 wire 上（编码在 class_id/code 里）；**转盘角度不在 wire 上**。
- **L17** `[已实现]` 每件运动参数（Z 取/放、夹爪闭合）**不占字节**，走固件"按形状查表"。
- **L18** `[待定]` 是否需要新增"转盘就绪/落料确认"回传？——属协议变更（L4 红线），默认**不加**。

## 3. 一帧的处理流程（Pi 决策核心）

```
收帧 → L20 时效 → L21 稳定门(首件) → L22 投票(可选) → L23 code解析/拒识
   → L24 动态分格(code→box) → L25 排序(全帧) → L26 取"当前最该抓的一件"
   → L27 生成抓取点/落点 → L28 下发 ITEM_TASK → L29 转盘/运动 → L30 显示/记账
```

- **L20** `[已实现]` 陈旧帧护栏：帧龄 > 2.5s 丢弃（防"视觉停了还在用旧坐标"）。
- **L21** `[已实现·现场开]` 首件稳定门：前 N 帧（默认 3）可见件集合签名不变才派第一件；有超时降级。
- **L22** `[已实现·默认关]` 多帧类别投票（见 L8）。
- **L23** `[已实现]` `code→(shape,color)` 解析；`code=0`/越界 ⇒ 该件拒识（不猜盒）。
- **L24** `[已实现·要启用]` 货格分配：`code→box_id`（`--slot-mode dynamic`；默认 static 为旧 BoxMap）。
- **L25** `[已实现]` 帧内排序：见 §4。
- **L26** `[已实现]` **一帧只派一件**（取排序第一）；不排队（防坐标过期）。
- **L27** `[已实现]` 抓取点：像素 → 仿射/视差 → 装置 mm → 加 `ToolOffset` → 滑台记账；落点：由策略给。
- **L28** `[已实现]` 下发 12B `ITEM_TASK`；等 ACK/NACK；拿 `ITEM_RESULT`。
- **L29** `[已实现·要接]` 转盘按格转角度 + 滑台去单落点 + 15 步动作链（见 §6）。
- **L30** `[已实现]` 屏幕两段显示 + 台账 + 日志。

## 4. 排序逻辑（选"下一件抓谁"）

- **L31** `[已实现]` 候选集 = 本帧所有"可派件"（box 已分配、不在已服务位置附近、不在 skip 集合）。
- **L32** `[已实现]` `order_mode` 可切：`legacy`(不排序) / `group`(分组→难度→行扫描) / `weighted`(加权) / 其他旧模式。
- **L33** `[已实现]` **加权分** = `0.70*前端 + 0.15*夹取难度 + 0.10*路线 + 0.05*隔离度`。
  - 前端 = 离"无壁开口边"越近越优先 → **依赖 `[Tray] open_side` 与相机前端轴**（`【待复测】`，机械已改）。
  - 夹取难度 = 形状难度层 + 置信度。
  - 路线 = 空爪行程 + 到上次落点距离。
  - 隔离度 = 周围件越少越优先（环带 = 夹爪包络半宽 + 10mm）。
- **L34** `[已实现]` **难件护栏**：圆柱/圆锥（难夹）不得排首位（否则第一件就掉 = 本轮结束）。
- **L35** `[已实现·要启用]` **主动放弃**：`skip_shapes=3,5` 时圆柱/圆锥**不发件**（但仍算障碍物）。
- **L36** `[待定]` **满格/无格可分配的件**：拒识（不抓）还是挤占？——见 Q1。
- **L37** `[已实现]` 停稳判据：连续 3 帧且位移 < 4mm 才算"停稳可抓"；超时降级。
- **L38** `[已实现]` 路线锚点：默认"上一次落点"，可切固定点。

## 5. 货格分配（动态，code 必上后）

- **L40** `[已实现]` 语义：`code(1..30) → box_id(1..6)`；**同一个 code 永远复用同一格**（同色同形同盒 = 5 分/件的前提）。
- **L41** `[已实现]` 新 code：从"未占用格"里选一格分配；格满 ⇒ 抛 `AllocatorFull` 或返回 None（不猜）。
- **L42** `[要改]` 选格准则：现实现是"与上次落点同侧优先"（两侧时代遗留）→ 360° 单落点应改为**转到该格角度最小/顺序最简单**（或干脆按固定顺序 1→6）。
- **L43** `[已实现]` 每次分配**持久化**（`--slot-journal`），断点续跑不丢；换轮重置。
- **L44** `[已实现]` 复看纠正：`correct(expected_code, actual_code, box_id)`；冲突时只记日志不改（避免静默覆盖）。
- **L45** `[已实现]` 满格/无格 = 该件**不派**（不是"塞进已有格"——那会混盒 0 分）。
- **L46** `【待定】` 6 格是否够：取决于 24 件的"色形组合数"（Q2）。

## 6. 落料 / 转盘（360° 单落点，目标形态）

- **L50** `[要改]` 配置形态：**只用 `[TurntableAngles]`**（`turntable_drop_point = X,Y` + `1..6 = 角度`）；删 `[TurntablePositions]/[TurntableSides]/[DropPoints]`。
- **L51** `[要改]` 角度来源：`box_id → 角度 → 位置值(0..4095)`；**位置域 API**（现有脉宽域只有 ±137°，180° 会被 [500,2500]µs 拦死）。
- **L52** `[已实现]` 驱动链路：Pi UART2 `/dev/ttyAMA1`，1Mbps，ID=1，`FF FF ID LEN INST …`；`SerialServoBackend` 已存在且是默认后端。
- **L53** `[已实现]` 时序：**派发前**下发目标角度（转盘与滑台并行，不占 15s 失活窗）；位置舵机绝对定位，重复发不累加。
- **L54** `[要改]` 到位校验：现守卫是方案C 的 GPIO17 索引；360° 改为**读回位置值**，与目标差 ≤ 20 counts（≈1.8°）算到位；超时/读不到 ⇒ **记 ERROR、锁转盘、停链**（fail-closed）。
- **L55** `[要改]` `run_chain` 解禁方案B（现在 `:1355-1363` 主动拒绝）。
- **L56** `[已实现]` 运动 15 步（PARK→PICK→Z取→夹爪闭→Z行→PICK→PLACE→Z放→开槽门→夹爪开→关槽门→Z回→PLACE→PARK→Z安全位），槽门必须"Z 到位后才开、放完要关"。
- **L57** `【待标定】` 每类件的 `z_pick/z_place/grip_close` 三组 µs（固件按形状查表）。
- **L58** `[已实现·待烧录]` 固件 v2 未编译烧录；当前 `FAULT_LOCK`，跑链前必须复位。
- **L59** `【待标定】` 单一落点坐标 + 6 格角度（SOP 已备）。

## 7. 落料位复看（副相机，颜色级）

- **L60** `[已实现·默认关]` 三档：`off / observe / correct`。
- **L61** `[已实现]` 副相机（Pi USB DF200）抓帧 → `[PlaceEye] roi` 采样 → HSV 众数 → `color_id`。
- **L62** `[已实现]` 判决三态：`MATCH / MISMATCH / UNKNOWN`（`UNKNOWN` 不动台账）。
- **L63** `[已实现]` `correct` 模式：MISMATCH 时纠正"code→box"台账（让后续同色件跟实际一致）。
- **L64** `[已实现]` 复看**只判颜色，不判形状**（Pi 无 YOLO 运行时；副相机模型在 PC）。
- **L65** `【待标定】` `[PlaceEye] roi` + 五色阈值；副相机要对准落料位。

## 8. 回合 / 记分 / 结束条件

- **L70** `[已实现]` 一轮开始：转盘回零/中位自检（`zero_check`，目视"指针在线 0"）→ 首件稳定门。
- **L71** `[已实现]` 记分：同 code 同盒 5 分/件；单品盒 2 分/件；混盒 0 分（不允许混格）。
- **L72** `[待实现]` **掉件检测**：赛规"掉件 = 本轮结束"。当前逻辑**没有可靠掉件检测**（只能靠视觉/复看发现异常）→ 见 Q3。
- **L73** `[已实现]` 结束条件：无件（连续空帧）/ 3 分钟 / 掉件 / 15s 无动作。
- **L74** `[待定]` 两次机会的策略：第一轮保守（A 或 C），第二轮激进（B）？见 Q4。
- **L75** `[已实现]` 每轮台账（得分/件数/跳过/复看统计）落盘，便于赛后对比三套方案。

## 9. 失败与回退（每层都有开关）

| 症状 | 回退动作 |
|---|---|
| 排序乱/变慢 | `--pick-strategy off` 或 `order_mode=legacy` |
| 分格转错 | `--slot-mode static`（旧 BoxMap）|
| 复看误判/拖慢 | `--verify-place off` |
| 转盘异常 | 锁转盘 + 停链（fail-closed）|
| code 模式出问题 | 发送端 `--id-mode shape` + 接收端 `BATCH_ID_BYTE_MODE=box_id` |
| 角度/落点可疑 | 回到方案A/旧配置（备份 ini）|
| 任何新功能 | 默认关 + 一键回退（不变量）|

## 12. 不变量（改代码不能破）

1. 一帧只派一件，不排队。
2. `class_id = code`（1..30），`image_id = class_id`。
3. 颜色/角度都不上 wire。
4. 判不出/满格/坐标越界 ⇒ **拒识，不猜**。
5. 转盘失败 ⇒ 锁死 + 停链。
6. 所有新功能默认关闭，可一键回退。
7. 改协议/固件/IO = L4，需明确授权。
8. 所有数值以**设备实读**为准，文档滞后时以设备为准。
