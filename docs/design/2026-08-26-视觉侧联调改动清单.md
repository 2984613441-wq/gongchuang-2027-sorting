# 视觉侧联调改动清单（2026-08-26）

> 用途：电控侧对视觉侧的要求，转交视觉/Pi 侧执行。三侧联调前必须对齐这些点。

## 1. 坐标边界 1350 → 1450（最高优先级）

XY 行程从 27cm 改为 **29cm**，工作空间边界从 ±135mm 放宽到 **±145mm**。

- 视觉侧任何 `±135mm` / `1350` 的坐标边界检查/限制，全部改成 `±145mm` / `1450`。
- 联调提示词 [2026-08-26-stm32-three-side-integration-prompt.md](../prompts/2026-08-26-stm32-three-side-integration-prompt.md) 第 38 行的 `1350（+-135.0 mm）` 改成 `1450（+-145.0 mm）`。
- 树莓派侧 [item_context.py](../../电控/src/electrical_control/protocol/item_context.py) 的 `_ITEM_TASK_X_LIMIT` 电控侧已改为 1450，**MaixCAM 侧若有边界常量需自查同步**。

> 不改的后果：视觉算出的坐标落在 ±135~145mm 之间会被旧边界卡掉/拒绝。

## 2. 落点表（电控执行投放的关键输入，必须实测）

电控侧编不出来，必须由视觉/机械侧实测提供：

```
box_id 1 → (X, Y)  # 0.1mm 单位，原点=装置中心，有符号
box_id 2 → (X, Y)
box_id 3 → (X, Y)
box_id 4 → (X, Y)
box_id 5 → (X, Y)
box_id 6 → (X, Y)
```

六个储物盒的实际中心坐标。没有它，电控收到 ITEM_TASK 后无法确定投放位置。

## 3. 协议约定需视觉侧确认（避免联调来回改）

| 约定 | 待确认 |
|---|---|
| `image_id == class_id` | 是否仍成立 |
| 活跃 `class_id` 集合 `{0,2,3,4,5,6}`（1=cuboid 本轮不出现） | 是否仍成立 |
| 颜色已折叠进 `box_id`，协议不单列颜色字段 | 确认 |
| `grip_angle` 恒 `0xFF`（夹爪不旋转） | 确认 |

## 给视觉侧的一句话

> 电控侧已把协议边界从 ±135mm 改为 **±145mm**（29cm 行程），视觉侧所有相关边界常量同步改；**落点表（box_id 1..6 → 实际 X/Y）是电控执行投放的必要输入，需实测提供**；其余协议约定（class_id 集合、image_id==class_id、颜色折叠进 box_id）请确认不变。
