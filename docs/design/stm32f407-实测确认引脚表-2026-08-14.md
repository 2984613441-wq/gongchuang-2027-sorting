>

> 规则：一个物理 GPIO 在最终设计中只分配一个角色。STM32 的复用功能只能选择其一，不能同时把同一引脚当作两个功能使用。

## 当前固定角色

下面四个角色用于下一步 X 轴限位停步测试，不允许互换：

```text
PC6 = X_STEP      （TIM8_CH1 脉冲输出）
PG7 = X_HOME      （GPIO 输入，上拉）
PA5 = X_ENABLE    （GPIO 输出，安全态为禁能）
PD8/PD9 = USART3  （与树莓派通信）
```

“停止”不是独立的停止引脚，而是 `PG7` 触发后由固件停止 `PC6` 脉冲，并把 `PA5` 置为禁能状态。

## 尚未确认

- USART2 的备用链路已在 `test12` 中实测发送稳定并完成回显；正式通信角色仍保持 USART3，备用链路不与其并接。
- M144Z-M4 官方针序、板载冲突和每个排针物理位置：仍需官方资料或万用表连续性验证。
- `PG7` 触发后 `PC6` 停止脉冲、`PA5` 禁能：尚未完成联动测试。
- PWM 引脚对应的最终定时器通道：除 `PB6/TIM4_CH1`、`PC6/TIM8_CH1`、`PE5/TIM9_CH1` 外，需以最终 `.ioc` 逐项复核。

## test6 联动实测结果

用户实测反馈：

```text
PG7 断开 GND：PC6 指示灯亮，PA5 指示灯灭；串口显示 STEP=RUN、ENABLE=ENABLED
PG7 接 STM32 GND：PC6 指示灯灭，PA5 指示灯亮；串口显示 STEP=STOP、ENABLE=DISABLED
```

结论：`PG7 -> X_HOME -> 停止 PC6 PWM -> 禁能 PA5` 的固件联动逻辑已在 LED 与 USART3 观察层面通过。此结果不等于真实驱动器、电机或 PCB 已验证。

## 防止配置漂移

- `test2` 是 PC6/TIM8_CH1 的独立成功测试工程。
- `test5` 是 UART/输入测试工程；要做 X 轴停步测试，必须在 `test5` 中显式加入 TIM8，并重新生成代码。
- 不得仅凭 `main.c` 中的 GPIO 初始化判断定时器复用是否存在，必须同时检查 `.ioc`、`stm32f4xx_hal_msp.c` 和 `main.c`。

## test7 联动实测结果

用户实测反馈：`PG9` 接地时串口显示 `Y_HOME=0 STEP=STOP ENABLE=DISABLED`，断开后显示 `Y_HOME=1 STEP=RUN ENABLE=ENABLED`，重复触发与释放均能切换。

结论：`PG9 -> Y_HOME -> 停止 PB6 PWM -> 禁能 PD7` 的固件联动逻辑已在 USART3 观察层面通过；LED 观察应以本测试实际接线为准，Y 轴 STEP 灯应接 `PB6`，ENABLE 灯应接 `PD7`。

## test8 联动实测结果

用户实测反馈：`PF11` 或 `PG14` 任意一个接地时，串口显示 `STEP=STOP ENABLE=DISABLED`；两个输入都释放为高电平时，串口显示 `STEP=RUN ENABLE=ENABLED`，`PE5` 指示灯恢复点亮。

结论：`PF11/PG14` 双限位“任意触发即停、全部释放才恢复”的联动逻辑已在 USART3 与 LED 观察层面通过。

## test12 备用 UART 实测结果

用户实测反馈：树莓派串口助手稳定收到多行 `USART2 UART OK`；`test12` 同时实现字符回显。

结论：`PA2/PA3 = USART2` 备用链路在 115200 8N1 下通过当前接线测试。该结论不改变正式通信优先使用 `PD8/PD9 = USART3` 的角色。
