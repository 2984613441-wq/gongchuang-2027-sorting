## 2. 共享不变量

1. 校赛实施链唯一为 `MaixCAM Pro → Raspberry Pi 4B → STM32F407 → 执行器`；STM32 是唯一运动、安全和15秒边界控制端。
2. 树莓派只发送单件高层任务，不发送逐轴脉冲或实时关节控制。
3. `BARRIER_READY`、`MOTION_DONE`、`ITEM_RESULT`、`DISPLAY_ACK` 必须分离；成功计数只由成功 `ITEM_RESULT` 更新。
4. 挡板必须以可验证的就绪判据产生 `BARRIER_READY`，不能只因已发送 PWM 命令而放行。
5. 本件首次有效 `DISPLAY_ACK` 前不得接受下一件；重复、旧序或乱序帧不得重复动作、投放或计数。
6. 只有可观察执行器进展与本件首次有效 `DISPLAY_ACK` 能更新15秒基准；重传、日志、心跳、重识别和重复刷新不能续时。
7. 急停通过独立硬件回路切断危险执行器动力；同轮禁止自动跳件、重放、自动回零、重抓和人工复位后续跑。
8. X/Y 各一台步进电机是当前通道输入；淘宝链接对应的 A4988 只是 X/Y 两个可插拔候选驱动模块位。电机电气参数、适配、限流与散热未经资料和台架验证前，不得把 A4988 升格为最终驱动。
9. 电机电气参数、舵机、夹爪、限位、显示和补光参数未冻结前，不确定电池、保护器件、线束、端子、PCB 线宽或引脚数值。

## 3. 集成顺序：并行起草，门禁汇合

```text
硬件接口/参数卡 ───┐
模块化 PCB/BOM ────┤
协议契约/方向测试 ─┼─> 共享不变量对账 ─> 静态审查 ─> 等待 Claude 与 ME 输入
状态机/fake HAL ───┤
STEP/DIR 适配骨架 ─┘
```

这不是串行开发：硬件、PCB、协议、纯状态机和驱动适配模块可以同时完善。只有以下事项必须在汇合点处理：共享不变量变更、执行器参数冻结、采购/正式接线/上电授权、实机验收结论。

## 4. 静态验收标准

- 各模块与记录文件均存在、非空，并包含其约定的标题和链接。
- 硬件模块覆盖单电源、逻辑/动力分区、急停、三路运动、四路挡板、夹爪、限位、故障、补光、通信、参数卡与选型门禁。
- 状态机模块包含五个硬件抽象接口、关键事件门、幂等规则、15秒规则、故障锁定/人工复位及要求的故障场景。
- 协作模块声明文件所有权、无固定主笔、弱独立性条件，以及 Claude/机械组待确认项。
- PCB 模块采用“探索者开发板 + 自制载板 + 外购成熟功能模块”，A4988 只作 X/Y 候选模块位，第三运动通道只保留通用外接驱动接口。
- 接口契约明确 `DISPLAY_ACK` 仅由树莓派在实际渲染后发往 STM32；代码入口包含反方向拒绝测试。
- 新文档不得把未验证的电机、驱动器、电池、保险、线径、端子额定值、引脚电流、具体时序参数或型号写成定值。
- 本静态验收不替代台架、接线、急停、运动、通信或供电验证；这些均保持“待验证”。
