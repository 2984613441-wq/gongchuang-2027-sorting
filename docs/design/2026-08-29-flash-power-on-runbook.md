## §1 准备清单（任务 4）

### 1.1 烧录前检查（固件核对结论，2026-08-29 实跑）

**结论：✅ 可以烧录（附条件）。Keil 本机实测编译 0 错误 0 警告，hex 已重新生成（`MDK-ARM/diankongv1.0/diankongv1.hex`，48770 B，加载地址 0x08000000）；stm32_logic 主机测试 73/73 通过。**

⚠️ **重要预期**：当前构建按设计 fail-closed——烧录后上电 **不会产生运动**，只能验证"启动 → POST 失败 → FAULT_LOCK"与串口帧行为。原因与条件：

| # | 项 | 状态 | 影响 |
|---|---|---|---|
| 1 | 失电许可（POWER_PERMISSION） | 应用逻辑已激活，`ec_board_stm32.c` GPIO 采样仍注释 → `power_permission_check_lost()` 恒真 | POST 必然失败 → FAULT_LOCK；要跑完整启动链必须按 `POWER-PERMISSION-GPIO-SETUP.md` 接线（高有效+10k 上拉）或由用户明确决定临时跳过 |
| 2 | 挡板反馈 | 无反馈输入映射，`ec_startup_sequence.c` 只靠 5s 超时 | BARRIER 阶段必超时失败 → 运动闭环不可达（与 SAFETY_FIXES v3"启动序列占位"一致） |
| 3 | USART 通道 | **固件用 USART2 PA2/PA3（115200 8N1），2026-08-30 用户已拍板为正式主链路**（与固件 `huart2` 一致）；`m144z-m4-tested-pin-pcb-map.md` 已同步 | 接线必须接 **PA2/PA3**（交叉 TX/RX + GND），勿接 PD8/PD9；备用链路为 USART3 PD8/PD9 |
| 4 | 诊断输出 | 生产固件 `EC_DIAGNOSTIC_BUILD=0` → 无 ASCII 诊断（`ec_diag_*` 空桩） | 串口验证需用二进制协议（0xA5 帧）客户端，或临时诊断构建观察 |
| 5 | 固件主机测试 | `ec_motion_plan/demo/diag_disabled` 过；`ec_axis_driver_tests` 过期（单轴限制已解禁未同步）、`ec_firmware_host_tests` 缺 HAL 桩 | 测试滞后，非固件编译问题（Keil 编译已证明源码有效） |
| 6 | ST-Link/BOOT0 | 调试器 ST-Link；BOOT0=0（否则进系统存储器） | 烧录前置确认 |
| 7 | 回零 | 需机械在原点（X_HOME+Y_HOME 同时触发≥500ms） | 上电验证运动前的机械条件 |

**烧录验证预期**：烧录成功 → 上电 → 按 START → 观察到 FAULT_LOCK（串口 0xA5 帧或临时诊断构建日志）。要进入运动闭环，下一步是接线 POWER_PERMISSION + 集成挡板反馈/回零真实输入。

## §2 操作顺序（任务 3）

### 步骤 1：接线（按速查 §1-§2）
1. 驱动板 X/Y：VIN=12V、V=5V（**不是 3.3V**）、STEP/DIR/EN 接速查表引脚（X: PC6/PA7/PA5；Y: PB6/PC7/PD7）、电机 1A/1B、2A/2B。
2. 精简共地：12V 负 → 驱动板 GND → 降压 IN- → STM32 GND → 树莓派 GND（万用表验证）。
3. 串口调试线：USB-TTL TX→PA3、RX→PA2、GND→GND（**树莓派先不接**）。

### 步骤 2：烧录固件
1. Keil 打开 `电控/firmware/stm32f407_m144z/MDK-ARM/diankongv1.0.uvprojx`。
2. 确认器件 STM32F407ZGTx、烧录器 ST-Link、Flash Download 配置正确。
3. 编译（目标：0 error；2 个嵌套注释警告为已知无害）。
4. 下载烧录 → 显示 Programming Done。
5. 若本机无 Keil：改用已核对通过的 host 侧 C 测试（stm32_logic 73/73）作为逻辑层证据，固件编译在装有 Keil 的机器执行。

### 步骤 3：首次上电（最小系统）
1. 只给 STM32 供电，接 USB-TTL。
2. 串口 115200 8N1，发 `PING` → 期待 `OK PONG`。
3. 无回显按速查 §5 排查（PA2 电平 3.3V？烧录成功？复位？）。
4. `INPUTS` → `ACTIVE=0000`（9 路悬空不触发）。

### 步骤 4：电机/舵机分阶段验证（诊断命令，速查 §4）
1. `MOTION ARM`（10s 窗口）→ `MOVE X DIR0 STEPS 800 HZ 500`（X 走 10mm）→ 观察方向/步数。
2. Y 轴同理（PB6/PC7/PD7）。
3. 舵机：`SERVO ARM` → `SERVO PB11 P1500/1000/1900`（Z 中位/升/降）——脉宽待机械组确认后标定。
4. `STOP ALL` 随时停止。

### 步骤 5：屏幕上电验证（指南 §4 八项）
1. micro-HDMI → 树莓派 HDMI0、USB 供电线 → CTouch 口、config.txt 加 1024×600 配置。
2. 按指南 8 项清单判读（自动亮屏/全屏/断电恢复/可读性/中文字体/图片/DISPLAY_ACK 闭环）。

### 步骤 6：树莓派侧主机闭环联调（新代码）
1. 树莓派装 Python 依赖（Pillow 等），把 `电控/src` 部署上去。
2. 串口适配器注入（波特率 115200 已固定——确认后冻结）。
3. 跑主机侧闭环（fake 串口已验证）：真实 `SerialLink` 实现 + `OutboundGateway` + `HdmiDisplayRenderer` + Scheduler 全链。
4. 验证赛题闭环：一件分拣 → 显示 → DISPLAY_ACK → 下一件；15 秒边界实测。

### 步骤 7：标定（要求汇总 §8 + 实机标定清单）
- XY 方向/步数/速度（80 steps/mm 暂定）、回零、行程；Z/夹爪/挡板脉宽；六箱落点坐标；视觉光照/白平衡/颜色阈值。
