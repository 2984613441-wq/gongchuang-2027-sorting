## 0. 一句话结论

**方案 C 不需要新增命令字，也不需要改帧长，甚至不需要改固件。**

`ITEM_TASK`（0x21，12 字节）的 **offset 7 已经是一个冻结的预留角度字节**，两端把它锁死在 `0xFF`
⇒ 把它"激活"成**转盘格号**是一条可行路径（§3 路径甲），零帧长变化、零命令字变化。

**但更强的路径是绕开协议**：用户已确认 PWM 扩展板是 **PCA9685 16 路 I2C 驱动板**，
而树莓派侧的 **I2C 与 GPIO 全空闲**（只用串口）
⇒ **转盘由树莓派经 I2C 直控 + 索引接树莓派 GPIO**，
**不改协议、不改固件、不重烧，且转盘动作天然落在 15 秒失活窗口之外** ⇒ **不是 L4**。

> **⇒ 推荐路径乙。** 只有在"索引必须进 STM32"或"必须由 STM32 在件内转盘"时，才走路径甲。

## 2. 回答 §14.3 的 6 个设计问题

### Q1 角度怎么表示？

**用"格号 1..6"，不传绝对角度。**

理由：
- 转盘是 **6 格等分（60°）**，格号是表达该动作所需的最小信息；
- 连续旋转舵机**没有角度反馈**，传"绝对角度"既无法闭环也不能验证；
- 格号与已有的货格映射口径一致：**`class_id N → 货格 N`**（用户 2026-09-20 定案）。

编码：`0xFF` = **不转**（保持向后兼容，见 §4）；`1..6` = 转到第 N 格。
**保留 0x07..0xFE 未定义**（未来若要做 270° 舵机或更多格位再用，现在不占）。

### Q2 命令字选哪个？

**分两种情况，取决于 §6 的硬件归属**：

- **路径乙（推荐，若扩展板能接树莓派）**：**完全不涉及协议**。转盘由树莓派通过 PWM 扩展板直控，
  不需要任何新命令字、不需要动 `ITEM_TASK`。
- **路径甲（复用 offset 7）**：**不新增命令字**。把 `ITEM_TASK` offset 7 的 `grip_angle`
  语义从"恒 0xFF"放开为"0xFF=不转，1..6=格号"。

> **另外记录：已占用/已冲突的命令字**（万一将来真的需要新命令字，从这里挑）
>
> | 已占用（冻结契约） | 值 |
> |---|---|
> | HEARTBEAT / HEARTBEAT_ACK / DEVICE_READY / ERROR / ACK / NACK | `0x01`–`0x06` |
> | BARRIER_READY / ITEM_TASK / MOTION_DONE / ITEM_RESULT / DISPLAY_DATA / DISPLAY_ACK / ESTOP | `0x20`–`0x26` |
>
> 🔴 **`0x20`/`0x21`/`0x22` 已经被撞过号**：未进编译工程的
> `ec_config_handler.c:32-34` 也声明了 `CMD_CONFIG_UPDATE 0x20 / CMD_ACK 0x21 / CMD_NACK 0x22`
> （台账 E-10）。**这是本项目"先改再说"的原始事故**。
> ⇒ 若日后确需新命令字，**从 `0x27` 起取**，并同步 `interface-contract.md` 的版本表。

### Q3 时序：PLACE 与旋转谁先谁后？

**转盘先到位，夹爪才放下**（用户已定）。**但关键在于"这段旋转放在哪一段时间里"**：

```
上一件 DISPLAY_ACK  （← 固件 15 秒窗口在此关闭）
   ↓  窗口关闭、板子处于 WAIT_TASK
视觉识别到新一件 → 树莓派算出它的格号 k → 让转盘转到第 k 格 → 等索引/等固定时间
   ↓  这一段没有窗口开着
发 ITEM_TASK（带抓取点 + 落点）← 固件 15 秒窗口在此开启
   ↓
机器抓取 → 移动 → 夹爪放下（此时格 k 已就位）
```

**⇒ 推荐把转盘旋转放在"视觉识别之后、发 ITEM_TASK 之前"。**
理由见 Q5：那一段**没有失活窗口开着**，转盘耗时不计入 15 秒预算，也不需要改看门狗语义。

### Q4 零位：上电要不要回零？回零失败怎么办？

**要回零，且必须 fail-closed。**

- **上电后第一件事**：让转盘朝索引方向转，**等到索引信号触发**才停 —— 这一步建立零位。
- **回零失败**（超时仍等不到索引）⇒ **报错并拒绝开始本轮**，
  **绝不"猜着转"**（连续旋转舵机无反馈，猜就是必然错格）。
- **每件选格前**：从已知的零位出发计时定位（转 (k−1)×60° 所需时间）。这样**误差不跨件累积**。
- 索引信号的**断线方向必须是安全的**：用**常开(NO)** 输出 ⇒ 断线 = 悬空 = 被上拉读成"无信号"
  ⇒ 只会导致"转不到位并报错"，**不会误判成"已到位"**。
  🔴 **若用常闭(NC)，断线会被读成"已到位"** ⇒ 直接错格。**必须用黑线（常开）。**

### Q5 15 秒预算：转盘动作要不要计入失活窗口？

**计入与否，取决于它被安排在哪一段。**

- 固件窗口语义（已核实）：**每件一个窗口，从运动开始计时**（`ec_app.c:197-198`），
  **只有第一个有效 DISPLAY_ACK 能关闭**（`ec_app.c:218-223`），运动中零再计时
  （`ec_app.c:552-566`，`EC_APP_PROGRESS_SOURCE_ENABLED=0`）。
- **实测用量**：13.16~13.53s / 15s ⇒ **余量只有约 1.5~1.8s**。
  单件步数、时间与落点的关系（已在 37200 步这一个点实测校验到 0.3%）：
  `Σ步数 = 16×(落点x_mm10 + 落点y_mm10) + 30800`，`T ≈ Σ步数/5000 + 4.765s`。
  当前落点 (14.5,19.0) ⇒ Σ=36160 步 ⇒ 到 MOTION_DONE ≈ 12.00s。

⇒ **结论**：
- **若转盘动作放在 Q3 那个"窗口外"的时段** ⇒ **不计入**，零风险，**且不需要改看门狗**。
- **若由 STM32 在件内执行** ⇒ 必须挤进那 **1.5~1.8s** 余量里，
  60° 旋转 + 稳定时间 + 可能的回零等待，**基本不可行**。

🔴 **这一条直接决定路径选择**：想省掉协议/固件改动、又不想赌时间余量，
**就应该让转盘走树莓派直控（路径乙）**，或让 STM32 在**件与件之间**执行（而非件内）。

### Q6 驱动资源：转盘舵机接哪个口？

✅ **已确认**：扩展板 = **PCA9685 16 路 12 位 I2C PWM 驱动板**（板载丝印 `PCA9685 V1246`）。

- **逻辑电源** `VCC`：3-5V ← 接树莓派 3.3V
- **舵机电源** `V+`：**≤6V**（用 5V）← 接舵机，**必须走 V+**
- **通信**：I2C（`SCL`/`SDA`）← 接树莓派 **GPIO3 / GPIO2**（I2C-1，已核实空闲）
- **通道**：16 路，转盘只占 1 路（通道 0）
- 🔴 **`OE`（2026-09-20 更正，原句已作废）**：低有效输出使能（**低 = 使能全部 16 路；高 = 关全部输出**）。
  **原句「接一个物理开关到 GND」是错的**：低有效 + 下拉 = **常态即使能**，
  开关断开时 `OE` 仍被下拉到低 ⇒ **这个开关什么也没做，不能当急停**。
  （Codex 与 Grok 本轮各自独立发现同一结论，见 `docs/交付/2026-09-20/审核v7-2308.md`）
  正确两案（细节见 §5 坑 2）：
  - **A · 手按即停**：`OE` 经**常开按钮到 3.3V**（不另加下拉）⇒ 常态使能、**按下**拉高 = 关全部输出
  - **B · 上电默认禁输出**：`OE` 加**上拉**到 3.3V、由 GPIO 主动拉低才使能 ⇒ 最安全，但须先确认本板不是上拉板
  ⚠️ **接线前必须断电量 `OE–GND` 与 `OE–VCC` 的电阻**，先判定本板是下拉板 / 上拉板 / 无电阻。
  （原句保留如下）"舵机急停"
  （用户本轮决定暂不装机械急停，这个可以当最低限度的补偿）
- **索引信号**：接树莓派 **GPIO17（物理针 11）**，外部 10kΩ 上拉到 3.3V

⇒ **接树莓派，不接 STM32。** 理由：树莓派侧 I2C/GPIO 全空闲；
而接 STM32 需要新写 I2C 驱动 + PCA9685 驱动 + 改协议，成本高得多，且会把转盘拖进 15 秒窗口内。

**若日后仍决定接 STM32 侧**，则：
- 转盘 PWM：**PB0 / TIM3_CH3**（挡板已取消，通道空闲；载板 JP_L-35）
- 索引输入：**PG7**（现成插座 JP_R-14，**内部上拉、低有效**，与 NPN 输出天然匹配）

> 🔴 **绝对不要把转盘舵机接 PB11 / TIM2_CH4**：它与夹爪 `PB10 / TIM2_CH3`
> **共用 TIM2 同一个计数器**。`ec_board_stm32.c:574-579`、`:685-696` 有明文记录：
> 停 CH4 会把 CH3（夹爪）的输出一起掐断，并把 CH3 状态字卡在 BUSY ⇒ **夹爪静默失能**。

### 路径乙：转盘由树莓派直控（**推荐**）

```
光电开关 ──► 树莓派 GPIO（索引）
转盘舵机 ──► PWM 扩展板 ──I2C──► 树莓派
```

| | |
|---|---|
| **要不要改协议** | ❌ **不要** |
| **要不要改固件** | ❌ **不要** |
| **要不要重烧** | ❌ 不要 |
| **15 秒窗口** | 天然在窗口外（转盘动作发生在发 ITEM_TASK 之前） |
| **改哪里** | 只在树莓派侧：新增转盘驱动模块（PCA9685 over I2C）+ 接到 `run_chain.py` 的调度里 |
| **可行性依据（已核实）** | ✅ 树莓派侧代码**只用串口**，**GPIO 与 I2C 全空闲**（grep `RPi.GPIO|gpiozero|pigpio|smbus|I2C` 在 `电控/` 下只命中 `import serial` 两处）<br>✅ PCA9685 的 `Logic: 3-5V` 与树莓派 3.3V I2C **电平直连安全**<br>✅ 软件成本极低（现成 Python 库，或直接写 I2C 寄存器） |

| PCA9685 `SDA` | **GPIO2**（物理针 3，I2C-1 SDA） | 空闲 ✅ |
| PCA9685 `SCL` | **GPIO3**（物理针 5，I2C-1 SCL） | 空闲 ✅ |

### 路径甲：复用 `ITEM_TASK` offset 7（**协议语义变更，属 L4**）

把冻结的预留字节激活为转盘格号。

| | |
|---|---|
| **要不要改协议** | ✅ **要**——但是**语义变更，不是格式变更**：帧长仍 12 字节、命令字仍 `0x21`、CRC 不变 |
| **要不要改固件** | ✅ 要（放开校验 + 加转盘驱动 + 加索引读取） |
| **改动点（已定位）** | `ec_protocol.c:165`（encode 校验）、`:192`（decode 校验）、`item_context.py:140-141` 与 `:170`（Python 侧校验）；外加运动层 |
| **15 秒窗口** | ⚠️ **若在件内执行会挤爆余量**（见 Q5）；须安排成"件与件之间" |

**✅ 一个很好的安全性质（务必保留）：升级顺序天然 fail-closed**

- **旧固件 + 新树莓派**：树莓派发非 `0xFF` ⇒ 旧固件 `ec_protocol.c:192` 校验失败 ⇒ **整帧拒收**
  ⇒ **绝不会"静默投错箱"**，只会这一件不出货。
- **新固件 + 旧树莓派**：树莓派永远发 `0xFF` ⇒ 新固件按"不转"处理 ⇒ 向后兼容。

⇒ 两条路径里，**若选甲，必须保留"非 0xFF 即拒收"这个语义在旧固件上的表现**，
**不要**把旧固件的那行校验一起删掉（那是升级期的安全网）。

## 4. 编码提案（若选路径甲）

`ITEM_TASK` offset 7 `grip_angle`：

| 值 | 含义 |
|---|---|
| `0xFF` | **不转**（保持现状 = 向后兼容；旧树莓派永远发这个） |

## 5. 接线（两条路径共用的部分）

### 光电开关 FC-SPX303Z（NPN、4 线、12~24VDC）

| 开关线 | 接到哪 | 备注 |
|---|---|---|
| **棕** | **+12V 或 +24V**（外部电源正） | 开关自己供电，**不能从 3.3V/5V 取** |
| **蓝** | 电源负，**并与 MCU/树莓派 GND 共地** | 共地是硬要求 |
| **黑（常开 NO）** | 索引输入脚 | 路径乙（推荐）⇒ **树莓派 GPIO17（物理针 11）**；路径甲 ⇒ **STM32 PG7**（JP_R-14） |
| **白（常闭 NC）** | **不接**，绝缘 | 见 Q4：常闭断线会被误判成"已到位" |

> 🔴 **接线前必须量一次**：不接 MCU 的前提下给开关上电，量**黑线对蓝线（地）**的电压。
> - 只有「导通≈0V」与「高阻（悬空）」两态 ⇒ **集电极开路，可直连**
> - **若量出稳定 12V 或 24V** ⇒ 不是集电极开路型 ⇒ **必须加光耦或分压**，直连会烧 3.3V 引脚

### 索引信号的电气接法（树莓派 GPIO 侧）

- 光电开关是 **12~24V NPN 集电极开路**输出，树莓派 GPIO 是 **3.3V 域**
  ⇒ **外部 10kΩ 上拉到 3.3V**（**不要只靠树莓派内部上拉**：内部约 50kΩ，配 0.3ms 响应偏弱）
  ⇒ 开关导通 → 拉低到 ~0V（= 索引命中）；开关断开 → 被上拉到 3.3V
- 🔴 接线前量一次黑线对地电压（见上）
- 🔴 **不要用 GPIO14 / GPIO15**：那是 `/dev/serial0`（ttyS0），链与 STM32 的通信线。
- 🔴 **不要用 GPIO2 / GPIO3**：那是 I2C-1，留给 PCA9685。

### 转盘舵机（走 PCA9685）

| 线 | 接到哪 |
|---|---|
| 信号（通常橙/黄/白） | **PCA9685 通道 0 的端子 `PWM`**（16 路里只占 1 路） |
| 电源正（通常红） | **PCA9685 端子 `V+`**（**5V**；板载丝印 `V+: 6V Max`、`Use V+ for servo supply`） |
| 电源负（通常棕/黑） | PCA9685 端子 `GND`，**并与树莓派 GND 共地** |

### 🔴 PCA9685 的五个坑（都要写进代码，不然会出怪事）

1. **频率必须显式设成 50Hz**。PCA9685 上电默认不是 50Hz（常见库默认 200Hz）。
   板子支持 `40-1000Hz`。50Hz 下 12 位 → 20ms/4096 ≈ **4.88µs/计数**：
   `900µs≈184`、`1500µs≈307`、`1900µs≈389`、`500µs≈102`、`2500µs≈512`。
2. **上电顺序（前提是 `OE` 默认高）**：PCA9685 掉电/复位后寄存器全 0，16 路输出初值不确定。
   ⇒ 上电流程：**先把 `OE` 拉高（关全部输出）→ 初始化频率 50Hz → 把所有通道写成 1500µs（停止）
   → 再把 `OE` 拉低使能**。

   🔴 **更正（2026-09-20）**：`OE` 低有效 ⇒ **下拉 = 常态使能**，所以
   「`OE` 接一个开关到 GND」**给不了上电保护**——开关断开时 `OE` 仍被板载下拉拉到低。
   要让上电默认**关闭输出**，`OE` 必须**默认保持高**：

   - **A · 手按即停**：`OE` 经常开按钮到 **3.3V**（不另加下拉）⇒ 常态使能、**按下**关断
   - **B · 上电默认禁输出**：`OE` 加**上拉**（如 10 kΩ 到 3.3V），由 GPIO 主动拉低才使能

   ⚠️ 两案的取舍**互斥**，不能同时满足。且**接线前必须断电量 `OE–GND` / `OE–VCC` 电阻**判定板型：
   若本板已有下拉，**不要**直接再加 10 kΩ 上拉——对拉会停在约 **1.6 V** 的无效区
   （PCA9685 逻辑 VIH ≥ 0.7·VDD，需用更强的上拉拉过去）。

   ⚠️ 「寄存器全 0 ⇒ 连续旋转舵机会全速旋转」这句**未经验证**，保留但已标注。
3. **"停止"是写 1500µs，不是停止输出**。PCA9685 会一直保持最后写入的脉宽；
   连续旋转舵机靠"1500µs"停住。**不要靠"不再写"来停机**。
4. **V+ 上限 6V**。舵机电源不要超过 6V；且舵机**必须接 V+，不能接 VCC**
   （VCC 是 3-5V 逻辑电源，扛不住舵机电流）。
   ✅ **厂商产品页补充（2026-09-20 用户提供）**：`VCC 3–5.5V`、`V+ 6V max`、
   **逻辑电压与舵机电压分开供电**；`V+` 输入**板载已有 10V/1000µF 大电容**
   ⇒ 之前建议的「V+ 对地并 220–470µF」**板上已经有了，不必再加**
   （若供电线很长，可在**电源端**再并一颗，不是必须）。
   ✅ **免费判据**：板上有**红色逻辑电源指示灯**，且**只接舵机供电口时灯不亮**
   ⇒ 现场第一步可据此确认「逻辑供电是否到位」（只接 V+ 不接 VCC 时灯不亮是**正常**的，别误判成坏板）。
5. **接线端子有反接保护，排针没有**（板载丝印原文：
   `Terminal block is reverse polarity protected. Side breakout pins are not!`）
   ⇒ **优先用螺钉端子接线，少用侧边排针**。

6. 🔴 **输出驱动模式：必须设成「推挽（totem-pole）」，不能留默认的「开路（open-drain）」**
   —— 厂商产品页写明「**可配置的推拉输出或开路输出**」。
   这是 PCA9685 `MODE2` 寄存器的 `OUTDRV` 位（bit 2）：**上电默认是开路输出**。
   本模块每路输出**串了 220Ω 保护电阻**，若再是开路输出，**高电平没有主动驱动能力**，
   舵机可能收不到干净的高电平。
   ⇒ **初始化时必须显式写 `MODE2.OUTDRV = 1`（推挽）**——Adafruit 官方库的 `begin()` 就是这么做的。
   ⚠️ 写 I2C 寄存器时注意：PCA9685 的 `MODE1` 有 `SLEEP` 位，
   改 `MODE2` 前后的时序照数据手册来。
   ✅ 顺带：**每路 220Ω 串联保护**已板载 ⇒ **舵机信号线不需要再加外部上拉**。

7. **模块其它参数（备查）**：I2C 默认地址 `0x40`（A0–A5 全下拉为低；焊桥接 VCC 可改地址，
   理论上一条 I2C 可带 16×62 路）；内置 **25 MHz 晶振**；16 组 3 针舵机接口；
   支持级联；尺寸 **62.3 × 25.5 × 15 mm**；工作温度 −40~85 ℃。

> 🔴 另注：**不要把夹爪舵机 / Z 升降舵机也挪到 PCA9685 上。**
> 它们必须与 XY 运动由 **STM32 在同一段运动程序里**同步驱动（`ec_motion_plan.c` 的固定 6 段），
> 挪到树莓派侧会破坏"夹取/释放与 XY 到位"的原子性。**扩展板只接转盘。**
