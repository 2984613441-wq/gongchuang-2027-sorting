# 方案 B：代码第一性问题与并行切入

> 状态：实施入口设计，不是可烧录代码  
> 日期：2026-08-12  
> 依据：`docs/requirements/analysis.md`、`docs/design/stm32-state-machine-pseudocode.md`、`docs/design/interface-contract.md`、方案 B 完整技术版  
> 当前阶段：先冻结可测试的不变量和边界，再分别建立协议、纯状态机、驱动适配骨架；实机闭环留到机械参数与硬件具备后。

## 1. 真实问题与目标状态

表面问题是“先写哪段 STM32 代码”，真正问题是：在电机、传动、限位和动作参数尚未冻结时，怎样先建立不会因后续换硬件而失效的控制内核，并用测试证明安全顺序不可被通信重发、状态恢复或驱动细节绕过。

目标状态不是“主循环能跑”，而是以下核心不变量成为协议、状态机和驱动边界共同维护的约束：

> **一件任务最多执行一次；在该件首次有效 `DISPLAY_ACK` 被消费前不接下一件；急停与 15 秒边界不可由任何软件路径绕过。**

它可拆为五条可判定规则：

1. 同一 `(taskId, frameSeq)` 的 `ITEM_TASK` 最多触发一次抓放执行序列；重复帧只能得到缓存响应或状态重发。
2. 从接受 `ITEM_TASK` 到消费该件首个有效 `DISPLAY_ACK` 期间，系统只有一个未结案件，新任务必须被拒绝且不能排队暗存。
3. `BARRIER_READY`、`MOTION_DONE`、`ITEM_RESULT`、`DISPLAY_ACK` 是四个独立事件；前一个事件不蕴含后一个事件。
4. 急停在任意活动状态出现都进入不可自动恢复的故障锁定；软件停脉冲/禁能只补充独立硬件切动力，不能替代硬件急停。
5. 心跳、日志、ACK/NACK、重传、视觉重询、重复刷新和重复 `DISPLAY_ACK` 均不能刷新 15 秒基准；预算耗尽停止本轮，不能自动跳件、重放运动或用人工复位续跑旧任务。

## 2. 事实、推断、观点与未知

| 类型 | 内容 | 对代码切入的影响 |
|---|---|---|
| 事实 | 校赛只实施方案 B；STM32 是唯一底层运动与安全控制器。 | 控制内核不为方案 A 设计第二条活动路径。 |
| 事实 | 树莓派负责界面实际渲染，并在渲染完成后允许控制闭环继续。 | `DISPLAY_ACK` 必须从树莓派发往 STM32。 |
| 事实 | `MOTION_DONE` 只表示运动序列结束；只有成功 `ITEM_RESULT` 可用于上层累计成功数。 | 状态机和测试不得把运动完成直接映射为成功计数。 |
| 事实 | 下一件必须等待当前件首个有效 `DISPLAY_ACK`；15 秒由 STM32 独立监控且内部活动不得续时。 | `WAIT_DISPLAY_ACK` 是强制门，不是可选 UI 步骤。 |
| 推断 | 先实现纯逻辑边界，可在机械参数未定时提前发现任务重放、事件错序和超时漏洞。 | 协议与状态机测试不应依赖真实电机。 |
| 观点 | 最低返工的切入不是从 `main` 或完整抓放序列开始，而是四条并行泳道共享一个冻结的事件模型。 | 先建立接口和测试证据，再把真实 STEP/DIR 输出接入。 |
| 未知 | 电机/驱动器型号、电流、细分、丝杆或皮带参数、行程、速度/加速度、限位形式和位置、重力轴防坠方案。 | 不得写入步数换算、脉冲频率、引脚、定时器、回零方向和安全阈值。 |

## 3. 第一处契约问题：`DISPLAY_ACK` 方向（已修正）

审查时发现旧版接口契约把 `DISPLAY_ACK (0x25)` 写成 **STM32→树莓派**，这与方案 B 数据流及状态机的 `WAIT_DISPLAY_ACK` 接收逻辑冲突。该问题已在接口契约 V0.2 修正，V0.3 又补齐显示内容 CRC32；当前实现必须以如下源宿矩阵为准：

| 事件 | 唯一语义 | 方向 |
|---|---|---|
| `BARRIER_READY` | STM32 已验证挡板处于避让位，允许上层提交本件任务 | STM32 → 树莓派 |
| `MOTION_DONE` | STM32 已结束本件运动序列，不代表结果成功 | STM32 → 树莓派 |
| `ITEM_RESULT` | STM32 给出本件结果；只有 `SUCCESS` 可被树莓派计入累计成功数 | STM32 → 树莓派 |
| `DISPLAY_ACK` | 树莓派已完成同一件界面的实际渲染，通知 STM32 可以结案 | **树莓派 → STM32** |

不得合并或重命名这四个事件，也不得让 `MOTION_DONE`、成功 `ITEM_RESULT` 或普通协议 ACK 代替 `DISPLAY_ACK`。`DISPLAY_ACK` 的任务号、目标序号、显示内容 CRC32 与渲染结果字段以接口契约 V0.3 为准。

方向问题虽然已在文档层修正，但仍须通过 `PROTO-DIR-001/002` 自动化测试后，才可视为生产协议实现已满足契约。

## 4. 模块边界：让安全语义不依赖硬件细节

```text
protocol codec ──已校验的领域事件──► pure state machine ──动作意图──► AxisDriver
      ▲                                  │                          │
      └────────编码后的响应/事件─────────┘                          └─ STEP/DIR adapter skeleton

单调时钟、急停、限位、挡板、夹爪 ──经端口注入────────────────────────► 状态机/动作执行边界
```

- **protocol codec** 只负责帧的编解码、长度/CRC/版本/源宿/序号校验和消息类型映射，不直接启动运动。
- **pure state machine** 只根据当前不可变状态、领域事件和单调时间产生“新状态 + 动作意图 + 待发送事件”；不得直接访问 GPIO、定时器或阻塞等待。
- **fake HAL** 记录动作调用、可控地返回成功/故障/进度，用于证明状态转换和“最多一次”。
- **AxisDriver** 暴露 `enable/disable/home/moveTo/stopAll/pollProgress/driverFault` 语义；状态机只依赖该接口。
- **STEP/DIR adapter skeleton** 只建立 AxisDriver 到“脉冲请求、方向请求、使能请求、停止、进度采样”的适配边界及参数校验入口；不写具体引脚、定时器、频率、步数换算或可上板动作表。
- **安全边界** 中，急停信号具有最高优先级。无论 codec、状态机或驱动当前处理到哪一步，观测到急停都只允许产生停止、禁能、动力禁止请求、故障记录和锁定；解除信号不能自动恢复。

协议与状态机之间只传递已校验的领域事件，不让状态机重新解析原始帧。最小接口形状如下；具体编程语言可变，但字段语义不得漂移：

```text
DomainEvent =
  ItemTaskReceived(taskId, frameSeq, target, firstSeen)
  | DisplayAckReceived(taskId, frameSeq, targetSeq, crcMatch, firstValid)
  | DuplicateFrame(taskId, frameSeq, cachedResponse)
  | InvalidFrame(reason)
```

只有 codec 可以生成这些通信领域事件；`InvalidFrame` 和校验未通过的 `DisplayAckReceived` 都不能产生运动意图或刷新15秒基准。

## 5. 四条并行泳道，而非串行逐任务

四条泳道现可依据接口契约 V0.3 并行推进；共同输入是事件语义和核心不变量，共同汇合点是无电机的集成测试。

### 泳道 A：protocol codec + direction tests

**交付边界**：主机侧可编译/可测试的帧模型、编码/解码器和方向白名单；坏帧只产生拒绝结果，不产生领域动作。

**首个验收**：四关键事件的合法源宿被接受，反方向全部拒绝；重复、旧序号、任务号冲突的判定信息可被状态机消费。

### 泳道 B：pure state machine + fake HAL

**交付边界**：纯状态转移函数、单件上下文、有界去重记录、单调时钟输入、动作意图和 fake HAL；不接 MCU 外设。

**首个验收**：用事件序列证明“一件最多一次、显示确认前不接下一件、急停/15 秒不可绕过”，并验证四事件不会互相替代。

### 泳道 C：AxisDriver STEP/DIR 适配骨架

**交付边界**：接口适配形状和编译期契约；用假脉冲端口验证 DIR 必须先于 STEP、停止后不再请求脉冲、禁能与故障传播有效。

**首个验收**：无需电机也能证明驱动适配不会绕过状态机发出第二段动作，不包含任何声称适用于实机的运动参数。

### 泳道 D：hardware-in-loop later

**启动条件**：电机/驱动器/传动/限位/行程/负载/重力轴防坠数据已由机械接口给出，急停动力回路可测试，台架风险评审完成。

**交付边界**：从单轴空载开始，逐步验证脉冲、方向、回零、限位、急停、失步/堵转可观测性和 15 秒真实进度判据；之后才进入单件闭环。该泳道不能反向修改核心事件语义来迁就硬件。

### 并行汇合闸口

进入任何真实执行器联调前，A+B+C 必须在主机侧共同通过：合法 `ITEM_TASK` 被解码后只产生一次动作序列；重复帧不增加 fake HAL 调用计数；`ITEM_RESULT` 后仍拒绝下一件；仅首个匹配的树莓派→STM32 `DISPLAY_ACK` 结案；急停或截止时间到达后不存在后续脉冲意图。

## 6. 首批可执行测试

以下测试先写成自动化主机测试；每项均需记录输入事件序列、状态序列、动作调用计数、输出事件和最终故障码。具体测试框架由代码仓库技术栈确定，不在设计入口中预设。

### 6.1 不依赖电机、传动或 MCU 外设

实施优先级：P0 为协议方向/帧结构，P1 为单件幂等/事件门，P2 为安全/计时/复位，P3 为驱动骨架，P4 为主机集成；第 6.2 节 HIL 为 P5。各组可以并行起草，但低编号测试失败时不得宣称更高编号汇合通过。

| 测试 ID | 输入/注入 | 必须断言 |
|---|---|---|
| `PROTO-DIR-001` | 四关键事件分别使用合法源宿编码后解码 | `BARRIER_READY/MOTION_DONE/ITEM_RESULT` 仅接受 STM32→树莓派；`DISPLAY_ACK` 仅接受树莓派→STM32。 |
| `PROTO-DIR-002` | 将上述四事件逐一反向 | codec 拒绝并记录方向错误；状态机和 fake HAL 调用数均为 0。 |
| `PROTO-FRAME-001` | 已知字节向量往返编码/解码 | 版本、源宿、taskId、frameSeq、命令、长度和载荷保持一致。 |
| `PROTO-FRAME-002` | CRC 错、截断、超长、未知命令、协议版本不兼容 | 全部拒绝，不生成动作事件，不改变 15 秒基准。 |
| `PROTO-ACK-CRC-001` | 对 `DISPLAY_ACK` 注入正确向量、CRC 数值错误、五字段顺序错误及 CRC 输出字节序错误 | 仅接口契约 V0.3 的规范输入与网络序 CRC 被接受；其余均不得结案、放行或续时。 |
| `SM-ONCE-001` | 合法 `ITEM_TASK` 后重复发送同一 `(taskId, frameSeq)` | 完整动作意图序列只出现一次；重复帧只触发缓存响应。 |
| `SM-ONCE-002` | 相同 taskId/frameSeq 但载荷不同 | 进入任务冲突故障锁定；不执行第二段动作。 |
| `SM-GATE-001` | 当前件执行中、报告 `MOTION_DONE` 后、报告成功 `ITEM_RESULT` 后分别发送下一件 | 三个阶段都拒绝下一件，直到当前件首个有效 `DISPLAY_ACK` 被消费。 |
| `SM-GATE-002` | 注入错 taskId、旧 frameSeq、内容校验失败或重复 `DISPLAY_ACK` | 不结案、不放行下一件、不刷新 15 秒基准；重复有效 ACK 只重发已消费状态。 |
| `SM-EVENT-001` | 只注入 `MOTION_DONE` | 不生成成功计数语义，不跳到可接下一件状态。 |
| `SM-EVENT-002` | 注入成功 `ITEM_RESULT`，不注入 `DISPLAY_ACK` | 当前件仍未结案，保持等待显示确认。 |
| `SM-TIME-001` | 使用假单调时钟推进至 deadline，其间注入心跳、日志、重传、视觉重询、重复刷新 | deadline 不变；到期进入 `ROUND_TIME_EXHAUSTED` 和故障锁定。 |
| `SM-TIME-002` | 注入新的已验证 `ProgressToken`，随后重复同一 token | 仅新 token 更新基准；重复 token 不续时。 |
| `SM-ESTOP-001` | 在每个活动状态分别置急停有效 | 立即产生停止/禁能/动力禁止请求并锁定；无后续动作意图。 |
| `SM-POWER-001` | `permitActuatorPower()` 返回成功但许可反馈未建立，或在任一活动状态撤销许可 | 回零不得开始；运行中立即停止、禁能并进入故障锁定，不恢复旧件。 |
| `SM-RESET-001` | 急停释放或人工复位，但旧件仍存在 | 不恢复旧任务；合法复位只能创建新轮上下文并重走自检、回零。 |
| `DRV-SKEL-001` | fake pulse port 接收正/反向动作请求 | DIR 请求先于任何 STEP 请求；停止后 STEP 请求计数不再增加。 |
| `DRV-SKEL-002` | 注入驱动故障、禁能或停止 | 故障向上传播；适配层不能自行重试或重放动作。 |
| `INTEG-HOST-001` | codec→状态机→fake HAL 完整单件序列 | 首个合法任务只执行一次；`MOTION_DONE` 与 `ITEM_RESULT` 分开发出；合法 `DISPLAY_ACK` 后才可接受下一件。 |

这些测试不需要真实电机。`SM-TIME-002` 中的“已验证进度”只是由 fake HAL 注入的领域事实，用于验证计时规则；它不证明真实 STEP/DIR 输出已经形成赛场可观察动作。

### 6.2 必须等待电机、传动、安全结构或实机参数

| 测试 ID | 依赖输入 | 实机要验证的事实 |
|---|---|---|
| `HIL-AXIS-001` 单轴空载方向/行程 | 电机接线、驱动器、传动方向、单位位移换算、安全行程 | DIR 极性和坐标方向正确，指令位移与实测位移一致且不越界。 |
| `HIL-PULSE-001` 速度/加速度边界 | 细分、每转步数、传动比或导程、负载、驱动能力 | 脉冲频率与加速度不导致失步、堵转、过流或机械冲击。 |
| `HIL-HOME-001` 回零/限位 | 限位类型、常态电平、安装位置、回零方向与速度 | 断线/粘连/异常触发可诊断；回零失败不反复碰撞。 |
| `HIL-PROGRESS-001` 可观察进度 | 机构实际运动、进度测量依据、赛规观察口径 | 哪一种输出进展可被认定为真实、可观察动作，从而允许刷新 15 秒基准。 |
| `HIL-ESTOP-001` 急停 | 独立动力切断回路、执行器惯性、重力轴防坠 | 危险动力被硬切；逻辑与显示保留；解除后不自启、不续跑旧件。 |
| `HIL-FAULT-001` 驱动/堵转/掉压 | 驱动器故障输出、电源设计、负载 | 停脉冲、禁能、锁定和日志行为与真实故障一致。 |
| `HIL-BARRIER-001` 挡板到位 | 舵机范围、机构避让位、到位判据 | 只有实际验证到位才产生 `BARRIER_READY`，仅发 PWM 不算就绪。 |
| `HIL-CYCLE-001` 单件与连续循环 | 完整机构参数与前述 HIL 通过证据 | 单件闭环后再做多件与 100 次循环；无串号、重复执行和显示提前放行。 |

任何 HIL 测试都必须先设机械限位、人工断电手段和低能量起步条件；具体阈值需来自实测和机械接口，不得由软件默认值替代。

## 7. 最小实施顺序与决策闸口

这里的“顺序”只描述共享契约的闸口，不把四条泳道排成一条长队：

1. **契约闸口**：接口契约 V0.3 已修正 `DISPLAY_ACK` 方向并补齐内容校验字段；下一步用方向和载荷测试冻结代码实现。
2. **并行开发**：A、B、C 同时进行；B 可先使用领域事件，C 只接 fake pulse port，均不等待电机选型。
3. **主机汇合**：运行第 6.1 节测试并保存事件轨迹与调用计数。任一核心不变量失败，都禁止进入实机。
4. **参数闸口**：机械与电气输入齐全后，审核运动参数、安全结构和测试台架；未知项不得用“临时经验值”升格为正式参数。
5. **HIL 试行**：按第 6.2 节从单轴低能量测试逐步进入完整单件闭环。试行通过不自动授权整机比赛运行，仍需独立审核；当前若由同一团队自审，标注为“弱独立性”。

## 8. 本入口的验收标准

- 明确写出并可测试化核心不变量，而不是以“正常流程”隐含安全要求。
- `DISPLAY_ACK` 的正确方向及其与另外三事件的区别无歧义。
- protocol codec、pure state machine + fake HAL、AxisDriver STEP/DIR 骨架可并行开始，并有明确汇合闸口。
- 首批测试分清“现在无需电机可执行”和“必须等待电机/传动/安全参数”。
- 未写入引脚、定时器、运动参数、硬件型号或可烧录主循环；未把未知机械参数补写成事实。
- 保留急停硬件独立性、单调 15 秒边界、故障后旧任务不可恢复和四事件语义。
