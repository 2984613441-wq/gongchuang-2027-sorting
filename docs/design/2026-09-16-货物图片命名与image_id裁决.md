# 货物图片命名 + image_id 语义：裁决材料（2026-09-16）

> 背景：校赛 6 种货物（3 形状 × 2 颜色），线格式里 class_id 是**形状**（7 类），
> 于是"按 class_id 给 6 张图命名"必然撞成 3 个。本文把冲突、影响面、重命名方案
> 和名称表论证一次说清。**重命名与改码都还没执行**，等授权。

## 0. 结论（先看这三条）

1. 今晚"点亮屏幕"用 `工具/pi_screen_probe.py`，它绕开 run_chain 的 8 道门，
   直接用 HdmiDisplayRenderer 合成真图帧写 fb0。**不去碰链路。**
2. image_id 改用 box_id（1..6）是正确方向，但它**不是**显示侧的局部改动：
   电控协议层有一条**冻结断言** `image_id must equal class_id`
   （`电控/src/electrical_control/protocol/item_context.py:142` 编码、
   `:183` 解码），不改它，链路一发包就 `PayloadError`。
   改它 = 解冻一条已冻结约束，需要你明确批准（改动清单见 §3，仍未执行）。
3. 屏幕上的"具体的货物名称"应带颜色（青色正方体/绿色正方体/…）。
   依据见 §5；只写形状名会在赛规"分拣错误按颜色或形状判定"的语境下变成歧义名称。

## 1. 事实（哪一行代码决定的）

| 事实 | 位置 |
|---|---|
| `--image-dir` 按 `<image_id>.png/.jpg/.jpeg/.webp/.bmp` 找文件 | `电控/deploy/run_chain.py:446-462` |
| 真实模式没给 `--image-dir` 直接 SystemExit | `run_chain.py:470-474` |
| 真实链路把 image_id 取成 class_id（identity） | `run_chain.py:322-323`、`:631` |
| 队列里 image_id 由 class_id 算出 | `电控/src/electrical_control/rpi/vision_ingest.py:202` |
| 名称按 `names[content.class_id]` 查表 | `rpi/display.py:42-47` |
| `image_ids` 覆盖参数存在，但 run_chain 没传 | `rpi/display.py:29-55`、`run_chain.py:718` |
| **冻结**：`image_id must equal class_id (frozen 1:1 invariant)` | `protocol/item_context.py:142`（encode）、`:183`（decode） |
| ITEM_TASK 载荷 V0.9 已 12 字节（新增 pick_x/pick_y） | `protocol/item_context.py:18-25` |
| **box_id 不进协议**（视觉侧红线） | `docs/design/2026-08-27-视觉侧-boxid冻结映射与落点表注入.md:105` |
| box_id 是固定物理盒编号 1..6，(颜色,形状)→box_id 是冻结映射 | 同上 `:8-17` |
| STM32 只把 class_id/image_id **回显**进 DisplayContent 求 CRC，不校验相等 | `电控/stm32_logic/src/ec_protocol_gateway.c:204-207` |
| 检测模型是 7 类**形状**，不含颜色 | `视觉/training/data.yaml:6-15`、`视觉/models/labels_yolo5s_geom7c.txt` |
| 颜色是另一条通道（11 色词表） | `视觉/src/sorting_vision/sort_plan.py:23-35` |

推论：`class_id`（形状）无法区分同形状的两种颜色；屏幕要显示"哪种货物"，
必须拿到 box_id 或颜色——而这两样**都不在 ITEM_TASK 的 12 字节里**。

## 2. 三种方案对比

| | A. image_id 存 box_id（用户已批准方向） | B. 保持 image_id == class_id | C. 给协议加 box_id 字段 |
|---|---|---|---|
| 6 种货物能否各有图/名 | 能 | **不能**（3 个 class_id → 3 张图，同形状另一颜色必错） | 能 |
| 要改哪里 | `item_context.py` 2 处断言 + `vision_ingest.py:202` + `run_chain.py:322` + 名称查表键 | 什么都不用改，但显示必然错一半 | ITEM_TASK 载荷加字节 → 两端固件/主机全改 |
| 碰冻结线格式 | 不动字节布局，只动**取值语义** | 不碰 | **动**（12→13 字节），影响面最大 |
| 固件是否要重烧 | 不用（STM32 只回显+CRC） | 不用 | 要 |
| 赛规风险 | 低 | 高：规则 269-271"信息出现任何错误不得分" | 低但工期最贵 |

**推荐 A**，理由：B 会在"同形状不同色"上必然显示错图错名（直接送分给规则 269-271），
C 代价最大且要重烧固件；A 只需解冻 host 侧一条断言。

## 3. 走 A 的最小改动清单（**未执行**，等批准）

## 5. 名称表该不该写成「青色正方体」——从赛规论证

赛规原文（`docs/references/赛题原文-提取文本/省赛规则.txt`）：

- 269-271："货物分拣完成并存储到相应的储物盒后，正确显示货物对应的**分类信息**
  （序号、**具体的货物名称**、货物图片、分拣成功总数量），每条信息得 2 分，
  上述信息出现任何错误不得分。"
- 262-264："多个**颜色和形状相同**的货物放进同一个储物盒，每个货物得 5 分。"
- 265-266："将**不同颜色或者不同形状**的货物放入同一个储物盒…为分拣错误，不得分。"

论证：
1. 本次货物是 6 种 = 3 形状 × 2 颜色，"颜色"是货物身份的组成部分（262/265 把颜色
   与形状并列作为判定维度）。因此"具体的货物名称"若只写"正方体"，指代的是**两个**
   不同货物，不满足"具体"。
2. 269-271 是逐条 2 分的加分项，且"出现任何错误不得分"。名称写形状名而图片是其中
   一个颜色时，屏幕上的名称与该件实际货物不是一对一关系——现场裁判质疑时没有退路。
3. 得分点里另有独立的"货物图片"一条：图片已经承担了"颜色+形状"的识别职责。
   名称只写形状会让两条信息**互相矛盾**（图是绿正方体、名字是"正方体"）。
4. 命题给的信息示例（`工具/control_panel.py:203-209` 注释引用的"五棱柱/正四面体"）
   是形状词，但那是**形状示例**，不是"不要写颜色"的规定；规程没有禁止更具体的名称。

结论：**建议改为「颜色+形状」**，即 `青色正方体 / 绿色正方体 / 红色三棱柱 /
蓝色三棱柱 / 黑色圆柱 / 橙色圆柱`。这与 box_id 命名 1:1，不增加任何显示字段。

颜色词必须与视觉侧 `DEFAULT_COLOR_VOCABULARY`（`视觉/src/sorting_vision/sort_plan.py:23-35`）
对齐：cyan→青色、green→绿色、red→红色、blue→蓝色、black→黑色、orange→橙色。
（"orange" 建议就叫"橙色"，别写"橙红色"——词表里没有"橙红"。）
