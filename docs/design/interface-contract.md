## 1. 适用范围

本文件定义 MaixCAM Pro ↔ 树莓派 4B ↔ STM32F407 三设备间的通信协议。

校赛阶段仅实施**方案 B**（MaixCAM → 树莓派 → STM32）。方案 A 的 MaixCAM ↔ STM32 直连链路在此文件中同样定义但标注 `[方案A:预留]`，校赛版本不激活。

## 3. 统一外层帧结构

三台设备共用相同二进制帧格式：

```
┌─────────┬──────────┬──────────┬──────────┬────────┬──────────┬──────────┬──────────┬────────┬──────┐
│ 帧头    │ 协议版本  │ 发送方   │ 接收方   │ 任务号  │ 消息序号  │ 命令字   │ 数据长度  │ 数据区  │ CRC  │
│ 2 bytes │ 1 byte   │ 1 byte   │ 1 byte   │ 2 bytes │ 2 bytes  │ 1 byte   │ 2 bytes  │ N bytes │ 2 bytes│
└─────────┴──────────┴──────────┴──────────┴────────┴──────────┴──────────┴──────────┴────────┴──────┘
```

| 字段 | 大小 | 说明 |
|------|------|------|
| 帧头 | 2 bytes | `[待定]` 如 0xA5 0x5A |
| 协议版本 | 1 byte | 校赛冻结为 0x01；不兼容时禁止启动 |
| 发送方 | 1 byte | 0x01=MaixCAM, 0x02=树莓派, 0x03=STM32 |
| 接收方 | 1 byte | 同上 |
| 任务号 | 2 bytes | 每轮比赛递增，隔离不同轮次 |
| 消息序号 | 2 bytes | 每方独立递增，用于去重和幂等 |
| 命令字 | 1 byte | 见第 4 节 |
| 数据长度 | 2 bytes | 数据区的字节数（网络字节序） |
| 数据区 | N bytes | 命令相关的结构化数据 |
| CRC | 2 bytes | `[待定]` CRC-16/CCITT 或 CRC-16/MODBUS |

## 4. 命令字枚举

### 4.1 基础命令（L0 — 所有链路共用）

| 命令字 | 助记符 | 方向 | 说明 |
|--------|--------|------|------|
| 0x01 | `HEARTBEAT` | 双向 | 心跳，含设备状态 |
| 0x02 | `HEARTBEAT_ACK` | 双向 | 心跳应答 |
| 0x03 | `DEVICE_READY` | 链路内双向 | 发送设备初始化完成 |
| 0x04 | `ERROR` | 双向 | 故障报告，数据区含故障码 |
| 0x05 | `ACK` | 双向 | 通用肯定应答 |
| 0x06 | `NACK` | 双向 | 通用否定应答，含原因码 |

### 4.2 视觉链命令（L1 — MaixCAM ↔ 树莓派）

| 命令字 | 助记符 | 方向 | 说明 |
|--------|--------|------|------|
| 0x10 | `BATCH_TARGETS` | MaixCAM→树莓派 | 整批识别结果 |
| 0x11 | `TARGET_REACQUIRE_REQ` | 树莓派→MaixCAM | 请求复核指定目标 |
| 0x12 | `TARGET_REACQUIRE_RSP` | MaixCAM→树莓派 | 复核结果 |
| 0x13 | `DIAG_SCAN` | `[默认关闭]` | 可选诊断二次核验 |

### 4.3 调度链命令（L2 — 树莓派 ↔ STM32）

| 命令字 | 助记符 | 方向 | 说明 |
|--------|--------|------|------|
| 0x20 | `BARRIER_READY` | STM32→树莓派 | 挡板已就绪，允许运动 |
| 0x21 | `ITEM_TASK` | 树莓派→STM32 | 单件高层任务 |
| 0x22 | `MOTION_DONE` | STM32→树莓派 | 本件运动序列结束 |
| 0x23 | `ITEM_RESULT` | STM32→树莓派 | 本件结果（成功/失败+原因） |
| 0x24 | `DISPLAY_DATA` | STM32→树莓派 | `[保留/非主链]` 只用于 STM32 向树莓派补充报告显示所需且 `ITEM_RESULT` 未携带的数据；校赛主链不依赖此帧 |
| 0x25 | `DISPLAY_ACK` | 树莓派→STM32 | 树莓派在本件界面实际完成渲染后发送；STM32 收到匹配确认后才允许下一件 |
| 0x26 | `ESTOP` | STM32→树莓派 | 急停通知 |

### 4.4 方案 A 预留命令

| 命令字 | 助记符 | 方向 | 说明 |
|--------|--------|------|------|
| 0x30 | `[预留]` | MaixCAM→STM32 | `[方案A:预留]` 直连目标列表 |

## 5. 关键消息数据区定义（待详细设计）

### 5.1 `BATCH_TARGETS` (0x10)

```
┌──────────┬──────────┬─────────────────────────────┐
│ 目标数量  │ 任务号    │ 目标[0]..目标[N-1]           │
│ 1 byte   │ 2 bytes  │ 每目标：[待定] bytes         │
└──────────┴──────────┴─────────────────────────────┘

每个目标含：
- 类别 ID (1 byte)
- 置信度 (1 byte, 0-100)
- X 坐标 (2 bytes, 0.1mm 单位)
- Y 坐标 (2 bytes, 0.1mm 单位)
- 抓取角度 (1 byte, 0-180°, 0xFF=无效)
- 角度有效标志 (1 bit)
```

### 5.2 `ITEM_TASK` (0x21)

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│ 目标序号  │ 类别 ID   │ 图片 ID   │ X 坐标    │ Y 坐标    │ 抓取角度  │
│ 1 byte   │ 1 byte   │ 1 byte   │ 2 bytes  │ 2 bytes  │ 1 byte   │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```

`image_id` 由树莓派在创建本件高层任务时确定，并随 `ITEM_TASK` 显式传给 STM32。STM32 将 `(任务号, 目标序号, 类别 ID, 图片 ID)` 保存为当前件上下文；重复 `ITEM_TASK` 不得覆盖已经锁定的当前件内容。相同 `(任务号, 目标序号)` 若携带不同载荷，视为协议冲突并进入故障，不得运动。

上图冻结的是 `image_id` 的存在、语义以及它在逻辑字段中的位置，不等同于完整 `ITEM_TASK` wire codec 已冻结。X/Y/角度的最终单位、有效值表达、端序以及完整载荷长度仍待专门裁决；当前协议代码不得根据该示意图猜写这些未冻结细节。

### 5.3 `ITEM_RESULT` (0x23)

```
┌──────────┬──────────┬──────────┐
│ 目标序号  │ 结果码    │ 依据      │
│ 1 byte   │ 1 byte   │ 1 byte   │
└──────────┴──────────┴──────────┘

结果码：
  0x00 = SUCCESS
  0x01 = DROP_FAILED
  0x02 = GRIP_FAILED
  0x03 = POSITION_UNREACHABLE
  0x04 = SAFETY_INTERRUPT
  0xFF = UNKNOWN

依据：
  0x00 = CONTROL_SEQUENCE（基础链，无可检测故障）
  0x01 = CONFIRMED（启用了结果确认传感器）
```

### 5.4 `DISPLAY_DATA` (0x24)

`[保留/非主链]` 校赛方案 B 中，树莓派已持有调度数据，并通过 `ITEM_RESULT` 获得本件结果，可直接生成显示内容，因此主链不发送 `DISPLAY_DATA`。若后续确认确有树莓派未掌握的显示字段，才启用本帧，且方向固定为 **STM32→树莓派**。启用前须重新冻结下列数据区；本帧不代替 `ITEM_RESULT`，也不作为树莓派开始渲染的必要条件。

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 目标序号  │ 类别 ID   │ 图片 ID   │ 累计成功  │ 结果码    │
│ 1 byte   │ 1 byte   │ 1 byte   │ 1 byte   │ 1 byte   │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

### 5.5 `DISPLAY_ACK` (0x25)

方向固定为 **树莓派→STM32**。树莓派只能在对应本件的画面已实际完成渲染后发送，不得在收到 `ITEM_RESULT`、开始渲染或仅更新内存状态时提前发送。

```
┌──────────┬──────────┬────────────────────┐
│ 目标序号  │ 渲染结果  │ 显示内容 CRC32      │
│ 1 byte   │ 1 byte   │ 4 bytes            │
└──────────┴──────────┴────────────────────┘

渲染结果：
  0x00 = RENDERED
  其余值 = [待定，不得视为放行确认]
```

`显示内容 CRC32` 使用 CRC-32/ISO-HDLC（多项式正常表示 `0x04C11DB7`、反射输入/输出、初值与最终异或均为 `0xFFFFFFFF`）。输入是树莓派实际用于本件画面的规范字节序列 `目标序号 + 类别 ID + 图片 ID + 累计成功数 + 结果码`；五个字段均为单字节，按该顺序直接拼接。CRC 结果在载荷中按网络字节序（高字节在前）发送。其中目标序号、类别 ID、图片 ID 必须匹配当前 `ITEM_TASK` 上下文，结果码必须匹配当前 `ITEM_RESULT`，累计成功数必须匹配第 6.1 节规则计算出的本轮值。该校验只证明树莓派确认了与本件相同的数据版本，不替代“实际渲染完成”这一发送前提。

已知测试向量：规范字节序列 `01 02 03 04 05` 的 CRC32 为 `0x470B99F4`，载荷中的四个字节为 `47 0B 99 F4`。树莓派与 STM32 的协议测试必须共同通过该向量。

STM32 必须同时校验帧头中的任务号、数据区中的目标序号、渲染结果和显示内容 CRC32；只有全部与当前本件匹配且渲染结果为 `RENDERED` 的首个 `DISPLAY_ACK` 才能放行下一件。

### 5.6 `ERROR` (0x04)

```
┌──────────┬──────────┬──────────┐
│ 故障等级  │ 故障码    │ 附加信息  │
│ 1 byte   │ 2 bytes  │ N bytes  │
└──────────┴──────────┴──────────┘

故障等级：0x01=数据扰动 0x02=任务异常 0x03=安全故障
```

## 6. 时序约束

| 约束 | 值 | 说明 |
|------|---|------|
| 应答超时 | [待定] ms | 超时后有限次数重发 |
| 最大重发次数 | [待定] 次 | 耗尽后进入对应故障等级 |
| 心跳间隔 | [待定] ms | 用于检测失联 |
| 失联判定 | [待定] 次连续心跳丢失 | 触发失联处理 |
| 挡板动作 → `BARRIER_READY` 最长时间 | [待定] ms | 含安全余量 |
| `DISPLAY_ACK` 超时 | [待定] ms | 不得超过 15 秒阶段预算剩余 |

逐件主链时序为：`ITEM_TASK` → `MOTION_DONE` → `ITEM_RESULT` → 树莓派完成本件界面实际渲染 → 树莓派发送 `DISPLAY_ACK` → STM32 校验匹配后允许下一件。

- `MOTION_DONE` 只表示运动序列结束，不表示本件成功，也不能放行下一件。
- 只有成功的 `ITEM_RESULT` 才允许更新成功计数；失败结果仍须显示并完成本件渲染确认流程。
- `DISPLAY_DATA` 为保留的非主链帧，它的缺失不得阻塞树莓派依据已有数据渲染。
- 未收到与当前本件匹配的成功 `DISPLAY_ACK` 时，STM32 不得接受或启动下一件；超时数值和重发次数按待定项冻结，本文不预设。

### 6.1 本轮成功计数一致性

树莓派与 STM32 必须按下列确定性规则维护同一个 `success_count`：

1. **初值与范围**：每个经验证的新轮次开始时，两端均将计数设为 `0`；字段为无符号单字节，合法范围 `0..255`。
2. **唯一更新事件**：只有当前件首次有效的 `ITEM_RESULT(result_code=SUCCESS)` 使计数加一。STM32 在形成该结果后更新本地计数；树莓派在首次接收并接受同一结果后更新本地计数。随后两端均以更新后的值构造或校验本件显示内容。
3. **不更新事件**：失败 `ITEM_RESULT`、重复结果、消息重传、心跳、日志、重新识别、重新渲染、重复 `DISPLAY_ACK` 和普通通信恢复均不得改变计数。
4. **幂等键**：成功结果的计数消费按当前轮次内的本件身份去重；同一成功结果无论收到多少次都只计一次。身份与去重的外层字段编码仍受统一外层帧冻结项约束，但不得因此弱化“一件一次”的行为要求。
5. **溢出**：禁止从 `255` 回绕到 `0`。计数为 `255` 时不得接受可能产生第 256 个成功结果的新 `ITEM_TASK`；若仍观察到溢出条件，进入协议/轮次故障，保持原计数并等待人工复位。
6. **轮次复位**：仅经验证的新轮次初始化允许两端同时复位为 `0`。重连、重传、显示超时、同一轮通信恢复或单节点重启不得自行清零。若任一节点不能证明其轮次与计数上下文和另一端一致，禁止继续接件并进入待人工恢复状态。

本规则使 STM32 能用 `ITEM_TASK` 的 `target_seq/class_id/image_id`、当前 `ITEM_RESULT.result_code` 和本地同步的 `success_count` 计算本件 `DISPLAY_ACK` 的期望 CRC32。它不冻结外层帧头、外层 CRC16、超时或重传次数；STM32 主/备 UART 均已固定为 115200 8N1。

## 7. 幂等与去重规则

1. 接收端按 `(任务号, 消息序号)` 判定重复帧。
2. 重复帧 → 重发上次应答，**不得重复执行运动或投放**。
3. 任务号不匹配的帧（旧轮次）→ 静默丢弃。
4. 消息序号跳跃（丢帧）→ 记录日志，按命令字类型决定重传或继续。
5. 同一视觉识别结果不得同时由树莓派和 STM32 两个调度端执行。
