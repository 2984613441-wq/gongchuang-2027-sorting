# 视觉侧改动清单：box_id 冻结映射 + 落点表注入（2026-08-27）

> 用途：电控侧对视觉侧的要求。方案 A 已拍板——`box_id` 是**固定物理盒编号（1..6）**，
> 落点表按 `box_id → (X,Y)` 键，跨批次稳定，不再每批动态字典序分配。

## 0. 背景：box_id 语义冲突（已裁决）

`sort_plan.py:127-133` 现在按 `(color_id, shape_id)` 字典序每批动态分配 `box_id`：

```python
unique = sorted(set(keys))
box_of = {key: index + 1 for index, key in enumerate(unique)}  # 每批漂移
```

而落点表（`drop_table.py`）按 `box_id 1..6` 固定键。两者冲突：同一物理盒这轮是 box 1、下轮变 box 3，投放会错位。

**裁决（方案 A）**：`box_id` 是固定物理盒编号。冻结一张 `(颜色, 形状) → box_id` 映射表，替换动态字典序分配。职责分离——视觉定「哪类放哪盒」（映射表），机械定「盒在哪」（落点表 `box_id → (X,Y)`）。

## 1. 电控侧已就位（视觉手需知悉的接口）

树莓派侧 `电控/src/electrical_control/rpi/vision_ingest.py` 已接好落点表链路，**无需视觉手再改**：

- `VisionTarget` 新增 `box_id: int | None = None` 字段。
- `build_item_task_queue(..., drop_point_for_box=...)` 新增落点表解析参数（`box_id → (x_0_1mm, y_0_1mm)`）。
- 语义：给了 `drop_point_for_box` 且 `box_id` 存在 → 填真实坐标 + `grip_angle=0xFF`（可序列化）；否则保持占位 `0/0/0`（wire 边界拒绝，fail-closed）。

所以视觉手要做的，是让 `box_id` 正确地产出并流到 `VisionTarget`。

## 2. 视觉侧要改的三件事

### 2.1 `sort_plan.py`：冻结映射表已就位，只差填值（核心）

`sort_plan.py` 已实现 `BoxAssignment` 冻结容器，`build_sort_plan` 已加
`box_assignment` 参数，**无需视觉手再写代码**，只差实测后填值：

```python
from sorting_vision.sort_plan import BoxAssignment

# 冻结表：(color_id, shape_id) -> box_id，内容待机械/赛题实测填入
box_assignment = BoxAssignment(
    {
        (0, 2): 1,  # (颜色, 形状) -> 物理盒编号
        (1, 3): 2,
        # ... 共 6 条
    },
    box_count=6,
)

# 调用时传入：
build_sort_plan(..., box_assignment=box_assignment)
```

- key 不在映射表 → `BoxAssignment.box_for` 抛 `UnknownGroupError`（fail-closed），不再 `enumerate` 动态分配。
- 不传 `box_assignment` 时保持旧的字典序分配（仅诊断用，禁止上生产）。

### 2.2 `drop_table.py`：注入真实落点表数据

`DropTable` 类骨架已在（`box_id 1..6 → DropPoint`，±1450 校验都对），但**无真实数据注入**。需机械实测后填入：

```python
# 例：机械实测 6 个物理盒中心坐标（单位 0.1mm，原点=装置中心，有符号）
drop_table = DropTable({
    1: DropPoint(x_0_1mm=..., y_0_1mm=...),
    ...
    6: DropPoint(x_0_1mm=..., y_0_1mm=...),
})
```

数据来源：**机械 + 视觉同测**——摄像头安装/标定可能有偏差，相机坐标不能单独信任，以机械量出的物理盒位置为准，视觉复核。

### 2.3 数据流打通：`SortPlan.box_id` → `VisionTarget.box_id`

视觉 `SortPlan` 产出的 `box_id`（2.1 的冻结映射结果）要传进树莓派的 `VisionTarget`，链路才是通的：

```
build_sort_plan(...) -> PlacedItem.box_id
    -> VisionTarget(target_seq=..., class_id=..., box_id=box_id)
    -> build_item_task_queue(..., drop_point_for_box=drop_point_for_box)
    -> ItemTaskPayload(x=真实, y=真实, grip_angle=0xFF)
```

注意类型匹配：`build_item_task_queue` 的 `drop_point_for_box` 期望 `box_id -> (x_0_1mm, y_0_1mm)`
二元组，而 `DropTable.point_for(box_id)` 返回 `DropPoint` 对象，需拆包：

```python
def drop_point_for_box(box_id: int) -> tuple[int, int]:
    point = drop_table.point_for(box_id)
    return (point.x_0_1mm, point.y_0_1mm)
```

`drop_table.point_for` 已实现（`drop_table.py`），只需 2.2 注入数据。
