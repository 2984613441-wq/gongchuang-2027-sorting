## 三、视觉改动详解（5 项）

### 3.1 形状识别：YOLO 模型训练（V1，P0）

**目标**：识别 6 类形状（圆柱、球、圆锥、正方体、四棱锥、三棱柱/正四面体）。

**方案（路线 C）**：
1. **形状**：YOLO 模型（MaixCAM 跑 `.mud`）
2. **颜色**：HSV 像素统计（保留现有逻辑）
3. **深度**：TinyF 测 3 点（§3.2）
4. **特征点**：置信度加权辅助（`final = 0.3·特征 + 0.7·模型`）

#### 3.1.1 标注（Roboflow）

**工具**：Roboflow（在线标注平台，支持 YOLO 格式导出）

**步骤**：
1. **采集数据**：拍 1260 张（6 类各 210 张）
   - 不同位置（托盘 9~24 格）
   - 不同角度（俯视为主，略微倾斜）
   - 不同堆叠状态（单件、2~3 件叠放）
   - 不同光照（补光灯开/关，若已装）
   - 不同背景（托盘空/满）
2. **上传到 Roboflow**：
   - 创建项目 → 上传 1260 张
   - 标注：框选每个件 + 标类别（`cylinder / sphere / cone / cube / pyramid / prism`）
   - 审核建议：1260 张 × 3 分钟/张 = **63h**（可多人并行）
3. **数据增强**（Roboflow 自带）：
   - 旋转 ±15°
   - 亮度 ±20%
   - 翻转（水平/垂直）
   - 噪声
   - 增强后约 **3000~4000 张**
4. **导出**：
   - 格式：YOLOv5 / YOLOv8 / YOLOv11（看 MaixHub 支持哪个）
   - 下载 `dataset.zip`（包含 `train/val/test` 三个文件夹 + `data.yaml`）

#### 3.1.2 训练（本地 or Colab）

**环境**：
- GPU：推荐 RTX 3060 以上（或 Google Colab 免费 T4）
- Python 3.8+
- PyTorch 1.10+
- ultralytics（`pip install ultralytics`）

**步骤**：
1. 解压 `dataset.zip`
2. 训练：
   ```bash
   yolo train \
     model=yolov8n.pt \
     data=data.yaml \
     epochs=100 \
     imgsz=320 \
     batch=16 \
     device=0
   ```
   - `yolov8n.pt`：最小模型（MaixCAM 能跑）
   - `epochs=100`：训练轮数（可调）
   - `imgsz=320`：MaixCAM 分辨率（320×240 或 224×224，看 MaixHub 要求）
   - `batch=16`：显存够就调大
3. 等待训练完成（约 4~8h，看 GPU）
4. 输出：`runs/detect/train/weights/best.pt`

#### 3.1.3 转换（MaixHub）

**步骤**：
1. 登录 MaixHub（https://maixhub.com）
2. 模型转换 → 上传 `best.pt`
3. 选择目标平台：MaixCAM（芯片 K230）
4. 转换 → 下载 `best.mud`
5. 把 `best.mud` 传到 MaixCAM（`/root/models/` 或 `/home/`）

#### 3.1.4 MaixCAM 推理（MaixPy）

**代码**（伪代码，实际要看 MaixPy API）：
```python
from maix import camera, nn

# 加载模型
model = nn.YOLOv8("best.mud")

# 采集图像
img = camera.capture()

# 推理
results = model.detect(img)

# 解析结果
for obj in results:
    class_id = obj.class_id      # 0~5 对应 6 类
    confidence = obj.confidence  # 置信度
    x, y, w, h = obj.bbox        # 边界框
    
    # 根据 class_id 判断形状
    shape = ["cylinder", "sphere", "cone", "cube", "pyramid", "prism"][class_id]
    
    # 发给树莓派（§3.4 协议）
    send_to_pi(shape=shape, color=color_from_hsv(img), x=x, y=y)
```

**效果**：MaixCAM 能识别 6 类形状 + 6 类颜色 = 36 种组合。

### 3.2 ToF 深度测量：TinyF 多点测量（V2，P1）

**目标**：测每一件的高度，区分"平顶 vs 尖顶"。

**方案**：TinyF 装在 Z 轴/夹爪头上，抓之前移到件正上方测 3 个点（中心 + 偏 10mm 两侧）。

#### 3.2.1 固件侧（STM32）

**接线**：
| TinyF 端子 | 接 STM32 | 说明 |
|---|---|---|
| VDD（5V） | 5V 输出 | 从降压模块 ① 取 |
| RX | UART4 TX（PC10） | STM32 发给 TinyF |
| TX | UART4 RX（PC11） | TinyF 发给 STM32 |
| GND | GND | 地 |

**协议**：UART 115200 8N1，TinyF 输出帧格式（见 TinyF 手册，类似）：
```
0xAA 0x55 <距离高位> <距离低位> <校验>
```

**固件代码**（在 `ec_board_stm32.c` 或新建 `ec_tinyf.c`）：
```c
#include "stm32f4xx_hal.h"

UART_HandleTypeDef huart4;

void tinyf_init(void) {
    // 初始化 UART4（PC10/PC11，115200）
    huart4.Instance = UART4;
    huart4.Init.BaudRate = 115200;
    huart4.Init.WordLength = UART_WORDLENGTH_8B;
    huart4.Init.StopBits = UART_STOPBITS_1;
    huart4.Init.Parity = UART_PARITY_NONE;
    HAL_UART_Init(&huart4);
}

uint16_t tinyf_measure(void) {
    uint8_t rx_buf[5];
    // 读 5 字节：0xAA 0x55 <高> <低> <校验>
    HAL_UART_Receive(&huart4, rx_buf, 5, 100);
    
    // 校验（简单异或）
    uint8_t checksum = rx_buf[0] ^ rx_buf[1] ^ rx_buf[2] ^ rx_buf[3];
    if (checksum != rx_buf[4]) {
        return 0xFFFF;  // 校验失败
    }
    
    // 距离（mm）
    uint16_t distance = (rx_buf[2] << 8) | rx_buf[3];
    return distance;
}

void measure_shape_profile(uint16_t *d_center, uint16_t *d_right, uint16_t *d_left) {
    // Z 轴移到件正上方 80~100mm 高度
    // ...
    
    // 测中心
    *d_center = tinyf_measure();
    
    // XY 偏移 +10mm
    // move_xy_relative(10, 0);
    *d_right = tinyf_measure();
    
    // XY 偏移 -20mm（从中心算 -10mm）
    // move_xy_relative(-20, 0);
    *d_left = tinyf_measure();
    
    // XY 回中心
    // move_xy_relative(10, 0);
}

bool is_flat_top(uint16_t d_center, uint16_t d_right, uint16_t d_left) {
    return (abs(d_center - d_right) < 5 && abs(d_center - d_left) < 5);
}

bool is_peaked(uint16_t d_center, uint16_t d_right, uint16_t d_left) {
    return (d_center < d_right - 5 && d_center < d_left - 5);
}
```

**调用**（在 `handle_item_task()` 里）：
```c
uint16_t d_center, d_right, d_left;
measure_shape_profile(&d_center, &d_right, &d_left);

bool flat = is_flat_top(d_center, d_right, d_left);
bool peak = is_peaked(d_center, d_right, d_left);

// 发给树莓派（§3.4 协议）
send_to_pi_depth(flat, peak, d_center);
```

#### 3.2.2 视觉侧（MaixCAM）

**改动**：在 MaixCAM 发给树莓派的帧里加 3 个字节：
```
原来：0xAA 0xBB <盒号> <x高> <x低> <y高> <y低> <校验>（7 字节）
改后：0xAA 0xBB <颜色形状> <x高> <x低> <y高> <y低> <is_flat> <is_peaked> <d_center高> <d_center低> <校验>（11 字节）
```

或者**简化**：深度信息由 STM32 直接发给树莓派（不过 MaixCAM），MaixCAM 只发形状和颜色。

#### 3.2.3 树莓派查表

**逻辑**（在 `vision_ingest.py` 里）：
```python
if shape == "circle":
    if is_flat_top:
        class_id = 1  # 圆柱
    elif is_peaked:
        class_id = 2  # 圆锥
    else:
        class_id = 3  # 球
elif shape == "square":
    if is_flat_top:
        class_id = 4  # 正方体
    else:
        class_id = 5  # 四棱锥
elif shape == "triangle":
    class_id = 6  # 正四面体（三棱柱中心是平的，暂不区分）
```

**效果**：能区分"圆柱 vs 圆锥"、"正方体 vs 四棱锥"。

### 3.3 补光灯 + 重标 HSV（V3，P2）

**目标**：HSV 阈值稳定，不受自然光照变化影响。

**方案**：白光补光灯（5V、6000~6500K、环形，¥30）装到相机旁。

#### 3.3.1 安装

**位置**：MaixCAM 镜头周围（距离约 10~20cm）

**固定**：双面胶 / 魔术贴 / 3D 打印支架

**供电**：5V 从降压模块 ① 取（和树莓派/STM32 同一路）

#### 3.3.2 重标 HSV

**步骤**：
1. 补光灯装好、开启
2. 用 6 类件（红/蓝/绿/黄/橙/紫各 1 个）拍 20 张（每类件在不同位置/堆叠状态）
3. 用 `cv2.inRange()` 重新标 HSV 下限/上限：
   ```python
   import cv2
   import numpy as np
   
   img = cv2.imread("test.jpg")
   hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
   
   # 手工调参（用 HSV 颜色拾取器）
   lower_red = np.array([0, 100, 100])
   upper_red = np.array([10, 255, 255])
   
   mask = cv2.inRange(hsv, lower_red, upper_red)
   cv2.imshow("mask", mask)
   ```
4. 写回 `stage1_color_v6_send.py`：
   ```python
   COLOR_RANGES = {
       "red": ([0, 100, 100], [10, 255, 255]),
       "blue": ([100, 100, 100], [130, 255, 255]),
       # ...
   }
   ```

**效果**：HSV 阈值在补光灯下稳定，不受自然光变化影响。

### 3.4 协议改动：MaixCAM 报颜色+形状、树莓派查表（V4，P2，L4）

**现状**：MaixCAM → 树莓派的 `BATCH_TARGETS` 帧，第 1 字节是**盒号**（1~6） ⇒ **6 类件现场才知道放哪个盒，改规则就得重刷 MaixCAM**。

**问题**：
- 省赛现场裁判说"红色圆柱放 3 号盒、蓝色球放 1 号盒"
- 现在 MaixCAM 代码里写死"红色圆柱 → 盒 1"
- ⇒ 要改成"红色圆柱 → 盒 3"，必须重刷 MaixCAM（约 10 分钟）

**方案**：第 1 字节从"盒号"改成 **高 4 位颜色 + 低 4 位形状**

#### 3.4.1 MaixCAM 改动

**原来**（`encode_target`）：
```python
def encode_target(box_id, x, y):
    # box_id = 1~6
    return bytes([0xAA, 0xBB, box_id, x >> 8, x & 0xFF, y >> 8, y & 0xFF, checksum])
```

**改后**：
```python
COLOR_CODE = {"red": 1, "blue": 2, "green": 3, "yellow": 4, "orange": 5, "purple": 6}
SHAPE_CODE = {"cylinder": 1, "sphere": 2, "cone": 3, "cube": 4, "pyramid": 5, "prism": 6}

def encode_target(color, shape, x, y):
    color_code = COLOR_CODE[color]
    shape_code = SHAPE_CODE[shape]
    byte1 = (color_code << 4) | shape_code  # 高 4 位颜色 + 低 4 位形状
    return bytes([0xAA, 0xBB, byte1, x >> 8, x & 0xFF, y >> 8, y & 0xFF, checksum])
```

**示例**：
- 红色圆柱：`byte1 = (1 << 4) | 1 = 0x11`
- 蓝色球：`byte1 = (2 << 4) | 2 = 0x22`

#### 3.4.2 树莓派改动

**原来**（`vision_ingest.py:52`）：
```python
box_id = data[2]  # 第 1 字节当盒号
```

**改后**：
```python
byte1 = data[2]
color_code = (byte1 >> 4) & 0x0F  # 高 4 位
shape_code = byte1 & 0x0F          # 低 4 位

# 查表（从配置文件读）
box_id = config[(color_code, shape_code)]
```

**配置文件**（`box_mapping.ini`）：
```ini
[BoxMapping]
# (颜色, 形状) → 盒号
1,1 = 3  # 红色圆柱 → 3 号盒
2,2 = 1  # 蓝色球 → 1 号盒
3,4 = 5  # 绿色正方体 → 5 号盒
# ...
```

**效果**：现场分配盒号只需改 `box_mapping.ini`，**不用重刷 MaixCAM**（约省 10 分钟）。

#### 3.4.3 同步改动

| 文件 | 改什么 |
|---|---|
| MaixCAM 发送端 | `encode_target(color, shape, x, y)` |
| 树莓派 `vision_ingest.py:52` | 解码 `byte1` + 查表 |
| `interface-contract.md` | 升版（协议 v2.0） |
| 端到端测试 | MaixCAM 发 `0x12` = 红色圆柱 → 树莓派查表 → STM32 收到 `class_id=3` |

### 3.5 Week1 验证实验：确认两个关键假设（V5，P1）

**目标**：
1. **几何特征准确率**：确认"特征点辅助"是否有用
2. **数据量对比**：确认 600 还是 1260 张够

#### 3.5.1 实验 ① 几何特征准确率

**方法**：
1. 用现有物料（6 类件各 10 个）拍 60 张（不同位置/角度/堆叠）
2. 跑 `stage1_color_v6_send.py` 的几何特征提取（面积/周长/凸包/矩）
3. 手工标注真值（每张标"这是什么"）
4. 统计准确率：`正确数 / 总数`

**通过标准**：**>70%** 才继续用特征辅助；否则只用模型 + HSV 颜色。

**预期结果**：
- 若 **<70%**，则不用特征辅助，改为 `final = 1.0·模型`
- 若 **>70%**，则用 `final = 0.3·特征 + 0.7·模型`

#### 3.5.2 实验 ② 数据量对比

**方法**：
1. 用 Roboflow 标注 1260 张（审核建议值）
2. 分三组：300/600/1260，训练 3 个模型
3. 用同一测试集（60 张，标注但不参与训练）测 mAP@0.5
4. 画曲线：数据量 vs mAP，找拐点

**通过标准**：
- 若 600 张已达 mAP >0.85 且 1260 张只提升 <5%，则只标 600 张
- 否则按 1260 张

**预期结果**：
- 若拐点在 600，节省 660 张标注（约 33h）
- 若拐点在 1260，说明数据量不够，继续标到 2000 张

#### 3.5.3 时间安排

| 日期 | 事项 | 工时 |
|---|---|---|
| 10-23 Day1 | 实验 ① 拍 60 张 + 跑特征提取 + 手工标注 | 4h |
| 10-24 Day2 | 实验 ① 统计准确率 + 分析结果 | 4h |
| 10-25 Day3 | 实验 ② 标注 300 张 + 训练 | 4h |
| 10-26 Day4 | 实验 ② 标注 600/1260 张 + 训练 + 画曲线 | 4h |

**合计**：16h（4 天）

## 七、风险与退路

| 风险 | 概率 | 后果 | 退路 |
|---|---|---|---|
| 几何特征准确率 <70% | 中 | 特征点辅助无用 | 只用模型 + HSV 颜色 + ToF 深度 |
| 数据量不够（1260 张 mAP 仍 <0.85） | 低 | 模型准确率不达标 | 继续标到 2000 张；或降低准确率要求到 0.80 |
| TinyF 近距离（50~100mm）读数不稳 | 低 | 深度消歧义失效 | 退回 STP-23L（¥87）或 PMOD_TOF100（面阵） |
| MaixHub 不支持 YOLOv8 | 低 | 无法转 `.mud` | 改用 YOLOv5 或 YOLOv11 |
| MaixCAM 跑 `.mud` 太慢（<10 FPS） | 中 | 实时性差 | 降低分辨率（320×240 → 224×224）；或换 YOLOv8n → YOLOv8-tiny |
| 协议改动后 MaixCAM 和树莓派不同步 | 低 | 通讯失败 | 回退到协议 v1.0（发盒号） |

## 八、关键注意事项

### 8.1 标注质量检查

**每标 100 张检查一次**：
1. 框是否完整（没有漏标、多标）
2. 类别是否正确（圆柱 vs 圆锥）
3. 边界框是否紧贴件边缘

### 8.2 数据增强参数

Roboflow 默认增强可能不够，手动调参：
- 旋转：±15°（托盘是固定的，不会 360° 旋转）
- 亮度：±20%（补光灯后变化小）
- 翻转：水平/垂直（但托盘方向固定，可能不需要）
- 噪声：5%（模拟相机噪声）

### 8.3 训练参数调优

**第一次训练**（快速验证）：
- `epochs=50`（约 2h）
- `imgsz=224`
- `batch=16`

**第二次训练**（正式版）：
- `epochs=100`（约 4~8h）
- `imgsz=320`
- `batch=8`（若显存不够）
