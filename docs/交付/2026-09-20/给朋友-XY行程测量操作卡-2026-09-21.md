# 给朋友：X / Y 轴实际行程测量操作卡

> **目标**：量出 X 轴、Y 轴**真正能走多少毫米**。
> **做这件事的原因**：固件里写的可达范围（X 19.0 cm / Y 19.0 cm）**可能被人为设小了**，
> 而机械丝杆是 **29 cm**。这一条直接决定"落点能不能放到想要的位置"。
> **预计用时**：30–40 分钟。**全程需要有人在机器旁边看着。**

---

## 🔴 三条铁律（先读完再动手）

1. **绝对不能用"发命令 + 数脉冲"来测行程。**
   机器是**开环步进**：滑台顶死之后电机照样转、照样报"成功"。
   2026-09-21 凌晨就是这样把 Y 轴指令发到 **311.5 mm**（而丝杆只有 290 mm），
   **结果顶死堵转 → 电流拉高 → 供电跌落 → STM32 欠压重启**，坐标基准全废。
2. **每次上电/复位前，必须先把 X、Y 滑台用手推到最里角顶住。**
   固件把"复位那一刻滑台的位置"当成原点（HOME），**它不会自己找零**。
   顺序错了，后面所有定位都会整体偏移。
3. **听到持续的嗡嗡声 / 咔咔声 = 已经顶死了，立刻松手或断电。** 不要硬撑。

---

## 第 0 步 · 准备

**需要的**：一把卷尺（或直尺）。**不需要**改任何软件。

**在树莓派上确认这几件事**（一条一条跑）：

```bash
# 1) 链没有在跑
pgrep -af run_chain.py || echo "链未运行 OK"

# 2) 串口空闲
sudo fuser /dev/serial0 || echo "串口空闲 OK"

# 3) 舵机常驻脉冲在跑
systemctl is-active pi-pwm.service

# 4) 板子能应答
python3 /home/pi/pi_peek.py
```

**判据**：第 4 条应该打印出 `PING -> OK PONG` 和 `STATUS ...`。
如果 `PING` 没应答，**停下**，先查供电和串口。

---

## 第 1 步 · 建立原点（**每次测量前都要做**）

1. **断电**（拔掉机器总电源）
2. **用手把 X 滑台推到最里角顶住**，再把 **Y 滑台也推到最里角顶住**
3. **在这个状态下上电**（或按板子上的 RESET）
4. **上电之后不要再用手移动滑台**

**判据**：

```bash
python3 /home/pi/pi_peek.py
```

应看到 `... MOVES=0`、`TICK_MS=` 是一个**很小的数**（几十秒以内）。
`TICK_MS` 很大（几分钟以上）说明**没有真正断电重启过**，回第 1 步重做。

---

## 第 2 步 · 用尺量（**推荐，零风险，一次搞定**）

**这一步完全不用电机**，所以绝对不会顶死。

1. **断电**
2. 把 **X 滑台推到最里角顶住**。在滑台上（或夹爪上）随便找一个**固定参照点**，
   用卷尺量它到**机架上任意一个固定点**的距离 —— 记作 **A**
3. 把 **X 滑台推到最外角顶住**，量**同一个参照点**到**同一个机架固定点**的距离 —— 记作 **B**
4. **X 净行程 = |B − A|**（单位 cm，请记到 **0.1 cm**）
5. **Y 轴重复 2–4 步**，得到 **Y 净行程**

> 💡 因为两次量的是**同一个点**，所以"夹爪本身的长度"自动被扣掉了，不用另外换算。

---

## 第 3 步 · 复核（可选，只在第 2 步量不出来时才做）

⚠️ **这一步会让机器动，务必有人在旁边，听到异响立刻断电。**

它只做一件事：**验证"某个位置还能不能动"**，**不追求走到尽头**。

```bash
# 从 HOME 走到「距最里角 200mm」（分成两段，因为单条 MOVE 上限 200mm）
cd /home/pi
python3 pi_bench_goto.py -95.0 -97.5 -95.0 2.5     # Y +100mm
python3 pi_bench_goto.py -95.0 2.5 -95.0 102.5     # Y 再 +100mm
```

**判据**：
* 每条都应打印 `运动 x.xxs  实测约 4xxx 步/秒  STEP_RESULT=1`
* **"实测约 4900 步/秒"是满速**；如果掉到几百步/秒，或者出现 `STEP_RESULT=-1`，
  **那就是顶死了** ⇒ **立刻断电**，并把这个现象记下来（说明 200mm 都走不到）

**测完必须回到原点**：断电 → 推 X/Y 到最里角顶住 → 上电/复位。

## 附 · 为什么这两个数这么要紧

* 现在固件里写的可达范围是 **X 19.0 cm / Y 19.0 cm**（`ec_motion_plan.h` 的
  `EC_MOTION_REACH_LIMIT/FAR_*_MM10 = 950/900、975/925`），**这是当年按"实测总行程 190mm"设的**。
* 而用户说机械丝杆是 **29 cm**，扣掉夹爪占位（X 向 7 cm、Y 向 5 cm）⇒ 应该是 **22 / 24 cm**。
* **两者差了 3～5 cm。** 如果机械真的大于 19 cm，那么：
  * 想要的落点只要落在 19 cm 之外，**链就走不到** ⇒ 要么被拒识，要么**走到极限顶死丢步**
    ⇒ 丢步会让**整个开环坐标基准越走越偏** ⇒ **这就是"夹取精度不对、圆柱夹不准"的根因**；
  * 修法是**改固件把范围放宽**（`EC_MOTION_REACH_FAR_X/Y_MM10` + `EC_STEP_MAX_STEPS`），
    并同步 `calibration_config.ini` 的 `[WorkspaceLimits]`。**这属改固件，需要用户批准。**

**⇒ 所以第 2 步量出来的两个数，是决定后面所有工作的前提。**
