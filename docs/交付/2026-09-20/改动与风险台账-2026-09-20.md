## 3. 构建环境的事实（本次实测，供后续复用）

| 事实 | 证据 |
|---|---|
| **固件用 Keil 命令行可编** | `D:\keil\UV4\UV4.exe -b <工程绝对路径> -o <日志>`，**必须用 `Start-Process -Wait`**（UV4 是 GUI 程序，`&` 调用会立刻返回、`$LASTEXITCODE` 为空）。退出码 0=无错无警 / 1=有警告 / 2=有错误 |
| **中文路径会挡住两种生成器** | `ninja: error: FindFirstFileExA(.../工创赛/电控/...): The filename, directory name, or volume label syntax is incorrect`；`mingw32-make: stat: ...: Illegal byte sequence`。**根因**：二者用 ANSI 版 Win32 API，而工作区路径含非 ASCII |
| **VS 2022 生成器能编但会被 `\WX` 挡住** | `ec_diag.c:374` 的 MSVC 专有 `C4996 'sscanf' 不安全` 被当成错误（C2220）；`test_motion_plan.c:117+` 的 `C4127 条件表达式是常量` 同理。**均为改动前既有问题** |
| **主机测试在本机跑不起来** | 上述两条叠加 ⇒ 只能在**非中文路径**下用 Ninja 跑（需把 `电控` 复制出去） |
| 现有构建目录 | `build-verify`(Ninja)、`build-s`(VS 2022)、`build-make`/`build-fresh-*`(MinGW Makefiles) |
| 本机 Python | `python` 指向**没有 pip 的 venv**；必须用 **`py -3`** |
| **🔴 `Test-Connection` 在本机不可靠**（2026-09-20 踩） | 它对可达主机**也返回 false** —— 曾据此误判"树莓派离线"两次。
**不要用它做连通性门禁**：改用**原生 .NET `Ping`（每个地址一个独立 `Ping` 对象）**，或**直接试 ssh**。<br>
另：用**同一个 `Ping` 对象**并发 `SendPingAsync` 会抛 `An asynchronous call is already in progress`（第一个之后的全部失败）
⇒ 扫网段时**每个地址都要 new 一个 `Ping`**。 |
