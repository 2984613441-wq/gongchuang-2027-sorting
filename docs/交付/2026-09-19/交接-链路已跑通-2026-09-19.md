## 4. 安全红线（每条都流过血）

1. **上电/复位前，必须把滑台推到最里角**（= 负 X 极限 ∩ 负 Y 极限）。
   固件把那里当作 HOME `(-950,-975)`（mm10）= `(-95,-97.5)` mm。
   规划器发的是**增量**，默认起点就是 HOME。滑台不在那儿，整段动作就整体偏移。
2. **每次运动测试必须有人手握急停**，全程别松手。
3. **链路运行时绝不开 `/dev/serial0`** —— 包括 `pi_listen_serial.sh`、`cat`，会抢串口把链路搞死。
4. **X/Y 没有限位开关**，顶死不会自动停。历史上顶死已经让主控挂过 2–3 次（表现为板子突然零应答）。
5. **出故障时先别断电**：`AXIS` 的故障锁存是排查唯一现场。**复位键（RESET）可以按，断电不行。**
   （实测：复位也会清零锁存，但断电更彻底、连板子上电时长都没了。）
6. **15 秒失活窗口是失败阈值，不是性能目标**。超了动作会**中途被砍断**（`DEADLINE_EXPIRED` → `FAULT_LOCK`），
   主机侧表现就是"从不发 MOTION_DONE"，很容易误判成机械故障。

## 11. 2026-09-19 03:5x 的固件加固（改了 3 处，需重烧）

**问题一句话**：`HAL_TIM_PWM_Stop()` 内部是 `__HAL_TIM_DISABLE(htim)` ——
**它关的是整个 TIM2 计数器，不是只关那一个通道**（`stm32f4xx_hal_tim.c:1523`），
而 `:1526` 只把**传进去的那个**通道标回 READY。
PB10 舵机挂 TIM2_CH3、PB11 挂 TIM2_CH4，**两者共用一个计数器**：
`ec_servo_port_stop_z()` 停 CH4 时会把 CH3 的舵机输出一起掐断，却把 CH3 的状态字留在 BUSY。
此时旧代码的守卫会误判"还在输出"而直接返回成功 → **一个脉冲都不发且不报故障** → 夹爪静默失能。

**为什么以前没炸**：只靠 `ec_axis_driver.c:139-140` 两行的先后顺序挡着（先 `stop()` 再 `stop_z()`），
属隐式依赖，任何人重排这两行就会破。

**改了什么**（文件 `电控/firmware/stm32f407_m144z/App/Src/ec_board_stm32.c`）：

| 位置 | 改动 |
|------|------|
| `:536-540` | 新增文件级 `static bool servo_ch3_started = false;` |
| `:583-590` | `ec_servo_port_start()`：守卫由 `TIM_CHANNEL_STATE_GET != READY` 改为 `if (!servo_ch3_started)`，成功启动后置 true |
| `:653-659` | `ec_servo_port_stop()`：补 `servo_ch3_started = false;` |
| `:681-694` | `ec_servo_port_stop_z()`：补"若 CH3 本应在输出则 `__HAL_TIM_ENABLE(&htim2)`"把被它连带关掉的计数器救回来 |

**验证**（主机侧语法+语义编译，非实机）：

```
gcc -fsyntax-only -std=c99 -Wall -Wextra -DSTM32F407xx -DUSE_HAL_DRIVER \
  -I App/Inc -I Core/Inc -I Drivers/STM32F4xx_HAL_Driver/Inc \
  -I Drivers/STM32F4xx_HAL_Driver/Inc/Legacy \
  -I Drivers/CMSIS/Device/ST/STM32F4xx/Include -I Drivers/CMSIS/Include \
  -I ../stm32_logic/include App/Src/ec_board_stm32.c
→ exit=0，警告 2 条，全部来自 CMSIS core_cm4.h 的 int-to-pointer（64 位主机固有，非本改动引入）
```

**行为等价性**：正常路径（程序开始/结束各调一次 `stop_all()`）下，
