# 一、⚡ 下次开机第一件事（最重要）

**今晚电池没电，整机突然断电 —— 滑台基准已经丢失。**

- X/Y **没有限位开关、没有编码器**，固件把"**上电那一刻滑台所在位置**"当作 `HOME (−95.0, −97.5)`。
- 断电瞬间滑台停在哪，固件并不知道；重新上电后它会**错误地认为**当前位置就是 HOME。
- **后果**：整链第一段增量会整体偏移。**2026-09-18 已因此撞停 34.6mm**（`ec_motion_plan.h:163-181` 有事故记录）。

**所以每次开机前必须：**

```
1. 手动把滑台推到 负向最里角（X 负到底、Y 负到底）
2. 然后才上电（或推到后按 RESET 键重新建立基准）
3. 严禁"先上电、后推" —— 那样固件认的原点就是错的位置
```

**故障时按 RESET，不要断电**（断电同样会丢基准）。

# 二、本次解决的核心问题

## 问题 1：视觉标定怎么调都对不上（误差 190mm）★ 根因级

**症状**：物块放在已知位置，视觉算出的装置坐标差 190mm；反复改 `tx/ty` 完全不收敛。

**根因**：**图像坐标轴与机器轴错位约 85°**（相机/图传装歪了），而配置里 `a12 = a21 = 0` 把**交叉项冻结成了零** —— 但交叉项才是主导项。

**怎么发现的（决定性实验）**：
把物块**沿机器 +Y 方向平移 30mm**，前后各读一次像素：

```
移动前 box_id=6  px=134  py=103
移动后 box_id=6  px= 72  py= 96
Δ像素 = (-61.5, -6)
```

**物块在机器 Y 方向走了 30mm，像素却几乎纯水平挪了 62px。**
一个"u 对应机器 X"的相机，Y 方向位移必须产生**竖直**像素位移 —— **实测是水平的** ⇒ 轴错了。

**修复**（只改配置，代码本来就支持 6 参数）：

```
[CameraCalibration]
a11 =  0.047142      a12 = -0.483206      tx = 148.453
a21 = -0.483206      a22 = -0.047142      ty =  52.105
```

**验证**：两个独立点，误差 **0.24mm / 0.7mm**（修前 190mm）。
另用 `−X 20mm` 位移交叉验证：Δ像素 `(-2.5, +42.0)`，预测 `(-4.0, +41.0)` —— **一个走水平、一个走竖直，85° 偏转在两个轴上都成立**。

**为什么以前没发现**：旧值 `a11=0.55 / a22=0.552` 很接近，"方形像素自检"因此一直通过 —— **但那正是两个错值错得一样（共模错误），自检通过不是证据**。

## 问题 2：工具偏置（夹爪 vs 滑台坐标）没有实测值

**症状**：视觉坐标对了，但夹爪落点偏 120mm。

**做法**：把物块放已知位置 → 我算目标 → 机器走 → **你目视报偏差** → 修正 → 重跑。

**五个独立样本**（每次目视确认夹爪正中物块）：

| # | 物块（装置坐标） | 滑台（记账） | 偏置 |
|---|---|---|---|
| 1 | (85.0, 12.5) | (−30.0, −34.5) | (115.0, 47.0) |
| 2 | (40.5, −36.5) | (−87.5, −78.5) | (128.0, 42.0) |
| 3 | (62.3, −4.6) | (−56.2, −46.1) | (118.5, 41.5) |
| 4 | (103.8, −45.4) | (−16.7, −88.9) | (120.5, 43.5) |
| 5 | (50.8, −2.3) | (−69.7, −45.8) | (120.5, 43.5) |

**定稿 = (120.5, 43.5)**。样本 4 是**大跨度移动**（X 78.3mm）后仍成立 ⇒ 偏置在大行程上稳定。

**写入配置（注意符号是负的）**：

```
[ToolOffset]
x_mm = -120.5
y_mm =  -43.5
```

**为什么是负值**：整链发出的目标 = 「像素→装置坐标」+ tool_offset（`pixel_to_device.py:456-458`）。
要让滑台实际走到「物块 − (120.5, 43.5)」，配置里就得写负的。

## 问题 3：树莓派上的代码不认 `[ToolOffset]`

**症状**：配置里写了 `[ToolOffset]` 但完全不生效（`AttributeError: no attribute 'tool_offset_mm'`）。

**根因**：树莓派上部署的 `pixel_to_device.py` 是**旧版本**（2026-09-18 02:33），**根本没有这个功能**。之前那个节从来不存在，**是因为代码不支持，不是配置漏了**。

**修复**：把仓库里的新版部署上去（新版是旧版的**严格超集**，多了 `tool_offset_mm` 与 `check_workspace`）。
旧版备份：`/home/pi/p2d-bak-old-20260919.py`

## 问题 4：像素域常量过期，会把正常物块全部误杀

**症状**：换上新代码后，物块放在正常位置却被判"像素域外"拒识。

**根因**：`pixel_to_device.py` 里的常量是**旧粗标时代的**：

```python
# 旧（2026-09-18 粗标）
_CALIBRATED_PIXEL_X_LIMITS = (57.0, 232.0)
_CALIBRATED_PIXEL_Y_LIMITS = (142.0, 232.0)   # ← py<142 全拒
```

而新标定的实测锚点 **py 一路低到 96** ⇒ 物块正常摆放也被拒，**整链一件都出不来**。

**修复**（按今天已确认的九组锚点重新取范围，各留约 10px 余量）：

```python
_CALIBRATED_PIXEL_X_LIMITS = (60.0, 240.0)
_CALIBRATED_PIXEL_Y_LIMITS = (85.0, 270.0)
```

## 问题 5：整链发了 `ITEM_TASK` 但机器一动不动

**症状**：日志反复刷 `空闲: state=RECOVERY_LOCK success=0`，什么都不做。

**根因**：`run_chain.py:1091` 是 `if args.start_round or demo:` —— **启动命令漏了 `--start-round`**，调度器永远锁在 `RECOVERY_LOCK`，一发都不发。

**修复**：启动命令加 `--start-round`；同时它有个**人工 HOME 门禁**（`:477-506`），要求 stdin 精确输入 `HOME`：

```bash
cd /home/pi/电控/deploy
export PYTHONPATH=/home/pi/电控/src
echo HOME | python3 run_chain.py --port /dev/serial0 --start-round \
    --frame-output fb0 --round-id live --round-task-id 1 \
    --names-file names.json --image-dir /home/pi/images
```

## 问题 6：整链崩在显示环节（缺货物图片）

**症状**：`FileNotFoundError: image_id=6 在 /tmp/images 下未找到`

**根因**：`--image-dir` 指错了（`/tmp/images` 是空的）。图片实际在 **`/home/pi/images/`**（有 `6.jpg` 等）。

**注意**：崩溃发生在**运动完成之后**，所以抓取本身不受影响 —— 但崩了就不发 `DISPLAY_ACK`。

## 问题 7：屏幕全黑（Xorg 抢屏）

**症状**：`--frame-output fb0` 明明在写，屏幕却不显示。

**根因**：**树莓派上 Xorg 在 tty7 运行，通过 DRM/KMS 接管了显示** —— 这时往 `/dev/fb0` 直写，内容进的是控制台帧缓冲，**不会出现在屏幕上**。

**已做**：

```bash
sudo raspi-config nonint do_boot_behaviour B2   # 永久改为控制台启动
sudo systemctl stop lightdm                     # 立即释放
```

（如需恢复桌面：`sudo raspi-config nonint do_boot_behaviour B4`）

**仍未解决**：你说"屏幕显示不同步" —— 两侧时序还没对齐，属遗留项。

# 四、仍未解决（按优先级）

## P0 · 每件都走"超时重传"，赛场会超时

日志里**每一件**都是这个模式，正常路径一次都没走通：

```
两段显示已上屏 → inbound ACK_ACK_CONSUMED → BARRIER_READY
→ "建轮次那一发 ITEM_TASK 已被启动序列吞掉，立即重发"
→ ACK_ACCEPTED → DUPLICATE（重放/重传帧）
→ ITEM_TASK 超时 5.0s 无应答，重传 ...
→ MOTION_DONE accepted
```

**每件多耗约 10 秒。** 不影响成功率（`success` 一直在涨），但**赛场上会超时**。
根因未查。**这是当前最该修的。**

## P1 · 物块可抓窗口是硬约束 —— 托盘有一片区域永远抓不到

滑台目标 = 物块 − (120.5, 43.5)，而滑台可达域是 `X∈[−95,90]`、`Y∈[−97.5,92.5]`。反推：

```
物块可抓窗口：  X ∈ [ 25.5, 210.5]      Y ∈ [−54.0, 136.0]
```

**托盘靠负向内角的带状区域，物理上永远抓不到。** 整链日志已实测拦截（会打
`越界：… 加 ToolOffset=(-120.5,-43.5)mm 后 PICK=… 不在工作区…拒识该件`）。

三次实测都撞在这条上：`box_id=3 (23.6,6.8)` 需滑台 X=−97.9（超限）；
`box_id=6 (98.7,−67.9)` 需滑台 Y=−111.4（超限）；`box_id=6 (92.9,−53.8)` 需 Y=−97.3（**余量仅 0.2mm**）。

**建议**：要么减小偏置（把夹爪往滑台坐标点挪近），要么接受这片抓不到的区域 ——
**这条要给机械组看。**

## P2 · 屏幕显示不同步

已停 Xorg 释放 fb0，但两侧时序未对齐。你说之后并行处理。

## P3 · 短移动判据盲区

`pi_bench_goto.py` 的完成判据要求先看到 `STEP_REMAIN>0`，而 5000Hz 下**小于约 0.2 秒**
（≈1000 步）的移动在第一次成功轮询前就结束了。实测：

```
  400 步 / 0.08s  → 抓不到
  960 步 / 0.19s  → 抓不到
 1120 步 / 0.20s  → 抓到
 1920 步 / 0.40s  → 抓到
```

**影响**：毫米级微调**无法被机器确认**，只能靠目视。

## P4 · 换向间隙（疑似存在，未证实）

样本 1/2 与样本 3 之间差 (15, 10)，而中间**恰好跨了一次换向**。
但没做独立实验证实。**建议：每个目标统一从同一方向逼近。**

## P5 · 无绝对位置反馈

X/Y 无编码器、无限位开关，`STEP_REMAIN` 只描述当前一动 ——
**无法事后回查位置，也无法自证原点**。这导致每次开机都必须人工归位。

## P6 · 其他待办

- **`[BoxMap]` 为空** —— 整链只警告不拒启动，但 `box_id` 没有现场冻结的对应关系
- **托盘 330mm(X) × 160mm(Y) 与 X 行程 190mm 矛盾** —— 托盘比 X 行程长 140mm，待查
- **橙色圆柱归类不一致** —— 历史报 `class_id=4/黑色圆柱`，2026-09-19 全部报 `box_id=6`
- **`工具/pi_set_tx.py:46` 用两项式复核（漏交叉项）** —— 若据此写 `tx` 会破坏配置，未修
- **`start_vision_bridge.sh` 端口写错** —— 里面是 `/dev/ttyAMA0`（蓝牙串口），实机应为 `/dev/serial0`；且直接跑 `run_chain.py` 需 `PYTHONPATH=/home/pi/电控/src`
