### 1.5 对"a22 偏小"推导的正面质疑

**派工包推导**（`派工包v2-自包含-2026-09-19.md:60-62`）：
```
反推 a22：已知锚点 py=159 ↔ y=−57.5；若物块实际在托盘远端 y≈−95，
则 a22 = (−95 − (−32.5)) / (85 − 159) = 0.845，而标定所用为 1.0833。
⇒ **a22 只在单点校准过，外推到别处就崩。a11 同样从未被两点法验证。**
```

**质疑 1：分子计算错误**

**结论**：`−95 − (−32.5) = −62.5`，不是 `-62.5 / -74 = 0.845` 的分子。

**证据**：
- 反推公式：`a22 = Δy / Δpy`
- 锚点：`py=159 ↔ y=−57.5`
- 假设：物块在 `y=−95`（托盘远端）
- **分子**：`Δy = −95 − (−57.5) = −37.5`（不是 `−95 − (−32.5) = −62.5`）
- **分母**：`Δpy = 85 − 159 = −74`
- **正确值**：`a22 = −37.5 / −74 = 0.507 mm/px`（不是 0.845）

**置信度**：5/5

**证据缺失计数**：0

**逻辑跳跃计数**：0

**替代解释**：
- 派工包的 `−32.5` 可能来自**光轴落点** nadir_y（`pixel_to_device.py:238-262`），但该公式不应出现在**仿射比例项**的推导中
- 若 `−32.5` 是**摄像头中心的 Y 坐标**（`ec_motion_plan.h:175`：相机中心 = HOME + (160,65) = (65.0, −32.5)），那更不应该在这里

**建议动作**：
1. **重新推导**：用正确的锚点差值 `(−95) − (−57.5) = −37.5 mm` 和 `85 − 159 = −74 px`
2. 若 `a22 ≈ 0.507`，则托盘 Y 全长 97.5mm 对应 `97.5 / 0.507 ≈ 192 px`，**远超** `calibration_config.ini:33` 记载的 90px
3. **矛盾**说明假设"物块在 y=−95"本身可能不成立

---

**质疑 2："-32.5" 的来源混淆**

**结论**：推导中的 `−32.5` 既可能是"摄像头中心 Y"，也可能是"光轴落点 nadir_y"，两者不等价。

**证据**：
- `ec_motion_plan.h:175`（注释）：
  ```c
  /* 相机中心 = (65.0, −32.5) = A + (160, 65)（用户 2026-09-19 实测） */
  ```
- `pixel_to_device.py:238-262`（`_optical_axis_point()`）：
  ```python
  cx = self.frame_width / 2.0  # 320/2 = 160
  cy = self.frame_height / 2.0  # 320/2 = 160
  matrix = self.affine_matrix
  return (float(matrix[0][0] * cx + matrix[0][1] * cy + matrix[0][2]),
          float(matrix[1][0] * cx + matrix[1][1] * cy + matrix[1][2]))
  ```
  实际计算（用当前标定值）：
  ```
  nadir_y = a21*160 + a22*160 + ty = 0*160 + 1.083333*160 + (−251.333)
          = 173.333 − 251.333 = −78.0 mm
  ```
- **摄像头中心 Y** = −32.5 mm（机械位置）
- **光轴落点 nadir_y** = −78.0 mm（仿射变换的几何中心）
- **两者相差 45.5 mm**

**置信度**：5/5

**证据缺失计数**：0

**逻辑跳跃计数**：0

**替代解释**：
- 派工包用 `−32.5` 可能误把"摄像头机械中心"当成"仿射几何中心"
- 正确的视差补偿应绕 `nadir_y = −78.0` 展开（`pixel_to_device.py:323-343`），不是 `−32.5`

**建议动作**：
1. **明确派工包推导的假设**：`−32.5` 到底指什么？
2. 若指摄像头中心，那不应出现在仿射推导中（仿射是纯像素→mm 变换，与相机机械位置无关）
3. 若指光轴落点，则数值错误（应为 −78.0）

## 审查点 2：折进同一 tx/ty 的结构性隐患

### 2.1 当前做法

**文档记录**（`派工包v2-自包含-2026-09-19.md:49-51`）：
```
**推导锚点（实测）**：滑台 (−10.0, −57.5) 时**夹爪正罩住物料**（遮挡测试：橙色圆柱从画面消失），
当时物料像素 (156, 159)。由此反解 tx = −10.0 − 1.085714×156、ty = −57.5 − 1.083333×159。
该值**已把工具偏移 (65,0) 与滑台→Z轴偏移一起折进去**。
```

**用户明确约束**（`派工包v2-自包含-2026-09-19.md:32`）：
```
**三个中心的关系**：摄像头中心 / Z轴中心 / 夹爪中心**三者无直接关系**；
唯一确定关系是「夹爪中心 = Z轴中心 + (65,0)」
```

### 2.2 结构性隐患 1：**高度变化会破坏标定**

**结论**：当前标定锚在"夹爪罩住物料"，隐含物块高度 h；换不同高度的物块，视差补偿会用错基准。

**证据**：
- `pixel_to_device.py:323-343`（视差补偿公式）：
  ```python
  if h > 0.0:
      scale = self.camera_height / (self.camera_height - h)
      nadir_x, nadir_y = self._optical_axis_point()
      x_bottom = nadir_x + (x_top - nadir_x) / scale
      y_bottom = nadir_y + (y_top - nadir_y) / scale
  ```
- 标定时物块高度：**未记录**（`calibration_config.ini:83-88` 全置 0，有意关闭视差）
- 工具偏移 `(65, 0)` 是**固定的机械偏移**，不随物块高度变化
- 但 `tx/ty` 锚在"夹爪罩住物料"，隐含了**那次标定时的物块高度**

**置信度**：5/5

**证据缺失计数**：1（缺失标定时物块的实际高度）

**逻辑跳跃计数**：0

**替代解释**：
- 当前 `[ObjectHeights]` 全置 0，视差补偿关闭，所以**暂时不发作**
- 一旦有人把件高填回去（`calibration_config.ini:80-82` 明确说"必须填回来"），补偿会绕错的点展开
- **量化影响**（假设标定时 h=40mm，现在抓 h=0 的物块）：
  ```
  标定时 scale = 262 / (262-40) = 1.1802
  现在补偿 scale = 1.0（h=0）
  若物块在光轴旁 50mm → 误差 = 50 × (1 - 1/1.1802) = 7.6mm
  ```

**建议动作**：
1. **分离工具偏移与标定**：
   - `tx/ty` 只负责"像素中心 → Z轴中心"的仿射变换
   - 工具偏移 `(65, 0)` 在**运动规划层**加上（`ec_motion_plan.c` 或调度器），不折进标定
2. **记录标定条件**：在 `calibration_config.ini` 新增 `[CalibrationConditions]` 节，记录标定时的物块高度
3. **验证高度敏感性**：用不同高度的物块（0mm、20mm、40mm）各测一次，看误差是否随高度线性变化

### 2.3 结构性隐患 2：**换夹爪后标定失效**

**结论**：工具偏移 `(65, 0)` 是夹爪的机械参数；换夹爪后，这个偏移会变，而 `tx/ty` 无法单独更新。

**证据**：
- `派工包v2-自包含-2026-09-19.md:30`：
  ```
  **夹爪中心** = Z轴中心 + **(65, 0)** mm（用户口述）
  ```
- 工具偏移已折进 `tx/ty`（`:49-51`）
- 若换夹爪（例如加长爪片、换不同型号），`(65, 0)` 会变成 `(65+Δx, Δy)`
- 但 `tx/ty` 是 6 参数仿射的一部分，**无法单独修改工具偏移**而不影响比例项

**置信度**：5/5

**证据缺失计数**：0

**逻辑跳跃计数**：0

**替代解释**：
- 当前夹爪固定，所以**暂时不发作**
- 但工程实践中，夹爪是**易损耗件**（爪片磨损、碰撞变形、更换型号）
- 每次换夹爪都要**重新九点标定** → 工作量大、易出错

**建议动作**：
1. **架构重构**（优先级：高）：
   ```
   像素 (u,v)
     ↓ [仿射] a11,a12,tx_cam / a21,a22,ty_cam
   Z轴中心 (x_z, y_z)
     ↓ [工具偏移] tool_offset_x, tool_offset_y
   夹爪中心 (x_grip, y_grip)
     ↓ [视差补偿] 基于物块高度
   底面抓取点 (x_pick, y_pick)
   ```
2. **配置文件分离**：
   - `[CameraCalibration]`：只含 `a11, a12, tx_cam, a21, a22, ty_cam`（像素→Z轴中心）
   - `[ToolOffset]`：单独配置 `tool_offset_x=65.0, tool_offset_y=0.0`（Z轴中心→夹爪中心）
3. **换夹爪时**：只需测量新的工具偏移，不必重做九点标定

### 2.4 当前做法的"单点必然正确"陷阱

**结论**：折进同一 `tx/ty` 在**锚点**必然正确，但无法验证比例项与偏移项的独立正确性。

**证据**：
- `交接-标定未完成-串口失联-2026-09-19.md:9-11`：
  ```
  **收敛过程（闭环法，不依赖滑台记账）**：从已知起点 HOME → 读物块像素 → 算 D →
  夹爪开到 D → 用户目视报残差 → 用残差修 tx。两轮收敛：
  tx: −151.886 → −182.5（残差4.5cm）→ −187.5（残差0.5cm）
  ```
- 闭环法**只验证了一个点**（锚点）的 X 偏移
- `a11`（X 比例）、`a22`（Y 比例）、`ty`（Y 偏移）**从未被独立验证**

**置信度**：5/5

**证据缺失计数**：0

**逻辑跳跃计数**：0

**替代解释**：
- 单点校准 = 4 自由度（`tx, ty, tool_offset_x, tool_offset_y`）耦合求解
- 无穷多组解都能让锚点正确：例如 `tx` 偏小 10mm、`tool_offset_x` 偏大 10mm → 锚点仍对齐
- 离锚点越远，耦合误差累积越大

**建议动作**：
1. **两点法必做**（派工包已要求）：

## 审查点 4：_optical_axis_point() 隐患

### 4.1 光轴假设与仿射零点的偏差

**结论**：`_optical_axis_point()` 用 `(160, 160)` 当光轴，而仿射隐含零点在 `(144.5, 232)`，差约 36mm。

**证据**：
- `pixel_to_device.py:256-262`（当前实现）：
  ```python
  cx = self.frame_width / 2.0  # 320/2 = 160
  cy = self.frame_height / 2.0  # 320/2 = 160
  matrix = self.affine_matrix
  return (float(matrix[0][0] * cx + matrix[0][1] * cy + matrix[0][2]),
          float(matrix[1][0] * cx + matrix[1][1] * cy + matrix[1][2]))
  ```
- **当前标定下的光轴落点**（用 `a11=1.085714, tx=-156.886, a22=1.083333, ty=-251.333`）：
  ```
  nadir_x = 1.085714 × 160 + 0 × 160 + (−156.886) = 173.714 − 156.886 = 16.828 mm
  nadir_y = 0 × 160 + 1.083333 × 160 + (−251.333) = 173.333 − 251.333 = −78.0 mm
  ```
- **仿射零点**（哪个像素映射到装置原点 (0,0)）：
  ```
  0 = a11 × px + tx  →  px = −tx / a11 = 156.886 / 1.085714 = 144.5
  0 = a22 × py + ty  →  py = −ty / a22 = 251.333 / 1.083333 = 232.0
  ```
- **偏差**：
  - X: `|(160 − 144.5) × 1.085714| = 16.8 mm`
  - Y: `|(160 − 232.0) × 1.083333| = 78.0 mm`
  - **合成偏差**：`√(16.8² + 78.0²) = 79.8 mm`

**置信度**：5/5

**证据缺失计数**：0

**逻辑跳跃计数**：0

**风险等级**：**Level 2**（当前不发作，但潜在误差大）

**为什么当前不发作**：
- `calibration_config.ini:83-88`：`[ObjectHeights]` 全置 0
- `pixel_to_device.py:342-343`：`if h > 0.0: ...` 跳过视差补偿
- 一旦有人把件高填回去，补偿会绕 `(16.828, −78.0)` 展开，而不是正确的仿射零点 `(144.5, 232)` 映射的装置坐标

**一旦发作的影响**（假设 h=40mm，物块在 (50, -50)）：
```
正确：nadir = 仿射(144.5, 232) = (0, 0)
      补偿：(50, -50) → nadir + [(50, -50) - (0, 0)] / scale
          = (0, 0) + (50, -50) / 1.1802 = (42.4, -42.4)  误差 7.6mm

错误：nadir = (16.828, -78.0)（当前实现）
      补偿：(50, -50) → (16.828, -78.0) + [(50, -50) - (16.828, -78.0)] / 1.1802
          = (16.828, -78.0) + (33.172, 28.0) / 1.1802
          = (16.828, -78.0) + (28.1, 23.7) = (44.9, -54.3)
      与正确值差：(44.9 - 42.4, -54.3 + 42.4) = (2.5, -11.9) mm
```

**建议动作**：
1. **修正 `_optical_axis_point()`**（必做）：
   ```python
   def _optical_axis_point(self) -> Tuple[float, float]:
       """光轴落点 = 仿射零点（哪个像素映射到装置原点）映射的装置坐标。
       
       正确做法：直接返回装置原点 (0, 0)。
       理由：视差补偿的几何中心就是"像素→装置"变换的零点，
            而仿射变换已经隐含了这个零点（通过 tx/ty）。
       """
       return (0.0, 0.0)  # 装置原点就是仿射几何中心
   ```
2. **或者**（若相机确实不在装置正上方）：
   ```python
   # 从仿射参数反解零点像素
   px_zero = -self.affine_matrix[0][2] / self.affine_matrix[0][0]
   py_zero = -self.affine_matrix[1][2] / self.affine_matrix[1][1]
   # 零点像素映射到装置坐标 = (0, 0)（这是仿射的定义）
   return (0.0, 0.0)
   ```
3. **回归测试**：用 `h=40mm` 的物块在不同位置测试，验证误差 ≤ 5mm
