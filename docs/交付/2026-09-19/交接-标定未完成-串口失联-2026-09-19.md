## 二、已确立的事实（带证据）

1. **台架 `MOVE ... HZ f` 的 `f` 不生效**。`电控/firmware/stm32f407_m144z/App/Src/ec_board_stm32.c:191-192` 原文承认"真正生效的是本行的 cruise 实参"；`:200` 把 cruise 硬编码成 `5000U`，`HZ` 只在 `period==0` 分支兜底。
   实测：`pi_step_trace.py` 抓到 2800 步运动峰值 ≈4900Hz；用梯形剖面（200→5000→200，accel 10000）验算 1200/2800/4000/4800/5600/11328 步六次，全部吻合。
   **代价：所有基于"设定 HZ"的耗时估计都是错的**（我据此误算过多次）。

2. **丢步判定：单程无丢步，换向有回程差。**
   `pi_square.py 50` 四条腿各 50mm±1mm（80 步/mm 正确），但正方形**不闭合，偏差 >5mm**。
   我自己整晚的记账反推：需要 `G_A−G_B ≈ 130.8mm`，我记的是 `151.6mm`，差 **20.8mm**，分摊到十余次换向 ≈ **1~2.5mm/次** —— 与正方形不闭合同量级。
   → 结论倾向**回程差(backlash)**，不是高速整体丢步。`ec_board_stm32.c:194-198` 说 5000Hz 丢步验证"必须重做"，至今未做。

3. **`[ObjectHeights]` 六类全 0 是【有意】的**，不是忘了填。`电控/calibration_config.ini:74-78`：粗标是把物块**底面**推到托盘两端反解的，仿射已直接给底面坐标，再套视差 = 做两遍。
   → 我一度判它是 bug，**已撤回**。

4. **越界即整帧被丢弃** = 用户说的"识别到了也不认"。`vision_ingest.py:240-244` 静默 `continue`，无任何日志。
   复现：`(148,128)` → `y = 1.0833×128 − 251.333 = −112.67 < y_min −97.5` → 返回 `None` → 静默丢。

5. **发来的像素是 320 系**（`stage1_color_v6_send.py:215,261-263` 用 `sx = original_w/width` 还原回原图，原图 = `camera.Camera(320,320)`）。配置里 `frame_width/height = 320/320` **正确**。

6. **相机装在固定机架上**（用户目视确认）→ `pixel_to_device(u,v,box_id)`（`电控/src/electrical_control/rpi/pixel_to_device.py:264`）**签名无滑台位置项是正确的**，不存在结构性错误。

7. **潜在 bug（当前休眠）**：`_optical_axis_point()`（`pixel_to_device.py:238-261`）用 `frame_width/2, frame_height/2 = (160,160)` 当光轴，算出 device `(21.8,−78.0)`；而仿射隐含零点在 `(144.5, 232)` → device `(0,0)`，**两者差约 36mm**。现在 `h=0` 视差关着所以不发作，**一旦打开 `[ObjectHeights]` 就会绕错的点补、越补越偏**。代码注释 `:254` 自己也承认这个口径有问题。

## 四、我自己脚本里的 bug（已修，但值得记住）

**完成判据失效** —— 出现在 `pi_bench_goto.py` / `pi_square.py` / 早期 `pi_move.py`：

```
send("MOVE ...", 0.4)  →  白等 0.4s
send("STATUS", 0.2)    →  再等 0.2s，而 read(900) 的 timeout 是 0.5s
=> 第一次看到状态已是 t≈1.1s，而一动只要 ~1.0s（5000Hz 硬编码）→ 永远看不到 STEP_REMAIN>0
```
更早的版本更糟：`if rem == 0: break` 会拿到**上一动残留的 0**，于是在上一动没走完时又发下一条 MOVE。
**正确写法**（见 `工具/pi_step_trace.py`，已验证）：`timeout=0.1`、发完立刻轮询、读到 `APP_STATE` 即返回、**必须先见到 `STEP_REMAIN>0` 才认 `=0`**。

待验证的一步（板子恢复后直接跑）：
```
物块放在相机画面正中 → 读像素 → 算 D → 夹爪开到 D+(40,0) → 用户目视确认
# 当前：D=(18.6,-55.2)，目标 = (58.6,-55.2)
python3 /home/pi/pi_bench_goto.py -25.0 -95.0 58.6 -55.2
```

### 6.2 若上一步不成立 → 改用**托盘物理边缘当标尺**（不依赖夹爪、不依赖目视报数）
托盘 X 全长 190mm、Y 全长 97.5mm 是机械组给的确定尺寸：
1. 物块贴托盘 X 一端读 `u1`，另一端读 `u2` → `a11 = 190/|u2−u1|`，`tx = −95 − a11·u1`
2. Y 同理用 97.5mm 定 `a22` / `ty`
注意：视野两端框不完，端点读数可能取不到 —— 那就改用**已知间距的两个内部点**（用夹爪走已知步数放到两个位置），只要两点间距准，比例就准。

### 6.3 回程差处置
每个目标点**从同一方向逼近**（先走到目标 −3mm，再正向走 3mm 到位），把回程差变成固定常量而非随换向变化的误差。不改硬件、不降速（降速会撞 15s 窗口）。

### 6.4 频率扫一遍给用户定论
板子恢复后，用 `pi_square.py` 在不同 cruise 下各跑一次（当前 cruise 硬编码，需改 `ec_board_stm32.c:200` 后重刷）。参照 `:178-181`：2000Hz→21.7s 必失败、4000Hz→14.7s 余量仅 0.35s、5000Hz→12.6s。

## 七、工具清单（本轮新增/修改，都在 `工具/`，Pi 上同名部署在 `/home/pi/`）

| 脚本 | 用途 |
|---|---|
| `pi_step_trace.py` | **抓一次 MOVE 的原始轨迹**，算真实脉冲频率。判据写法的标杆 |
| `pi_bench_goto.py` | 从**已知真值**走到目标真值，带托盘边界护栏；真值由调用方传参 |
| `pi_read_object.py` | 听 MaixCAM 一次，打印像素 + 换算 + 相对真值的误差（支持 `count>1`） |
| `pi_set_calib.py` | 改配置一个数值，**无 BOM 写回** + 自动备份 + 加载器自检 |
| `pi_calib_truth.py` | 用**真实加载器**解析 Pi 上标定，打印光轴基准/件高表/工作区 + 已知像素回放 |
| `pi_closeloop.py` | **闭环收敛 tx/ty**：读物块像素 → 夹爪开到 D → 用户目视报残差 → 修 tx（本轮两轮收敛用）。⚠️ 已知缺陷：多目标并列时 `max()` 任取一个（曾误把 `box_id=3` 当主目标）；夹爪压件时物块被遮挡、只剩杂散检出，会把 `box_id=4` 当主目标把夹爪开跑 → 必须按颜色/形状锁定 box_id，禁止压件时跑闭环 |
| `pi_step1_dircheck.py` | 5mm 方向核对（`X+=DIR0`、`Y+=DIR1` 确认） |
| `pi_square.py` | **丢步验证**：50mm 正方形，四条腿首尾相接，不闭合即丢步（判据已修） |
| `pi_state_now.py` | 只读探针：STOP ALL / INPUTS / STATUS / AXIS |
| `pi_serial_wake.py` | 串口无响应时的诊断：谁占口、设备在不在、灌数据有无回音 |

## 八、安全不变量（每轮都要守）

- **X/Y 没有限位开关**，超程无任何硬件能发现；上电/建参考前把滑台推到负向极限
- **链路启动前必须确认滑台在 HOME**（`ec_motion_plan.h:178-181` 的不变量：组腿只发**增量**、规划假定"程序开始时滑台就在 HOME"；启动时不在 HOME → 首段从错误起点出发 → 顶死堵转）
- **标定/台架操作后把滑台留在非 HOME 位置，会污染下一次整链运行**（2026-09-19 整链首跑失败直接成因：标定闭环后夹爪停在 (−35.5,−67.2) 未推回 HOME 即启动链路，见 `docs/交付/2026-09-19/派工-整链异常排查-2026-09-19.md:57-63`）
- **任何运动测试都要有人守着急停**
- **链路运行时绝不打开 `/dev/serial0`**
- 出故障**不要直接断电**（RESET 可以）
- 结论必须带 `file:line` 或原始输出；证据不足写【证据不足】
- **本项目不做 git 操作**
