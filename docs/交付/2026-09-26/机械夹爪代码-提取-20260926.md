## 0. 先明确一件事：本项目**没有**独立的"夹爪模块"

| 事实 | 依据 |
|---|---|
| 夹爪 = **Z 升降 + 夹爪开合 = 同一只舵机**，一个自由度，机械联动 | `ec_axis_driver.h:212-215`、`ec_servo_test.h:29-34` |
| 型号 **LDX-335MG** 数字舵机，接 **PB10 = TIM2_CH3** | `ec_servo_test.h:30-31`、`ec_axis_driver.c:301-307` |
| 旧文档里的 **DS3120MG / 三指自定心夹爪 / 1100-1900µs** 口径**已作废** | `ec_servo_test.h:31-34`、`ec_axis_driver.h:52-56` |
| 代码形态：**给这一路舵机发一个脉宽（µs）**，没有别的 | 全文 |

**方向规律（2026-09-19 台架逐档目视，单调无死区）**：

```
脉宽越小  →  张开越大  +  抬得越高
脉宽越大  →  闭合越紧  +  压得越低
```

⇒ **改开度 = 同时改高度**（耦合，见 `ec_motion_plan.h:280-285`）。这是本夹爪所有时序设计的根源。

**夹爪没有传感器反馈**：`ITEM_RESULT.success` 只表示"程序跑完且驱动无报错"，**不证明真的夹住了**
（`当前进度与交接.md` U4）。

## 2. 唯一的标定面：4 个常量

`App/Inc/ec_axis_driver.h:86-140`（**现行值**，注释已压缩，原注释见源码）：

```c
/* 张开端：[0] 起点与 [7] 落料后张开共用此处开度。
 * 沿革：1100 → 900 → 850 → 900 → 750 → 800（2026-09-21 用户要求"设一次就定住"）。
 * ⚠️ 800 仍是【未验证值】：台架已验证的最低值止于 900。
 * 🚨 听到持续嗡嗡声/异响立刻 SERVO STOP —— 越过机械端点会持续堵转、发热甚至烧舵机（不可逆）。*/
#define EC_AXIS_GRIPPER_OPEN_US UINT16_C(800)

/* 待机/初始/回程开度 = 625µs（2026-09-21 用户现场裁决）。
 * 为什么是 625 而不是 800：脉宽越小张开越大，三类张开值 650/750/800 里最宽的是 650；
 * 待机必须比所有类别都宽，否则回程时爪片会拦住/刮走托盘上其他物块。
 * 625 已实测无堵转嗡鸣（下探序列 900→870→800→750→725→700→675→650→625）。*/
#define EC_AXIS_GRIPPER_STANDBY_US UINT16_C(625)

/* 闭合端：现场确认已能完全夹紧，自 2026-09-19 起未动。*/
#define EC_AXIS_GRIPPER_CLOSE_US UINT16_C(1900)

/* 发完脉宽后等多久才认为舵机到位。
 * 2026-09-19 由 200 提到 600：200ms 时爪子还没合拢就启动 XY ⇒ 把物块撞移位、一件都夹不起来。
 * 代价：程序里有 5 个舵机步 ⇒ 每 +100ms 整轮多 0.5s，必须与 15s 失活窗口对账。*/
#define EC_AXIS_GRIPPER_SETTLE_MS UINT32_C(600)

#define EC_AXIS_SERVO_SETTLE_MS EC_AXIS_GRIPPER_SETTLE_MS   /* 别名，不是第二个值 */

/* Z 只是同一只舵机的另一个名字 —— 不是第二只舵机。*/
#define EC_AXIS_Z_DOWN_US EC_AXIS_GRIPPER_CLOSE_US   /* 取料点：闭合 + 下压（夹住） */
#define EC_AXIS_Z_UP_US   EC_AXIS_GRIPPER_OPEN_US    /* 落料点：张开 + 抬起（释放） */
```

## 3. 动作序列：每件程序里的 5 个舵机步

`App/Src/ec_motion_plan.c` 生成 **12 步**（`EC_AXIS_PICK_PLACE_STEP_COUNT = 13`，留 1 个空槽）：

| 步 | 类型 | 脉宽/时长 | 含义 |
|---|---|---|---|
| **[0]** | Z_SERVO | **625**（固定） | 起点待机：先张开。上电/复位后舵机不输出脉宽，爪可能停在闭合态，**这步不可删** |
| 1–2 | MOVE | — | PARK → PICK（空爪腿） |
| **[3]** | Z_SERVO | **类别开度** 650/750/800 | **到达取料点之后**才降到该件开度（09-22 现场裁决） |
| [4] | WAIT | 200 ms | 纯等待，**不碰硬件**，给人眼确认停位 |
| **[5]** | Z_SERVO | **1900** | 闭合 = 夹住 |
| 6–7 | MOVE | — | PICK → PLACE（带料腿，强制先 Y 后 X） |
| **[8]** | Z_SERVO | **类别开度** | 张开 = 释放 |
| **[9]** | Z_SERVO | **625** | 回程前切回待机（否则最窄的 650 会在回程刮走其他件） |
| 10–11 | MOVE | — | PLACE → PARK |

**为什么 [0] 是固定 625 而不是类别值**（`ec_motion_plan.c:268-279`，2026-09-22 现场裁决）：
单舵机联动下起点写类别值会让**起点高度逐件不同**（650 最高、800 最低），现场表现为"刚开始的高度不一样、不对"。
用户原话：「他要先移动到那个位置之后，它先降到那个脉宽，然后再降一次」。

**按类别查表**（`ec_motion_plan.c:143-172`）：

```c

{
    uint16_t open_us;

    switch (class_id) {
    case 1U: case 2U: open_us = EC_MOTION_OPEN_US_CUBE;     break;
    case 3U: case 4U: open_us = EC_MOTION_OPEN_US_PRISM;    break;
    case 5U: case 6U: open_us = EC_MOTION_OPEN_US_CYLINDER; break;
    default:
        return EC_AXIS_GRIPPER_OPEN_US;  /* 未知/未受理 ⇒ 退回默认，绝不猜类别 */
    }
    /* 防误改：0 或 ≥闭合端的值绝不下发到舵机通道。 */
    if ((open_us == 0U) || (open_us >= EC_AXIS_GRIPPER_CLOSE_US)) {
        return EC_AXIS_GRIPPER_OPEN_US;
    }
    return open_us;
}
```

### 4.4 实机 PWM 输出（`ec_board_stm32.c:537-591` + `:654-695`）

```c
static bool servo_ch3_started = false;

bool ec_servo_port_start(uint16_t pulse_us)
{
    if ((pulse_us == 0U) || (pulse_us > htim2.Init.Period)) return false;

    grip_pin_select(GPIO_AF1_TIM2);          /* PB10 复用到 TIM2_CH3(AF1) */
    __HAL_TIM_SET_COUNTER(&htim2, 0U);
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_3, pulse_us);

    /* 通道已在输出时【只更新 CCR】，不重启通道：
     * 既不丢保持力矩（没有停-启空档），也不产生 HAL_ERROR。
     * 用自持标志位而不是 HAL 状态字 —— HAL_TIM_PWM_Stop 关的是【整个 TIM2 计数器】，
     * 却只恢复传入的那一个通道的状态字，会误判成"还在输出"⇒ 一个脉冲都不发且不报故障。*/
    if (!servo_ch3_started) {
        if (HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_3) != HAL_OK) {
            return false;
        }
        servo_ch3_started = true;
    }
    return true;
}

void ec_servo_port_stop(void)
{
    (void)HAL_TIM_PWM_Stop(&htim2, TIM_CHANNEL_3);
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_3, 0U);
    servo_ch3_started = false;
}

/* 遗留通道：TIM2_CH4 = PB11。它【不驱动 Z 轴】，只有 ec_demo.c 还在用。
 * 但 ec_axis_driver.c 的 stop_all() 仍会调它，而它会连带掐断 CH3 —— 故必须救回计数器。*/
bool ec_servo_port_start_z(uint16_t pulse_us)
{
    if ((pulse_us == 0U) || (pulse_us > htim2.Init.Period)) return false;

    __HAL_TIM_SET_COUNTER(&htim2, 0U);
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_4, pulse_us);
    return HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_4) == HAL_OK;
}

void ec_servo_port_stop_z(void)
{
    (void)HAL_TIM_PWM_Stop(&htim2, TIM_CHANNEL_4);
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_4, 0U);
    if (servo_ch3_started) {
        __HAL_TIM_ENABLE(&htim2);     /* 把被连带关掉的 TIM2 计数器救回来 */
    }
}
```

**急停路径**：`stop_all()`（`ec_axis_driver.c:136-142`）先 `ec_servo_port_stop()` 再 `ec_servo_port_stop_z()`
—— **这两行的先后顺序是隐式依赖，重排就会让夹爪静默失能**（`ec_board_stm32.c:579-581`）。

## 8. ⚠️ 注意事项（改之前必须知道）

### 8.1 硬件红线

1. **这一路舵机必须独立供 6~7V，不能从 STM32 板载 LDO 取电。**
   2026-09-23 现场："夹爪完全不动"的根因就是**误接 5V**（数字舵机在 5V 下彻底静默）。
   ⇒ **夹爪无声不动，第一件事是量这一路的电压，不是查固件。**
2. **越过机械端点 = 持续堵转 → 电流拉满 → 发热 → 烧舵机（不可逆）。**
   凡是往更小脉宽下探，必须**小步（≤25µs）逐档听声**，听到持续嗡嗡声立刻 `SERVO STOP`。
   最终取值应落在"刚好完全张开"**之上**，不要贴死端点。
3. **改脉宽会连带动高度**（单舵机联动）。改 `OPEN_US` / `STANDBY_US` / 三个类别值，
   同时改掉 `[0]` 起点高度、`[3]` 到件高度、`[8]` 落料高度。

### 8.2 时序红线

4. **`EC_AXIS_GRIPPER_SETTLE_MS` 每 +100ms，整轮多 0.5 秒**（程序里有 5 个舵机步）。
   15 秒失活窗口是硬约束（`ec_app.c:553` 的 `>= 15000`），赛规"15 秒没动作/没显示"本轮结束。
5. **`EC_AXIS_PICK_DWELL_MS` 不许改成 0** —— `step_is_valid()` 判 `servo_pulse_us==0` 为非法步，
   会让**整个程序被驱动拒收**；也不许把这一步整个删掉（步号断言会全错）。
6. **`EC_AXIS_PICK_PLACE_STEP_COUNT = 13`（现行用满 12 步，只剩 1 个空槽）**：
   再加任何一步都会让 `append_*` 返回 false ⇒ **整条计划不成立、一件都不动**。

### 8.3 同步红线（改一处必须改另一处）

7. 新增/删除脉宽档位要**同时**改：`ec_servo_test.c:is_allowed_pulse()` + `ec_diag.c` 命令表。
8. 改类别开度值要**同时**确认它落在台架白名单里（否则现场没法复现/回退扫描）。
9. `ec_motion_plan.c` 与 `ec_motion_plan_interp.c` 里的域校验是**两份拷贝，必须同步改**
   （后者不参与构建，但改错会在切换路线时炸）。

### 8.4 语义陷阱

10. **`EC_AXIS_STEP_GRIPPER` 和 `EC_AXIS_STEP_Z_SERVO` 是两种步类型，不是两只舵机** ——
    它们驱动的是**同一路 PB10**。看代码时别当成两个执行器。
11. **`servo_pulse_us` 字段的语义随步类型变**：GRIPPER/Z_SERVO 是**微秒**，WAIT 是**毫秒**。
12. **成功 ≠ 夹住了**。夹爪无位置/力反馈，`success` 只代表程序跑完。
