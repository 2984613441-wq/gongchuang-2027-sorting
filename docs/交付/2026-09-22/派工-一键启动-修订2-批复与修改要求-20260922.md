## 一、🔴 必须改：RUNNING 的判据不能是"我 Popen 的那个子进程"

```
证据（请自行复核 `/home/pi/p_go8.sh` 内部）：
    echo HOME | nohup python3 deploy/run_chain.py … > "$LOG" 2>&1 &
    echo "PID=$!  日志=$LOG"
    sleep 30
⇒ 链是 **nohup 起的独立进程**；你 Popen 的 `bash p_go8.sh` 约 40 秒后**自己就退出了**，
   而真正的链还在跑。
⇒ 两个后果：
   ① `self.chain_process.poll()` 会在链仍在跑时报"已退出" ⇒ 状态机误回 STANDBY（状态失准）
   ② 此后任何一次起链都会**起第二条链** ⇒ **两个 run_chain 抢 /dev/serial0** ✗✗（最严重）
```
**要求（改这三条）**
```
1) RUNNING 判据 := `pgrep -f "[r]un_chain.py"` 有结果（每 BUTTON_POLL_INTERVAL_S 轮询一次），
   **不要**用子进程 poll() 判断链的生死。
2) `start_chain()` 开头**必须先查"链是否已在跑"**（现有实现没有这道门，必须补）：
   有 ⇒ 拒绝启动 + WARNING 日志（不要静默，也不要再起一条）。
3) 子进程退出码只用于判断"p_go8.sh 自身"成功/失败；链的结局从**日志**判：
   出现"干净收场，退出码 0" ⇒ STANDBY；否则 ⇒ FAULT（fail-closed）。
```

## 二、4 条加固（不阻塞，但请一并做）

```
① p_go8.sh 起链前会先跑 `p_look2.py` 视觉粗筛；**台上 0 件会直接退出、根本不起链**

② "释放沿 + RUNNING ⇒ pkill" 之后状态回 **STANDBY**（不是 FAULT）；板子状态按规矩**不动**

```
