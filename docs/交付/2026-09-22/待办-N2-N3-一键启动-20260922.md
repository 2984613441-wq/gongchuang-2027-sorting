## N2 · 链没有「本轮结束」条件 🔴

### 症状（2026-09-21 18:31 那轮，日志 `/home/pi/logs/round-R8-183157.log`）
```
18:33:18  显示完成并确认: 青色正方体 success=5      ← 5 件全成
18:33:19 ~ 18:44:42  state=READY success=5          ← 空转 11 分钟等新件
18:44:52  ITEM_TASK sent: target_seq=1 class_id=3 抓取点=(-35.6,3.9)   ← ⚠️ 又派了一件
18:44:52 ~ 18:46:53  ITEM_TASK 超时 5.0s 无应答，重传 frame_seq=6     ← 板子静默，无限重传
```

### 根因
- 链的主循环只在「有可用件」时才派件；**没有任何"这一轮结束了"的判据**。
- 于是它把**已丢进盒子、还在画面里的件**又识别了一遍（见 N3），派第 6 发。
- 板子对该发**完全静默**（固件缺项：拒绝不回错帧）⇒ 链永远等不到 MOTION_DONE。

### 改法（**动手前先读主循环，别猜行号**）
1. 找到主循环（`电控/deploy/run_chain.py`，约 `:1226` 起，轮询 + 派件那一段）。
2. 加一个**本轮静默看门狗**：时钟从「最后一次有效动作 或 最后一次成功上屏」起算；
   超过阈值（默认 15.0s，可配、可一键回退 `=0` 关闭）⇒ **fail-closed 干净收场**：
   ```
   停止派件 → 记 FAULT → 屏幕显示失败原因 → 停视觉监听线程 → 关串口 → 停监控服务 → 退出
   ```
   ⚠️ 退出时**不得**向 STM32 发 `STOP ALL` / `HOME` / `RESET` 或任何电机复位动作。
3. 重置时钟的事件（并写进注释说明理由）：
   - ✅ `inbound: MOTION_DONE accepted`
   - ✅ 成功上屏 + `DISPLAY_ACK` 完成
   - ❌ `ITEM_TASK sent`（只证明主机发了命令，不证明装置动了）
4. **兼容性**：正常件间间隔实测 **0.90~0.93 s**，离 15 s 有一个数量级余量 ⇒ 不会误判。
   唯一实测异常是 **16.95 s**，按赛规**本就该判本轮结束** ⇒ 不要为了掩盖它调大阈值。
5. **回退**：`--round-silence-timeout 0` 或环境变量 `=0` ⇒ 恢复旧行为。
6. **顺手同一批做**（Codex 已出方案，见 `docs/交付/2026-09-22/` 或派工回收件）：
   **越界拒识去重 + 窗口汇总** —— 同一件身份在 N 秒窗口内只打 1 条 WARNING，
   窗口结束汇总一次（首次/末次像素、抖动范围、次数、原因）。
   底层两处逐帧 WARNING 用 `logging.Filter` 挡：`pixel_to_device.py:496`、`vision_ingest.py:251`。

### 判据
连跑两轮：**0 FAULT / 0 DEADLINE / 链在结束时自己退出**。

## 一键启动程序（用户明确要求）

### 用户已定的口径
- 电脑与装置通讯**是允许的**；用户接受"调试期用 MaixVision 起视觉"。
- 用户已买到 **16mm 自锁金属按钮 + 环形灯，4 脚**（2× NO 接触 + 灯 ±）。

### 接线（已给用户，见本轮对话）
```
接触：NO-A → GPIO23（物理针脚 16）；NO-B → GND（针脚 14）；GPIO23 配 INPUT + 内部上拉
      ⇒ 按下读到 LOW。⚠️ NO 脚上【只接 GPIO 和 GND，不接任何电源】
灯：  灯+ → 装置电源正极；灯− → 装置电源负极（常亮）
      ⚠️ 灯的额定电压【必须先测】（6/12/24/220V 都有）—— 不确定前不要接任何电源
占用检查：GPIO17 = 转盘索引（turntable_guard.py:61）；GPIO18 = 转盘 PWM（pi_pw.py）⇒ 都不能用
```

### 状态机（自锁按钮必须这么用）
```
[上电] → 链起来但【待机】（不派件）；视觉已在跑；屏幕显示「等待启动」
        ⇒ HOME 确认落在【上电那一刻】（合法窗口；比现在"启动时才问"早得多）
        ⇒ 上电保险：若按钮已锁在闭合位，绝不能启动 —— 必须"先见过它松开一次"
[按下]   边沿触发（HIGH→LOW），且已见过松开 ⇒ 才开始 --start-round，计时开始
[运行中] 人再也不碰任何东西；状态只从屏幕自证
```

### 要写的文件（最小集）
1. `工具/pi_side/pi_onkey.py`（或 `deploy/` 下）—— 守护脚本：
   - 读 GPIO23（pigpio，INPUT + PUD_UP），做去抖 + 沿触发 + arming guard
   - 待机态：起链进程时**不传 `--start-round`**；按键后如何触发由实现定
     （最省事：脚本自己在按键后 `subprocess.Popen` 起 `run_chain.py --start-round`，
      并把 `HOME\n` 喂给它的 stdin 以满足 `require_home_confirmation()`）
   - 屏幕「等待启动」→ 直接用现有 `display_hdmi.py` 的画面接口
2. `/etc/systemd/system/pi-onkey.service` —— `WantedBy=multi-user.target`，`Restart=on-failure`
3. MaixCAM 侧视觉自启（现靠 MaixVision 手点）—— 与一键启动配套的另一半

### 禁忌
- **不许任何遥控/无线**；不许运行期依赖笔记本；不许碰市电。
- 不许在 `EXECUTING` 之外给 STM32 发舵机/轴命令。

## 现场纪律（本轮新增两条）

1. **烧录前必须先把链停掉。** 今天老链在用户烧录期间一直活着并继续发指令，
   导致板子出现 5 次移动、原点作废。烧录前：`pkill -f "[r]un_chain.py"` 并确认端口已释放。
2. **链跑完不会自己停**（N2）⇒ 现场看到 `success=N` 且长时间 `READY` 就手动停，
   否则它会一直派件直到板子静默、然后无限重传。
