### P0-1 栈溢出 —— **今晚全部故障的根因，未修**
```
现象  ：20:06 轮 ❌ / 20:12 轮 ✅ / 20:20 轮 ❌（间歇性）
        表现为：板子 ACK_ACCEPTED 后彻底静默、PING 无应答、轴朝最后方向继续走飞、永无 MOTION_DONE
根因  ：Stack_Size = 1024 B（startup_stm32f407xx.s:32），
        而链接图最深调用链 = 1208 B（ec_app_poll_motion 1184 / startup_seq 1176 / start_button 1168）
        主犯：ec_app.c:165 与 :257 两个 416 B 的 ec_axis_pick_place_t program 局部变量（13 槽 × 32 B）
机制  ：栈溢出 → 踩 RAM → hard fault → CPU 停，但 TIM4/TIM8 的 PWM 硬件继续发脉冲
        ⇒ 轴沿最后设定方向走飞 + 板子不应答 + 没有 MOTION_DONE
修法  ：① 两个 program 改 static（首选）② Stack_Size 0x400 → 0x800（兜底）
判据  ：重编后链接图里 **所有 Max Depth < Stack_Size**；实跑连续 3 轮无"ACK 后静默"
⚠️    ：这个溢出在我改容量(11→13)之前就存在（1184 那条链与 program 无关）；我的 +64B 只影响含 program 的链
```

### 6.3 工作区 ≠ Pi 实况（这是最大的隐患）

### 6.4 `[ToolOffset]` 是标定闭环的一半，不是"偏移旋钮"
```
标定端算的是：装置真实坐标 = 滑台 − [ToolOffset]，当时 TO = (-108.5, -20.5)
链的运行时：  滑台 = 装置 + [ToolOffset]
⇒ **改 TO 就等于把整条映射推偏**（现值 -15.5 ⇒ 每个取料点比标定真值偏 +5mm Y，是用户要的 0.5cm）
⇒ 我一度按"+1cm 向外"改成 -10.5 ⇒ 取料点偏 +10mm ⇒ **夹爪停在件旁边合嘴、夹空**
若确实要"夹爪相对件外偏"，应**另加一个只为夹取用的偏置**，不要动 TO
```
