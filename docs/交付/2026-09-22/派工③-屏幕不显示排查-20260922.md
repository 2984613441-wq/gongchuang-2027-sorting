## 三、要交付的方案（缺一项都算没交）

```
① **软件侧 vs 屏幕侧的分界**：怎么证明"链确实把帧写进了 /dev/fb0"
   （日志 + 哪些文件/命令可作证据）⇒ 把故障锁定到"帧缓冲 → 屏幕"这一段
② **静态检查清单**（现在就能做）：每条给"命令 + 期望输出 + 异常含义"，至少覆盖：
   /dev/fb0 是否存在、虚拟尺寸与 bpp、HDMI 是否被检测到（drm status）、字体是否存在、
   屏参配置、**是否有第二个 framebuffer 干扰**（config.txt 里 max_framebuffers=2）
③ **动态验证清单**（有电后）：怎么**不跑整轮**单独渲染一帧
   （用 `display_hdmi.py` 的哪个入口/哪个构造参数）⇒ 给**最小复现命令**；
   做不到就写「未核实」并给替代验证
④ **候选原因清单**（按可能性排序），每条附"如何证伪"
   （例如：被 fb1 占用、bpp 打包错、HDMI 未热插拔、字体缺失、overscan 裁切、屏自身输入源选错）
⑤ 最小修复方案（改哪个文件哪几行 / 或纯现场做法）+ 回滚
⑥ 验收判据：跑一轮时屏幕**逐件**出现两行（序号 + 目标件名），且与日志 `显示已上屏` 一一对应
⑦ 最坏情况与风险
```
