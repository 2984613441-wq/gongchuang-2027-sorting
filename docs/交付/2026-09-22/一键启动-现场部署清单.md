## 🔌 步骤 1：物理接线（断电操作）

> ⚠️ **全程断电**：拔掉树莓派电源、拔掉 STM32 电源、拔掉指示灯电源。

### 1.1 按钮接线

| 端子 | 目标 | 物理针脚 | BCM 编号 | 备注 |
|------|------|---------|---------|------|
| NO-A | GPIO23 | 针 16 | BCM 23 | 常开触点 A |
| NO-B | GND | 针 14 | — | 常开触点 B |

**接线图**（俯视，USB/以太网口朝下）：
```
    [USB]  [以太网]
    ┌─────────────┐
    │             │
    │   14(GND)   │ ← NO-B
    │   16(GPIO23)│ ← NO-A
    │             │
    └─────────────┘
```

**🔴 红线禁忌**：
- **NO 脚只接 GPIO 与 GND**，绝不接 3.3V/5V（会烧 GPIO）
- 若按钮有 NC（常闭）触点，空着不接
- 若按钮有 COM（公共端），接 NO-A（不接 NO-B）

### 1.2 指示灯接线（可选）

> ⚠️ **必须先测额定电压**：用万用表测灯的电阻，查规格书确认额定电压。

| 端子 | 目标 | 备注 |
|------|------|------|
| 灯+ | 独立电源正极 | **不接树莓派 GPIO** |
| 灯− | 独立电源负极 | 与树莓派共 GND（可选） |

**🔴 红线禁忌**：
- 不用 GPIO 直驱指示灯（电流可能超限）
- 独立电源电压 = 灯额定电压（12V 灯用 12V 电源、5V 灯用 5V 电源）

### 1.3 接线自检

**检查清单**：
- [ ] NO-A 接 针16（GPIO23）
- [ ] NO-B 接 针14（GND）
- [ ] NO 脚未接任何电源
- [ ] 指示灯接独立电源（若有）
- [ ] GPIO17/18 未动（转盘仍在用）
- [ ] 所有接线牢固、无短路

**判据**：用万用表蜂鸣档，按钮松开时 NO-A/NO-B 开路，按下时导通。

**若不通过**：检查按钮类型（NO/NC）、接线顺序。

## 🧪 步骤 3：首次功能测试（前台运行）

> ⚠️ **不要立刻开机自启**，先手动跑一次验证功能。

### 3.1 前台测试（无 systemd）

```bash
# 树莓派侧，前台运行
cd /home/pi
python3 pi_onkey.py --log-level DEBUG
```

**预期输出**：
```
2026-09-22 10:30:00 [INFO] pi_onkey: GPIO23 已配置为输入+内部上拉
2026-09-22 10:30:00 [INFO] pi_onkey: 按钮初始值 = 1 (松开)
```

**判据**：
- [ ] 输出 `GPIO23 已配置为输入+内部上拉`
- [ ] 输出 `按钮初始值 = 1 (松开)`（若按钮已按下，会输出 0 并进 arming guard）

**若失败**：

**步骤**：

3. 观察输出

**预期输出**：
```
2026-09-22 10:31:00 [INFO] pi_onkey: 按钮按下 → ARMED
2026-09-22 10:31:00 [INFO] pi_onkey: 准备起链：round_id=R-20260922-103100, 日志=/home/pi/logs/round-R-20260922-103100.log

2026-09-22 10:31:01 [INFO] pi_onkey: 起链成功 → RUNNING
```

**判据**：
- [ ] 输出 `按钮按下 → ARMED`
- [ ] 输出 `链已起动：PID=...`
- [ ] 输出 `起链成功 → RUNNING`
- [ ] 链路实际运行（MaixCAM 有 TCP 连接、STM32 有串口输出）

**若失败**：
- `起链失败 → FAULT` → 检查链路本身（`bash p_go8.sh` 能否跑通）
- 无输出 → 检查按钮接线（万用表测 GPIO23 电平）

### 3.3 Arming Guard 测试（自锁按钮专用）

> ⚠️ 仅当使用**自锁按钮**时才需要此步骤。

**步骤**：
1. **先按住按钮**（保持按下状态）
2. 启动服务：`python3 pi_onkey.py --log-level DEBUG`
3. 观察输出

**预期输出**：
```
2026-09-22 10:35:00 [INFO] pi_onkey: 按钮初始值 = 0 (按下)
2026-09-22 10:35:00 [WARNING] pi_onkey: ⚠️ 上电时按钮已按下，进入 arming guard（必须先松开才能 arm）
```

**判据**：
- [ ] 输出 `按钮初始值 = 0 (按下)`
- [ ] 输出 `arming guard`
- [ ] **不起链**（持续按住不触发）

**然后**：
1. **松开按钮**
2. 观察输出：`arming guard 已解除（按钮松开）`
3. **再次按下**
4. 观察：应该正常起链

**若失败**：
- 上电时按钮已按下，但仍立刻起链 → arming guard 未生效，**禁止使用自锁按钮**

## 🎯 步骤 5：现场联调验收

### 5.1 完整流程测试

**模拟比赛流程**（R-R01/R-R02）：

1. **上电前**：把滑台推到 HOME（X/Y 负方向最里角顶住）
2. **上电**：树莓派、STM32 上电，**不要 ssh、不要连笔记本**
3. **等待 30 秒**：服务自动进入 `state=standby`
4. **裁判发令后**：按一次按钮
5. **观察**：链路自动起动、视觉开始识别、滑台开始运动

**判据**：
- [ ] 上电后服务自动进入 `standby`（不派件）
- [ ] 按钮按下后链路自动起动（无需 ssh、无需终端）
- [ ] 链路正常运行（视觉/串口/运动全通）
- [ ] 15 秒内有动作（满足 R-R04）

**若失败**：立刻 **急停**，检查日志：
```bash
sudo journalctl -u pi-onkey.service -n 100
```

### 5.2 异常停止测试

**场景**：链路运行期间按急停、或链路异常退出。

**步骤**：
1. 按按钮起链
2. **运行中按急停**（或 `pkill -f "[r]un_chain.py"`）
3. 观察服务状态

**预期**：
- 链路退出（退出码 ≠ 0）
- 服务进入 `FAULT` 状态
- 日志输出 `链异常退出 → FAULT`

**判据**：
- [ ] 服务进入 `FAULT`（不自动重试）
- [ ] 必须 `sudo systemctl restart pi-onkey.service` 才能恢复

### 5.3 多轮测试

**场景**：链路正常结束后，再按一次按钮（第二轮）。

**步骤**：
1. 第一轮正常跑完（链路退出码 0）
2. 观察服务状态 → 应回到 `STANDBY`
3. 再按一次按钮
4. 观察 → 应正常起第二轮

**判据**：
- [ ] 第一轮结束后服务回到 `STANDBY`
- [ ] 第二次按钮可正常起链

## 🔧 常见问题排查

### Q1: 服务启动失败（`failed`）

**排查**：
```bash
sudo journalctl -u pi-onkey.service -n 50
```

**常见原因**：
- `RPi.GPIO 不可用` → 确认在树莓派上运行、确认 `python3-rpi.gpio` 已安装
- `FileNotFoundError: /home/pi/电控/deploy/run_chain.py` → 检查路径
- `Permission denied` → 检查文件权限：`chmod +x /home/pi/pi_onkey.py`

### Q2: 按钮无响应

**排查**：
```bash
# 读取 GPIO23 实时值
python3 -c "import RPi.GPIO as GPIO; GPIO.setmode(GPIO.BCM); GPIO.setup(23, GPIO.IN, pull_up_down=GPIO.PUD_UP); print(GPIO.input(23)); GPIO.cleanup()"
# 松开时应输出 1，按下时应输出 0
```

**常见原因**：
- 接线错误（NO-A 未接 GPIO23）
- 按钮类型错误（NC 当成 NO）
- GPIO23 被其他进程占用

### Q3: 起链失败 → FAULT

**排查**：
```bash
# 手动测试链路
bash /home/pi/p_go8.sh
```

**常见原因**：
- 链路本身坏了（不是一键启动的问题）
- HOME 门禁被改（`run_chain.py` 版本不匹配）
- 串口被占用（`/dev/serial0` 被其他进程打开）

### Q4: 开机自启不生效

**排查**：
```bash
# 检查是否启用
sudo systemctl is-enabled pi-onkey.service
# 预期输出：enabled

# 检查依赖
sudo systemctl list-dependencies pi-onkey.service
```

**常见原因**：
- `sudo systemctl enable` 未执行
- 依赖 `network-online.target` 未就绪（网络未启动）
