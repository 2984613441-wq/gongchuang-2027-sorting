## 一、相机监督式自启（**在既有方案上改两处**）

### 1.1 前置：先在设备上查证"自启机制到底是什么"（**用户执行，5 分钟**）
```bash
ssh root@<相机IP> "ls -l /root/main.py 2>&1; head -5 /root/main.py 2>&1"
ssh root@<相机IP> "ls /etc/init.d/ 2>/dev/null; cat /etc/rc.local 2>/dev/null; ls /etc/systemd/system/ 2>/dev/null | head"
# 断电上电后**立刻**看进程：
ssh root@<相机IP> "ps aux | grep -i -E 'python|maix' | grep -v grep"
```
**判据**：若上电后 `ps` 里**没有** `stage1_color_v6_send.py`，但 `/root/main.py` 存在 ⇒ 说明"入口存在、跑的是别的程序"⇒ 改入口即可。

### 1.2 我的方案：**监督式**（而不是"开机跑一次"）
```
入口文件（/root/main.py 或系统实际的启动入口）= 一个监督脚本：
  1) 等网络就绪：TCP 连 172.20.10.8:8765 成功（或最多等 30s），每 2s 探一次
  2) 循环：
       若 pgrep -f forensic_v6_frame 存在 ⇒ 等 3s 再判（取证优先，**无需改取证脚本**）
       否则 python3 /root/stage1_color_v6_send.py
       进程退出后 sleep 2 再拉起          ← 关键：崩溃自愈
```
**为什么必须这样**：今天两次"读不到"到底是**断电**还是**程序崩了**，我们没有证据 ⇒
"开机跑一次"只覆盖断电 ✗；监督式**两种都覆盖** ✓

**验收（必须两条都过）**
```
A1 断电上电 → 不碰设备 → **30 秒内**树莓派侧能收到批次（`p_look2` 读到 task_id），且 60 秒不掉线
A2 **人为杀掉 sender**（`pkill -f stage1_color_v6_send`）→ **5 秒内自动恢复**（`p_look2` 再次读到）
   ⇒ 这条是"监督"二字的证明；只跑一次的方案过不了 A2
```
**回滚**：恢复备份的入口文件（实施时先 `cp` 备份并记 sha）✓
**上限（诚实说）**：监督脚本救不了"OS 本身没起来/网络栈没起来"；那种情况仍需人工 ✓
