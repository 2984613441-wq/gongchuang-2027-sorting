# 决定 · 运动原点移到 Y 正端停车位（2026-09-22 现场）

## 决定（用户授权 DSH 自定，不再询问）

```
新 HOME = (-95.0, +85.5) mm   ⇒   mm10 = (-950, +855)
X 保持负端 -950（真硬限位、可重复，不动）
Y 由 -975（负端最里角）改为 +855（正端停车位）
```

**依据（2026-09-22 现场实测走位）**
```
从 HOME(-95,-97.5) 起：
  ① pi_goto.py 0 145  ⇒ +145.0mm = 11600 步 ⇒ 到【第二落点】(-95.0, +47.5)   STEP_RESULT=1 ✓
  ② pi_goto.py 0 38   ⇒  +38.0mm =  3040 步 ⇒ 到 y=+85.5                    STEP_RESULT=1 ✓
⇒ 现场认定的停车位 = y +85.5mm
```

**为什么选 +85.5（而不是贴到端头 +97.5）**
- `ec_motion_plan.h:127` 的 `REACH_FAR_Y_MM10 = 925`（正端留 5.0mm 余量）⇒ 855 < 925
  ⇒ **HOME 合法，不需要改这条宏**（贴端头 +975 则必须改，且会带来"每件回程顶撞硬限位"的副作用）
- 距可达域上限 7.0mm、距 Y 机械端 12.0mm ⇒ 有裕度、不贴边、回程不撞端头
  ⇒ 规避了项目记录过的「撞限位堵转 → 可能带挂主控」风险

## 目的（为什么值得改）

1. **消除夹爪被误判成黑件**：夹爪常驻在 Y 正端（相机视野之外/边缘）⇒ 不再进 `black` 窗
   （现场实测第七件就是"误判的夹爪的黑色"）
2. **离落点更近** ⇒ 路径变短（旧 HOME 的往返约 38800 步）⇒ 单件更快、15s 余量更大
3. 已确认**不影响标定/坐标系**：`ec_motion_plan.h:173` 原话「⚠️ 坐标系**不变**：线上坐标仍是设备
   中心系，协议合法域 ±1450 不动 ⇒ 所以 PICK / 落点 / 相机中心全部继续用中心系的数」
   ⇒ 链侧坐标、ToolOffset、工作区**都不用动**
