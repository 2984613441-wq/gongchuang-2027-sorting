# 转盘脉宽通路 —— 事故与现场纪律（2026-09-22）

## 一、通路是什么（**必须先理解这条，否则会误杀进程**）

```
       链（方案C）                       常驻进程                        硬件
  run_chain.py + rpi/turntable_guard.py   /home/pi/pi_pw.py              MG996R 舵机
        │  PwFileBackend                  │  pigpio.pi()                  │
        └──► 写 /home/pi/pw.txt ──────────►│  持续把 pw.txt 的内容           │
            （只写文件，不驱动 GPIO ✗）    └──► 输出到 **GPIO18** ─────────►│ 信号线
```

**关键事实（证据）**
- `电控/src/electrical_control/rpi/turntable_guard.py:283`：
  `turntable = Turntable(config, PwFileBackend())` ⇒ 真实模式走 **写文件** 的后端 ✓
- `电控/src/electrical_control/rpi/turntable.py:148-169`：`PwFileBackend.set_pulse_us()` 写 `DEFAULT_PW_FILE`
- `/home/pi/pi_pw.py`：读 `/home/pi/pw.txt`，`PIN = 18`，持续输出（带 mtime 重发）
- 中位 = **1500µs**（`turntable.py`: `zero_pulse_us=1500`，盘面「线 0」；行程 ≈270°，1500 是正中间）

⇒ **没有 `pi_pw.py`，链写得再对，GPIO18 上也不会有脉冲 ⇒ 转盘一格都不动，而且链不会报错** ✗✗

## 二、2026-09-22 事故（"转盘一直在动"）

```
现象：用户报告转盘舵机一直动
定位：/home/pi/pw.txt 里是 **2155µs** ✗（远超中位 1500，已接近脚本上限 2500）
      ⇒ 常驻进程一刻不停把 2155µs 发给 GPIO18 ⇒ 舵机被持续驱到极限 ✗
来源：台架实验手写的遗留值（不是链写的；链只会写各货格对应的脉宽）
处置：① pw.txt 改回 1500  ② 清掉重复实例，统一由 /etc/init.d/S98turntable 管理
```

**同时暴露的第二个问题（比赛级）**
```
/home/pi/pi_pw.py 此前**不在任何自启里** ✗
⇒ 树莓派每次重启后必须人工起它，否则转盘失效 ✗（现场表现：跑轮时转盘不动/投错格）
⇒ 已补：/etc/init.d/S98turntable（start/stop/restart/status，用 pgrep -f 判活，
   缺失 pw.txt 时补 1500），S98 早于 S99 ⇒ 链起来之前通路已就绪 ✓
```

## 三、现在生效的安全加固（用户 2026-09-22 批准）

```
① /etc/init.d/S98turntable       开机自动拉起 pi_pw.py；pw.txt 缺失则补 1500 ✓
② run_chain.py（开工处，`:1272` 之后）
   非 demo 模式下先把 **pw.txt 写成 1500** 再 preflight
   ⇒ 清掉任何遗留脉宽（"上一场台架实验的值"不会被带上赛场）✓
   ⇒ 失败只记 WARNING、不阻断开工（它只是加固，不是门禁）
```

## 四、现场纪律（写进操作卡）

```
· 平时：pi_pw.py 保持运行 ✓（它和链不抢 GPIO：链写文件、它输出脉宽 ✓）
· 台架实验（直接 `echo 21xx > /home/pi/pw.txt` 那类）做完，**把 pw.txt 写回 1500** ✓
  或直接 `sudo /etc/init.d/S98turntable restart`（若 pw.txt 存在则不改动它）
· 跑链前：确认 `cat /home/pi/pw.txt` 是 1500（链开工自会写一次 ✓）
· 转盘完全不动时，第一件事查：`pgrep -f pi_pw.py` 有没有进程 ✗
· ⚠️ 千万不要把 pi_pw.py 当"多余进程"杀掉 —— 它是必需品（2026-09-22 我杀过一次，已记录）
```

## 五、可证伪预测

1. 杀掉 `pi_pw.py` 后跑一轮 ⇒ 转盘不动、且链**无报错**、日志里转盘相关行照常出现。
2. 把 `pw.txt` 写成 2600（超上限）⇒ 舵机会被驱到极限（异常动作）。
3. 重启树莓派 ⇒ `pgrep -f pi_pw.py` 应有 1 个进程（S98turntable 生效），且 `pw.txt` 为 1500。
4. 起一轮 ⇒ 日志出现 `转盘已置中位 1500µs（清掉 …）` ✓
