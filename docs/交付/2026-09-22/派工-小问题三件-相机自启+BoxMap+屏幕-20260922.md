## 二、`[BoxMap]` 冻结（防"投错盒=负分"）

**现状**
```
链每次开轮都警告：`[BoxMap] 为空 —— 视觉侧仍会给出 box_id，但没有任何现场冻结的对应关系可校验`
（今日每轮日志都出现；`电控/src/electrical_control/pick_strategy/chain_adapter.py:117` 注释：
  "payload 不带 box_id；本工程 class_id → box_id 是**冻结 1:1**"）
```
**含义（给用户的解释，供你复核）**：链现在**只照视觉给的 box_id 落料，没有第二道校验** ⇒
视觉若把颜色/形状认错，件会**直接进错盒**，链不会发现 ✗

**要做的（先给方案）**
```
1) 先**读代码确定 `[BoxMap]` 的确切语义与格式**（在哪个 ini、什么键、谁读它、读来做什么校验、
   空表时行为是什么）⇒ 逐条给 `文件:行号`
2) 找出**已有的可推导来源**：链日志里有【六盒落点表】
   `[FixedBox] 六盒落点表: {1: (-430,875), 2: (-950,475), 3: (450,475), 4: (-430,875), 5: (-950,475), 6: (450,475)}`
   ⇒ 说明它与 `[BoxMap]` 是不是同一套对应关系（是/否/部分），并给出 6 条待冻结记录
3) 与视觉侧冻结表的一致性：`docs/design/2026-08-27-视觉侧-boxid冻结映射与落点表注入.md:17,39,97`
   （视觉侧有 `(颜色,形状) → box_id` 冻结表）⇒ 两张表**必须一致**，给出核对方法
4) 验收判据：写入后跑一轮，链日志**不再出现** BoxMap 为空的警告；并给出"若故意写错一条会怎样"的验证
5) ⚠️ 不得改协议 wire（`ITEM_TASK` 8 字节格式冻结，`box_id` 不进协议）
```

## 三、屏幕显示（**先判断是不是真问题**）

**用户反馈**："刚刚屏幕也没有显示"

**已知事实**
```
· 链的显示走 HDMI framebuffer：`electrical_control/rpi/display_hdmi.py:33-34`
  （"帧到屏幕的最后一段（像素打包写 /dev/fb0）也在这里"；bpp 必须从 sysfs 读，不能假定 32bpp）
· 今天两轮日志都有 `两段显示已上屏: 1024x600 序号=N target_seq=N box_id=N` ⇒ **软件侧是成功的**
```
**要做的（先给方案）**
```
1) 先分辨两种情形（**别把正常当故障**）：
   (a) **待机时屏幕不显示** ⇒ 本来就不显示（只有派件那一刻才渲染）⇒ 不是问题
   (b) **跑轮时也不显示/显示残缺** ⇒ 才是故障
   ⇒ 请给出**两者的区分判据**（例如：跑轮时屏幕角落应出现什么、几秒内出现）
2) 若 (b) 成立，给排查树：`/dev/fb0` 是否存在/格式 (`display_hdmi.py` 的 FramebufferFormat)、
   HDMI 是否被识别 (`/sys/class/drm/*/status`)、屏幕分辨率/overscan 配置
   （`/boot/config.txt` 现有 `hdmi_cvt 1024 600 60 6 0 0 0`、`disable_overscan=1`、`hdmi_force_hotplug=1`）
3) 验收判据：跑一轮时，屏幕上**逐件**出现两行（序号 + 目标件名），与日志的 `显示已上屏` 一一对应
```
