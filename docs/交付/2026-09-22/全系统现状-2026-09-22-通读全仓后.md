## §1 真实的端到端数据流（一条件走完全程）

```
[1] MaixCAM  视觉/src/maixcam_deploy/stage1_color_v6_send.py
      320×320 RGB 采集 → 缩到 224 检测（scale 0.7）→ HSV 阈值分色
      → 颜色查硬表得 (形状, 货格号 bin) → 坐标乘回 320 系 + ROI 偏移
      → TCP 客户端发往 172.20.10.8:8765
      帧格式：target_count(1) + task_id(2,BE) + N×(id_byte,conf,X(2),Y(2),angle(1))
      其中 id_byte = 货格号 1..6；conf = 颜色纯度×100（不是模型置信度）；angle 恒 0xFF
      【分工读】

[2] 树莓派  电控/src/electrical_control/rpi/socket_vision_source.py
      收帧 → 像素→装置坐标（仿射）→ 视差补偿（当前全 0 = 关闭）
      → +[ToolOffset] → 滑台记账坐标 = PICK → 比 [WorkspaceLimits]
      → 排序（行扫描 key = (-y_mm, x_mm, target_seq)）→ 一帧只取第 0 件
      → 首件稳定门（默认连续 3 帧签名稳定，最多等 0.5s）
      【分工读】

[3] 树莓派  电控/deploy/run_chain.py 主循环
      转盘预置（方案C，发 ITEM_TASK 之前）→ 发 ITEM_TASK → 段1 上屏
      → 等 MOTION_DONE / ITEM_RESULT → 规则帧（含 CRC32）→ 发 DISPLAY_ACK → 段2 上屏
      【分工读】

[4] STM32   App/Src/ec_app.c:695  0xA5 起头的字节 → 网关组帧；其余 → ASCII 诊断解释器
      → ec_state_machine 12 态机 → WAIT_TASK 受理 → VALIDATE_TASK → EXECUTING
      → ec_app_start_motion() 取坐标+类别 → ec_motion_plan 生成 12 步
      → ec_axis_driver 逐步执行 → ec_board_stm32 梯形速度 → TIM4(Y)/TIM8(X) PWM
                                                          + DIR/EN GPIO + PB10(TIM2_CH3) 舵机
      【亲自读】

[5] 回程   MOTION_DONE → ITEM_RESULT → DISPLAY_ACK(0x25) → 板子回 ACK(0x01 CONSUMED) → 下一件
```

### 2.3 单件时间模型（可复算）

```
固定部分 = 5 个舵机步 × 600ms + WAIT 200ms = 3.2 s
运动部分 ≈ Σ(每腿步数) / 5000 Hz + 梯形加减速开销（每腿约 0.96 s 的加减速段，步数 ≥ 2496 时）
实测 12.8 s 与模型吻合 ⇒ 模型可用
```

### 2.4 🔴「挂死后轴走飞」的硬件机制（亲自读，第一次有底层证据）

```
栈溢出 → hard fault → CPU 停 ⇒ ec_axis_driver 的 fault()/stop_all() 永不执行
                      ⇒ TIM4/TIM8 的 PWM 是硬件在跑，继续发脉冲
                      ⇒ 且 ec_step_port_enable_axis() 已把该轴 ENABLE 拉低（使能中）
                      ⇒ 电机继续按最后方向走 = 走飞，直到撞限位堵转
板子 PING 无应答 = CPU 停（不是复位；复位会重新应答）
```
关键代码：`ec_board_stm32.c:718-731`（使能）、`:733-738`（stop_all 只在 CPU 活着时执行）。
