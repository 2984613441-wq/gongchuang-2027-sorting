# 夹取点标定 · 精确法（3 点）· 2026-09-21

> **为什么换方法**：前一套「走到视觉给的点 → 用户目视报残差（单位 cm）」测出来的数据自相矛盾 ——
> 用共形 4 参拟合**自己的 4 个点**，残差最大 **9.9mm**，比两个**没参与拟合**的圆柱（5.5 / 11.5mm）还大。
> ⇒ 瓶颈不是模型参数不够，是**测量方法本身带 ±5mm 噪声**。

## 方法（倒过来做）

```
① 夹爪开到一个【自选的滑台坐标】——机器坐标精确已知（相对移动，全程 STEP_RESULT=1）
② 用户把件塞进爪片开口，对到正中
③ 读视觉拿像素
⇒ 得到一对 (像素, 精确机器坐标)；误差只剩「对正」这一件事
```

**装置真实坐标 = 滑台坐标 − [ToolOffset] = 滑台坐标 + (108.5, 20.5)**
（因为链的口径是 `滑台 = 装置 + TO`，TO 当前 = (-108.5, -20.5)）

## 🔴 方法修正（2026-09-21 现场，用户提出）

**件塞在爪片中间时，爪片必然挡它一半**，会造成两个后果：
1. **中心偏移**；2. **颜色被阴影压暗 ⇒ class 误判**。
实测同一位置、同一个件：

```
被爪片挡着读到的 = (258, 128)      ← 且 class 被误判成 box_id=5（黑圆柱）
夹爪让开后读到的 = (231,  75)      ← class 正确 box_id=1（青正方体）
⇒ 遮挡造成的偏差 = (-27, -53) px   —— 非常大
```

**⇒ 用户提议"把夹爪移开再读"是正确的，否则拿到的是偏几十像素的脏数。**

### 修正后的单点流程

```
① 夹爪开到目标点 P（机器坐标精确已知）
② 用户把件塞进爪片开口对到正中
③ 用户在托盘上对着件【画圈】做记号（= P 的物理锚点）
④ 用户把件取出
⑤ 夹爪开到 P + (0, +120) 让开
⑥ 用户把件放回圈里
⑦ 读像素 ⇒ 得到 (像素, 精确机器坐标)
```

## 模型（本项目原有口径：共形 4 参）

```
device_x = a·u + b·v + tx
device_y = b·u - a·v + ty
```
⇒ 只有 **4 个未知数** ⇒ **2 点即可解，3 点有余量做检验**。
