## 10.5 🔴 我这次部署造成的一个回归，以及修法（**必读**）

**回归**：repo 版 `run_chain.py` 新增了 `require_home_confirmation()`（`:508` 定义，`:1041` 调用）。
真实模式 `--start-round` 现在**要求 stdin 精确输入 `HOME`**，非交互一律拒绝；
而 `nohup` 会把 stdin 变成 `/dev/null` ⇒ **旧写法的启动脚本全部直接拒启动**。

实测（`< /dev/null` 模拟 nohup）：
```
确认滑台已在 HOME 后输入 HOME（其他输入均退出）：HOME 未确认：当前启动环境不可交互。
移除 --start-round 保持待命，或在现场终端人工确认后启动。
```

**受影响**：`/home/pi/` 下**11 个**脚本带 `--start-round`：
`p_go8.sh  pi_chain_debug.sh  pi_repro_and_read.sh  pi_start_chain.sh  p_start7.sh
p_start_round.sh  start2.sh  start3.sh  start4.sh  start5.sh  start_round.sh`

**已修**：`p_go8.sh`（现网最新、对应 R8）。做法是**保留人确认这一步**，不削弱安全门：
```bash
echo "!!! 期望起点：X=-95.0mm, Y=-97.5mm（X/Y 负方向最里角，均顶住）!!!"
printf '确认滑台已在 HOME 后输入 HOME（其他输入均退出）：'
read -r ANS
if [ "$ANS" != "HOME" ]; then echo ">>> 未确认 HOME，拒绝起链。"; exit 1; fi
...
echo HOME | nohup python3 deploy/run_chain.py ... --start-round -v > "$LOG" 2>&1 &
```
备份 `/home/pi/p_go8.sh.bak-homegate-20260921`；受管副本 `工具/pi_side/sh/p_go8.sh`（LF、无 BOM，已核）。

**验证（都不碰硬件）**：
```
bash -n          语法 OK
输入 "NOPE"      → 未确认 HOME，拒绝起链（未起链）
输入 "HOME" + --port /dev/nonexistent
                 → 过门后走到 run_chain.py:1137 的串口打开才失败 ⇒ 门放行 ✅
```

**其余 10 个脚本仍是坏的**，用之前必须同样处理（或改用 `p_go8.sh`）。

**教训**：我只验了"代码能不能跑"，**没验"调用它的脚本还能不能用"**。
⇒ 规矩：**改一个被脚本/服务调用的入口，必须把调用方一起找出来读一遍**（`grep -ln` 该参数）。
这一条比任何单点测试都值钱 —— 同样适用于 `p_look2.py`（它被 `p_go8.sh` 调用，
我改了它的输出格式，幸好 `grep -c 'box_id='` 仍然匹配）。
