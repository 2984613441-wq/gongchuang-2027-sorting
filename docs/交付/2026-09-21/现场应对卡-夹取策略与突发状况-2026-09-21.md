# 第一部分 · 夹取策略：机器到底怎么干活的

## 1.1 单件全流程（固件里的 10 步程序）

每一件，STM32 按固定顺序执行这 10 步，**全程不许人插手**：

| 步 | 动作 | 在哪 | 说明 |
|---|---|---|---|
| **[0]** | 舵机 → 张开脉宽 | HOME（最里角） | **每件开头都做一次**。上电/复位后舵机是无电的、位置不可知，可能是闭合态；不先张开就带着闭爪去取料点，会把物块撞飞 |
| **[1][2]** | X、Y 走到**取料点** | HOME → 取料点 | **X 先、Y 后** |
| **[3]** | 等 200 ms | 取料点 | 纯等待，不驱动任何硬件 |
| **[4]** | 舵机 → 1900µs（**闭合 + 下压**） | 取料点 | 夹住件。600 ms 整定 |
| **[5][6]** | X、Y 走到**落料点** | 取料点 → 落点 | 🔴 **Y 先、X 后**（见 1.2） |
| **[7]** | 舵机 → 张开脉宽（**张开 + 抬起**） | 落点 | 释放件。600 ms 整定 |
| **[8][9]** | X、Y 回到 **HOME** | 落点 → HOME | **X 先、Y 后**。程序**必须**收尾在 HOME |

**三条硬事实：**
1. **夹爪是单舵机联动** —— 一个舵机同时决定"开合"与"升降"：**脉宽越小 = 开口越大 = 抬得越高**。
2. 程序**必须**收尾在 HOME（下一件是从 HOME 出发的，这是规划器的前提）。
3. 一次运动指令里的**零位移轴会被自动省略**（比如 X 已经在目标位置，那一段就只有 Y 一条腿）。

## 1.2 路径策略：三条腿的轴序（这是防"刮飞"的关键）

| 腿 | 轴序 | 为什么 |
|---|---|---|
| `HOME → 取料点`（空爪） | **X 先，Y 后** | 这条腿的 X 横移走在 `y = HOME` 那条线上，**落在托盘近壁带里**；而且此刻是空爪。改成 Y 先反而会把横移推进目标那一排 |
| `取料点 → 落点`（**夹着件**） | 🔴 **Y 先，X 后** | **先沿 +Y 退出托盘，再在盘外横移。** 夹着件在托盘上方沿 X 横穿，会把同排其他件刮飞 |
| `落点 → HOME`（空爪） | **X 先，Y 后** | 这条腿的 X 横移走在 `y = 落点` 线上（落点在盘外）；改成 Y 先会变成"沿落点那一列纵向切过整个内腔" |

**⚠️ 前提（很重要）**：带料腿 Y 先**只有在"落点真的在托盘外"时才成立**。
而且件自身还占 ±20mm，所以**落点中心出盘 ≠ 件出盘** —— 落点 y 至少要高出托盘内腔上界 20mm。
现测三个落点 y = **+47.5 / +47.5 / +87.5**，**都满足** ✅（旧落点 +19.0 不满足，这正是要把落点往外挪的原因）。

**回退开关**：`ec_motion_plan.h` 的 `EC_MOTION_CARRY_LEG_Y_FIRST` 改 0 重编 ⇒ 三条腿全回 X 优先。

## 1.3 开口策略：按类别选张开脉宽

**6 类 → 3 个值**（现场实测，**均在托盘最高点测的**）：

| 类别 | class_id | 张开脉宽 |
|---|---|---|
| 正方体 | 1 青 / 2 绿 | **650 µs** |
| 三棱柱 | 3 红 / 4 蓝 | **750 µs** |
| 圆柱 | 5 黑 / 6 橙 | **800 µs** |

- 值由 `ITEM_TASK` 载荷里的 `class_id` 决定（该字节本来就在协议里，**不改协议**）。
- **读不到类别 ⇒ 退回默认值**，绝不猜。
- ⚠️ 这个脉宽**同时是 [0] 和 [7] 两处的开度**，所以它也同时决定这两处的高度。

## 1.4 抓取顺序：抓哪一件

- 现状：链上跑的是 `--pick-strategy order`（"离托盘无壁边最近"规则，当前配置下 ≈ **Y 从大到小**）。
- 目标（**尚未落地**）：改成**行扫描** —— 第一键 Y 从大到小（从靠 Y 正方向那排开始、逐行往里），
  第二键同一行内 X 从小到大（从最靠 HOME 那件开始向 +X）。
- ⚠️ **`--pick-strategy` 默认是 `off`**。起链时不加这个参数，就是**按相机给的原始顺序**抓。

## 1.5 落料策略：3 个固定落点 × 转盘 2 个位置

- **只有 3 个固定落点**（A 侧）；6 个货格分两组、每组 3 个，两组在转盘上相差 **180°**。
- 夹爪只在每组的 3 个落点之间移动（靠滑台 XY）；目标格不在 A 组 ⇒ **转盘翻 180°** 到 B 组。
- 1 类 1 格：6 类 → 6 格，一一对应。
- `sorting_config.ini` 的 `[DropPoints]` 写 6 行，**4/5/6 与 1/2/3 同坐标**，靠转盘区分。
- 落点（滑台记账坐标）：① (−25.0, +87.5) ② (−95.0, +47.5) ③ (+45.0, +47.5)
- ⚠️ **转盘驱动目前还没接入链**（`turntable.py` 写好了，但 `run_chain.py` 从不调用它）。
  ⇒ **现在跑链只会往 A 侧那 3 个点放**，不会翻面。

# 第二部分 · 突发状况处置

## 2.1 一眼判据（先看这三个）

| 看什么 | 正常 | 异常 |
|---|---|---|
| 板子串口 | `PING` 回 `OK PONG` | 回空 ⇒ 板子没上电 / 串口线松 |
| 板子状态 | `AXIS` 的 `FAULTS=0` | `FAULTS≠0` ⇒ 真故障 |
| 跑链日志 | 每件 `ITEM_TASK → MOTION_DONE → ITEM_RESULT → DISPLAY_ACK` 四配套齐 | 缺任何一个 ⇒ 那件没走完 |

## 2.2 处置表

| 现象 | 可能原因 | 动作 |
|---|---|---|
| **板子完全不应答**（PING 空、静听 0 字节） | 没上电 / 串口线松 / 树莓派串口被占用 | ① 看板子电源灯 ② 按复位等 3 秒 ③ 查树莓派↔板子那根线（GPIO14/15，物理针 8/10）④ 确认没有别的进程占 `/dev/serial0` |
| **夹爪舵机持续"嗡嗡"响** | 顶到机械端点 / 被件卡住 | 🔴 **立刻 `SERVO STOP`**。持续堵转 → 电流拉满 → 发热，**会烧舵机（不可逆）**。板子上也能发 |
| **X/Y 电机响但滑台不动** | 顶死（超出实际行程） | 🔴 **立刻断电**。持续堵转 → 供电跌落 → STM32 欠压重启 → **坐标基准全废**（这条今天已经发生过一次）。之后必须**手推回最里角再上电** |
| **件被夹飞 / 被刮移位** | ①开口不够（爪片压到件）②带料横移扫到邻件 | ① 该类的张开脉宽往下调一档（更开）② 检查带料腿是否真的是 Y 先（回读程序步序） |
| **件"凭空消失"，链不去抓** | 三种不同的原因，**都不是机器坏** | 见 2.3 |
| **落料后件弹到格外 / 没进格** | 释放高度不对 / 转盘没转到位 | ① 目视落料时爪是否碰到格口壁 ② 确认转盘真的在 A 还是 B 侧 |
| **`DEADLINE_EXPIRED` / `FAULT_LOCK`** | 单件超过窗口没关（15 秒） | 现在窗口已改回**赛规口径**：**只要在动就续命**，只有真的连续 15 秒不动才超时。⇒ 出现它 = **机器真的停了 15 秒**，按"板子卡住"处理 |
| **链停在半路、日志报 `scheduler FAULT`** | 板子注入了 `POSITION_UNREACHABLE`（坐标越界），而链在等 `MOTION_DONE` | 起链前先确认三个落点都通过校验；看日志里被拒的那件的坐标 |
| **屏幕花屏 / 斜切 / 颜色错** | 帧打包出错（若做过提速改动） | 回退 `display_hdmi.py`；用它自带的三色条自检一眼判性质 |
| **转盘不动** | 驱动没接入链（现状）/ pigpiod 没起 / 舵机供电断 | `systemctl status pigpiod`、`systemctl status pi-pwm`；看 `/home/pi/pw.txt` 的值 |
| **要立刻停一切** | — | ① 急停/断电 ② `pkill -f "[r]un_chain.py"`（**方括号不能省**，否则会误杀自己的 ssh 命令） |

## 2.3 「件凭空消失」的三种原因（**最容易误判成机器坏了**）

| 现象 | 原因 | 判据 | 动作 |
|---|---|---|---|
| 物块**有一部分出画面** ⇒ 完全识别不到 | MaixCAM 里写死的"**贴边即当背景丢掉**" | 屏幕上根本没有这个件的框 | 把件往里挪；或等"视觉贴边修复"落地 |
| 件**识别到了**，链就是不用它 | **越界拒识**：装置坐标超出 `[WorkspaceLimits]` | 日志里有 `越界：换算坐标 x=… 不在 …` | 把件往可抓区里挪（今天的修复已把可抓区扩到正确范围） |
| 件识别到了、也在可抓区，还是不用 | **像素域外**：中心像素离画面边 < 15 px | 日志里有 `像素域外` | 把件往画面中间挪 |

## 2.4 复位纪律（每次断电/复位**必须**照做）

> **断电 → 用手把 X、Y 推到最里角顶住 → 再上电/复位 → 之后不再用手移滑台**

**为什么**：固件把"上电那一刻的位置"当作机械原点 HOME（滑台坐标 (−95.0, −97.5)）。
上电时滑台不在最里角 ⇒ 固件以为的坐标和实际位置差一大截 ⇒ 一移动就算错步数 ⇒ 顶死。

**今天已经踩过两次。**

## 2.5 起链命令（照抄）

```bash
PYTHONPATH=/home/pi/电控/src python3 deploy/run_chain.py \
  --port /dev/serial0 --image-dir /home/pi/images \
  --names-file /home/pi/电控/deploy/names.json --frame-output fb0 \
  --round-id R6 --round-task-id 1 --pick-strategy order --start-round -v
```

- ⚠️ **`--round-task-id` 必须是 1**（MaixCAM 的 `TASK_ID = 1`）；写错 ⇒ **整帧被丢，一件都不动**
- ⚠️ 不加 `--pick-strategy order` ⇒ 按相机原始顺序抓
- 收尾：`pgrep -f "[r]un_chain.py"` 确认退出
