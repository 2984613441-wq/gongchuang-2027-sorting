# 2. 任务 T6c · 屏幕帧打包 numpy 化

## 2.1 改后的完整 `encode_frame`（接口与返回类型不变）

```python
def encode_frame(frame: "PIL.Image.Image", fmt: FramebufferFormat) -> bytes:
    """PIL RGB 帧 -> 可直接写 fb 的字节（按真实 bpp 打包 + 行填充）。

    · 16bpp：RGB565 小端 —— 红 (255,0,0) = 0xF800 = 字节 00 F8。
      fbdev 的 fb 内容是 CPU 字节序的像素值，Pi 是小端；工具/pi_blit_png.py
      用同一打包方式在本机 16bpp 上出图成功。
    · 24/32bpp：fbdev truecolor 的内存序是 B,G,R[,X]
      （red 在 bit16 / green 在 bit8 / blue 在 bit0）；32bpp 第 4 字节留 0。
    · line_length 大于一行宽度（行填充）时，每行末尾补零，否则整幅会斜切。

    实现是 **numpy 向量化**（2026-09-21，原逐像素循环在 1024x600@16bpp 上是
    614,400 次迭代 ≈ 单件窗口里的 0.3–0.6 s）。三条硬约束逐字节锁死语义，
    改这条路径前先读：

    1. **16bpp 必须先 ``astype(np.uint16)`` 再移位** —— uint8 左移会按 8 位回绕，
       红色会整片变成 ``00 00``（黑）。
    2. **24/32bpp 用 ``np.zeros`` 起手，不用 ``np.empty``** —— 32bpp 第 4 字节
       靠"零初始化"保持 0；``np.empty`` 会把未初始化内存写进屏，偶发花屏。
    3. **行填充按行补，不能一次补到末尾** —— 一次性 pad 会让第 2 行起整幅斜切。
    """

    px = fmt.bytes_per_pixel
    width, height = frame.size
    validate_frame_size(width, height, fmt)

    row = width * px
    stride = fmt.line_length or row
    if stride < row:
        raise FramebufferFormatError(
            f"line_length/stride={stride} 小于一行应有的 {row} 字节"
            f"（{width}px @{fmt.bpp}bpp）"
        )

    # (height, width, 3) uint8；PIL 的 RGB 通道顺序就是要的 R,G,B
    rgb = np.asarray(frame.convert("RGB"), dtype=np.uint8)

    if fmt.bpp == 16:
        # 小端 RGB565：低字节先写 ⇒ 直接按 '<u2' 取字节
        r = rgb[:, :, 0].astype(np.uint16)  # 见上面第 1 条：先升位宽再移位
        g = rgb[:, :, 1].astype(np.uint16)
        b = rgb[:, :, 2].astype(np.uint16)
        value = ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3)
        data = value.astype("<u2").tobytes()
    else:  # 24/32bpp：B,G,R[,X]
        packed = np.zeros((height, row), dtype=np.uint8)  # 见上面第 2 条
        packed[:, 0::px] = rgb[:, :, 2]  # B
        packed[:, 1::px] = rgb[:, :, 1]  # G
        packed[:, 2::px] = rgb[:, :, 0]  # R；32bpp 的第 4 列起保持 0
        data = packed.tobytes()

    if stride == row:
        return data
    pad = b"\x00" * (stride - row)  # 见上面第 3 条：逐行补零
    return b"".join(
        data[at : at + row] + pad for at in range(0, len(data), row)
    )
```

配套改动：模块顶部加 `import numpy as np`（与 `rpi/pixel_to_device.py:38` 同款，硬依赖），
模块 docstring 增 3 行说明。**没有留 Pillow 备选分支**（Pi 上 numpy 1.19.5 已确认可用）。

## 2.4 ⚠️ 语料必须换 —— 而且**原建议的 `np.arange` 语料也不行**

**实测结论**（脚本 `_scratch/t6c-corpus-sensitivity.py`，6 种典型写错法 × 3 种语料）：

| 写错法 | A 纯色（现测试用） | B `np.arange(...).reshape(...)`（原建议） | **C 逐像素唯一图样帧（本补丁采用）** |
|---|---|---|---|
| 颜色类：16bpp 忘 `astype(uint16)`（红色回绕） | 抓住 | 抓住 | 抓住 |
| 颜色类：24/32bpp 通道序写成 R,G,B | 抓住 | 抓住 | 抓住 |
| **位置类：行序颠倒** | **漏掉** | **漏掉** | **抓住** |
| **位置类：整幅沿 Y 挪一行** | **漏掉** | **漏掉** | **抓住** |
| 位置类：行内沿 X 挪一像素 | **漏掉** | 抓住 | 抓住 |
| 布局类：行填充一次补到末尾 | 抓住（仅 stride>row） | 抓住 | 抓住 |

原因（可复核）：

* 纯色帧：**600 行里只有 1 种行**、1024 列里只有 1 种列 ⇒ 行序、平移全看不见。
* `np.arange(1024*600*3, dtype=np.uint8).reshape(600,1024,3)`：一行 = `1024*3 = 3072 B`，
  而 **`3072 % 256 == 0`** ⇒ 每行字节**与上一行完全相同**（实测 600 行里只有 **1** 种行）。
  它对 X 方向敏感、对 **Y 方向完全失明** —— 换了一种盲法，不是换了眼睛。
* 本方案：把像素序号按位切进 R/G/B（`(y,x) -> RGB` 是**单射**），实测
  **不同行 600/600、不同列 1024/1024、不同像素 614400/614400**。
  这个自检**每次跑都在打印**，语料日后被改瞎了一眼能看见。

def row_scan_key(det: Detection) -> tuple[float, float, int]:
    """**行扫描**排序键：Y 从大到小 → 同行 X 从小到大 → target_seq。

    用户口径（2026-09-21 确认）：从靠 Y 正方向那一排开始逐排往里；每排内从
    最靠 HOME 那件（X 最小）沿 +X 依次抓。⇒ 效果 = "从上到下、每排从左到右"。

    **它不吃 config**：不读 ``[Tray]``、不读 ``[Home]``，也不读 ``selection_mode``。
    ...（等价性边界见 3.4）
    ponytail: "同一行" 只认 Y **完全相等**。同一排各件 Y 因识别抖动差几毫米时，
    顺序会退化成"Y 大者先"，而不是严格的"这一排从左到右"。升级路径 = 按行容差
    分桶（``round(y / tolerance)``）；但容差必须实测、只能从配置来（不得内置
    魔法默认值），且那会把配置依赖再加回来 —— 本次按用户口径**不引入**。
    """
    return (-det.y_mm, det.x_mm, det.target_seq)

    usable, _ = usable_detections(frame, config)
