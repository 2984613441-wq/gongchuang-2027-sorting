## 一、三类张开脉宽 —— 定案值

| 类别 | class_id | **张开脉宽** | 判定链（【实测】） |
|---|---|---|---|
| **正方体** | 1（青）、2（绿） | **650** | 700 → **碰到**；675 → **仍碰一点**；650 → **明显有空隙** ⇒ 定 650 |
| **圆柱** | 5（黑）、6（橙） | **800** | 900 可用但用户要求按「托盘高度差」放宽；870 / 850 / 800 逐档放宽 ⇒ 定 800 |
| **三棱柱** | 3（红）、4（蓝） | **750** | 800 可用但偏紧；750 ⇒ **可以** ⇒ 定 750 |

**⇒ 三类取值互不相同（650 / 800 / 750）⇒ 「按类别选张开脉宽」有实据，必须做。**
（原先设想的"若三类同值就不做三值表"这条捷径 **不成立**。）

### 判定方法（现场）
- 把目标件放在**夹爪正下方**，从某档开始**逐档发脉宽**，每档保持 **12 秒**（`SERVO` 命令本身只保持 2 秒，需每 2.2 秒重发维持）。
- 判据 = **爪片与件的空隙**（目视）。**不用"刚好不碰"**：用户明确要求留余量，"能夹住、能跑起来"优先于"贴极限"。
- 板子侧取证：`SERVO PB10 P<值>` 回 `OK SERVO STARTING 2S`，运行中 `STATUS` 的 `SERVO_ACTIVE=1`、`SERVO_US=<值>`。

### 台架白名单
- 现值：`550 / 575 / 600 / 625 / 650 / 675 / 700 / 725 / 750 / 800 / 850 / 870 / 900 / 950 / 1000 / 1100 / 1200 / 1300 / 1500 / 1700 / 1900`（2026-09-21 分两次扩：先 650~725，再 550~625）。
- 白名单**两处必须同步**：`App/Src/ec_servo_test.c` 的 `is_allowed_pulse()` 与 `App/Src/ec_diag.c` 的命令表（`ec_diag.c:57` 自己写了这条）。

## 四、【实测】修复：`[WorkspaceLimits]` 用错了坐标系

### 症状
圆柱在画面里、也识别到了，**链就是不抓**（现场表现："看得见却抓不到"）。

### 根因
Pi 上 `calibration_config.ini` 的 `[WorkspaceLimits]` 写的是 **滑台行程** `±95 / ±97.5`，
却被当作 **装置坐标** 在用（`pixel_to_device` 的越界检查）。
⇒ 两头都错：
- `x_min = −95` **太松**：device x=−95 ⇒ 滑台 x=−215.5，**早已越过 HOME**；
- `x_max = +95` **太紧**：圆柱在 device x = 97.46 ⇒ **白白拒掉一件够得着的**。

### 正确值推导（用真实仿射矩阵算）
```
a11=0.047142  a12=-0.483206  tx=148.453
a21=-0.483206 a22=-0.047142  ty=52.105
x_mm = a11·u + a12·v + tx      y_mm = a21·u + a22·v + ty

夹爪够得着（滑台 x∈[−95,+85]、y∈[−97.5,+87.5]）+ (120.5, 43.5)
   ⇒ device x∈[+25.5, +205.5]  y∈[−54.0, +131.0]
相机可见（155.4mm 视场，仿射算四角）
   ⇒ device x∈[−5.7, +163.5]   y∈[−117.1, +52.1]
★ 交集 = device x∈[+25.5, +163.5]  y∈[−54.0, +52.1]
```

### 实际落盘值（被协议上限卡了一刀）
```ini
x_min = 25.5
x_max = 145.0     # ⚠️ 本应 163.5，但 pixel_to_device 的校验器把协议上限 ±145.0
y_min = -54.0     #    套在了【装置坐标】限制上 ⇒ 163.5 会被判"超出协议可序列化范围"
y_max = 52.1      #    ⇒ 整份标定作废、全部拒识。损失 device x∈(145,163.5] ≙ 滑台 x∈(24.5,43]
```
- 备份：`/home/pi/电控/calibration_config.ini.bak-wslimits-20260921-080223`
- **验证【实测】**：改前圆柱被拒；改后给出滑台 `(−23.1, −83.2)` ✅

### ⏳ 未解决
`pixel_to_device.py` 的校验器把**协议量程（管滑台坐标）**套在**装置坐标的工作区限制**上，
是"两套坐标系混用"的同一类病（和第四节根因同源）。要拿回那 18.5 mm 需改该校验器或重新对齐坐标系原点。
