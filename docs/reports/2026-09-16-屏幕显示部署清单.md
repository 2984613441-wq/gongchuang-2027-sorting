### 1.4 帧输出 `--frame-output`

| 项 | 值 |
|---|---|
| 目标值 | **`fb0`**（写 `/dev/fb0`） |
| 代码位置 | `run_chain.py:477-508` `build_frame_output()` |
| 默认值 | `auto` —— **有 `/dev/fb0` 用 fb0，否则 `none`（丢弃，只剩一行 INFO 日志）** |
| **树莓派上实际走哪条** | ❌ **未验证**，必须量 |

**两个具体失败模式（这是本任务发现的最高风险项）**：

1. **`/dev/fb0` 可能根本不存在。**
   新版 Raspberry Pi OS（Bookworm 起）默认用 KMS 驱动（`vc4-kms-v3d`），
   **不再提供 legacy fbdev 的 `/dev/fb0`**；老的 buster 镜像（随屏资料里那个
   `2021-10-18-raspbian-buster-full.7z`）通常有。
   → 如果不存在且用默认 `auto`：日志只打一行 `--frame-output auto -> none`，
   **不报错、不告警、屏幕全黑**，但 DISPLAY_ACK 照发（渲染"成功"了），
   **链路一路跑完，屏幕什么都没显示** → 触发「15 秒没有显示本次分拣信息，本轮比赛结束」。
   **这是最危险的一种：静默失败。**

2. **`/dev/fb0` 存在但 bpp 不等于 32。**
   `_to_framebuffer()` 直接 `fh.write(img.tobytes())`，**写的是 RGB888 原始字节**。
   帧缓冲若是 16bpp（RGB565），画面会**花掉/错位**，中文和图片全毁。
   `电控/deploy/README.md:198-200` 自己也把这条列为「待真机验证」。
   → 必须先量 `/sys/class/graphics/fb0/bits_per_pixel`。

**建议（本次不改代码）**：赛前确认 `/dev/fb0` 存在且 bpp=32 之后，
**显式写 `--frame-output fb0` 而不是 `auto`** —— 这样万一 `/dev/fb0` 没了，
是**当场报错**而不是**静默不显示**。

## 2. 图片从哪来？—— **没有真图，只有占位色块**

### 结论

> **占位图不算，赛题要的是货物图片。当前仓库里没有任何可用的货物图片。**

`build_image_loader()` 只有两条路（`run_chain.py:446-474`）：

- 给了 `--image-dir` → 读 `<image_id>.png/.jpg/...`（**需要 7 张真实文件，现在没有**）；
- 没给 `--image-dir` 且 `--fake-link` → `_demo_placeholder()`，
  生成 `Image.new("RGB", (200,200), ...)` —— **一块纯色方块，只用于开发冒烟**。

### 我试过用训练数据集凑，**验证后判定不可用**（证据留档）

仓库里唯一的真实照片是 MaixCAM 实拍数据集（`archive/datasets/raw-capture-2026-08-27/` 等，
546 张图 + YOLO 标注，7 类各有 40–119 个实例）。我写脚本按标注框裁剪，
**结果不可用**，三个硬证据：

1. **跨类撞车**：裁出来的 `0.png` 与 `6.png` **字节完全相同**（md5 `e684505a0a`），
   `4.png` 与 `5.png` 完全相同（md5 `2fdb33b407`）。
   原因是数据集里同一场景的**连续帧**被当成不同样本 —— 于是「五棱柱」和「四棱锥」
   会在屏幕上显示**同一张图** → 赛题「出现任何错误不得分」。
2. **糊到认不出形状**：按锐度+面积挑每类最好的一张拼成对照图，
   视觉复核结论是「**7 格中没有任何一格能确认出立体形状**，只有模糊色块」。
   证据：`docs/reports/2026-09-16-货物图片来源-数据集裁剪不可用.png`。
3. 数据集是**多目标场景图**（一张 448×448 里躺好几个块、带木桌背景），
   不是单件「货物目录图」，本来就不该直接上屏。

**该脚本与产物已删除**（`工具/make_cargo_images.py`、`电控/deploy/cargo_images/`）——
留着会让人误以为有图可用，而且它产的标签是错的。

### 那图片应该谁提供？

按可行性排序，**需要你决策**：

| 方案 | 谁做 | 说明 |
|---|---|---|
| **A. 赛前补拍（推荐）** | 人（机械组/你） | 7 个形状各拍 1 张干净单件照（白底、正对、光线均匀），直接命名 `0.png`…`6.png` 丢进 `/opt/ec-chain/images/`。**半小时的活，一次解决赛题「各种格式的图片播放」+「显示货物图片」两条**。顺带把 jpg/png/bmp 各存一份，正好演示"支持各种格式" |
| B. 从数据集里挑单帧手工裁 | 人 | 我已验证**自动裁不可用**；人工在 546 张里挑 7 张清晰单帧再裁，可能可行但费时且质量上限低 |
| C. 网上下载示意图 | 谁都不该做 | 形状/颜色对不上实物的风险极高，裁判一眼就能看出「货物图片」与实物不符 → 直接不得分 |

> 顺带一个附带风险：**`image_id == class_id` 是 1:1 冻结的，7 张必须齐**。
> 少一张 → `ImageLoadError`（fail-closed，该件不上屏）；而且这个异常**没有被 `_render_and_ack` 捕获**
> （`run_chain.py:669` 无 try/except），会把整个主循环带崩 —— 整轮结束，不只是跳过那一件。

## 3. 可复制的启动命令

参数名已逐个对着 `run_chain.py:338-411` 的 argparse 与 `--help` 输出核对过，**全部一致**。

```bash

  --port /dev/ttyAMA0 --baud 115200 \

  --names-file /opt/ec-chain/names.json \
```

说明：

- **`--font` 故意没写**：`resolve_font()` 会自动探测 wqy-zenhei 的标准路径，探不到会 warning。
  想显式固定就加 `--font /usr/share/fonts/truetype/wqy/wqy-zenhei/wqy-zenhei.ttc`。
- **`--start-round` 是必需的**：`run_chain.py:792` 只有 `args.start_round or demo` 才会
  `start_verified_new_round()`；不加则链路停在 `RECOVERY_LOCK`，
  **不派发任务、屏幕不动、什么都不发生**（`README.md:179-180` 也这么写）。
  > ⚠️ 面板「生成 run_chain 启动命令」按钮生成的命令里**没有 `--start-round`**，
  > 直接拿去真实模式跑会"静默不动"。要么加上这个开关，要么按赛题改造成操作员确认流程。
- **`-v`** 建议先带上：`--frame-output auto -> X` 这条关键日志是 INFO 级，
  `-v` 能把 `resolve_font`/`build_frame_output` 的决策过程看全。稳定后可去掉。
- 环境变量同名可用（`PORT/BAUD/IMAGE_DIR/FONT/NAMES_FILE/ROUND_ID/ROUND_TASK_ID/FRAME_OUTPUT`），
  `ec-chain.service` 用的就是环境变量那套。

## 6. 风险 / 阻塞 / 分歧声明

### 阻塞（要人或要授权）

| B4 | 字体/Pillow 是否已装未知 | 取决于 `install.sh` 有没有跑过；§4 一量就知道 |

### 风险（不用等人，但要知道）

- **R1（最高）**：`--frame-output auto` 在 `/dev/fb0` 不存在时**静默降级成 `none`** ——
  不报错、屏幕全黑、DISPLAY_ACK 照发、链路照跑完，直接触发「15 秒没显示 = 本轮结束」。
  **缓解**：赛前量 `/dev/fb0`，确认后显式写 `fb0`。
- **R2**：`fb0` 直写 RGB888，**bpp≠32 时画面是花的**（`README.md:198-200` 自认待验证）。
  **缓解**：量 `bits_per_pixel`；不是 32 就先别上 fb0，走 `file` 模式验证内容，bpp 适配另开一条（要改代码，需你批）。
- **R3**：`_render_and_ack()`（`run_chain.py:644-685`）**没有 try/except**。
  任何一件图片缺失（`ImageLoadError`）或 fb0 打不开，异常会穿出主循环，
  **把整条链路打崩 → 本轮结束**，而不是只跳过那一件。
  7 张图必须齐，或给这里加保护（**改代码，未做，等批**）。
- **R4**：名称表只按形状命名，同形状不同颜色同名。若裁判认为「货物名称」应含颜色 → 有不得分风险。
- **R5**：面板「生成 run_chain 启动命令」缺 `--start-round`，真实模式直接跑会"静默不动"（§3）。

### 分歧声明

1. **关于「正四面体」**：`06` 号文档 §3 记了这是用户裁决（= 我们的 `square_pyramid`），
   我按裁决执行（名称表第 5 项就是「四棱锥」），**不重复提异议**。
   仅重申一次现场动作：**拿到实物看底面** —— 正方形=四棱锥（认得出），三角形=三棱锥（7 类里没有，会分错盒 = 零分）。
2. **关于把异常收进 `_render_and_ack`（R3）**：我认为显示失败应该"该件不上屏 + 记日志 + 上报"，
   而不是把整条链路打崩（崩了就是本轮结束，比少显示一件更惨）。
   但这是**改代码**，且涉及失败语义（`07` 号任务的地盘），**本节点不动**，交你裁决。
