# 二、为什么不用 ToF 做形状消歧

## 2.1 冻结类别清单（`交付-给标注同学-20261018/class.txt`）

```
0 cube              立方体
1 cuboid            长方体   ← ACTIVE_CLASS_IDS={0,2,3,4,5,6} 已排除
2 cylinder          圆柱
3 hexagonal_prism   六棱柱
4 pentagonal_prism  五棱柱
5 square_pyramid    四棱锥
6 triangular_prism  三棱柱
```

**预留槽位**：`sphere`（球）、`regular_tetrahedron`（正四面体）—— 本轮不采集。

## 2.2 `depth_fusion.py` 的三个歧义组与本轮物料的关系

| 歧义组 | 需要的形状 | 本轮是否涉及 | ToF 是否有效 |
|---|---|---|---|
| 圆柱 vs 球 | cylinder + **sphere** | ❌ 球本轮不做 | （未测，预计有效） |
| 三棱柱 vs 正四面体 | triangular_prism + **tetrahedron** | ❌ 四面体本轮不做 | （未测，预计失效） |
| **立方体 vs 四棱锥** | cube + square_pyramid | ✅ **都涉及** | ❌ **实测失效** |

## 2.3 立方体 vs 四棱锥 为何失效（双重原因）

**原因一：四棱锥的斜面把激光反射走，接收端无回波**

| 物体 | ToF 命中率 | 说明 |
|---|---|---|
| 立方体（平顶） | **100%（11/11）** | 顶面垂直反射，光原路返回 |
| 四棱锥（斜面） | **11%（3/16）** | 斜面镜面反射，光被反射到侧面 |

**原因二：两者高度几乎相同，ratio 判据分不开**

| 物料 | ToF 实测高度 |
|---|---|
| 立方体 | **17 mm** |
| 四棱锥 | **20 mm**（仅 3 次有效样本的中位数） |

`depth_fusion.py` 的判据是 `height_ratio = 高度 / 底宽`：
- 立方体要求 `0.9 ~ 1.1`
- 四棱锥要求 `≤ 0.6`

**⇒ 高度差只有 3mm，唯一区分依据只剩"底宽"，需靠相机测；且四棱锥 87% 测不到高度，判据无法稳定执行。**

**⇒ 改用图像特征（`视觉/src/sorting_vision/shape_features.py`）判形状**：
俯视时四棱锥可见 4 个三角面与尖顶的明暗过渡，立方体顶面是一个平的正方形 —— 图像特征比 ToF 更可靠。

# 三、本轮 ToF 实测数据

## 3.1 测量条件（**必须遵守**）

| 项 | 值 |
|---|---|
| 测量位置 | 机械臂 **X +100mm、Y = 0**（托盘正上方） |
| 参考距离（空托盘） | **179.0 mm**（14 次，极差 15mm、std 5.89mm） |
| 换算公式 | `物料高度 = 179 − ToF读数` |

### ⚠️ 三个致命前提

1. **运动原点不能用** —— 那里有空隙，ToF 看穿到转盘下面（读数 341mm，非托盘面）
2. **每次测量前必须复位到运动原点再移动** —— 否则不知道 ToF 在哪个物理位置，也就不知道它下方是什么
3. **ToF 相对夹爪中心偏移**：**+Y 方向约 30mm** ⇒ 测物块要放在 ToF 正下方，不是夹爪正下方

## 3.2 三种物料实测

| 物料 | 姿态 | ToF 读数（中位） | **高度** | 可靠性 |
|---|---|---|---|---|
| **立方体** | 正放 | 153 mm | **17 mm** | ✅ 100%（11/11） |
| **三棱柱** | 侧棱朝上（俯视矩形） | 158.5 mm | **11.5 ~ 16 mm** | ⚠️ 中（极差 29mm） |
| **四棱锥** | 棱边朝上 | 159 mm | **20 mm** | ❌ 仅 11%（3/16） |

## 3.3 读数毛刺：**21%**

| 现象 | 说明 |
|---|---|
| 偶发 ~966~1436mm | 占约 21%，**其中部分置信度仍为 100** |
| **不能只靠置信度过滤** | 必须按物理范围过滤 |

**生产代码必须这样过滤：**

```python
# 已知参考距离 REF，物料高度不可能超过 100mm
LO, HI = REF - 100, REF + 30
valid = [d for d in readings if LO <= d <= HI]
if len(valid) >= 3:
    height = REF - statistics.median(valid)
else:
    height = None   # 无有效读数，走兜底策略
```

# 四、ToF 的能力边界（总结）

| 目标表面 | ToF 表现 | 举例 |
|---|---|---|
| **平面、垂直于光束** | ✅ **100% 可靠** | 立方体顶面、圆柱顶面、托盘面 |
| **曲面（顶点垂直入射）** | ✅ 预计可靠 | 球顶（未实测） |
| **斜面 / 尖顶 / 脊线** | ❌ **11~87% 无回波** | 四棱锥、正四面体、三棱柱侧棱朝上 |
| **下方为空** | 输出 ~1000mm（打到远处地面） | 不是故障 |

**⇒ ToF 只适合测"平顶物体"的高度。**

# 五、本轮修好的东西

## 5.1 ToF 通信完全修复

```c
/* App/Inc/ec_tof.h */
- #define EC_TOF_CONF_MAX   62U
+ #define EC_TOF_CONF_MAX   100U
```

**根因**：协议文档（v2025）写"置信度 0~62"，但**模块实际输出 0~100**。
固件按 62 上限校验 ⇒ 每帧被判"超出范围"丢弃 ⇒ 表现为
`errors` 狂涨、`frames` 不动、`age_ms` 一直增大（看着像没数据）。

**修复后**：`valid=1`、`errors` 冻结、`uart_err=0`、`age_ms=1~10ms`。

## 5.2 新增 `TOFRAW` 诊断命令

```
TOFRAW n=64 hex=20 31 38 38 2C 20 31 30 30 0A ...
TOFREJ reason=4 line=[191, 100]
```

| 原因码 | 含义 |
|---|---|
| 1 | 行内找不到逗号 |
| 2 | 距离解析失败 |
| 3 | 置信度解析失败 |
| 4 | 超出范围 |
| 5 | 行超长 |

**这个命令是定位"92% 解析失败"的关键** —— 没有它只能靠猜。

**改动文件**：
- `App/Inc/ec_tof.h`：新增 `EC_TOF_LINE_MAX`、`ec_tof_raw_ring()`、`ec_tof_last_reject()`
- `App/Src/ec_tof.c`：新增 64 字节原始环形缓冲 + 被拒行记录，`reject()` 取代裸 `s_errors++`
- `App/Src/ec_diag.c`：新增 `TOFRAW` 命令、HELP 更新
- `tests/test_diag.c` / `test_diag_disabled.c`：补对应桩

**主机测试 7/7 通过。**

## 5.3 定位一个真实 bug（尚未修复）

```c
ec_ws2812_send_grb() 为生成 WS2812 时序，关中断约 480µs
115200 波特率下 1 字节 = 87µs
⇒ 每发一次 LIGHT 命令，丢约 5 个 ToF 字节
```

**证据**：`TOFREJ reason=1 line=[183100]` —— `" 183, 100"` 丢了 `,` 和空格。

**修复方向**（待办）：WS2812 发送期间用 **DMA + 定时器**，或在 ToF 解析层容忍丢字节，或发灯命令时暂停 ToF 采集。

# 七、复测方法（以后要重做时照做）

```
前置：
  ① 断电 → 手推到运动原点（XY 最负角）→ 上电
  ② 上电后先 `PING` / `TOF` 确认通信
  ③ 确认补光灯已开（LIGHT LV 255 + LIGHT ON）

测量：
  ① 只往【正方向】移动：MOVE X DIR0 STEPS 8000（+100mm，到托盘上方）
  ② 确认空托盘参考距离：连读 14 次 → 期望 ~179mm（若差异大，以实测为准）
  ③ 放物料到 ToF 正下方（夹爪 +Y 3cm 处）
  ④ 连读 16 次 → 按物理范围过滤 → 取中位数 → `高度 = REF − 中位数`

⚠️ 安全：
  · 从运动原点出发【只往正方向走】，绝不发负方向指令
  · Y 轴任何负方向移动前必须先确认离原点足够远
  · 每次移动前说明方向、距离、是否会撞限位
```

# 八、本轮事故记录（教训）

## 8.1 碰撞事故（2026-10-18）

**经过**：复位后机械臂位于 Y 轴原点（最负端、顶住硬限位），AI 仍向 Y 负方向（`MOVE Y DIR1`）发 30mm 扫描指令 ⇒ 顶到硬限位碰撞。

**根因**：明知"运动原点 = XY 最负角"，仍向负方向发指令。

**处置**：立即 `STOP ALL` + `STEP STOP`，用户断电，检查无损坏后重新归零。

**三条新规矩（后续必须遵守）**：
1. **从原点出发只往正方向走**，绝不发负方向指令
2. 每次移动前**明确说明方向、距离、是否会撞限位**
3. **Y 轴凡涉及负方向，一律先问用户**

## 8.2 误判记录（避免以后重走）

| 误判 | 真相 |
|---|---|
| "ToF 倾斜导致多回波" | 下方为空，打到 1 米外地面，属正常 |
| "塑料对 940nm 透红外" | 不是主要原因；真正原因是斜面反射 |
| "补光灯干扰" | 关灯后读数不变，排除 |
| "传感器损坏" | 复位到原点后稳定读到 341mm（近目标），正常 |
| "341mm 是托盘面" | 那是空隙看穿后的读数，托盘面是 179mm |

**共同教训：不知道机械臂在哪个物理位置时，任何 ToF 读数都无法解释。**
