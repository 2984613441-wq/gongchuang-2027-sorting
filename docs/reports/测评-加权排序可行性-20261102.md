# 测评报告：加权排序方案可行性（离线仿真）— 2026-11-02

> 用户要求：「不是你要先测评一下这个方案的可行性再改」。
> 本文是**先测评**的产物：用真实代码（`order_by_weighted` + demo 配置）跑 300 帧离线仿真，
> 量化评估稳定性、与「先易后难」的冲突、行程代价、对未实测参数的敏感性。
> 结论：**GO（有条件）** —— 但必须加一条「难件不得排首位」护栏，且必须先实机确认前端轴。

---

## 一、测评方法（可复现）

脚本：`工具/eval_weighted_order.py`（离线、不碰硬件）

```
帧数 300，每帧 6 件（随机形状 1..6、随机位置、置信度 70..96）
配置：电控/deploy/pick_strategy.demo.ini（open_side = y_max，tool_offset 等按 demo）
对比口径：weighted / order_by_group_scan（旧口径）/ order_by_row_scan / 贪心就近
```

指标定义：

| 指标 | 含义 |
|---|---|
| 首位变化率 | 权重 ±0.1 扰动后，首件是否变（越小越稳）|
| Kendall τ | 顺序一致性（-1..1，1=完全同序）|
| 难件首位率 | 首件是 tier≥1（圆柱/圆锥）的比例 → 与「先易后难」的冲突度 |
| 总行程 | home→pick→drop→pick…→drop 的累计 mm |
| X 横跳率 | 相邻两件分居 home 两侧的比例（来回横跳）|

## 二、核心结果

### 2.1 稳定性：**优**

| 指标 | 值 | 判读 |
|---|---|---|
| 权重 ±0.1 后首位变化率 | **4.38 %** | 稳 |
| 权重 ±0.1 后 Kendall τ 平均 | **0.952** | 顺序几乎不变 |

⇒ 权重不必调得极精细，±0.1 的误差不会让顺序翻盘。

### 2.2 与「先易后难」的冲突：**存在，且可消除**

默认权重 A（0.70/0.15/0.10/0.05）下，**10.33 % 的帧首件是难件**（圆柱/圆锥）。
原因：前端权重占 0.70，若某件难件恰好最靠前，就会被排第一 —— 这是「前端最先」与「先易后难」的**真实冲突**。

不同权重与护栏的效果（300 帧）：

| 权重方案 | 难件首位率 | 总行程 mm | τ vs 旧口径 |
|---|---|---|---|
| A 0.70/0.15/0.10/0.05（原始）| **10.33 %** | 1164.5 | 0.3502 |
| A + 护栏 | **0.00 %** | 1158.9 | 0.3649 |
| C 0.60/0.25/0.10/0.05（原始）| 3.00 % | 1160.1 | 0.4827 |
| C + 护栏 | 0.00 % | 1158.3 | 0.4867 |
| B 0.55/0.30/0.10/0.05（原始）| 1.67 % | 1159.3 | 0.5436 |
| B + 护栏 | 0.00 % | 1157.9 | 0.5458 |

**护栏定义**：若排序后首件是 tier≥1（圆柱/圆锥），把它与序列中**第一个 tier=0 的件交换**。
效果：难件首位率 **10.33 % → 0 %**，且**总行程还略降**（因为首件更容易落在 home 附近）。

### 2.3 行程代价：**比旧口径多 4.3 %，比贪心多 19 %**

| 口径 | 总行程 mm（6 件均值）| 相对贪心 |
|---|---|---|
| 贪心就近（现状近似）| 975.6 | 0 % |
| 旧口径（group）| 1116.0 | +14.4 % |
| 行扫描 | 1159.6 | +18.9 % |
| **weighted A + 护栏** | **1158.9** | +18.8 % |

判读：加权排序比「旧口径」多 **+4.3 %** 行程（约 43 mm/帧/6件），比贪心多 18.8 %。
**但换来的是一致的前端优先 + 好夹优先**；是否值得取决于实测节拍余量（未测）。

### 2.4 横跳：**无**

相邻两件分居 home 两侧的比例 **0.00 %** ⇒ 不会出现「左一件右一件」的来回走。

### 2.5 对未实测参数的敏感性：**极高（最大风险）**

把 `front` 权重置 0 后，与默认方案的顺序一致性 τ = **−0.055**（几乎完全无关）。
说明 **front 项主导了整个排序**，而 front 依赖：

- `[Tray] open_side = y_max`（demo 里标【待实测】）
- 相机朝向/装位（前端到底是画面哪一侧）

⇒ **这两个没实测前，加权排序不可上实机**：装错一侧，整份顺序就是错的。

## 三、结论与条件

### 结论：GO（有条件）

| # | 条件 | 状态 |
|---|---|---|
| 1 | 加「**难件不得排首位**」护栏（默认开） | 本次实现 |
| 2 | 实机确认 `[Tray] open_side` 与相机前端轴 | **未做**（阻塞上机）|
| 3 | 台架空跑对比 weighted vs group，确认无来回跳/超时 | **未做** |
| 4 | 实测节拍余量，确认 +4.3 % 行程可接受 | **未做** |

### 不满足条件 2 的后果（已量化）

τ = −0.055 ⇒ 顺序与设计意图几乎无关，等于白开。

## 五、方法局限（如实登记）

1. 仿真用的是**随机几何**，不是真实托盘摆位/真实检测噪声
2. 未模拟**多帧停稳**（停稳在加权排序里是更高一级条件，仿真未含）
3. 行程只算 XY，**没算转盘换挡与 Z 轴升降**时间
4. 置信度用随机整数，不是真实 YOLO 输出分布
5. 300 帧 × 6 件 = 1800 次排序，样本够看趋势，但不足以定权重最终值
