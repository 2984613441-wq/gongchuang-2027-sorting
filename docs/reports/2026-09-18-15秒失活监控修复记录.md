# STM32 15 秒失活监控修复记录

日期：2026-09-18

范围：STM32 主机侧纯逻辑、主机构建和 Keil 编译证据。未接线、未上电、未烧录，本文不把主机或 Keil 结果表述为固件实机通过。

## 1. 规则语义和风险判断

赛规 R-R04（`27年工创.pdf` 第 12 页）规定：“超过 15 秒装置没有动作，或没有显示本次分拣信息，本轮比赛结束。”`电控/资料/要求汇总.md:230` 和 `:276` 将其冻结为滚动静默窗口：只有经台架验证、对应可观察动作的执行器输出进展，以及本件界面完成渲染后的首次 `DISPLAY_ACK` 可以更新时间基准；心跳、日志、重复应答、通信重传、重新请求视觉结果和同一界面重复刷新均不得重置。

本次代码把“单轴计数动作自然完成”接成**条件式适配源**，但当前没有找到 `HIL-PROGRESS-001` 或同等台架记录，不能证明开环 STEP/DIR 计数完成本身就是赛规认可的“可观察动作”。已有审查记录 `工具/_review_v4.txt:1027-1043` 还明确区分了“电机转动等机械级可观察动作”和“脉冲发送、步数计数、内存状态”。因此生产 Keil Define 保持 `EC_APP_PROGRESS_SOURCE_ENABLED=0`，正式固件仍 fail-closed；不能据此宣称已经完成实机合规。

启用前的替代验证方案是：接入编码器、到位/位置反馈、限位反馈等可观察信号，或形成正式台架记录，证明对应执行器完成事件在装置外部可观察；取得证据后才允许在专用生产构建中将宏改为 `1`，并显式打开 runtime gate。

## 2. 代码改动

### 2.1 App 接线和令牌语义

- `App/Inc/ec_app.h:9-36`：声明 `EC_APP_PROGRESS_SOURCE_ENABLED`，默认值为 `0U`；增加令牌 API 和 runtime gate API。宏为 0 时两条 API 都是硬 no-op。
- `App/Src/ec_app.c:121-146`：令牌路径同时要求编译期开关、runtime gate 和 `watchdog_active`；令牌必须严格大于历史令牌，重复/更旧令牌直接丢弃。窗口未打开时令牌不能开窗。
- `App/Src/ec_app.c:498-519`：在执行器 `poll` 前后取完成计数快照；只有计数因真实自然完成而增加时才调用 `ec_app_note_observable_progress()`。心跳、日志、应答、重传和重复 `DISPLAY_ACK` 没有调用路径。
- `App/Src/ec_app.c:551-571`：看门狗检查移到执行器 poll 和完成令牌处理之后，边界上的真实完成优先于 `15000 ms` 判定；仍使用原值 `UINT32_C(15000)`，没有放大赛规窗口。
- `App/Src/ec_app.c:220-230`：首次有效 `DISPLAY_ACK` 只关闭当前窗口；`MOTION_DONE` 不清零、不重启、不延长窗口。
- `App/Src/ec_app.c:576-593`：初始化轴驱动；新运动窗口不清除进程单调令牌历史，旧 token 不能跨件续期。

### 2.2 真实完成事件来源

- `App/Src/ec_axis_driver.c:27,345-355,377-405`：增加 `completed_move_count`，只在消费端口自然完成锁存时递增；abort、timeout、stop、servo settle 和仅计数归零均不递增。计数保持单调，供 App 产生 token。
- `App/Inc/ec_step_test.h:96-102`、`App/Src/ec_board_stm32.c:53-58,700-733`：定时器 ISR/安全路径发布一次性自然完成或 abort latch，主循环原子消费。`remaining == 0` 不再单独作为完成证据。
- 未修改 `EC_STEP` / `MOVE` / `SERVO` 命令字或 wire 格式，未新增协议帧，未修改 `EC_AXIS_MOVE_TIMEOUT_MARGIN_MS`，未修改运动计划。

## 6. 31.5 秒路径说明

本任务给出的梯形速度参数为起步/停止 `200 Hz`、巡航 `2000 Hz`、加减速度 `5000 Hz·s^-1`。单段在达到巡航速度时的计算为：

```text
t_ramp = (2000 - 200) / 5000 = 0.36 s
N_ramp_each = (200 + 2000) / 2 × 0.36 = 396 steps
t_segment = 2 × 0.36 + (N - 2 × 396) / 2000
```

按任务提供的最坏运动路径逐段代入当前 profile，最长单段约 `7.7 s`，8 步 pick-place 路径合计约 `31.5 s`；这说明原先只在运动开始设置一次基准时，会在约 `15 s` 处把仍在动作中的路径误判为 `DEADLINE_EXPIRED`。接入**已被 HIL 证明可观察**的自然完成令牌后，每个真实完成事件重新设置滚动基准，且最长单段约 `7.7 s < 15 s`，所以在该计算模型下不存在连续 15 秒无令牌的窗口，整条约 `31.5 s` 路径不会因静默 watchdog 中断。

这个结论是 profile 计算的条件结论，不是实机测量结论；若实际输出未被外部观察，或台架测得某段超过 15 秒，必须先修正可观察源/运动参数并重新留证，不能通过把 `15000` 改大来规避赛规。

## 7. 验收结论

- 代码、主机测试和 Keil 0 error/0 warning 证据已保留。
- 令牌的去重、窗口 gate、通信事件排除和编译期开关 0 的硬 no-op 已覆盖。
- 当前生产构建仍关闭进展源；缺少 `HIL-PROGRESS-001`，因此本记录不宣称“实机已满足赛规”。
