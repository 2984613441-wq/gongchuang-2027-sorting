## 1. 三处必须的改动（缺一不可）

| # | 文件 | 行 | 原值 | **新值** |
|---|------|----|------|---------|
| 1 | `Core/Inc/stm32f4xx_hal_conf.h` | 99 | `#define HSE_VALUE 25000000U` | **`8000000U`** |
| 2 | `Core/Src/main.c` | 253 | `RCC_OscInitStruct.PLL.PLLM = 25U;` | **`8U`** |
| 3 | `Core/Src/system_stm32f4xx.c` | 51 | `#define HSE_VALUE ((uint32_t)25000000)` | **`((uint32_t)8000000)`** |

### 为什么第 3 处容易被漏掉

`system_stm32f4xx.c` **不包含** `stm32f4xx_hal_conf.h`，它自己有一份 `#if !defined (HSE_VALUE)` 的默认值。只改第 1 处的话：
- 硬件时钟会变对（PLL 按 PLLM=8 配置）
- 但 `SystemCoreClockUpdate()` 仍按 25 MHz 反算 → `SystemCoreClock` 错成 525 MHz

**不改第 3 处的后果是可观测的**：`AXIS` 报的 `TICK_MS` 与真实时间对不上。

### 其余参数一个都不要动

`8 MHz ÷ PLLM(8) = 1 MHz`，与原来 `25 MHz ÷ PLLM(25) = 1 MHz` 的 **PLL 输入完全相同**，所以下面这些保持原值即得 168 MHz：

```
PLLN = 336      1 MHz × 336 = 336 MHz (VCO)
PLLP = DIV2     336 / 2     = 168 MHz (SYSCLK)
PLLQ = 7        336 / 7     = 48 MHz
AHB  = DIV1     HCLK  = 168 MHz
APB1 = DIV4     PCLK1 =  42 MHz
APB2 = DIV2     PCLK2 =  84 MHz
```

因为 PCLK1/PCLK2 不变，**所有定时器预分频（TIM2 50Hz、TIM3 50Hz、TIM4=839、TIM8=1679 等）自动恢复正确，无需同步改动**。

### ⚠️ 不要用 CubeMX 重新生成代码

`.ioc` 落后于源码（`RCC.HSE_VALUE` 仍是 25000000），用 CubeMX 重新生成会覆盖手改的 168MHz、PWM 预分频、USART3 的 PB10 迁移等。

## 2. 根因与证据（供你复核，不是推测）

### 2.1 两个独立的"3.125 倍"指向同一根因

| 观测量 | 代码意图 | 实测 | 比值 |
|---|---|---|---|
| USART2 波特率 | 115200 | **实际约 38400**（在 Pi 侧按 38400 打开才读到合法 ASCII） | 3.0 |
| `STATUS` 心跳间隔 | 1000 ms | **平均 3.0748 s**（8 个间隔，min 3.0031 / max 3.5038） | 3.07 |

单个 3 倍可能是巧合，两个**互不相关的时间基准**同时偏 3 倍 ⇒ 只能是 MCU 主频错。

### 2.2 计算完全吻合

板上 HSE 晶振实为 **8 MHz**，而代码按 **25 MHz** 配置：

```
实际 SYSCLK = 168 × (8/25) = 53.76 MHz
相对 168 MHz = 1/3.125
```

- USART2：PCLK1 声明 42 MHz 实际 13.44 MHz ⇒ 115200 × (13.44/42) = **36864**（≈38400 档位）✓
- HAL_GetTick：SysTick 按 168 MHz 配 1 ms，实际 53.76 MHz ⇒ 1.000 s 走成 **3.125 s** ✓

### 2.3 修复后的三项验证（全部通过）

| 检查项 | 实测 | 判定 |
|---|---|---|
| 时基：`TICK_MS` 增量 vs 真实时间 | 11.123 s / 11.120 s = **1.0003** | ✅ |
| `STATUS` 间隔 | 平均 **1.0011 s** | ✅ |
| 波特率 115200 下文本 | `STATUS ...` / `OK PONG` 完全可读 | ✅ |

三项同时对上，才说明 168 MHz 真跑起来了（单看波特率不够，因为波特率只依赖 PCLK1）。

### 2.4 修复前的连带影响（说明这个 bug 的严重性）

| 子系统 | 应为 | 实际 | 后果 |
|---|---|---|---|
| USART2（Pi 主链路） | 115200 | ≈36864 | 生产链**一个字节都收不到** |
| UART4（PC10/PC11 ToF） | 115200 | ≈36864 | **ToF 完全不可用** |

## 3. 新发现①：`MOVE` 的 `HZ` 参数基本不生效

**位置**：`App/Src/ec_board_stm32.c:345-349`

```c
/* Plan trapezoidal velocity profile: start 200 Hz -> cruise 2000 Hz -> end
 * 200 Hz, accel/decel 5000 Hz/s. Conservative values; tune on-site for
 * faster throughput. Falls back to constant frequency_hz when planning
 * fails (moves too short for accel/decel). */
if (start_axis_counted(axis, steps, frequency_hz, &step_profile) == NULL) {
```

**结论**：正常路径使用**硬编码梯形曲线**（起步 200 Hz → 巡航 **2000 Hz** → 收尾 200 Hz，加减速 5000 Hz/s）。命令行传入的 `HZ` **只在曲线规划失败时作为回退值**。

**实测印证**（4 组不同 HZ 全部收敛到约 2000 步/秒）：

| 命令 HZ | 步数 | 按 HZ 理论 | 按 2000Hz 理论 | 实测 |
|---|---|---|---|---|
| 500 | 800 | 1.60 s | 0.40 s | 快，肉眼易错过 |
| 500 | 1600 | 3.20 s | 0.80 s | ~0.96 s |
| 100 | 2400 | 24.0 s | 1.20 s | ~1.2 s（`REMAIN` 2400→114 @1.1s） |
| 100 | 1000 | 10.0 s | 0.50 s | <0.58 s |

⇒ 实际固定 **2000 步/秒 = 25 mm/s**（80 steps/mm）。

**影响**：定位不受影响（步数是绝对值）；但
- 项目里用 `HZ` 调速度**会白调**
- `sorting_config.ini [Motion]` 的速度倍率可能同样失效（需你确认是否走同一条路径）

**建议**：要么把 `frequency_hz` 接进曲线参数，要么在文档里明确标注"仅回退值"。

## 6. 🔴 新发现③：转盘舵机型号与驱动方式**不匹配**（需尽快确认）

用户提供的转盘资料：`101090142_Feetech_ST-3215-C046_Datasheet.pdf`

**手册明确写的**：

| 项 | 值 |
|---|---|
| 型号 | ST-3215-C046（7.4V，1:147，磁编码，双轴） |
| **控制信号** | **Digital Packet** |
| **协议类型** | **Half Duplex Asynchronous Serial Communication，8bit、1stop、No Parity** |
| 通讯波特率 | **38400 bps ~ 1 Mbps（出厂默认 1 Mbps）** |
| 旋转角度 | 360°（0~4095） |
| 分辨率 | 0.088°/pulse（360°/4096） |
| 中位 | 2048 |
| 运行模式 | 模式0 角度伺服 / 模式1 速度闭环 / 模式2 速度开环 / 模式3 步进 — **全是串行总线模式** |

**矛盾点**：手册中**没有任何 PWM/脉宽输入模式**，它是纯 TTL 串行总线舵机。
但当前项目是用 `pi_pw.py` + `pigpio.set_servo_pulsewidth(GPIO18, 845..2155)` 即**普通 PWM 脉宽**在驱动它。

**这两种方式不兼容** ⇒ 若转盘确实是 ST-3215，则写 `pw.txt` **不会让舵机转动**。

### ✅ 2026-10-17 已实测确认：PWM 驱动对它完全无效

现场验证过程：
1. `pi_pw.py`（PID 491）确认运行中，`pigpio` 正常
2. 下发序列 `1500 → 845 → 2155 → 1500`（含一次 A→B **180° 大幅甩动**），`~/logs/pw.log` 逐条确认已输出
3. **舵机有独立供电**，但**纹丝不动**

⇒ **确认转盘装的就是 ST-3215 串行总线舵机，当前 PWM 路径（GPIO18 脉宽）无效。**

⇒ `sorting_config.ini:172` 那条"2026-09-21 现场实测 845µs=A 侧 / 2155µs=B 侧"是用**另一个普通 PWM 舵机**测的，**口径对本机已失效**。

### 当前硬件缺口（Pi 实测）

| 检查 | 结果 |
|---|---|
| `/dev/ttyUSB*` / `/dev/ttyACM*` | **不存在** |
| `lsusb` | 只有根 hub + VIA hub，**无 USB 转串口芯片** |

### 角度 ↔ 位置值换算（ST-3215：360° / 4096 计数，中位 2048）

**每 90° = 1024 计数**

| 货格侧 | 角度 | **ST-3215 position** |
|---|---|---|
| A 侧 | −90° | **1024** |
| 中位 | 0° | **2048** |
| B 侧 | +90° | **3072** |
| A↔B | 180° | 差 **2048** |

与旧标定"两侧相差 180°"吻合 ✓（但**哪一侧是 1024、哪一侧是 3072 必须装机实测确认**，因为手册写 0→4095 为顺时针）。

### ✅ 2026-10-17 深夜：已打通并完成实测（方案 A 走通，无需 STM32 参与）

**硬件链路**：树莓派 UART2 (`/dev/ttyAMA1`, GPIO0/GPIO1) → 微雪 Bus Servo Adapter (A) 的 **3 芯 UART 口** → ST-3215

#### 🔴 关键接线（踩了近两小时，务必记住）

```
能用的接法（同名直连）：   Pi 物理27脚 (GPIO0/TXD2)  ── 转换板 TX
                          Pi 物理28脚 (GPIO1/RXD2)  ── 转换板 RX
                          Pi GND (30/25/39 任一脚)  ── 转换板 GND
```

**⚠️ 这块板不是常规交叉接法！** 按惯例接成"Pi27→板RX，Pi28←板TX"时**完全无响应（0 字节）**；改成同名直连后立刻通。
其他已排除项：逻辑电平实测 **3.3V**（非 5V）、转换板 LED 亮、舵机 LED 亮且有扭矩、跳帽置于串口侧。

#### 协议参数（实测确认）

| 项 | 值 |
|---|---|
| 舵机 ID | **1** |
| 波特率 | **1,000,000 (1 Mbps)** |
| 帧格式 | `FF FF ID LENGTH INST PARAM... CHECKSUM` |
| LENGTH 定义 | **参数个数 + 2** |
| CHECKSUM | `~(ID + LENGTH + INST + PARAM...) & 0xFF` |
| 目标位置 | 地址 **0x2A**，2 字节小端 |
| 目标时间 | 地址 **0x2C**，2 字节小端（毫秒，用于限速） |
| 当前位置 | 地址 **0x38**，2 字节小端 |
| 位置范围 | 0~4095 对应 0~360° |

**PING 实测响应**：`FF FF 01 02 00 FC`（ERROR=0，无故障）

#### 标定值（**替代**旧的 `center_us` / `us_per_90deg`）

| 位置 | 位置值 | 角度 |
|---|---|---|
| **A 侧** | **1024** | −90° |
| **中位** | **2048** | 0° |
| **B 侧** | **3072** | +90° |
| A↔B | 差 **2048** | 180° |

换算关系：**每 90° = 1024 计数**（4096/360 = 11.38 计数/度）

#### 实测精度（四次 90° 动作）

| 目标 | 到位 | 误差 |
|---|---|---|
| 1024 | 1033 | +9 |
| 2048 | 2039 | −9 |
| 3072 | 3065 | −7 |
| 2048 | 2054 | +6 |

到位误差均 **≤9 计数（≤0.8°）**，重复性良好。存在约 **−7 计数（−0.6°）** 的固定偏移，不影响使用。
用"目标时间 1500ms"可稳定限速，实测严格按 1.5 秒到位。

### 11.4 `pi_turntable.py` 接口（供 `run_chain.py` 集成）

```bash

```

退出码：`0` 成功 / `1` 串口打不开 / `2` 舵机无响应 / `3` 未到位 / `4` 参数错

**集成建议（最小改动）**：`run_chain.py` 里原来"写 `/home/pi/pw.txt`"的转盘调用，直接换成：

```python
subprocess.run(["python3", "/home/pi/pi_turntable.py", side], check=True, timeout=8)
```

其中 `side` 为 `"A"` / `"B"` / `"C"`。
