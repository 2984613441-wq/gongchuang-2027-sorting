# 二、数据集标注

## 2.1 自动预标（用仓库现有 7 类旧模型）

仓库已有 `视觉/models/yolo5s_geom7c_opset13.onnx`（7 类、448×448、YOLOv8 输出格式）。

**新写脚本** `_turntable-edit/autolabel.py`：
- 448×448 letterbox + RGB/255 归一化
- YOLOv8 输出解码 `[1, 11, 4116]` → 转置 `[4116, 11]`（4 框 + 7 类分数，无 objectness）
- **逐类别 NMS + 跨类别 NMS**
- **翻转 TTA**（原图 + 水平翻转，合并后再 NMS）
- 断点续跑、损坏图片跳过

## 2.2 修掉的两个质量问题

| 问题 | 现象 | 修复 |
|---|---|---|
| **同类重复框** | 同一物体被标两次（类别不同，框几乎重合） | 加**跨类别 NMS** ⇒ 框数 2098 → 1793 |
| **漏检** | 黄色长方体、橙色圆柱/四棱锥经常漏 | **翻转 TTA + 阈值 0.20→0.12** ⇒ 框数 1793 → **2025**，零检出图 308 → **232** |

# 五、cvimodel 转换

## 5.1 环境（全部在本机完成，无需 Docker）

| 组件 | 版本 |
|---|---|
| WSL Ubuntu | 22.04.1 |
| tpu-mlir | **1.30.2** |
| torch (WSL) | 2.14.1+cpu |
| numpy (WSL) | 1.24.3（tpu-mlir 强制要求） |
| onnx | 1.14.1 |
| onnxsim | 最新 |

## 5.2 环境踩的坑（已在脚本里记录）

| 坑 | 解决 |
|---|---|
| `python3-venv` 缺失，建不了 venv | 直接用 `pip --user` |
| numpy 2.x 与 tpu-mlir 冲突 | 降到 **1.24.3** |
| 装 onnx 会把 numpy 又升回 2.x | **`pip install --no-deps`** |
| `cv2` 是 numpy1.x 编译的 | 降 numpy 后自动可用 |
| 缺 `torch` / `onnxsim` | 分别补装 |

## 5.3 三步转换命令

```bash
# 1) ONNX -> MLIR
model_transform.py --model_name yolo11n_8c_448 \
  --model_def yolo11n_8c_448.onnx \
  --input_shapes "[[1,3,448,448]]" \
  --mean 0,0,0 --scale 0.00392156862745098,0.00392156862745098,0.00392156862745098 \
  --pixel_format rgb --mlir yolo11n_8c_448.mlir

# 2) 量化标定（用 100 张验证集图）
run_calibration.py yolo11n_8c_448.mlir --dataset calib --input_num 100 -o cali_table

# 3) 导出 cvimodel（MaixCAM = cv181x）
model_deploy.py --mlir yolo11n_8c_448.mlir --calibration_table cali_table \
  --chip cv181x --quantize INT8 --model yolo11n_8c_448_cv181x.cvimodel
```

**脚本已保存到 `_deploy_maixcam/convert_cvimodel.sh`。**

## 6.3 验证脚本（MaixPy）

```python
from maix import camera, display, nn, time

detector = nn.YOLO11(model="/root/my_models/yolo11n_8c_448.mud", dual_buff=True)
cam = camera.Camera(detector.input_width(), detector.input_height())
disp = display.Display()

while True:
    img = cam.read()
    objs = detector.detect(img, conf_th=0.3, iou_th=0.45)
    for o in objs:
        img.draw_rect(o.x, o.y, o.w, o.h, color=(0, 255, 0), thickness=2)
        img.draw_string(o.x, max(0, o.y - 16), "%s %.2f" % (o.class_name, o.score))
    disp.show(img)
```

**注意**：MaixPy 的 `detector.detect()` 自带 NMS，不用自己写。

# 七、已知限制与风险

| # | 限制 | 影响 | 处理 |
|---|---|---|---|
| 1 | **正四面体 0 标注** | 模型认不出正四面体，会误报成三棱柱/四棱锥 | **人工补标后训第二版** |
| 2 | **数据集与生产环境差异大** | 现场掉点风险高 | **相机回来后补采现场数据微调** |
| 3 | 模型输入 448×448，生产相机 1280×720 | MaixPy 会 letterbox，小物体可能变糊 | 可考虑改 640×384；但需重新转 cvimodel |
| 4 | 标注是自动预标，未人工复核 | 框位置/类别可能有错 | 人工复核后重训 |
| 5 | 验证集 mAP 是对"自动标注"的一致度 | 不等于对真值准确率 | 补人工标注后重估 |
