# 二、标定方法

## 2.1 硬件约束（决定了方法）

| 约束 | 后果 |
|---|---|
| 开环步进，**无位置回读** | 固件只认"上电瞬间在哪，哪里就是 0" ⇒ **每次上电前必须把机械臂推到运动原点（XY 最负角，顶住硬限位）** |
| **相机看不到运动原点** | 原点在画面顶部之外；Y > 50mm 时物块就跑出画面 ⇒ 标定点只能选在 Y ≤ 25mm 区域 |
| **机械臂移到托盘上方会挡住相机** | 拍照时必须把机械臂移回原点（视野外） |
| 无固定工装 | 物块靠手放在夹爪下方，水平误差 ±7~13mm |

## 2.2 流程（每点 5 步）

```
① 机械臂从原点出发，用 MOVE X DIR0 / MOVE Y DIR0 走到夹爪位置 P
② 用户把橙色方块放到夹爪正下方（方块中心 = 夹爪中心 +X 5mm）
③ 机械臂移回原点（MOVE X DIR1 / MOVE Y DIR1 反向）
④ 拍照（此时视野干净），用颜色阈值提取橙色方块质心
⑤ 记录 (机械坐标, 像素坐标)
```

## 2.3 方向约定（**这是本次最大的坑**）

固件曾有两套互相矛盾的 Y 方向定义：

| 文件 | 改前 | 说明 |
|---|---|---|
| `ec_motion_plan.h` | `EC_MOTION_POSITIVE_Y_DIR = EC_DIRECTION_1` | 运动规划用 |
| `ec_axis_driver.c` | `EC_AXIS_INTERP_POSITIVE_DIR = EC_DIRECTION_0` | 轴插值用 |

**实测证明 DIR0 才是 +Y**：机械臂在最内侧原点时
- 发 `MOVE Y DIR1` → 往内壁顶 → **堵转**
- 发 `MOVE Y DIR0` → 正确离开内壁朝 +Y

⇒ **已改固件**：`EC_MOTION_POSITIVE_Y_DIR` 由 `EC_DIRECTION_1` 改为 `EC_DIRECTION_0`，与轴插值统一。
（需重新烧录才生效；`MOVE` 诊断命令不受该宏影响。）

**最终方向约定（台架命令）**：

| 方向 | 命令 |
|---|---|
| +X | `MOVE X DIR0` |
| −X | `MOVE X DIR1` |
| **+Y** | `MOVE Y DIR0` |
| −Y | `MOVE Y DIR1` |

## 5.3 误差来源（已排除算法问题）

| 假设 | 验证 | 结论 |
|---|---|---|
| 3D 物块视差 | 做了径向校正，残差**完全不变** | ❌ 不是，径向缩放本质是线性、已被仿射吸收 |
| 物块高度不同 | 所有点同一物块同一高度 | ❌ 不是 |
| **手工摆放误差** | Y=0 组的 u 在 780~844 间随机跳（±63px ≈ ±13mm），而 X 移动理论上不影响 u | ✅ **主因** |

**⇒ 误差来自放置精度，不是标定算法。** 用户裁定：不追求高精度，加吸盘后重标。

# 六、复标方法（换吸盘/改机构后照做）

```
前置：
  ① 机械臂断电 → 手推到 XY 最负角（运动原点）顶住 → 上电
  ② 补光灯开：LIGHT LV 255 + LIGHT ON
  ③ 确认补光灯供电线、数据线、共地都牢靠（本次就因线松导致灯不亮）

采点（每点 5 步，见 §2.2）：
  建议采 8~10 个点，分布：
    · Y = 0 时 X = 50 / 75 / 100 / 125 / 150 / 175
    · Y = 25 时 X = 50 / 100 / 150
  ⚠️ Y 不要超过 25~50，否则物块跑出画面顶部

拟合：
  python _turntable-edit/fit_affine.py     # 改 POINTS 表即可

写入：
  python _turntable-edit/pi_write_calib.py  # 自动备份 + 校验
  （该脚本在树莓派上跑；Windows 上改完 scp 过去）
```

重复精度能到 1~2 mm，远好于手工摆放的 ±7~13 mm。

**本次因夹爪已被掰坏无法使用此招** ⇒ 加吸盘后建议用吸盘把物块吸起来再放下，
