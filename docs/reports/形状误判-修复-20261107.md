## 一、问题与证据

主相机 6 类模型（`_runs/main_6c_v2/weights/best.pt`，输入 448，YOLO11n）在**五棱柱 / 正方体 / 长方体**三类上互相误判。验证集（94 张 / 270 实例）结果：

| 类别 | Precision | Recall | mAP50 |
|---|---|---|---|
| cube 正方体 | 1.000 | **0.914** | 0.983 |
| cuboid 长方体 | 0.942 | 0.948 | **0.955** |
| cylinder 圆柱 | 0.896 | 1.000 | 0.993 |
| **pentagonal_prism 五棱柱** | **0.891** | 0.951 | 0.962 |
| cone 圆锥 | 0.994 | 0.932 | 0.984 |
| tetrahedron 四面体 | 1.000 | 0.975 | 0.995 |

归一化混淆矩阵（`runs/detect/_runs/val_main_v2/cls_report/confusion_matrix_normalized.png`）显示：
- cuboid 的预测里 **5% 判成 cube、5% 判成 penta、2% 判成 cone**
- penta 的预测里 **5% 判成 cube、5% 判成 cuboid**
- cube 的预测里 1% 判成 cuboid
- 另有 **25%/29%/17%**（cube/cuboid/penta）的预测落在 background（误检）

**根因**：俯视投影下这三类都是多边形，cube vs cuboid 只差长宽比，penta 的第五条边在小件/模糊/过曝时看不出；且训练集类别不均衡（cuboid 411 / penta 241 / cube 201 实例）。

## 二、实现内容

### A. 推理端「多帧类别投票」（Pi 侧，`socket_vision_source.py`）

**位置**：`电控/src/electrical_control/rpi/socket_vision_source.py`

**功能**：
- 对同一目标维护最近 N 帧的 `(class_id, conf, 像素坐标)` 历史
- `class_id` 至少 `quorum` 票才采纳；未达 quorum 时**不派该件**（视为不可用）
- 目标关联：优先用 `target_seq`；如果 `target_seq` 每帧会变，退化为**最近位置匹配**（阈值 40 像素）
- 超时保护：等待帧数超过 `max_wait` 仍未达 quorum 时按不可用处理并记 WARNING

**新增构造参数**（全部有默认值）：
```python
class_vote_enabled: bool = False          # 默认关闭（保持现状）
class_vote_frames: int = 3                # 历史窗口大小（默认 3 帧）
class_vote_quorum: int = 2                # 最少票数（默认 2/3）
class_vote_max_wait_frames: int = 6       # 超时上限（默认 6 帧）
```

**新增方法**：
- `vote_stats() -> dict[str, int]`：返回统计 `{"accepted": ..., "rejected_no_quorum": ..., "timeout": ...}`

**行为保证**：
- 关闭投票时输出必须与改动前逐字节等价
- 不破坏现有行为：`_resolve_box_ids`、`_filter_skipped`、`_visibility_signature`、`_expand`、首件稳定门、α 补尾语义都保持
- 统计信息可通过 `vote_stats()` 查询，在派件日志里可打印

### B. 设备端「分类别置信度阈值」（MaixCAM 侧，`yolo_v11_send.py`）

**位置**：`_pi_tools/maixcam_scripts/yolo_v11_send.py`

**功能**：
- 新增 `--min-conf-by-class "2:0.55,3:0.55"`（格式 `class_id(0-based):threshold`，逗号分隔）
- 不写的类用 `--conf`（默认 0.40）
- 未达阈值的检测**不加入 BATCH_TARGETS**；若整帧全被过滤，仍按现有逻辑发空批（保持链路心跳）
- 新增可选 `--unknown-as-code0`：开启 `--id-mode code` 时，若某件置信度介于 `--conf` 与分类阈值之间，可选择发 `code=0`（判不出）而不是丢掉——**默认关闭**（保持现状）

**新增参数**：
```bash
--min-conf-by-class "class_id:threshold,class_id:threshold"
    # 例："2:0.55,3:0.55" 对 cylinder(class_id=2) 和 penta(class_id=3) 用 0.55
    # 其他类用 --conf 0.40

--unknown-as-code0
    # --id-mode code 时，低置信件发 code=0（判不出）而不是丢掉
    # 默认关闭
```

**打印统计**（每帧 + 结束时）：
```
目标统计：sent=150 dropped_low_conf=12 dropped_class=8
```

## 三、开启/回退方法

### A. 多帧类别投票

**开启**（在 `run_chain.py` 或构造 `SocketVisionSource` 时）：
```python
source = SocketVisionSource(
    ...,
    class_vote_enabled=True,        # 开启投票
    class_vote_frames=3,             # 窗口 3 帧
    class_vote_quorum=2,             # 至少 2 票
    class_vote_max_wait_frames=6,    # 超时 6 帧
)
```

**回退**（改回默认值）：
```python
source = SocketVisionSource(
    ...,
    class_vote_enabled=False,   # 关闭投票（默认）
)
```

**一键回退**：删除或注释掉 `class_vote_enabled=True` 那一行，或显式设为 `False`。
