## 三、对改造提案的裁定

提案：五键排序 `停稳 → 待定 → 难度 → 隔离度 → 落点距离 → seq`，并补"落点锚点"。

**裁定：GO（有条件）**，逐键可行性：

| 键 | 数据是否现成 | 结论 |
|---|---|---|
| 停稳 | ❌ 需新增历史帧缓存（`VisionFrame.frame_id` 已单调，可用） | **需实现**，且必须带"超时降级"开关 |
| 待定 | ✅ `is_pending()`（`selector.py:327`，阈值 `DEFER_CONFIDENCE_BELOW`；用户 2026-10-26 裁决加入）| 直接可用 |
| 难度 | ✅ `PICK_TIER_BY_CLASS_ID`（cube0/cuboid0/cylinder1/penta0/cone2/tetra0，`selector.py` 表）| 直接可用，**但要补测试** |
| 隔离度 | ⚠️ 需在 frame 内算邻件距离（几何已有 `Rect`/`Point`，可复用）| **需实现**（建议：目标环带 R=夹爪半宽+10mm 内无其他件中心）|
| 落点距离 | ✅ `drop_point_for_box` / `make_drop_point_lookup`（`run_chain.py:800/833`）可取得上一件落点 | 需 `run_chain.py` 一行透传 |

### 附加条件（必须满足才允许接入）

1. **灰度开关**：新增 `[Strategy] order_mode = legacy | difficulty | open_edge`，**默认 `legacy`**（现状），台架验证后逐级切换；一键回退。
2. **补测试**：至少新增 4 组用例——难度排序、隔离度、停稳判据（含超时降级）、落点锚点透传。
3. **不动已跑通路径**：固件运动程序、`greedy_tsp` 保留，仅通过开关选择；不删除旧代码。
4. **停稳判据参数化**：帧数 N、位移阈值 ε、尺寸变化 δ 全部进 ini，带【待实测】标签。

### 7.1 自我纠正：D2 的表述需要修正（重要）

原报告 §二 把 D2 写成"策略库未接入"，**不准确**。复核代码后的事实是：

- **接入通道早就存在**：`run_chain.py` 用 `--pick-strategy=order` 时，
  经 `chain_adapter.payload_orderer_from_ini()` 构造排序器，注入
  `SocketVisionSource(payload_orderer=...)`；`socket_vision_source.py:433-439`
  优先使用注入的排序器，**只有**排序器缺失/抛错/件数不符时才退回 `greedy_tsp`。
- 所以准确表述应为：**接入通道存在但默认关闭**
  （`run_chain.py:1368-1369`：`payload_orderer = None`，仅 `--pick-strategy=order` 才构造）
  ⇒ 默认启动 = `greedy_tsp` + 固定锚点 `(0,0)`；显式开启 = 策略库排序。

D1（锚点固定 `(0,0)`）依然成立且已修（见 7.2）。
