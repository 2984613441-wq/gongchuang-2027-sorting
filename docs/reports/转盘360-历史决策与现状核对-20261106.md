## 二、四个"源"的现状对照（这才是不一致的地方）

| 层面 | 现状 | 与"360° + 单落点"是否一致 |
|---|---|---|
| **用户决策** | 2026-10-07 起：单一固定落点 + 转盘 360° | ✅ 基准 |
| **驱动脚本** `工具/pi_turntable.py` | 实测可用（UART2/1Mbps/ID1，任意 0~4095=0~360°） | ✅ 能力具备；但 CLI 的 A/B/C 预设仍是"两侧"时代 |
| **驱动库** `rpi/turntable.py` | 已有 `SerialServoBackend`（默认后端）；高层 `Turntable` 是**脉宽域**：`pulse = zero + angle*us_per_degree` | ⚠️ 脉宽域有效角只有 **约 ±137°**（±1000µs ÷ 7.28µs/°），**到不了 360°** ⇒ 6 格（尤其 180°）会被 [500,2500]µs 拦截 |
| **策略** `drop_strategy.py` | 方案B `TurntableStrategy` 存在：1 落点 + `[TurntableAngles]` 表（box 1..6 角度） | ✅ 结构匹配 |
| **链路** `run_chain.py` | **显式拒绝方案B**（`SystemExit`，`:1355-1363`）；转盘只在方案C 有守卫；只调用过一次 `make_backend().set_pulse_us(1500)` 做中位 | ❌ 未接线 |
| **设备配置** | 仍是**方案C**（`[TurntablePositions]` + `[TurntableSides]` + 6 行落点） | ❌ 与机械不符 |
| **落点数据** | `[DropPoints] 1~6 = (5.0,5.0)` 是 2026-09-18 的**遗留测试占位**（怕符号反）；真实坐标未填 | ❌ 未标定 |
| **角度数据** | 模板 `88.0, 90.0` + 0/60/…/300 全是**待标定占位** | ❌ 未标定 |

## 三、已确认的硬件事实（来自 10-17 实测脚本，可直接复用）

```
链路：树莓派 UART2（物理 27=GPIO0/TXD2、28=GPIO1/RXD2、GND 30/25/39）
      ── 同名直连 ── 微雪 Bus Servo Adapter (A) ── D/V/G ── STS3215
前提：/boot/config.txt 加 dtoverlay=uart2 ⇒ 出现 /dev/ttyAMA1；跳帽置串口侧 + DC 供电
参数：舵机 ID=1；波特率 1,000,000；位置 0~4095 ↔ 0~360°（每 90° = 1024）
帧  ：FF FF ID LENGTH INST PARAM... CHECKSUM；LENGTH=参数数+2；CS=~(ID+LEN+INST+PARAM)&0xFF
寄存器：目标位置 0x2A、目标时间 0x2C、当前位置 0x38（2 字节小端）
实测：A=1024(−90°)、中位=2048、B=3072(+90°)；到位容差 20 counts≈1.8°
```

| # | 不确定点 | 现状 | 需要做什么 |

## 六、本轮纠正 Lead 自己两处错误

1. **错**："转盘策略/守卫/索引校验齐全（方案C）" → 实际上**机械已是 360° 单落点**，方案C 那套（3 落点/2 侧/GPIO17）与实物不符。
2. **错**："`turntable.py` 仍是 PWM 老路" → 实际上 **10-17 已加 `SerialServoBackend`（默认后端）**，Pi 直驱总线舵机可用；真正缺的是**链路层接线（run_chain 拒绝方案B）+ 角度域 API + 守卫 + 标定**。
