## 二、改了什么

### 1) `pos:` 解析（`电控/src/electrical_control/rpi/drop_strategy.py`）

* `TurntableStrategy` 增加 `pos_table`（向后兼容：第二个参数仍是角度表）；
  新增 `uses_position_domain()` / `get_position()` / `pos_table` / `angle_table` 属性。
* `load_strategy_from_cfg` 方案B 分支逐个值识别 `pos:` 前缀（大小写、`pos: 2048` 空格均可）：
  * 全部 `pos:` ⇒ 位置表；全部数字 ⇒ 旧角度表；
  * **两种混用 ⇒ SystemExit**（提示里带出哪几格是 pos、哪几格是角度）；
  * `pos` 非整数/越界（0..4095）⇒ SystemExit；缺任一格 ⇒ SystemExit。
* `get_drop_point()` 的“未知货格拒识”改为**位置表 ∪ 角度表**判断（pos 模式下不再误拒）。

### 2) 位置域与守护（`turntable.py` + 新 `turntable_position_guard.py`）

* `TurntableConfig`：`pos_table`（优先）+ `boxes()` + `position_coverage()`；
  `pos_for_box()` 先查 pos 表，再退回“角度→位置”换算（旧模板兼容）。
* `Turntable`：`command_box_position/goto_box_position/goto_position`（0~4095 直发）；
  `goto_box_position` 的日志在 pos-only 配置下不再依赖角度。
* 新模块 `turntable_position_guard.PositionTurnGuard`，接口与方案C 的 `TurntableGuard` **完全对齐**
  （`preflight / before_dispatch / poll / note_motion_done / failed`），所以主循环代码一行没改：
  * 到位判据：**环形距离** `min(|a-b|, 4096-|a-b|) ≤ 20 counts`（0 与 4095 只差 1）；
  * 派发时若读回已在目标 ⇒ 立即记到位（重复派同格/位置舵机本来就在目标，不该等到 MOTION_DONE 才确认）；
  * 超时（默认 2.5s）或 `read_pos() is None` ⇒ 记 ERROR + `turntable.lock()` + 返回原因 ⇒ 链停（fail-closed）；
  * `MOTION_DONE` 到达时仍未确认 ⇒ 锁死（“可能在转盘中落料”，与方案C 同一口径）；
  * 读串口按 `poll_s`（默认 50ms）节流，主循环转得快也不会刷爆总线。

### 3) `run_chain` 接线（`电控/deploy/run_chain.py`）

* `_wire_position_turntable()`：装配 `Turntable`（`make_backend()`；demo 用 `FakeBackend`）+ 守卫；
  可选的 `[Turntable]` 段覆盖 `settle_s / arrive_tolerance_counts / arrive_timeout_s`，缺省用代码默认。
* 方案B 分支：开工 `goto_zero()`（清上一场遗留位置）+ `guard.preflight()`（读回通路必须活着）；
  生产模式强制 **code ⇒ 必须 `--slot-mode dynamic`**（否则会按 code 当货格号转错格），
  旧校赛模式（`BATCH_ID_BYTE_IS_BOX_ID=True`）不受此限。
* 方案C 的行为与代码路径**原样保留**（GPIO17 索引、`BATCH_ID_BYTE_IS_BOX_ID` 断言、开工自检）；
  仅把“方案C 专属块”的条件收敛为 `turn_guard is not None and turntable is None`。
* 顺带修了两个 **demo 路径**的 `UnboundLocalError`（S1 前 `--fake-link` 根本跑不到验收）：
  `place_runtime`（主循环无条件读）与 `slot_allocator`（转盘分支里读）；真实模式行为不变。

### 4) 模板

* `sorting_config.方案B模板.ini`：360°/`pos:` 口径；6 个 pos 值明确标注“示例排布、禁止上机”；
  文末附可选 `[Turntable]` 段；启用/回退步骤与代码路径核对表。
* 旧模板保留：`sorting_config.方案B模板-270deg.ini`（±112.5°、MG996R 口径）。

## 四、已知限制 / 待办

1. **M1–M3 未测**：模板 pos 值是示例；真机接线验收（`pi_turntable` 读到实际六格、单件真跑到位）等现场数据。
2. **主机缺 `pyserial`**：`turntable_guard.py` 自检的“非 demo 构造后端”一项在本机失败（`ModuleNotFoundError: serial`）——
   与本次改动无关（方案C 非 demo 路径本来就依赖 pyserial），在 Pi 上可过；若要主机跑全自检需 `pip install pyserial`。
3. **方案C 主机冒烟**：仓库 `sorting_config.ini` 无 `[TurntablePositions]`，本机无法在 demo 下构造方案C 配置；
   方案C 的回归以 `turntable_guard.py` 自带 12 项自检 + drop_strategy 自检为准（均通过）。
4. `--slot-mode dynamic` 与方案B 的联动只做了**启动期拒绝**，动态分配在真机上的映射仍需 Stage 2 验收。
