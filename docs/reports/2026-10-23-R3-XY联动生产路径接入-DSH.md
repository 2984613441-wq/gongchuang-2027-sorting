# 二、🔴 关键发现：仓库里那个"插补实现"不能用

`App/Src/ec_motion_plan_interp.c` 存在很久，但：

1. **不在 Keil 工程**（`uvprojx` 只收了 `ec_motion_plan.c`）⇒ 从没编译过
2. **不在任何主机测试目标** ⇒ ctest 覆盖不到
3. **更严重：它是 6 步简化版，丢了 4 个关键步**

## 2.1 逐条对比（这是不能用的原因）

| 步骤 | 生产串行版（12 步）| 6 步简化版 |
|---|---|---|
| **[0] 起点先张开（待机 625）** | ✅ | ❌ **缺失** |
| [1] PARK→PICK | 顺序 2 步 | XY 同时 |
| **[2] 到取料点降到该件类别开度** | ✅ | ❌ **缺失** |
| **[3] WAIT（dwell，人眼确认停位）** | ✅ | ❌ **缺失** |
| [4] 闭合夹住 | ✅ | ✅ |
| [5] PICK→PLACE | 顺序 2 步 | XY 同时 |
| [6] 张开释放 | ✅ | ✅ |
| **[7] 回程前切回待机 625** | ✅ | ❌ **缺失** |
| [8] PLACE→PARK | 顺序 2 步 | XY 同时 |

**缺 [0] 的后果（代码注释原文明写）**：
> 上电/复位后舵机不输出脉宽、爪子可能停在闭合态；必须在每件开头先张开一次，
> **否则会带着闭合爪走到取料点把物块撞飞。**

**缺 [7] 的后果**：
> 回程时爪片会拦住/刮走托盘上其他物块。

**⇒ 如果直接把构建切到那个文件，会同时引入"撞飞物块"和"刮走物块"两个已修过的现场故障。**

# 三、正确做法与实现

## 3.1 思路

**保留串行版全部 12 步的语义与顺序，只把 3 段 XY 移动各换成 1 个插补步。**

```
12 步  →  9 步（3 段 × 从 2 步降为 1 步）
```

容量 `EC_AXIS_PICK_PLACE_STEP_COUNT = 12`，9 步还有 3 步余量。

## 3.2 改动（5 个文件）

| 文件 | 改动 |
|---|---|
| **`ec_motion_plan.c`** | 新增 `append_xy_interp()` helper + `ec_motion_plan_build_with_open_interp()` |
| **`ec_motion_plan.h`** | 声明 + 完整设计注释（含与 6 步版的关系、轨迹形状的诚实说明）|
| **`ec_app.c`** | 新增 `static bool xy_interp_enabled`（**默认 false**）+ `ec_app_set/get_xy_interp_enabled()`；build 调用改为按开关二选一 |
| **`ec_app.h`** | 两个接口声明 |
| **`ec_diag.c`** | 新增 **`INTERP ON\|OFF\|?`** 命令 + HELP 条目 |

## 3.3 关键设计决策

**① 默认 OFF，不是 ON**
```c
static bool xy_interp_enabled;   // 静态零初始化 = false = 串行版
```
**⇒ 烧了这版固件，行为与接入前逐字节相同。** 想试插补必须显式发 `INTERP ON`。
避免"烧完就换了没验证过的运动计划"。

**② 只在【下一件】生效**
每件都会重新 build program，正在执行的那件不受影响。

**③ 掉电恢复 OFF**

**④ 为什么写在 `ec_motion_plan.c` 而不是 `ec_motion_plan_interp.c`**
`ec_motion_plan.c` **已在 Keil 工程里** ⇒ **不需要改工程文件、不需要用户手动加文件**。
这是最小改动路径。

# 四、⚠️ 一个必须说清的局限：轨迹是折线，不是几何直线

## 4.1 驱动层看起来是对的

`ec_axis_driver.c` 的 XY_INTERP 分支：
```c
uint32_t major_steps = max(x_steps, y_steps);
start_dual_axis(x_steps, dir_x, interp_axis_hz(x_steps, major_steps),
                y_steps, dir_y, interp_axis_hz(y_steps, major_steps), now_ms);
```
`interp_axis_hz` 按**步数比**给两轴不同频率 —— 看起来就是常速合成法的直线。

## 4.2 但那个频率最终没被用上

`ec_board_stm32.c:start_axis_counted()`：
```c
if (ec_step_profile_plan(profile, steps, 200U, step_cruise_hz, 200U, 10000U, 10000U)) {
    period = ...;                                    // ← 成功：用全局 cruise（现 8000Hz）
}
if (period == 0U) {
    period = (EC_STEP_TIMER_HZ / frequency_hz) - 1U;  // ← 只有失败才用传进来的频率
}
```

**⇒ 规划成功时 `frequency_hz` 被忽略 ⇒ 两轴各自跑自己的 8000Hz 曲线，按步数多少先后停。**

## 4.3 所以实际效果是

| 特性 | 是否满足 |
|---|---|
| **两轴同时起步（"一起动"）** | ✅ **满足** —— 这就是用户的要求 |
| 耗时 = `max(t_x, t_y)` 而非 `t_x + t_y` | ✅ 满足 |
| **完美几何直线** | ❌ **不满足**，是"短腿先停"的折线 |

**要真·直线，需要给两轴分别指定 cruise**（把 `start_axis_counted` 的 cruise 从全局改成参数）。
这是后续工作，已在 `ec_motion_plan.h` 的注释里标为已知局限。

# 六、实机验证方案（回到实验室后）

**前提**：机械臂在 PARK（或先回零）。

```
① INTERP?            → 应回 OK INTERP off（默认）
② 跑一件正常分拣      → 记录耗时与是否正常夹取（基线，串行版）
③ INTERP ON          → 切插补
④ 再跑一件           → 记录耗时与是否正常夹取
⑤ 对比：
   · 耗时应下降（对角线路径越斜降得越多）
   · 夹取质量不应变化（舵机步全保留）
   · 观察运动：两轴应【同时起步】，不是 X 走完 Y 才走
⑥ 若异常 → INTERP OFF 立刻回退
```

**回退**：`INTERP OFF`（运行时可退）或重新烧录（掉电也是 off）。

# 七、剩余风险与未验证项

| # | 风险 | 说明 |
|---|---|---|
| 1 | **实机未验证** | 本次全部是主机证据，不代表固件/实机通过 |
| 2 | **折线而非直线** | 见第四节；要直线需给两轴分别指定 cruise |
| 3 | **加速段电流** | 两轴同时加速 ⇒ 峰值电流约翻倍。电源/驱动是否够**未测**。这是实机验证第一要看的现象（丢步/异响/复位）。|
| 4 | **零位移边界** | `pick == place` 时插补版返回 false（串行版成功）。生产中不会出现，但需知道。|
| 5 | **超时窗口** | 耗时下降对 15s 失活窗口是利好；但两轴同时计数，`counted_all_done()` 的判据未变，需实机确认 `MOTION_DONE` 正常发出。|
