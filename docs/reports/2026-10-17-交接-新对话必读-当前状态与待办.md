## 2. 🔴 今天的核心修复：固件主频只有 53.76 MHz

### 问题

STM32 实测波特率对不上、`STATUS` 心跳 3 秒一次而非 1 秒、步进速度只有 1/3。

**根因**：板上 HSE 晶振实际是 **8 MHz**，而固件按 **25 MHz** 配置：

```
实际 SYSCLK = 168 × (8/25) = 53.76 MHz   →  比预期慢 3.125 倍
```

**连带影响**（全都偏慢 3.125 倍）：

| 子系统 | 应为 | 实际 |
|---|---|---|
| USART2（Pi 主链路） | 115200 | ≈36864 |
| UART4（ToF） | 115200 | ≈36864 |
| USART3（总线舵机 PB10） | 115200 | ≈36864 |
| TIM4/TIM8 步进脉冲基频 | 100 kHz | 32 kHz |
| TIM2 舵机/阀 PWM | 50 Hz | 16 Hz |
| `HAL_GetTick()` | 1 ms | 3.125 ms |
| IWDG（LSI 独立时钟） | — | **不受影响** |

### 修复（3 处常量，缺一不可）

| # | 文件 | 行 | 原值 → 新值 |
|---|---|---|---|
| 1 | `电控/firmware/stm32f407_m144z/Core/Inc/stm32f4xx_hal_conf.h` | 99 | `HSE_VALUE 25000000U` → **`8000000U`** |
| 2 | `.../Core/Src/main.c` | 253 | `PLL.PLLM = 25U` → **`8U`** |
| 3 | `.../Core/Src/system_stm32f4xx.c` | 51 | `HSE_VALUE …25000000` → **`8000000`** |

> 第 3 处最容易漏：`system_stm32f4xx.c` **不包含** `hal_conf.h`，有自己一份默认值。不改它 → `SystemCoreClockUpdate()` 会算错 → `TICK_MS` 对不上。

**其余 PLL 参数一个都不要动**（`8÷8=1MHz` 与 `25÷25=1MHz` 相同，PLLN/PLLP/PLLQ/APB 分频全部保持原值即得 168 MHz）。因为 PCLK1/PCLK2 不变，**所有定时器预分频自动恢复正确**。

### 修复后实测（全部通过）

| 检查项 | 结果 |
|---|---|
| `TICK_MS` 增量 vs 真实时间 | **1.0003** |
| `STATUS` 间隔 | **1.0011 s** |
| 115200 波特率 | `OK PONG` 可读 |

## 4. 转盘：已打通（重点）

### 硬件链路与接线（**反常规，务必记住**）

```
树莓派 物理27脚 (GPIO0/TXD2) ── 转换板 TX
树莓派 物理28脚 (GPIO1/RXD2) ── 转换板 RX
树莓派 GND (30/25/39)        ── 转换板 GND
```

> 🔴 **这块微雪 Bus Servo Adapter (A) 是"同名直连"，不是常规的 TX/RX 交叉！**
> 按惯例交叉接（27→板RX，28←板TX）→ **完全无响应（0 字节）**；改成同名直连后立刻通。
> 这一条卡了约两小时，记牢。

**前置条件**：
1. `/boot/config.txt` 有 **`dtoverlay=uart2`**（已加，备份 `/boot/config.txt.bak-20261017-uart2`）→ 产生 `/dev/ttyAMA1`
2. 转换板跳帽置**串口/UART**侧
3. 转换板有 **DC 供电**（板载 LED 亮）；ST-3215 是 **7.4V** 舵机，DC 给 7.4~8.4V，**别给 12V**

### 协议参数

| 项 | 值 |
|---|---|
| 舵机 ID | **1** |
| 波特率 | **1,000,000 (1 Mbps)** |
| 帧格式 | `FF FF ID LENGTH INST PARAM... CHECKSUM` |
| LENGTH | **参数个数 + 2** |
| CHECKSUM | `~(ID + LENGTH + INST + PARAM...) & 0xFF` |
| 目标位置 | 地址 **0x2A**（2 字节小端） |
| 目标时间 | 地址 **0x2C**（2 字节小端，毫秒，用于限速） |
| 当前位置 | 地址 **0x38**（2 字节小端） |
| 位置范围 | 0~4095 对应 0~360°，**每 90° = 1024 计数** |

### 标定值

| 位置 | 位置值 | 角度 |
|---|---|---|
| **A 侧** | **1024** | −90° |
| **中位** | **2048** | 0° |
| **B 侧** | **3072** | +90° |
| A↔B | 差 2048 | 180° |

实测精度：四次 90° 动作到位误差 **+9 / −9 / −8 / +6** 计数（**≤0.8°**），重复性良好。存在约 −7 计数的固定偏移，不影响使用。

## 7. 重要技术事实（别踩）

### 7.1 `MOVE` 的 `HZ` 参数基本不生效

`App/Src/ec_board_stm32.c:345-349` 用**硬编码梯形速度曲线**：

```c
/* Plan trapezoidal velocity profile: start 200 Hz -> cruise 2000 Hz -> end
 * 200 Hz, accel/decel 5000 Hz/s. Conservative values; tune on-site ... */
```

⇒ 实际固定 **2000 步/秒 = 25 mm/s**（80 steps/mm）。命令行 `HZ` **只是在曲线规划失败时才作回退值**。

实测印证：4 组不同 `HZ`（100/500）全部收敛到约 2000 步/秒。

**影响**：定位不受影响（步数是绝对值）；但用 `HZ` 调速度会白调。`sorting_config.ini [Motion]` 的速度倍率可能同样失效，**待确认**。

### 7.2 EN 极性 = 高有效

`App/Src/ec_board_stm32.c:362`：`/* PD42S1 EN极性：高有效（2026-10-11手册确认）*/` + `GPIO_PIN_SET` 使能。
现场印证：上电后手推滑台明显变紧。

### 7.4 原点规则（重要）

固件在**上电时直接认为"位置可信"**（`App/Src/ec_app.c:747-749`，注释：*上电前必须手推到负向最里角*）。

⇒ **必须先把滑台推到负向最里角，再上电/按复位**。
⇒ 推了但没复位、或不在原点复位，绝对坐标就错了。
⇒ 故障会清 `position_valid`，**只有重新上电才能恢复**。
⇒ **固件没有 `HOME` / `ZERO` / `SETPOS` 命令**。

### 7.5 协议速查

**外层帧 V0.5**（`protocol/outer_frame.py`）：
```
A5 5A | 01 | sender | receiver | task_id(2 BE) | frame_seq(2 BE) |
command | data_len(2 BE) | payload | CRC-16/MODBUS(2 BE)
```
12 字节头 + 2 字节 CRC。`Device`: MAIXCAM=0x01, RASPI=0x02, STM32=0x03。
黄金向量：`"123456789"` → CRC `0x4B37`

**ITEM_TASK（0x21）12 字节 payload**：
`target_seq(1) class_id(1) image_id(1, 必须==class_id) x(int16 BE, 0.1mm, |v|≤1450) y(int16 BE) grip_angle(1, 必须0xFF) pick_x(int16 BE) pick_y(int16 BE)` → 整帧 26 字节

**MaixCAM→Pi TCP 8765**：**裸 BATCH_TARGETS，无 A5 5A、无 CRC**
`target_count(1) + task_id(2 BE) + target[7N]`，target = `id(1) confidence(1) X(2 BE) Y(2 BE) angle(1)=0xFF`
`BATCH_ID_BYTE_IS_BOX_ID = True` ⇒ id 字节是 **box_id(1..6)**，不是 class_id

**命令字**：`0x01 HEARTBEAT` / `0x02 HEARTBEAT_ACK` / `0x03 DEVICE_READY` / `0x04 ERROR` / `0x05 ACK` / `0x06 NACK` / `0x10 BATCH_TARGETS` / `0x11,0x12 TARGET_REACQUIRE` / `0x13 DIAG_SCAN` / `0x20 BARRIER_READY` / `0x21 ITEM_TASK` / `0x22 MOTION_DONE` / `0x23 ITEM_RESULT` / `0x24 DISPLAY_DATA` / `0x25 DISPLAY_ACK` / `0x26 ESTOP`

### 7.6 STM32 诊断命令（ASCII，115200）

```
HELP / PING / LIGHT ON|OFF / GRIP / STATUS / AXIS / INPUTS
STEP X|Y / STEP STOP / STOP ALL
MOTION ARM / MOVE X|Y DIR0|DIR1 [STEPS n HZ f]
SERVO ... / GROUP ... / BARRIER ...
```

`MOTION ARM` → `OK MOTION ARMED 10S`（**只有 10 秒窗口**）
`MOVE` 前必须先 ARM，否则 `ERR MOTION_NOT_ARMED_OR_INHIBITED`
`MAKE` 可能返回 `ERR TEST_BUSY` / `ERR MOTION_INHIBITED`

## 10. 禁忌与已知坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **不要用 CubeMX 重新生成代码** | `.ioc` 落后于源码（`RCC.HSE_VALUE` 仍 25000000 等），重新生成会覆盖手改的 168MHz、PWM 预分频、USART3 的 PB10 迁移 |
| 2 | **`视觉/现场标定清单.md` 是错的** | 抄的是 HSL 判据，生产链用 HSV 6 色窗口（在 `stage1_color_v6_send.py` 的 `COLOR_RANGES`） |
| 3 | **`color_quant.py` 里没有 `COLOR_RANGES`** | 老文档让你改那里是过期的，真实位置在 MaixCAM 端 |
| 4 | **`feetech-servo-sdk` pip 包是空壳** | `PacketHandler` 无任何方法，别依赖，用裸帧 |
| 5 | **`MDK-ARM/diankongv1.0/` 里有 30+ 个历史 .hex** | **别删**，是回退件 |
| 6 | **`视觉/models/` 里只有 `.onnx`，没有 `.mud`** | 文档引用的 `8766.mud` 不存在 |
| 7 | **`电控/calibration_config.ini` 仓库副本过期** | 真值在 Pi 上 |
| 8 | **`sorting_config.ini` 的 `[Turntable]` 段不存在** | 只有 `[TurntablePositions]` / `[TurntableSides]` |
| 9 | **`stm32_baudrate` 是死配置** | `run_chain.py` 实际读 `--baud`/`BAUD` 环境变量 |
| 10 | **限位开关未装** | 所有 XY 运动都是开环，撞限位只会丢步无保护 |
| 11 | **实机运动需用户授权** | 项目治理要求，动机构前先确认用户在现场、急停在手边 |
