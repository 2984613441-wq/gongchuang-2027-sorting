## 二、阻塞问题（实测证据）

`pos_for_angle` 的公式（`turntable.py`）：
```
raw = center_pos + angle_sign * angle * us_per_degree * counts_per_90 / us_per_90
pos = round(raw)，越界 raise（不 clamp）
```
取 `center_pos=2048`、`counts_per_90=1024`、`us_per_90=655`、`angle_sign=-1`，SOP 口径 `1=0°,2=60°,…,6=300°`：

```
格 1 角度 0   -> pos 2048
格 2 角度 60  -> pos 1365
格 3 角度 120 -> pos 683
格 4 角度 180 -> pos 0
格 5 角度 240 -> RAISE: 角度 240.0° → 位置 -683 超出 [0,4095]
格 6 角度 300 -> RAISE: 角度 300.0° → 位置 -1365 超出 [0,4095]
```

`angle_sign=+1` 时：180°→4096、240°→4779、300°→5461，同样越界。
⇒ **不管符号怎么取，从中心 2048 出发只有 ±180°（±2048 counts）可用，300° 张角必然超出。**

更根本的一点：`SOP/measure_turntable_slots.py` 输出的是**相对第 1 格**的角度（第 1 格=0°），
而位置域是**舵机绝对坐标**（0~4095 相对舵机零位）。两者之间差**一个绝对基准偏移**，
而这个偏移量在测量结果里没有 ⇒ 用"角度表"表达 360° 六格天生缺一个自由度。

## 三、建议：`[TurntableAngles]` 改存**原始位置值**

**格式（向后兼容）**：`[TurntableAngles]` 的 `1..6` 允许两种写法，解析时按前缀区分：
```ini
[TurntableAngles]
turntable_drop_point = <X>, <Y>
1 = pos:2048      # 原始位置值 0~4095（推荐，测量工具直接给这个）
2 = pos:1365
3 = pos:683
4 = pos:0
5 = pos:3413
6 = pos:2731
# 兼容旧写法：不带 pos: 前缀 ⇒ 按角度解释（旧 270° 模板继续可用）
```

**为什么推荐位置值（4 条）**：
1. **测量直接给位置**：`pi_turntable.py --read` / `measure_turntable_slots.py` 读到的就是 0~4095，不用再猜 `center_pos / counts_per_90 / angle_sign` 三个标定常数。
2. **天然处理 360° 环绕**：位置值本身就是 0~4095 的环，不存在"240° 越界"这种假问题。
3. **少一层绝对基准**：角度是"相对第 1 格"，位置是"绝对"，存位置不需要额外 reference offset。
4. **fail-closed 更强**：越界只有一种情形（N 不在 0~4095），比"角度符号/中心/比例都可能标错"更容易守住。

**需要的改动（建议在 S1 第二步一起做）**：
- `TurntableConfig`：新增 `pos_table: dict[int,int] | None`；`pos_for_box()` 优先用它；`angle_table` 保留给旧脉宽后端/旧模板。
- `drop_strategy._load_turntable_strategy()`：`[TurntableAngles]` 解析时识别 `pos:` 前缀；**同一段里不允许混用**（混用即 fail-closed，避免一半角度一半位置）。
- `工具/measure_turntable_slots.py`：输出改成 `1 = pos:NNNN`（现在输出 `1 = 0.0  # pos=...`）。
- 文档：`目标逻辑` L50/L51、SOP §2 的记录与回填口径同步改成位置值。
