## 1. 模型与计算边界

下文 `App/`、`tests/` 均位于 `电控/firmware/stm32f407_m144z/`；`logic/` 指 `电控/stm32_logic/`。

| 事实 | 现行源码证据 |
|---|---|
| 巡航 5000、起止 200、加减速各 10000 | `App/Src/ec_board_stm32.c:200` |
| 时基 100000 Hz；逐步更新 ARR | `ec_board_stm32.c:28,201,510-521` |
| WAIT=2000 ms、舵机 settle=200 ms、80 steps/mm | `App/Inc/ec_axis_driver.h:138,61,32-33` |
| HOME=(-95,-97.5)mm；正端上限=(90,92.5)mm | `App/Inc/ec_motion_plan.h:190-191,126-127` |
| 先 HOME 张开，再到 PICK、WAIT、夹取、落料、回 HOME | `App/Src/ec_motion_plan.c:181-225`，WAIT 调用在 `:209` |
| 窗口起点、DONE 不关窗、有效 DISPLAY_ACK 关窗、15000ms 判失活 | `App/Src/ec_app.c:197,520-524,218-219,549-564` |

固定抓取点 K=(-41.8,-27.1)mm、当前落点 P=(20,20)mm。六腿步数为 **4256 / 5632 / 4944 / 3768 / 9200 / 9400**。评估程序直接链接现行 `logic/src/ec_step_profile.c`，不复制其算法；对每腿调用 `plan()`，再累加所有 `reload_at(i)+1`，除以 100000。这样同时计入整数平方根、三角曲线和 ARR 取整（`:49-204`）。不模拟真实中断延迟、脉冲输出或机械负载。

基准计算到 DONE 为 12.834080 s。报告记录的 DONE→主机发送 DISPLAY_ACK 为 1.163 s（`docs/交付/2026-09-19/交接-链路已跑通-2026-09-19.md:42-44`），到 DONE 实测约 12.9 s。因此采用：

```
名义整轮 = 六腿离散时长 + 3×0.200 + WAIT + 1.163 + 0.065920
0.065920 = 12.900000 - 12.834080
基准 = 14.063 s，余量 = 0.937 s
```

14.063 是对“约 14.06 s”的统一计算锚点，**不是毫秒级实测精度声明**。保留全部基准残差，是为避免外推时把它丢掉。主机发送 ACK 与固件实际消费 ACK 不同，窗口又从运动启动才开始；缺少两端同一时基记录，无法声称已测得精确窗口用量。1.163 s 也不是显示延迟上界。显示/调度额外增加 Δ 秒，会等量吃掉表中余量。

## 2. 量化结论：6000 Hz“白改”不成立

公式为 `ticks=(100000+f/2)/f`（整数运算），`ARR=ticks-1`，实际频率 `100000/ticks`，见 `logic/src/ec_step_profile.c:200-204`。

| 设定 Hz | ARR | ticks | 平台实际 Hz | 当前点到 DONE，s | 相对基准省时，s |
|---:|---:|---:|---:|---:|---:|
| 5000 | 19 | 20 | 5000.000 | 12.834080 | 0 |
| 6000 | 16 | 17 | 5882.353 | 12.246560 | 0.587520 |
| 6250 | 15 | 16 | 6250.000 | 12.094760 | 0.739320 |
| 7000 | 13 | 14 | 7142.857 | 11.866840 | 0.967240 |

6250 的**平台**确实没有量化误差；整个加减速过程仍有量化。6000 虽未达到设定频率，却明显快于 5000，不能叫白改。7000 会向上量化，不能当成精确 7000 使用。本轮建议仍取 6250 为第二档候选，不额外推荐 7000。

## 4. 换算为 Px+Py 上限

**适用域严格限定为上述固定 K、HOME，以及非负落点 0≤Px≤90、0≤Py≤92.5 mm。** 在此域路径长度为 `385+2(Px+Py)`mm。对任意抓取点，该公式不成立，必须重新按六腿绝对位移计算；不能仅凭落点和作全场承诺。

为避免三角曲线下“相同坐标和却不同耗时”，程序对域内 **901×926 个 0.1mm 网格点**逐点求六腿时长，并按坐标和取最坏值，再取所有较小和的累计最坏值。下表是**使域内所有不超过该和的点都满足预算的最大网格上限**。15s 列用严格 `<15`，因为源码在 `>=15000ms` 失活；14s 列为建议预留约1秒的工作线。它们仍是模型条件下的限值。

| 档位 | Px+Py 最大值：整轮<15s，mm | Px+Py 最大值：整轮≤14s，mm | 最远落点(90,92.5)整轮，s |
|---|---:|---:|---:|
| 基准 | **69.2** | **38.0** | 18.623000 |
| W | **125.5** | **94.2** | 16.823000 |
| V | **105.4** | **66.4** | 16.971680 |
| A | **98.0** | **66.8** | 17.702000 |
| W+V | **175.7** | **136.7** | 15.171680 |
| W+A | **154.3** | **123.0** | 15.902000 |
| V+A | **151.2** | **112.1** | 15.801200 |
| W+V+A | **182.5（已到几何上限）** | **182.4** | 14.001200 |

交叉核验：基准平台每多1mm坐标和增加160步，即0.032s，所以 `(15-14.063)/0.032+40=69.28125`mm，向下取0.1mm得69.2。显示多耗0.1s时，基准上限约减少3.125mm，6250平台约减少3.906mm。

DSH报告§6的108.6mm/77.3mm按到DONE的旧公式算出，不能作包含DISPLAY_ACK的15s/14s上限；§7的“Px+Py≤70安全”也不能作为当前整轮保证。**当前(20,20)的和为40，基准已略超14s工作线。W+V仍不能覆盖最远角；三项组合在该角也只是约1秒名义余量。**

## 6. 建议与未验证边界

**建议先选W。** 它不改变运动频率、斜率和位移，收益固定1.8s，当前点已有2.737s名义余量。用户已取消原先目视停留需求；但host不能把机械残余振动/夹取质量证明为“零风险”，本轮只确认其软件语义合法。
