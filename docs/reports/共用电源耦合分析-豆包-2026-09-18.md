# 共用电源耦合分析：步进浪涌如何经共用 12V 母线打到 STM32

> 日期：2026-09-18
> 角色：电源完整性与电气故障诊断审查者
> 范围：只读审查。依据现有固件源码、供电接线文档与用户实测事实；**未接线、未上电、未烧录、未跑实机运动**。
> 标注约定：【实测】= 用户现场观测或既有主机证据；【代码事实】= 本次只读源码确认；【推断】= 电气理论/机理推演，**未实测**，不得当作结论。
> 红线：不重复已推翻结论；VMOT/Vref/共地直流/EN 通路正常（电机能动即证），本报告只讨论**动态瞬态**，不质疑直流导通。

## 0. 一页结论（先读）

1. 【代码事实】**软件故障（轴超时/急停/端口失败）一旦发生，板子进 FAULT_LOCK 后不会自己走出来**——退出 FAULT_LOCK 的唯一路径是物理 START 按键（`ec_app.c:338` `ec_app_poll_start_button` 要求 `ec_gateway_state()==FAULT_LOCK` 且 `EC_INPUT_START` 有效）。软件 fault 路径**不会**自动重发 BARRIER_READY。
2. 【代码事实】但现场观测到 **BARRIER_READY 每 5.63±0.005s 复现**，且用户判断"与重跑启动序列一致"。这两件事在**不复位**的前提下逻辑上不能同时成立：FAULT_LOCK 是死态，谁来重跑启动序列？
3. 【推断】因此最自洽的解释是：**板子在运动中被复位**（欠压 BOR、或主循环被中断风暴饿死触发 IWDG），复位后重跑 POST(≥50ms)→HOMING(500ms)→BARRIER(立即放行)，约 0.6s 后到达 WAIT_TASK 并重发 BARRIER_READY。0.63s 的启动开销 + 约 5s 的运动到复位时间 ≈ 5.63s，与实测周期吻合。
4. 【代码事实】但这**只是推断**，不是定案。区分"软件故障"与"MCU 复位"有一个**不改固件、决定性**的实验（见 §4）：连续读 AXIS 的 `TICK_MS` 与 `FAULTS`。复位会让 `TICK_MS`（=HAL_GetTick）跳回接近 0、`FAULTS`（.bss 静态量）归零、串口出现 `BOOT SAFE HSI=...`；软件故障则 `TICK_MS` 单调递增、`FAULTS` 累加、无 BOOT 行。
5. 【推断】事发时电池电量不足，与"浪涌把本已偏低的母线/逻辑电压拉过阈值"在机理上相容；但**电量低只是必要背景，不是证据**，必须由 §4/§5 的实测坐实。

> 本报告**不宣布根因已定**。在拿到 §4 的 TICK_MS 序列与 §5 的母线波形之前，唯一可写的结论是：**"软件 fault"与"MCU 复位"在现有外部观测下尚未区分，且后者与 BARRIER_READY 周期复现更自洽。**

## 2. 机理分析：浪涌经共用母线影响 STM32 的全部耦合路径

### 拓扑回顾（【代码事实】+【设计文档事实】）

```
电池 12V+ ─[保险丝]─┬─ 公共点 ─► A4988① VMOT (12V 直给，斩波)
                   │           A4988② VMOT
                   │           DCP3512 VIN ─► 5V ─► 舵机 + STM32 5V入 ─► LDO ─► 3.3V VDD
电池 GND ───────────┴─ GND 公共点（星型）
```

步进电机是**电流型**负载：A4988 内部斩波把绕组电流钳在 Vref 设定值，在 VMOT 上表现为**高频脉冲电流**（斩波频率内部固定，量级 25–50kHz）；**启动/加速段**尤其狠——从 200Hz 爬升到 2000Hz 的梯形段（`ec_board_stm32.c:174`）转子还没跟稳，电流近似堵转量级。电池低电量（F7）→ 内阻升高 → 同样浪涌电流产生更大的 ΔV。

下面列全部候选路径 P1–P7。**每条都是【推断】**，直到 §5 的实测把它证实或排除。

---

### P1：12V 母线 IR 跌落（主路电压塌陷）

- **机理**：斩波/启动浪涌电流 I_surge 流过电池内阻 R_bat + 配线电阻 R_wire + 保险丝，ΔV = I·(R_bat+R_wire)。电量低时 R_bat 大，12V 瞬时被拉低。
- **传导**：DCP3512 的输入就是这条母线。
- **若成立，现象应该长什么样**：
  - 故障**只在运动受理后、电机真正起转/加速瞬间**出现，静态 PING/STATUS 完全正常（与 F5 一致：板子闲着能答 PING）。
  - 电量越高越不容易犯；电量越低越快犯（与 F7 一致）。
  - 不接电机空载跑同样命令**不犯**；带电机才犯。

### P2：DCP3512 输入跌落/UVLO → 5V→3.3V 跟着塌（直通到 BOR）

- **机理**：降压模块靠"输入 > 输出 + 压差"维持调节。12V 跌落到接近或低于 5V+压差时，5V 输出开始掉；若跌得更久更低，DCP 进入 UVLO 关断，5V 归零；板载 LDO 输入（5V）塌了，3.3V 也塌，STM32 VDD 跌破 BOR（F407 出厂 BOR 约 2.7V 量级）→ **硬件复位**。
- **这是把"电机侧电压扰动"翻译成"MCU 复位"的关键一级。**
- **若成立，现象应该长什么样**：
  - 故障瞬间串口**无 MOTION_DONE、无软 fault 帧**，直接**出现 BOOT SAFE 行**（`ec_app.c:598`）——因为复位后第一件事就是打这行。
  - 复位重跑启动序列后重发 BARRIER_READY（与 F3 一致）。
  - 用示波器看 5V 或 3.3V，故障瞬间有一次可观测下凹。

### P3：地弹（Ground Bounce）—— 动力回流经 GND 公共点抬电位

- **机理**：电机 A 级斩波回流必须经 GND 线回到电池负极。GND 线有电阻/电感，i 沿切变时 V = L·di/dt。星型点虽然把多根线汇在一起，但**从公共点到 STM32 的那段 GND**与**从公共点到 A4988 的动力回流**如果走的是同一根细线或端子接触电阻大，STM32 看到的"地"会相对电池负极跳动。
- **影响面**：所有以 GND 为参考的逻辑电平被整体抬/拉，STEP/DIR/EN、UART、ESTOP_FB 全部叠加一个共模偏移。
- **若成立，现象应该长什么样**：
  - 故障**与浪涌同步**，而不是与某个固定软件时刻同步。
  - 动力回流线径越细、端子越多，越容易犯；把 STM32 的 GND 单独直接拉到电池负极（与动力回流解耦）会明显改善。
  - 纯直流共地是通的（电机能动），但**动态**地弹仍可发生——这正是"电机能动"不能排除它的原因。

### P4：共模/辐射耦合（dV/dt 串进信号线）

- **机理**：VMOT 与电机相线是快速大电流开关节点，dV/dt 高，经分布电容/互感串入并排走的杜邦线（STEP/DIR/EN、UART RX/TX、ESTOP_FB）。
- **两个子后果**：
  - (a) **STEP 线毛刺**→ 定时器收到假脉冲，或假的上升沿，扰乱计步；严重时定时器 update 中断频率被打乱。
  - (b) **ESTOP_FB / POWER_PERMISSION 输入被误判**→ 走 `has_inhibit()` → `fault(ABORTED)`（软件故障，不复位）。
- **若成立，现象应该长什么样**：
  - (a) 会看到**丢步/多步**、计数与实际转角不符；开环计数仍可能发 DONE（因为不闭环），但位置会漂。
  - (b) 走**软件** fault 路径：AXIS 读到 `LAST_RESULT=5 (ABORTED)`，`FAULTS` 累加，**无 BOOT 行**，`TICK_MS` 不跳。注意轮询路径有 20ms 防抖（`ec_inputs.c:3`），窄毛刺被滤掉；但若 ISR 快速急停旁路（`ec_board_stm32.c` 的 ISR 内 abort）存在，可能绕过防抖——【需读代码确认是否真绕过，本报告不展开】。

### P5：DC-DC 开关纹波 + LDO 抑制不足

- **机理**：DCP3512 自身开关纹波叠加在 5V 上；板载 LDO 对高频纹波有 PSRR，但对**低频大跌落**（P2）无能为力。去耦不足时，VDD 上既有开关尖峰又有慢塌。
- **若成立，现象应该长什么样**：示波器 VDD 上常年有几十~几百 mV 尖峰；故障时叠加一个慢下凹。加够 100nF/脚 + 10µF/4.7µF 体电容后尖峰减小。

### P6：看门狗复位（IWDG）—— 不是欠压，是主循环被饿死

- **机理**：IWDG 标称约 1.0s（P，§1.2）。正常主循环每次 `ec_app_poll` 后喂狗（`main.c:137`）。若浪涌/毛刺导致：
  - 定时器 update 中断以远超设计频率触发（P4a），ISR 把主循环饿死；
  - 或主循环卡在某处长阻塞；
  - 则 ~1s 内没喂狗 → **IWDG 复位**（不是 BOR，但外部表现同为复位：RAM 清、BOOT 行、TICK_MS 归零）。
- 源码注释已经预见了这一点（`main.c:201-204`："堵转场景下主循环被中断风暴饿死…触发复位"）。
- **若成立，现象应该长什么样**：
  - 同样表现为复位周期（与 P2 外部观测无法区分）；
  - 但**母线 5V/3.3V 实际没塌**——用示波器看 VDD 很干净，却仍复位。这把"欠压复位(P2)"与"中断饿死复位(P6)"区分开。
  - 复位前若 UART 能侥幸吐几帧，可能看到主循环滞后（但通常直接复位，来不及吐）。

### P7：输入脚误判 → 软件 ABORTED（非复位）

- **机理**：同 P4(b)。地弹/共模把 ESTOP_FB（active-low）或 POWER_PERMISSION 拉到触发阈值。
- **关键判别**：这条路径**不复位**。它走 `fault(EC_AXIS_RESULT_ABORTED)`（`ec_axis_driver.c:354-356`），App 层转 EMERGENCY_STOP（`ec_app.c:530-541`）→ FAULT_LOCK。
- **若成立，现象应该长什么样**：
  - **无 BOOT 行**，`TICK_MS` 连续不跳，`FAULTS` 累加，AXIS `LAST_RESULT=5`。
  - **板子停在 FAULT_LOCK 不再动**——这正好解释 F5（20 次 STATUS 全 FAULT_LOCK 无变化），但**解释不了 F3（BARRIER_READY 每 5.63s 复现）**。即 P7 单独成立时，板子应该"死住"，不会周期性重发 BARRIER_READY。

### 2.8 把现象与路径对上号（【推断】，待 §4 实测裁决）

| 观测 | 支持 | 不支持 |
|---|---|---|
| F2 受理后 5s 内 FAULT_LOCK、无 DONE | P2/P6 复位后走 POST 失败落 FAULT；P7/P4b 软件 ABORTED | — |
| F3 BARRIER_READY 5.63s 复现 | **P2/P6 复位循环**（复位→0.6s 启动→BARRIER_READY→Pi 重发→再复位） | **P7 纯软件 fault**（FAULT_LOCK 死态，无人重跑启动序列） |
| F5 闲着 PING/STATUS 正常 | P1/P2/P6 只在运动浪涌时犯 | 持续硬件损坏 |
| F7 电量不足 | P1/P2（电量低→内阻大→更易塌） | — |
| F4 链路 8 周期稳定 | 浪涌未打到 UART 常态；故障是瞬发 | 持续共模干扰 |

> 【推断】F3 是最强的一张牌：**FAULT_LOCK 不会自己走出来，却周期性重发 BARRIER_READY**，只能由"复位"解释。这把天平压向 P2/P6（复位），而非 P7（软件 fault）。但"复位"的**成因**是欠压(P2)还是中断风暴饿死 IWDG(P6)，必须由 §5 的母线波形区分——两者外部都是复位。

## 4. 【重点】不改固件：怎样区分"软件故障"与"欠压复位"

### 4.1 原理（【代码事实】，决定性）

- `TICK_MS` = `ec_step_port_now_ms()` = `HAL_GetTick()`（`ec_board_stm32.c:666`）。这是一个**自由运行的毫秒计数器**：
  - 正常运行时单调递增；
  - **任何 MCU 复位（BOR/IWDG/软复位/外复位）后，HAL 初始化把它清回接近 0**。
- `FAULTS` = `diag.fault_count`，是 `.bss` 静态量（`ec_axis_driver.c:184`）。
  - 软件 fault 路径：`latch_fault_diag()` 累加它（`:206`），`ec_axis_driver_init()` **不清**它（`:182-183,303-313`）→ 跨故障保留、跨重启不保留；
  - **MCU 复位后，C 启动代码把 .bss 清零** → `FAULTS` 回到 0。
- 复位还会在串口吐 `BOOT SAFE HSI=...`（`ec_app.c:598`，DIAG 构建下必发，当前宏组合含 DIAG1）。

> 三个信号任意一个成立即"发生了复位"；三个都不成立即"板子没复位，是软件 fault"。这套判别**不需要改固件**，只需用已具备的 AXIS 命令 + 原始串口记录。

### 4.2 实验步骤（不改固件，Pi 侧操作）

**前提**：机构在行程中央，守急停；停掉整链/视觉/自动重发，只留一个独占串口会话；按 `运动完成上报-根因` 报告 §6.1 的安全与原始字节保留要求做。

1. **建立基线**：板子上电后，发一次 `AXIS`，记录 `FAULTS=N0`、`TICK_MS=T0`。等 30~60 秒让板子跑稳，再发一次 `AXIS`，确认 `TICK_MS` 已涨到几千~几万 ms、`FAULTS` 仍是 N0（确认这期间没复位过）。
2. **开始高速采样**：Pi 侧脚本以 ≤200ms 间隔循环发 `AXIS`，每条记录：墙钟时间、`FAULTS`、`TICK_MS`、`LAST_RESULT`、`STATE`；**同时把 UART 原始字节流（含二进制帧与 ASCII 行）整段落盘**，不要只解析字段。
3. **触发任务**：让板子受理一次运动任务（重现 F2）。持续采样到故障出现后再采 3 个周期（约 20 秒）。
4. **事后再发一次 `AXIS` 与 `STATUS`**，记录稳态值。

### 4.3 判据（【代码事实】推导）

**情况 A —— 发生了 MCU 复位（欠压 BOR 或 IWDG）：**
- `TICK_MS` **跳回小值**：序列会出现 …120500, 120600, 然后 **300, 800, 1400…**（从 boot 重新往上数）。两个相邻样本间 `TICK_MS` 不是 +1ms 量级，而是**跳水**。
- `FAULTS` **归零**：从 N0 或 N0+1 掉回 0（.bss 被启动代码清零）。
- 原始串口流里在故障时刻**出现一行 `BOOT SAFE HSI=16000000 ...`**。
- `LAST_RESULT` 回到 0（被清），不是 4/5/6。

**情况 B —— 软件故障（超时/急停/端口失败），板子没复位：**
- `TICK_MS` **全程单调递增**，跨故障点不跳水（…120500, 120600, 120700…）。
- `FAULTS` **累加**：从 N0 变 N0+1，且保持。
- **没有** `BOOT SAFE ...` 行。
- `LAST_RESULT` 落在 4(TIMEOUT)/5(ABORTED)/6(PORT_FAIL)，`LAST_ELAPSED_MS` vs `LAST_TIMEOUT_MS` 告诉我们是哪一步、超了多久。

> **一句话判据**：看 `TICK_MS` 在故障时刻**跳不跳水**。跳水=复位（转 P2/P6）；不跳水但 `FAULTS` 涨=软件 fault（转 P1/P4/P7 的轴层根因）。

### 4.4 这套实验为什么能一刀切开

- 它利用的是**复位对 RAM 与 tick 的必然副作用**，不依赖任何推测的故障码。
- 它把"复位的成因"与"是否复位"解耦：先 §4 定"是不是复位"，再 §5 用母线波形定"是欠压 P2 还是中断饿死 P6"。
- 它**不改固件**（AXIS 已在当前 DIAG 构建里），只读不改。

## 5. 母线/电源实测（在 §4 确认"是复位"之后做，用于区分 P2 vs P6）

1. **万用表 min/max 保持法（零成本先做）**：
   - 表笔搭 STM32 的 5V 入对地、3.3V 对地，开最小值记录，跑一次任务。
   - 若 3.3V 最小值 < ~2.9V（逼近 BOR）→ 支持 P2。
   - 若 3.3V 全程 > 3.0V 却仍复位 → 指向 P6（IWDG 饿死）。
2. **示波器法（推荐）**：
   - CH1 = 12V 母线（电池端/驱动 VMOT），CH2 = STM32 VDD(3.3V) 或 5V，CH3 = UART RX/TX 触发。
   - 触发设为"开始运动"或"UART 出现 BOOT 行"。
   - 量三个量：12V 谷底、5V/3.3V 谷底、复位相对谷底的时刻。
3. **分离供电对照（不改固件，改电源）**：
   - 把 STM32+舵机的逻辑 5V 改用**另一路独立电源**（如另一个电池/稳压源），只让 A4988 VMOT 用原电池；GND 仍共地。
   - 若分离后**不再犯** → 坐实"浪涌经共用电源耦合"（P1/P2/P3）。
   - 若分离后**仍犯** → 耦合不在电源（转向 P4 共模/信号线，或 P6 与电源无关）。
4. **串磁珠/小电阻对照（不改固件，单变量）**：
   - 在 A4988 VMOT 入口串一颗铁氧体磁珠（或 0.5~1Ω 功率小电阻），或在 DCP 5V 输出到 STM32 之间串磁珠，再跑。
   - 仅用于**判别**，不是终态方案。

## 6. 防护方案（按"最小改动"排序）

> 以下全是【推断】层面的工程建议，**必须在 §4/§5 实测确认耦合路径后再动手**；改动前仍需遵守项目红线（不改 I/O 映射、不擅自改协议、上电测试需授权）。

### 第 1 级：只加电容，不动线（最小改动）

- **A4988 VMOT 就近加体电容**：每路驱动 VMOT-GND 之间加 **100µF/25V 电解 + 0.1µF 陶瓷**（并贴在驱动 VMOT 端子旁）。作用：就近提供斩波脉冲电流，不让浪涌全部从电池经长配线取，直接压 P1/P5。
- **STM32 VDD 去耦补齐**：每个 VDD 脚 100nF，外加一颗 **4.7~10µF** 体电容贴 MCU 电源脚；NRST 脚串 100nF 到地（防复位脚毛刺）。
- **DCP 5V 输出加电容**：470µF/10V 电解 + 10µF 陶瓷，靠近 STM32 电源入口，给 LDO 当"水库"，吸收 P2 的慢塌。

### 第 2 级：磁珠/隔离（小改动）

- 在 A4988 VMOT 进线串**铁氧体磁珠**（大电流、低直流电阻、高频阻抗），把高频斩波浪涌挡在电池母线外。
- 在 DCP 5V 到 STM32 的路径上串磁珠或小 RC，把动力高频纹波与逻辑电源隔开（注意磁珠直流电阻不能把 5V 拉垮）。

### 第 3 级：共地点与线径（不改板，改接线）

- 复核星型 GND 公共点：**STM32 的 GND 与 A4988 的动力回流应"汇到同一点"而不是"串过同一根细线"**；理想上 STM32 的 GND 回到公共点的线不要与电机动力回流共用一段细线。
- 确认动力回流线径 ≥ 0.5mm²（`电控供电接线参考` §5 已规定），**绝不用杜邦线走动力**；端子压接牢固，降低接触电阻（接触电阻大是地弹的常见帮凶）。

### 第 4 级：电源分离（较大改动，确证后才做）

- 逻辑侧（STM32+舵机）与动力侧（A4988 VMOT）**各用一路独立 12V 输入**（双电池或双路 DCP），仅保留单点共地。这是治 P1/P2/P3 的根治方案，但动了供电架构，需按 L3/L4 流程授权。
- 舵机 5V 与 STM32 5V 若同支路，舵机动作也是浪涌源，必要时给 STM32 单独一路 5V。

### 第 5 级：大电解/续流（板级）

- 12V 母线就近（电池出口）加 **1000~2200µF/25V** 大电解，hold 住启动浪涌。
- 确认 A4988 底板/模块上已配 VMOT 续流与去耦（裸模块常省），缺则补。

## 8. 给现场的下一步（最小动作序）

1. **先做 §4 的 AXIS+原始串口长采样**（不改固件）。看 `TICK_MS` 跳不跳水、有没有 `BOOT SAFE` 行、`FAULTS` 归不归零。
   - 跳水/BOOT/归零 → 复位坐实 → 进第 2 步。
   - 不跳水、`FAULTS` 累加、`LAST_RESULT=4/5/6` → 软件 fault，回头看轴层根因（超时/急停/端口），本报告的电气假设降级。
2. **再做 §5 的母线 min/max 与示波器**：定"是 12V/5V/3.3V 真塌了(P2)"还是"VDD 干净却复位(P6)"。
3. **最后**按 §6 从第 1 级（加电容）开始，单变量改、改一次测一次，不要一次全改。

> 本报告不代替实机证据。在第 1 步的 `TICK_MS` 序列落盘之前，"欠压复位"与"软件故障"都只是候选，不是结论。
