## 1. 系统链路与职责边界（校赛只实施方案 B）

```
MaixCAM Pro ──UART/CP2102/USB──> 树莓派 4B ──USART2──> STM32F407ZGT6 ──> 执行器
（视觉识别）      115200 8N1        （调度+显示渲染）   115200 8N1      （运动+安全）
```

- **MaixCAM Pro**：只做视觉识别与复核应答，输出结构化目标列表；不做调度、不做运动决策、不直连 STM32（方案 A 直连仅预留，校赛不激活）。
- **树莓派 4B**：唯一调度端。消费视觉结果，逐件下发高层任务给 STM32，负责显示渲染与 `DISPLAY_ACK`。
- **STM32**：唯一底层运动与安全控制端。视觉/树莓派**不得**下发逐轴脉冲或实时关节控制。

## 2. 视觉↔树莓派 通信契约（必须遵守）

物理层：MaixCAM UART ↔ CP2102(3.3V) ↔ 树莓派 USB，**115200 8N1**（已冻结）。

外层帧（三设备统一，已冻结）：

| 字段 | 值/规则 |
|---|---|
| 帧头 | `0xA5 0x5A` |
| 协议版本 | `0x01` |
| 设备 ID | 0x01=MaixCAM，0x02=树莓派，0x03=STM32 |
| 任务号/消息序号/数据长度 | 均 2 字节**大端**；消息序号每方独立递增，用于去重幂等 |
| CRC | CRC-16/MODBUS（多项式 0x8005、初值 0xFFFF、无最终异或），**大端输出** |

视觉链命令字（L1）：

| 命令字 | 助记符 | 方向 | 说明 |
|---|---|---|---|
| 0x10 | `BATCH_TARGETS` | MaixCAM→树莓派 | 整批识别结果 |
| 0x11 | `TARGET_REACQUIRE_REQ` | 树莓派→MaixCAM | 请求复核指定目标 |
| 0x12 | `TARGET_REACQUIRE_RSP` | MaixCAM→树莓派 | 复核结果 |
| 0x13 | `DIAG_SCAN` | 默认关闭 | 可选诊断二次核验 |

`BATCH_TARGETS` 数据区（结构已定，**每目标总字节数尚未最终冻结**，见 §6）：
`目标数量(1) + 任务号(2) + 目标[N]`，每目标 = `类别ID(1) + 置信度(1, 0-100) + X(2) + Y(2) + 抓取角度(1, 0xFF=无效)`。

**坐标语义（2026-08-27 拍板，视觉侧最重要的一条）**：
- `BATCH_TARGETS` 的 X/Y 是**图像像素坐标，不做标定**，只用于去重/排序/复核定位，**不进入运动**。
- 运动落点由树莓派按 `box_id → 落点表` 查表得出，与相机坐标无关。视觉侧**不需要也不应该**做相机-世界坐标标定。

**类别/图片 ID（已冻结）**：`image_id == class_id`，1:1 映射；本轮 active 集合为 `{0, 2, 3, 4, 5, 6}`（1=长方体本轮不出现）。抓取角度恒 `0xFF`（夹爪不旋转）。

## 3. 下游链路概要（视觉只需了解，不需实现）

树莓派→STM32 用 `ITEM_TASK`(0x21) 逐件下发，8 字节载荷已冻结（X/Y 有符号 16 位 0.1mm、原点=装置中心、±145.0mm 越界拒绝、角度恒 0xFF）。逐件主链时序：

`BARRIER_READY` → `ITEM_TASK` → `MOTION_DONE` → `ITEM_RESULT` → 树莓派实际渲染完成 → `DISPLAY_ACK` → 允许下一件。

对视觉的含义：**系统一次只处理一件**。上一件的显示确认未完成前，树莓派不会消费下一个目标；视觉的复核请求（0x11/0x12）应在本件运动前的阶段响应，运动中的重询不会延长 15 秒时限。

## 4. 2026-08-30/31 拍板口径（影响视觉理解整机行为）

| 项 | 拍板结论 |
|---|---|
| X/Y 轴 | 17HS4401 步进 ×2，80 steps/mm |
| Z 轴 | **单只 DS3120MG 舵机联动**（升降+夹爪同一舵机）。1000us=下降/张开，1900us=上升/闭合——⚠️ **占位值，禁止硬编码，等机械标定后冻结** ⚠️。无独立夹爪舵机、无腕部旋转 → 这就是抓取角度恒 0xFF 的原因 |
| 挡板 ×4 | MG996R，**纯时序控制**（确定时间+速度）：发 PWM 后按标定固定延时视作就绪，**无位置反馈**。`BARRIER_READY` = 延时结束，不是位置验证 |
| 限位 | 六路已采购（X_HOME/X_END/Y_HOME/Y_END/Z_UP/Z_DOWN），STM32 负责回零/限位/故障保护 |
| 串口 | 树莓派↔STM32 主链 **USART2**（PA2/PA3），USART3（PD8/PD9）备用（固件待 CubeMX 落地） |
| 失电许可 | POWER_PERMISSION 暂不启用，急停反馈 ESTOP_FB 兜底 |

## 5. 视觉侧交付义务清单

1. **识别输出**：按 §2 帧格式发送 `BATCH_TARGETS`；类别 ID 严格用 active 集 `{0,2,3,4,5,6}`；置信度 0-100。
2. **复核能力**：实现 `TARGET_REACQUIRE_REQ/RSP`——树莓派对单个目标请求复核时，视觉须重新识别并应答（逐件抓取前的复核是调度链的一部分）。
3. **幂等**：消息序号单调递增；收到重复帧按契约重发上次应答，不重复上报。
4. **不越界**：不做坐标标定、不做调度决策、不直发 STM32、不发送契约之外的命令字。
5. **协议测试**：CRC-16/MODBUS 实现须与树莓派/STM32 端对齐（同一测试向量互通过）。
6. **补光配合**：补光稳定时间（曝光测试）由视觉侧实测给出，用于冻结时序参数。
