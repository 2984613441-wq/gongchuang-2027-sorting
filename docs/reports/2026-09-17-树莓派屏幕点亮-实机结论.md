# 树莓派屏幕点亮 · 实机结论（2026-09-17 凌晨）

> 执行：用户（实体操作）+ DSH（诊断、脚本、定因）
> 状态：**屏幕"能否点亮"这一环已实机验证通过**；项目自身的显示代码仍未跑通（原因见 §3.1、§3.2）
> 环境：Raspberry Pi（`172.20.10.8`，`Linux raspberrypi 6.1.21-v8+ aarch64`）
> 证据形式：全部为实机终端输出原文，已逐条附在 §5

---

## 0. 一句话结论

**树莓派默认的 `vc4-kms-v3d` 驱动下，`/dev/fb0` 直写不会显示到物理屏**；
把驱动切成 `vc4-fkms-v3d` 后，同一条命令立刻出图。**项目整套"直写 fb0"的显示方案
（`display_hdmi.py`、`run_chain.py --frame-output fb0`）的前提是 fkms/legacy + 无桌面，
而平台默认给的是 KMS + 图形桌面 —— 这是设计前提与平台默认值的错配，不是接线或代码 bug。**

## 2. 关键发现

### 2.1 🔴 根因：KMS 驱动下 fb0 是"影子"

- `/boot/config.txt:62` 原为 `dtoverlay=vc4-kms-v3d`（生效），`:81` 的 `vc4-fkms-v3d` 被注释
- `systemctl get-default` = `graphical.target`；`Xorg :0 -seat seat0 ... vt7` 在跑
- KMS 下：桌面经 **DRM 直连**显示，`/dev/fb0` 只是兼容层
- **佐证**：`sudo fuser -v /dev/fb0` **无输出**（X 根本不打开 fb0，却仍占着屏）
- **佐证**：`cat /sys/class/graphics/fb0/blank` **无输出**（KMS 的 fbdev 仿真缺该节点）

### 2.2 🔴 `install.sh` 的屏配置块在 KMS 下等于白写

`电控/deploy/install.sh:50-61` 写入的 `hdmi_force_hotplug` / `hdmi_group` / `hdmi_mode` /
`hdmi_cvt 1024 600 60 6 0 0 0` **全是旧固件驱动语法，KMS 下被忽略**。
切到 fkms 后立刻生效 —— 第 8 步的 `1024x600 @ 60.00Hz` 就是它的效果（切之前无效）。

> 推论：**任何声称"跑过 install.sh 所以屏配置已生效"的说法都不成立**，必须以 `tvservice -s` 为准。

### 2.3 fb 是 16bpp，不是 32bpp

- 实机 `bits_per_pixel = 16`（RGB565），`virtual_size = 1024x600`，`line_length` 读不到
- 16bpp 一帧 = `1024×600×2 = 1,228,800` 字节；按 32bpp 写 1,843,200 字节 → **多写 614,400 字节越界**（§3.4 的 Errno 28）
- `framebuffer_depth=32` 追加到 `/boot/config.txt` 第 96 行（**在 `[all]` 段内，位置正确**），重启后 **bpp 仍为 16** → **fkms 下该 legacy 选项似不被采纳**

### 2.4 🔴 Python 3.9 与 `slots=True` 不兼容（主链级阻塞）

- 树莓派 `python3 --version` = **Python 3.9.2**
- `electrical_control` 全包 **36 处 `@dataclass(..., slots=True)`，跨 14 个文件**，**零版本守卫**
- `dataclass(slots=True)` 是 **Python 3.10+** 才有的参数
- 实机报错（首次 import 即失败）：
  ```
  File "/opt/ec-chain/src/electrical_control/protocol/types.py", line 35
      @dataclass(frozen=True, slots=True)
  TypeError: dataclass() got an unexpected keyword argument 'slots'
  ```
- **含义：`electrical_control` 在这台树莓派上完全无法 import → `run_chain.py` 从未真正运行过。**
  "还没部署过"不是流程疏忽，是**代码与运行时版本不匹配**。

### 2.5 VNC 与 fb0 直写不可兼得

- fb0 直写要生效，**必须让 X 停下来**（`sudo systemctl stop lightdm`）
- 停 lightdm **会瞬时切断 VNC**；此时若脚本还要求按键交互，操作者将**无法继续**
  → 因此贴图工具必须支持**零交互自动轮播**（`--auto N`，见 §4）

### 2.6 其他实机教训

| 教训 | 说明 |
|---|---|
| **`/tmp` 重启即清空** | 第一次放在 `/tmp` 的脚本与样张，重启后全部消失。部署物应放家目录或 `/opt`（`/opt/ec-chain` 为 root 所有，`pi` 不可写，需 sudo） |
| **`install.sh` 的 pip 走 piwheels 极慢** | `pip install --upgrade pip` 从 `www.piwheels.org` 下载，实测 5.3 kB/s，`ReadTimeoutError`；因脚本是 `set -euo pipefail`，**第 2 步失败直接中止第 3/4 步**（`.pth` 未写、config.txt 未配） |
| **依赖其实用 apt 就够** | `requirements.txt` 只需 `pyserial` + `pillow`，二者的 apt 包（`python3-serial` / `python3-pil`）走清华源秒装，可完全绕开 pip |
| **VNC 括号粘贴会污染命令** | 多行粘贴时终端发 `ESC[200~`，bash 报 `$'\E[200~cd': command not found`。**一行一条地粘**最稳 |

## 4. 现场可用命令（已实机验证）

```bash
# 一条命令：停桌面 → 6 张图各停 3 秒自动切换 → 恢复桌面
#（SSH 不会断，只有物理屏在切换；VNC 会断开约 18 秒后自行恢复）
sudo systemctl stop lightdm ; python3 /home/pi/pi_blit_png.py /dev/fb0 '/home/pi/frames/*.png' --auto 3 ; sudo systemctl start lightdm
```

`/boot/config.txt` 当前改动（已备份 `config.txt.bak.*`）：
```
62:#dtoverlay=vc4-kms-v3d
81:dtoverlay=vc4-fkms-v3d
96:framebuffer_depth=32     ← 未生效（bpp 仍为 16）
```
