# 数据集采集与标注 · 任务书（给标注同学）

> 这份文档可以直接转给负责标注的同学。
> **前提**：你只能通过 **MaixVision** 操作 MaixCAM，**不能 SSH 树莓派**。
> 所以下面会明确写清楚"你能做什么"和"你做不到什么、由我们提前准备好"。

---

# 一、先搞清楚边界

## ✅ 你能做的

| 能力 | 怎么做 |
|---|---|
| 在 MaixCAM 上跑脚本 | MaixVision 里打开文件 → 点运行 |
| 看相机实时预览 | MaixVision 的预览窗口（MaixCAM 屏幕上也有） |
| 把 MaixCAM 上的文件下载到电脑 | MaixVision 的文件面板 |
| 在你自己的电脑上标注 | LabelImg（见 §四） |

## ❌ 你做不到、由我们负责的（**不要去尝试**）

| 我们负责的事 | 为什么你做不到 |
|---|---|
| **补光灯的开/关** | 补光灯接在 **STM32** 上（PC0），由树莓派发命令控制。你没有树莓派权限 |
| **移动机械臂 / 改落点** | 同上，需要树莓派发命令 |
| **修改树莓派上的相机标定** | 需要 SSH |
| **修改 `/root/stage1_color_v6_send.py`（生产视觉程序）** | 这是比赛用的生产代码，改了会影响分拣 |

> 🔴 **如果补光灯没亮、或者亮了但发蓝/发黄，立刻告诉我们，不要自己想办法。**
> 那是 STM32 那条链路的问题，不是你能修的。

# 二、我们会在你开始前准备好的

请先确认下面这些都已就绪（**没就绪就开始采，数据会报废**）：

- [ ] **补光灯常亮**（中性白光，不是偏蓝也不是偏黄）—— 由我们用树莓派开
- [ ] 相机的**高度和角度固定**（采数据全程不能动）
- [ ] **托盘位置固定**（不能挪）
- [ ] 相机**对焦清晰**（画面不糊）
- [ ] MaixCAM 上 `/root/capture.py` 是**最新版**（运行时会打印 `FRAME_W` 相关日志，见 §三）

> ⚠️ **补光灯一旦开了就必须全程保持开着。** 中途关灯/开灯会让前后数据的光照不一致，
> 模型学不到稳定的颜色特征。

# 三、第一步：采集数据（在 MaixVision 里做）

## 3.1 启动

1. 打开 **MaixVision**，连接 MaixCAM
2. 打开设备上的文件 **`/root/capture.py`**
3. 在代码顶部确认这两行是 **1280 / 720**：
   ```python
   CAPTURE_W = int(os.environ.get("CAPTURE_W", "1280"))
   CAPTURE_H = int(os.environ.get("CAPTURE_H", "720"))
   ```
   如果是 320，说明文件是旧版，**停下来告诉我们**。
4. 点运行（▶）

## 3.2 确认启动正常

运行后，输出窗口应该依次出现：

```
capture dir: /root/capture/session_1792309053
[1/3] camera OK  1280x720
[2/3] display on
[3/3] 预标注已关闭（NO_PRELABEL=1）—— 只存图片，.txt 留空
[warmup] 跳过前 2.0s（等 AE/AWB 收敛）
[warmup] done
saved img_00000.jpg  (0 obj)
saved img_00001.jpg  (0 obj)
...
```

**看到 `saved` 连续出现就说明在正常采集。**

> 如果这里报 `No buffer space available` 或 `SIGSEGV` → **相机被别的程序占着**，
> 告诉我们，我们远程处理（你处理不了，需要杀进程）。

## 3.3 采集节奏

默认**每 1 秒存一张**。摆好一组物料 → 等它存 3~5 张 → 换下一个摆法。

想改节奏的话（可选）：在 MaixVision 里把这一行改成你要的秒数
```python
INTERVAL_S = float(os.environ.get("INTERVAL_S", "1.0"))   # 0.5 = 每 0.5 秒一张
```

## 3.4 ⚠️ 采什么、怎么摆（**最关键的部分**）

### 要覆盖的 7 类物料

| class_id | 中文 | 英文 | 形状特征 |
|---|---|---|---|
| 0 | 立方体 | cube | 正方体，六面相等 |
| 1 | 长方体 | cuboid | 三边不等（2:1:1、3:2:1） |
| 2 | 圆柱 | cylinder | 圆截面 + 直边 |
| 3 | 六棱柱 | hexagonal_prism | 六边形截面 + 直边 |
| 4 | 五棱柱 | pentagonal_prism | 五边形截面 + 直边 |
| 5 | 四棱锥 | square_pyramid | 正方形底面 + 汇聚顶点 |
| 6 | 三棱柱 | triangular_prism | 三角形截面 + 直边 |

> **注意**：本轮 `1 = cuboid` 可能没有实物。有就拍，没有就跳过（后面告诉我们哪些类没拍）。

### 摆放要求（每种摆法拍 3~5 张就换）

| 维度 | 要拍的情况 |
|---|---|
| **位置** | 托盘**左 / 中 / 右 / 上 / 下** 都要有；靠近画面边缘也要有 |
| **数量** | 1 个、2 个、3 个、最多 5 个都要有 |
| **朝向** | 同一个物料**转不同角度**（转 30°/60°/90°） |
| **种类混搭** | 纯单一类别的场景 + 混合多类别的场景都要有 |
| **间距** | 紧挨着放 / 分开很远放，都要有 |

### ❌ 绝对不要的

| 禁止 | 原因 |
|---|---|
| **手、工具、胳膊入画** | 模型会把它们学成物料 |
| 物料超出画面（被裁掉一角） | 会教坏模型 |
| 强反光/过曝 | 颜色判据失效 |
| 空托盘拍几十张 | 浪费标注时间 |
| 画面里只有 1 个物料、反复拍 100 张 | 分布失衡，模型过拟合 |
| 采集中途挪动相机/托盘/补光灯 | 数据不一致，前面全部作废 |

### 数量目标

```
每个类别 ≥ 150 个标注框
总图片数 ≥ 500 张
```

## 3.5 停止并下载

1. 点 MaixVision 的**停止按钮**
2. 用 MaixVision 的文件面板找到 `/root/capture/session_xxxxxxxx_xxxxx/`
3. **把整个 session 目录下载到你的电脑**

目录里长这样：
```
session_1792309053/
├── img_00000.jpg      ← 1280×720 原始图
├── img_00000.txt      ← 空文件（预标注已关闭）
├── img_00001.jpg
├── img_00001.txt
└── ...
```

# 四、第二步：标注（在你自己的电脑上做）

## 4.1 安装 LabelImg

```bash
pip install labelImg
labelImg
```

## 4.2 配置（**这一步最容易出错，务必按顺序**）

1. **Open Dir** → 选你下载下来的 `images`（放 `img_*.jpg` 的那个目录）
2. **Change Save Dir** → 选 `labels` 目录
3. 点一下左边的 **PascalVOC** 按钮，让它切换成 **YOLO** 格式
4. **Load** → 加载 `class.txt`（见下）

## 4.3 🔴 类别的 `class.txt`（必须用这份，顺序不能变）

保存成 `class.txt`：

```
cube
cuboid
cylinder
hexagonal_prism
pentagonal_prism
square_pyramid
triangular_prism
```

> ⚠️ **加载后必须点开类别下拉框数一下：是不是 7 个、顺序对不对。**
> LabelImg 精简版有时读不到 `class.txt`，会按"你第一次输入的名字顺序"编号，
> 导致**类别整体错乱**（历史上踩过，靠脚本才救回来）。

## 4.4 标注规范

每行一个物体，格式：
```
<class_id> <x_center> <y_center> <width> <height>
```
所有值归一化到 **0 ~ 1**。

### ✅ 好的标注
```
0 0.512 0.345 0.123 0.234     ← 框紧贴物体边缘，数值合法
2 0.789 0.567 0.098 0.156
```

### ❌ 坏的标注
```
1 0.512 0.345 0.123 0.234     ← 类别错（cube 标成 cuboid）
0 0.512 0.345 0.500 0.600     ← 框太松（背景占一半）
2 0.789 0.567 0.050 0.080     ← 框太紧（物体边缘被裁）
0 1.200 0.345 0.123 0.234     ← 坐标越界（> 1.0）
```

### 常见错误排查
| 症状 | 原因 |
|---|---|
| 保存的 `.txt` 是空的 | 没切换到 YOLO 格式（还是 PascalVOC） |
| 坐标超过 1.0 | 框拉到画面外了，钳位回 [0,1] |
| 类别编号全错开 | `class.txt` 没加载成功，重新 Load |

## 4.5 自检

标完抽查 20~30 个 `.txt`，确认：
- [ ] class_id 在 0~6
- [ ] 所有数值在 [0, 1]
- [ ] 框和物体对得上
- [ ] 没有漏标/多标

# 五、交付什么

请把下面这些打包给我们：

```
交付/
├── images/          ← 所有 img_*.jpg（1280×720）
├── labels/          ← 所有同名 img_*.txt（YOLO 格式）
├── class.txt        ← 上述 7 类清单
└── 说明.txt         ← 请写清楚：
                        1. 哪些类别没拍到（比如没有 cuboid）
                        2. 总图片数、总标注框数
                        3. 采集中途有没有动过相机/托盘/灯光
                        4. 有没有遇到异常（崩溃、报错、卡住）
```

**⚠️ 文件名必须一一对应**：`img_00000.jpg` ↔ `img_00000.txt`。

# 六、🚫 禁止事项（会很麻烦）

| 禁止 | 为什么 |
|---|---|
| 不要改 `/root/stage1_color_v6_send.py` | 那是比赛生产代码 |
| 不要动 `/etc/init.d/` 下任何文件 | 会破坏开机自启配置 |
| 不要改 `/root/my_models/` 里的模型 | 比赛要用的 |
| 不要试图 SSH 树莓派 / 连 `172.20.10.8` | 你没有凭据，而且可能干扰运行中的程序 |
| 不要在采集中途拔 / 插相机 USB | 会导致媒体系统卡死，只能整机断电恢复 |
| 不要连续不停地快速启动/停止脚本 | 反复开关相机会让驱动进入坏状态 |

# 七、遇到这些情况怎么办

| 现象 | 处理 |
|---|---|
| `No buffer space available` / `SIGSEGV` | **停下来**，告诉我们。大概率是相机被别的程序占着，需要远程杀进程 |
| `model_type key not found` | 不用管，`NO_PRELABEL=1` 模式下不会加载模型 |
| 画面全黑 / 全白 | 告诉我们，可能是灯或曝光问题 |
| 补光灯不亮 / 偏蓝偏黄 | **告诉我们**，这是 STM32 侧的问题 |
| 脚本运行了但不出 `saved` | 检查 `capture dir` 那行有没有打印；把日志发给我们 |
| 图片是 320×320 不是 1280×720 | 说明是旧版 `capture.py`，**停下来告诉我们** |
