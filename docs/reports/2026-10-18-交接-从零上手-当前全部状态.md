## 2.3 ToF（MINIF DVP0501C1）—— 协议与踩坑

**协议是 ASCII，不是二进制！**（仓库里的 `AA 55` 二进制协议文档是错的）

```
帧格式：0x20 + 数字(1..5位) + 0x2C 0x20 + 置信度(1..2位) + 0x0A
例：  " 327, 61\n"
```

| 参数 | 值 |
|---|---|
| 波特率 | 115200 8N1 |
| 量程 | 20 ~ 4500 mm |
| 置信度 | 0 ~ 62（越大越可信） |
| 刷新率 | 30 Hz |
| 引脚 | 1=VCC(**5V**) / 2=RXD / 3=TXD / 4=GND / 5,6=NA |
| 供电 | **4 ~ 5.6V**（**不能用 3.3V！**） |
| 保护 | ⚠️ **无过压保护、无防反接** |

**🔴 我们踩过最大的坑**：ToF 显示 `valid=0 raw=0 frames=0` 查了很久，
寄存器 dump 显示 UART4 完全正常（`gState=0x20 RxState=0x22 CR1=0x202C SR=0xC0`），
**最后发现是 ToF 没供上电**。修好供电后立刻 30Hz 出数。

> **教训**：`raw=0` 时**先查供电和接线**，不要在协议/波特率上浪费时间。
> 诊断手法：`TOFDBG` 看寄存器 → 若软件侧正常则一定是硬件。

## 2.4 补光灯（WS2812）—— 接线与色温

**接线**：

```
降压模块 5V ──┬──► WS2812 VDD（并 1000µF 电解电容到 GND）
              │
降压模块 GND ─┴──► WS2812 GND  ══► 必须与 STM32 GND 共地
STM32 PC0 ──[330Ω]──► WS2812 DIN
```

| 项 | 值 |
|---|---|
| 灯珠数 | **16 颗** |
| 单颗功率 | 0.3W（满载 16×0.3 = **4.8W ≈ 1.0A @5V**） |
| 5V 容量要求 | **≥1A**（建议 ≥1.5A 留余量） |
| 控制协议 | **800kHz 单总线**（不是普通 GPIO 开关！） |
| 固件实现 | 软件位模拟，DWT→CYCCNT 自校正（`ec_light_ws2812.c`） |
| **白光标定值** | **RGB = (255, 200, 90)** ← 见 §5.4 |

**⚠️ `DETECT_SIZE` 从 224 改成 400 的原因（很重要）**：
代码是"按最长边等比缩放"，不是压扁。改分辨率后如果不同步改 `DETECT_SIZE`，

```
旧：0.5766 mm/px ÷ (224/320)  = 0.824 mm/px
新：0.2563 mm/px ÷ (400/1280) = 0.820 mm/px   ← 基本一致
```

# 5. ⚠️ 已知陷阱清单（**必读，全踩过**）

## 5.1 MaixCAM 相机是**独占设备**，且开机有程序抢占

**症状**：任何程序开相机报
```
VI_SDK_IOC_S_CTRL - vi_sdk_enable_chn NG, No buffer space available
Trigger signal, code:SIGSEGV(11)!
```
或 `CVI_SYS_Bind(VI-VPSS) failed` / `mmf add vi channel failed`

**根因**：`/etc/init.d/S99vision`（2026-09-22 我们自己加的）开机拉起
`/root/vision_supervisor.sh` → 它监督并不断重启
`/root/forensic/stage1_color_v6_send.py` → **该进程独占相机，且被杀就被监督器重拉**。

**处理**：
```bash
# 临时（推荐）
touch /tmp/vision_pause
ps | grep '[s]tage1_color_v6_send' | awk '{print $1}' | xargs -r kill
# 恢复
rm -f /tmp/vision_pause

# 或者停整套
/etc/init.d/S99vision stop

# 当前状态：S99vision 已被移出 init.d ⇒ 开机不自启
# 比赛前要恢复：
mv /root/S99vision.bak-auto /etc/init.d/S99vision && reboot
```

**⚠️ 两个或多个程序同时开相机会互相踢死，进程可能卡在 `D`（不可中断睡眠）状态，
`kill -9` 都杀不掉 ⇒ 只能整机断电重启。**

**⚠️ 反复快速开关相机（如连拍很多次）也会让媒体系统进入坏状态** —— 每次开完要留间隔。

## 5.2 MaixPy 请求正方形会**裁剪**传感器，不是缩放

传感器是 **2560×1440（16:9）**。请求 1:1（例如 320×320 或 1440×1440）时，
它从中间**裁出 1440×1440** 再缩放 ⇒ **水平只用 56.25%，左右各丢 22%**。

| 请求宽高比 | 水平视野 | 垂直视野 |
|---|---|---|
| 1:1 | 56% | 100% |
| 4:3 | 75% | 100% |
| **16:9** | **100%** | **100%** |

**要看全宽度必须用 16:9。**

## 5.3 模型加载必须用 `.mud`，不能传 `.cvimodel`

```python
nn.YOLO11(model="/root/my_models/model_8629.mud")      # ✅
nn.YOLO11(model="/root/my_models/model_8629.cvimodel") # ❌ model_type key not found
```
`.mud` 是 300 字节的元数据文件（含 `model_type = yolo11`），`.cvimodel` 只是裸权重。

## 5.4 🔴 WS2812 的 `R=G=B` **不是白光**

三色 LED 发光效率不同（红最弱蓝最强）。实测白纸：

| RGB | 白纸 RGB 输出 | 饱和度 S |
|---|---|---|
| (180,180,180) | (122, 148, 226) | **45.92%** ❌ 严重偏蓝 |
| (222,183,120) | (163, 161, 192) | 16.14% ❌ |
| (255,210,138) | (164, 162, 195) | 16.84% ❌ |
| **(255,200,90)** | **(176, 171, 177)** | **2.20%** ✅ |
| (255,180,70) | (177, 171, 175) | 3.41% ✅ |
| (255,160,60) | (181, 170, 178) | 6.11% |

**固件已写入 `(255, 200, 90)`**（`ec_light_ws2812.h` 的 `EC_WS2812_WHITE_R/G/B`）。
**换灯珠批次必须重新扫这组值。** 任何用 RGB 灯做机器视觉补光的场合都适用。

## 5.7 其他零碎陷阱

| 坑 | 说明 |
|---|---|
| 串口中文 | Keil ARMCC 报 `#870-D invalid multibyte character sequence`，C 字符串里**只能用 ASCII** |

# 6. 还没做完的：**相机标定（下一步唯一阻塞项）**

## 6.1 为什么必须重标

1. 当前值是**数学换算**出来的，不是实测
2. 用户**把托盘降下来了**（为了扩大视野），`camera_height = 262.0` 已失效
3. 相机曾经调过焦/动过位置，9-22 的五点解不再可信

## 6.2 推荐方法：**用机械臂当尺子**（不需要尺子，最准）

机械臂的移动距离由 `steps_per_mm = 80`（实测确认 50 次）保证，比量尺子准。

| 步骤 | 机械臂位置 | 做什么 |
|---|---|---|
| 1 | **(x=0, y=0)** | 拍照，记录夹爪/工具头在画面里的像素位置 |
| 2 | **(x=+50, y=0)** | 拍照，量像素位移 |
| 3 | **(x=0, y=+50)** | 拍照，量像素位移 |

**从中可得**：
- `50mm ÷ 像素位移` = 精确的 mm/px
- 位移方向 = 图像旋转角（当前约 90°）
- 三个点的绝对位置 = 完整仿射矩阵（a11/a12/a21/a22/tx/ty）

## 6.3 备用：四点/五点标定（历史方法）

之前用的是"五点解"（把物料推到托盘边缘取点），脚本可能是
`工具/calib_photo.py` 或 `校准/` 下的工具。**新方法更好，因为它不依赖托盘边缘的物理精度。**

## 6.4 标定完要做什么

1. 把新 `a11/a12/a21/a22/tx/ty` 写入 `/home/pi/电控/calibration_config.ini`
2. 更新 `camera_height`
3. **确认补光灯常亮下重新锁 AWB**（见 §6.5）
4. 跑一次 `run_chain.py` 验证抓取落点

## 6.5 ⚠️ 补光灯改了照明 ⇒ AWB 必须重锁

生产代码 `stage1_color_v6_send.py` 里是**锁死 AE/AWB 的**（2026-09-21 加的）。
现在照明条件变了（加了补光灯），旧的锁定值不对。

**采数据 / 比赛前必须**：
1. 补光灯 **`LIGHT ON` 保持常亮**
2. 让相机在当前光照下自动白平衡到中性后**再锁死**
3. 然后才开始采数据集 / 跑生产

### 关于模型输入尺寸的依据

MaixCAM 官方文档 <https://wiki.sipeed.com/maixpy/doc/zh/ai_model_converter/maixcam.html> 明确：
- **支持非正方形输入**（示例即 `--input_shapes [[1,3,224,320]]`，原文"常用输入尺寸 320x224"）
- 必须**固定**尺寸（不支持动态）
- **H/W 需为 32 的倍数**（候选框公式含 `H/8, H/16, H/32`）
- `.mud` 的 `model_type` 必须是 MaixPy 支持的（`yolov5`/`yolov8`/`yolo11`/`classifier`）
- 转换用 `tpu-mlir` 三步：`model_transform.py` → `run_calibration.py` → `model_deploy.py`

**选 736×416 的理由**：宽高比 1.769 ≈ 16:9 的 1.778，偏差仅 0.5%，几乎不用 letterbox；
且 736=23×32、416=13×32，满足 32 倍数要求。
