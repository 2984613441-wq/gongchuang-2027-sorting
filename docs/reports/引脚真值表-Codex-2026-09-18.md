## 结论

以下是**当前工作树源码的唯一答案**，不是按头文件注释或 CubeMX 引脚表单独推断：

| 信号 | 唯一引脚 | 外设通道 / 电平语义 | 直接证据 |
|---|---|---|---|
| `STEP_X` | **PC6** | **TIM8_CH1** PWM 脉冲 | `App/Src/ec_board_stm32.c:117-123` 将 X 映射到 `htim8`；`:164-190` 用该 timer 的 `TIM_CHANNEL_1` 启动 PWM；`Core/Src/stm32f4xx_hal_msp.c:254-263` 将 TIM8_CH1 复用到 PC6 |

因此，交接文档 §A 中“`STEP_X=PB0`、`STEP_Y=PB1`”的待确认推断应判定为**错误**。正确组合是：

```text
X: STEP=PC6, DIR=PA7, ENABLE=PA5
Y: STEP=PB6, DIR=PC7, ENABLE=PD7
```

## §B 冲突 1：舵机 PWM 是 PB10，不是 PB11

以 `ec_servo_port_start()` 的实际操作为准，生产 PWM 路径是 **PB10 = TIM2_CH3**：

1. `App/Src/ec_board_stm32.c:510-518` 中，`ec_servo_port_start()` 先调用 `grip_pin_select(GPIO_AF1_TIM2)`，再设置并启动 `htim2` 的 `TIM_CHANNEL_3`。
2. `App/Src/ec_board_stm32.c:226-240` 中，`grip_pin_select()` 实际重配的是 `GPIOB` 的 `GPIO_PIN_10`，即 PB10；传入的 AF 是 `GPIO_AF1_TIM2`。
3. 因此实际链路为：**PB10 → AF1/TIM2 → CH3**。

PB11 对应的是另一条旧入口：`Core/Src/stm32f4xx_hal_msp.c:189-199` 在初始化时把 PB11 配成 TIM2_CH4；`App/Src/ec_board_stm32.c:599-605` 的 `ec_servo_port_start_z()` 也确实启动 `htim2/TIM_CHANNEL_4`。但生产 `ec_servo_port_start()` 不调用这条 CH4 路径。

表面冲突的原因是 PB10 有运行时复用：启动时 `Core/Src/stm32f4xx_hal_msp.c:484-499` 将 PB10 配为 USART3_TX；调用 PWM 路径时，`grip_pin_select(GPIO_AF1_TIM2)` 再将同一物理脚切回 TIM2_CH3。反方向的总线舵机发送路径会在 `App/Src/ec_board_stm32.c:243-255` 把 PB10 切回 USART3_TX。两种功能不能同时输出。

**裁决：**题目所问的舵机 **PWM** 唯一答案是 **PB10 / TIM2_CH3**。**PB11 / TIM2_CH4 只属于仍留在源码中的旧 `ec_servo_port_start_z()` 路径，不是生产 PWM 路径。**

## §B 冲突 2：PB0/PB1 不是 STEP

步进端口没有使用 TIM3：

- `App/Src/ec_board_stm32.c:117-123` 的 `step_timer_for_axis()` 明确返回 `X→htim8`、`Y→htim4`。
- `App/Src/ec_board_stm32.c:296-329` 的 `ec_step_port_start_counted()` 把轴交给 `start_axis_counted()`；后者在 `:164-190` 对返回的 timer 启动 `TIM_CHANNEL_1`。
- 非计数入口 `ec_step_port_start()` 也在 `App/Src/ec_board_stm32.c:278-293` 通过同一个 `step_timer_for_axis()` 选择 timer，并只启动 CH1。

PB0/PB1 的真实用途是挡板 PWM：`Core/Src/stm32f4xx_hal_msp.c:211-221` 映射 PB0→TIM3_CH3、PB1→TIM3_CH4；`App/Src/ec_board_stm32.c:531-547` 将挡板 mask 的 `0x01/0x02` 分别启动为 `htim3` CH3/CH4。

**裁决：**`STEP_X/STEP_Y` **不是** PB0/PB1，而是 **PC6/PB6**。

## TIM8 / TIM9 / TIM10 / TIM11 四通道用途

| 通道（引脚） | 当前源码用途 | 判定证据 |
|---|---|---|
| **TIM8_CH1（PC6）** | **X 轴 STEP** | `App/Src/ec_board_stm32.c:117-123` 的 X→`htim8`；`:164-190` 启动 CH1；`Core/Src/stm32f4xx_hal_msp.c:254-263` 映射 PC6 |
| **TIM9_CH1（PE5）** | **已初始化但未被应用层启动，当前无业务用途** | `Core/Src/main.c:469-490` 只做 PWM 初始化；`Core/Src/stm32f4xx_hal_msp.c:275-284` 只做 PE5 AF 映射；`App/Src/ec_board_stm32.c:17-22` 的业务 timer 声明不含 `htim9`，`:117-123` 的步进映射也不含 TIM9。全量检索 `htim9` 在 App 下为 0 命中 |
| **TIM10_CH1（PF6）** | **挡板 PWM 第 3 路**（mask `0x04`） | `App/Src/ec_board_stm32.c:549-551`；`Core/Src/stm32f4xx_hal_msp.c:296-305` 映射 PF6 |
| **TIM11_CH1（PF7）** | **挡板 PWM 第 4 路**（mask `0x08`） | `App/Src/ec_board_stm32.c:553-555`；`Core/Src/stm32f4xx_hal_msp.c:317-326` 映射 PF7 |

补充：挡板前两路是 TIM3_CH3/PB0 与 TIM3_CH4/PB1，见 `App/Src/ec_board_stm32.c:541-547`。因此四路挡板 PWM 的当前代码排列是 PB0、PB1、PF6、PF7；TIM9/PE5 不在其中。

## 证据边界与复核

- 本报告只给出**当前源码的引脚/通道真值**，没有修改 `.c/.h`，没有烧录、上电或发运动命令。
- 本报告不能证明这些信号已从对应 MCU 管脚到达驱动器，也不能证明实机接线、驱动电源或电机相线正确。
- `TIM9` 的“当前无业务用途”来自当前树的负向检索：`App/` 下不存在 `htim9` 引用；它仍在 CubeMX 生成的 Core 初始化代码中存在，不能据此认定为可随意复用。
- 复核口径：六个目标信号均有“业务函数映射 + GPIO/AF 定义”两层证据；两个 §B 冲突均已收敛，无【待确认】项。
