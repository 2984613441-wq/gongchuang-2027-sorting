## 2. MaixCAM 的三个实际代码流程

### 2.1 当前交接路线：V6

`camera.Camera(320,320,RGB888)` → 共享RGB数组 → 内部缩到224 → 按六种颜色独立 HSV 掩码、开闭运算、轮廓 → 面积/边缘/形状比例/颜色纯度筛选 → 每色取最大区域 → 恢复320原帧 bbox → 连续确认/平滑/HOLD → 编成 BATCH → TCP发送 → 叠框显示。入口没有加载任何 ONNX/MUD 或 YOLO；形状是 `COLOR_TO_MATERIAL` 查表结果（V:193–219,223–273,345–379）。

细节及其后果：

- 只有 cyan/green/red/blue/black/orange 参与分类；虽定义 yellow 阈值，循环只遍历六色映射，所以黄色不会成为第七类（V:184–197,223）。
- `CONFIRM_FRAMES=2`；确认前不发，漏检短时仅留灰色 HOLD 框并把 `bin=None`，发送器丢掉；超过0.30秒不再保留（V:169–172,301–319,49–53）。主机真实 tracker 结果：首帧0、次帧货格1、HOLD不发、过期0（Q:33）。
- `analyze` 每色只保留最大面积候选，tracker 又按颜色建键。因此“2个同色物块”不能按2件输出；每帧 `target_count` 是当次可发送候选数，**不是台面总件数或累计成功数**（V:269–271,284–296；累计成功另由 `电控/src/electrical_control/protocol/item_context.py:214–243` 按结果维护）。Q:34 的人工同色 row 只验证 tracker 合并，图像候选上限以 analyze 源码为据。
- 贴 ROI 边的轮廓直接拒绝，不能把“画面能看见”当“候选一定保留”；现场视野已够用，本次不调整相机（V:216–217,237–242；`docs/交付/2026-09-18/分工提示词-七点拆解.md:97–99`）。
- “像素原样”指**同一320坐标系，无向毫米或其他帧尺寸缩放**；bbox经过检测还原与时序平滑，中心再用 `int(left+w/2)` 截断为整数，不是未处理的原始测量浮点数（V:261–268,299–315,54–62）。
- wire confidence 为 `round(color_fraction*100)` 并夹到0–100；它不是模型分类概率，Pi接入/最近邻选择路径也没有按 `[Vision] confidence_threshold` 再过滤它（V:59–62；I:128–140；S:155–170,195–213）。

### 2.2 历史 `main.py`

默认读板端 `/root/my_models/model_8766.mud`，`nn.YOLOv8(...,dual_buff=True)`；按模型宽高开相机；逐帧检测，过滤越界框和形状id1；有目标时原形状id组帧发TCP，可选调试 comm，同时显示/监控；无目标每500ms发空批心跳（M:29–50,378–387,427–479）。

本文件**未接入** `sorting_vision` 的 MMCQ→形状/颜色联合分组→`BoxAssignment`。这条纯逻辑方案确实存在（`视觉/src/sorting_vision/sort_plan.py:3–10,50–94`），但不能把“模块存在”写成“main 已经调用”。main 的 id 是 `obj.class_id`，无颜色折叠（M:342–368）。默认 TASK_ID=0 也与当前轮次1不符（M:36；V:39；S:227–229）。

因此即便旧 main 读取的设备模型恰好是320，也不能把它直接作为当前 V6 的替代。其 `detector.labels` 来源是设备模型，不能由本机 README 推定（M:472）。

### 2.3 `capture.py`

这是**采图和自动预标注工具**：默认 `model_8629.mud`、`nn.YOLO11`，宽高来自模型；每秒保存干净JPEG和同名归一化YOLO标签，然后显示框。它不负责 BATCH、货格分配或网络发送，也不保证固定320（C:27–31,34–45,48–84,89–101）。0.30是预标注阈值，不能代替现场V6颜色标定（C:29）。

## 3. BATCH_TARGETS：逐字段线格式对照

当前TCP直接发送 **BATCH 数据区**，不是 STM32 的外层帧。线上内容是 `count:u8 + task_id:u16BE + N × (id:u8, confidence:u8, X:u16BE, Y:u16BE, angle:u8)`，总长 `3+7N`；没有额外命令字、CRC、独立颜色或形状字段。TCP按count定长拆包（V:79,147；S:46–80），与后续 `ITEM_TASK` 外层链路区分。

| 字段/偏移 | V6发送 | 独立桥发送 | 旧main发送 | Pi读取/校验 |
|---|---|---|---|---|
| count `[0]` | 过滤后的字节数÷7，V:71–79 | B:91–102 | `len(objs)`，M:358 | I:78,80–85 |
| task_id `[1:3]` | `pack('>H')`，V:67–79 | B:85–102 | `to_bytes(2,'big')`，M:359 | I:79；轮次匹配 S:227–229 |
| 目标起点 `o=3+7i` | 逐目标追加，V:72–75 | B:92–97 | M:360 | I:88–90 |
| id `[o]` | `bin`，范围1..6，V:49–53,62 | B:59–64,77 | **原形状** `obj.class_id`，M:364 | 校赛复制到 class_id/box_id，I:106–118 |
| confidence `[o+1]` | 颜色占比×100，V:59–62 | B:72–77 | 模型score×100，M:363–364 | I:91,128–129 |
| X `[o+2:o+4]` | bbox中心取int、`H`大端，V:54–62 | B:66–77 | M:361,365 | I:92 |
| Y `[o+4:o+6]` | 同上，V:56–62 | B:68–77 | M:362,366 | I:93 |
| angle `[o+6]` | 恒FF，V:43,62 | B:49,77 | M:367 | I:94,130–131 |
| target_seq | 不传；列表位置隐含 | 同左 | 同左 | `index+1`，I:134；拒掉中间id时可不连续 |

**布局一致不等于语义一致。** 实际执行两个V6组帧函数并交给真实Pi解析器，结果逐字节相等；两件框 `(10,20,40,40)`、`(100,120,30,30)`，bin=1/3、fraction=.83、task=7得到（Q:25–26）：

```text
0200070153001e0028ff035300730087ff
→ count=2, task_id=7
→ class_id=box_id=1, confidence=83, pixel=(30,40), seq=1
→ class_id=box_id=3, confidence=83, pixel=(115,135), seq=2
```

空批为 `000007`，真实解析器接受；内存碎片流与两帧粘连均正确拆分；截断、confidence=101、angle=0均抛 `PayloadError`（Q:27–31）。发送器在运行时却跳过空批；Pi因未收到空批而不会清空既存候选，且没有批次时间有效期，导致§1所述旧目标可被保留（V:134–137；S:114,120–132,227–231；Q:46）。

旧 main 按 active 集发 `[0,2,3,4,5,6]` 时，校赛解析器丢掉0，把其余5个**形状号误当货格号**；这不是数据长度错误，是分类语义错误（M:47,444；I:106–118；Q:32）。若只将开关切False，解析后所有box_id=None，真实 `_expand` 全部拒识（I:119–126；S:148–157；Q:47）。

**需纠正文档的地方**：接口契约仍写每目标“待定”、像素“不进入运动”、形状active集排除1（`docs/design/interface-contract.md:134,147,168`）；I文件头也仍写“未冻结”（I:3–6）。现状是像素先在Pi换算再用于抓取，校赛id允许1..6；批准记录为 `docs/交接台账-2026-09-17.md:31–49`。本报告记录差异，不更改线格式或既有裁决文件。

### 4.2 数量、坐标与实际投放边界

Pi只保留最新批次，放行时一批只取最近的一件，距离以毫米抓取点计算；其余不排队，下一件等待新批（S:120–132,167–170,185–208）。这是调度件数，不应与BATCH count混称。主机2件批次只产出1件、再取为None（Q:42）。

现读六落点都为 `(50,50)` mm10；无 `[BoxMap]` 节，读取为 `{}`；缺映射仅记录WARNING而不阻止这六格使用临时坐标（Q:35；`电控/deploy/sorting_config.ini:144–149`；R:350–372,988–992）。因此**知道逻辑货格号**和**把物体放进不同实物货格**之间还没有完成；转盘未到属于既有边界（`docs/交付/2026-09-18/分工提示词-七点拆解.md:14`）。

毫米换算真实发生在Pi：仿射→按高度补偿→工作区校验→mm×10（P:318–355）。本地INI端点粗标加载后 `is_calibrated=True`，抓取工厂优先使用该转换器，`[PickPoint]=(0,-45)mm` 此时不会生效（R:697–720；Q:35–42）。探针用合成中心 `(144,190)px` 得到 `(-5,-455)mm10`，六货格可编码为12字节；这个结果仅验证算法/单位与配置选择，**不证明现场抓取精度**。
