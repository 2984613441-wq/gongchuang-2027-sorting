### 3) 代码侧两处必要改动（随同步落地）

1. **id 字节语义显式化**（`run_chain.py` + `vision_ingest.py`）
   - 新增 `--id-byte-mode box_id|code`（缺省取环境变量 `BATCH_ID_BYTE_MODE`，默认 `box_id` 校赛模式）；
   - 解析逻辑统一按 `BATCH_ID_BYTE_MODE` 判定（旧常量仅留兼容）；
   - 方案C 门禁：id 语义 ≠ box_id ⇒ 拒绝启动（转盘无法判断该翻不翻）；
   - 方案B 门禁：id 语义 = code 且 `--slot-mode` 非 dynamic ⇒ 拒绝启动。
   - 启动日志打印 `BATCH_TARGETS id 字节语义=...`，现场一眼可核对两端是否一致。
2. **方案C 的 `--fake-link` 修复**（`turntable_guard.py`）
   - 模拟 STM32 会**立刻**回 `MOTION_DONE`，此时 `settle_s` 未到 ⇒ 旧逻辑误判"未确认"并锁死，
     导致设备生产配置（方案C）在 Pi 上 `--fake-link` 永远失败；
   - 新增 `demo` 分支：MOTION_DONE 先到 ⇒ 立即读一次索引校验，通过即放行，不符仍锁死；
   - 自检新增 [11c] 覆盖该分支。
