## 一、三路对比视图：`_pi_tools/three_way_view.py`

### 它显示什么

```
[1] 主相机判断（MaixCAM → BATCH_TARGETS）
    seq=1 形状=1(cube) conf=90 像素=(640,360)
[2] 副相机判断（DF200 via Pi 快照）
    全帧主色=red(0.420)  检测 1 件  模型=json
    1(cube)  conf=0.91 颜色=red 框=[600, 320, 680, 400]
[3] 融合判断
    模式=set  结论=CONFIRMED  形状计数一致
    主相机形状计数={1: 1}
    副相机形状计数={1: 1}
```

三个结论的含义：

| 结论 | 含义 | 现场怎么用 |
|---|---|---|
| **CONFIRMED** | 主副一致 | 可派件 |
| **CONTRADICTED** | 不一致（形状计数不同/匹配点不同类）| 看是哪件、可能是遮挡或判错 |
| **UNPROVEN** | 副相机无数据 / 无匹配 | 不阻断（主相机单证），但要查副相机链路 |

窗口模式（不加 `--headless`）是三栏：**左=主相机检测点阵**（拿不到主相机画面，只画结果）、
**中=副相机实时帧**（带框/颜色）、**右=融合判决大字**。

### 现场五步

```powershell
# 0) 先确认 PC 与设备同网段（热点/交换机），能 ping 通
ping 172.20.10.9        # MaixCAM
ping 172.20.10.8        # 树莓派

# 1) 最稳：终端模式，不依赖 cv2/GUI
python _pi_tools/three_way_view.py --headless

# 2) 有 cv2：带窗口 + 副相机画面
python _pi_tools/three_way_view.py

# 3) 副相机跑 6 类 ONNX（PC 装了 onnxruntime 才行）
python _pi_tools/three_way_view.py --model _deploy_maixcam\yolo11n_6c_cam2.onnx

# 4) 主相机已切 code(1..30) 协议时
python _pi_tools/three_way_view.py --id-mode code

# 5) 存证据（每轮 json + 副相机 jpg）
python _pi_tools/three_way_view.py --evidence _three_way_evidence
```

### 关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--maixcam` | `172.20.10.9` | MaixCAM IP |
| `--port` | `8765` | 主相机 TCP 端口 |
| `--cam2-url` | `http://172.20.10.8:8080/snap` | 副相机快照（Pi 上的 HTTP 服务）|
| `--id-mode` | `shape` | 主相机 id 字节语义（`code` 为 V1.0）|
| `--model` | 空 | 副相机 ONNX；空=只 HSV 判色 |
| `--mode` | `set` | `set`=只比形状计数；`point`=按像素近邻匹配 |
| `--roi` | 空 | 副相机 ROI `x,y,w,h`（落料位判色用）|
| `--headless` / `--no-image` | 关 | 不开窗口 / 不取副相机图 |
| `--evidence` | 空 | 证据目录 |

## 二、设备代码快照：`工具/collect_deployed_code.py`

### 为什么

设备上可能被现场改过（拷过去没同步、临时改参数）。**接口对齐前必须先把真身取回来。**

### 三条命令

```powershell
# 1) 先看要执行什么（不连设备、不需要网络）
python 工具/collect_deployed_code.py --dry-run

# 2) 真拉取（ssh+tar，只读；默认不含模型权重）
python 工具/collect_deployed_code.py
python 工具/collect_deployed_code.py --with-models    # 连 /root/my_models 一起（很慢）

# 3) 与本地仓库比对
python 工具/collect_deployed_code.py --diff
```

### 默认拉取清单

| 设备 | 路径 |
|---|---|
| **pi**（`pi@172.20.10.8`）| `/home/pi/电控/src/electrical_control`、`/home/pi/电控/deploy`、`sorting_config.ini`、`calibration_config.ini`、`p_look2.py`、`pi_pw.py`、`check_turntable_strategy.py` |
| **maixcam**（`root@172.20.10.9`）| `/root/yolo_v11_send.py`、`/root/stage1_color_v6_send.py`（`--with-models` 再加 `/root/my_models`）|

产物：`_deployed_snapshot/<时间戳>/<device>/...` + `manifest.json`（逐文件 sha256 + 设备 git HEAD）。

### `--diff` 输出四类

| 类别 | 含义 | 处理 |
|---|---|---|
| 只在设备上 | 设备有、仓库没有 | 需要收回仓库或确认是临时文件 |
| 只在仓库里 | 仓库有、设备没部署 | 确认是否忘了同步 |
| **内容不同** | 两边都有但不一样 | **逐行比对**（接口对齐重点）|
| 无对应关系 | 路径映射表里没有 | 人工判断（如 MaixCAM 脚本 → `视觉/` 下哪个目录）|

路径映射表在脚本 `PATH_MAP` 里，可增补（当前 pi 的 `电控/src`、`电控/deploy`、两个 ini 有映射）。

### 自检

```powershell
python 工具/collect_deployed_code.py --self-test
→ self-test OK：diff 分类（只在设备/无对应/内容不同）工作正常
```

## 三、回来后的“接口对齐”流程（建议）

```
1. python 工具/collect_deployed_code.py            # 采快照
2. python 工具/collect_deployed_code.py --diff     # 看四类差异
3. 只对「内容不同」逐个看：
   - 电控/src/electrical_control/rpi/vision_ingest.py    ← BATCH_TARGETS 7 字节解析、id 字节语义
   - 电控/src/electrical_control/rpi/socket_vision_source.py ← 8765 收流、box_id 解析、排序
   - 电控/deploy/run_chain.py                            ← 参数、调度、落点、转盘
   - 电控/src/electrical_control/protocol/*.py           ← ITEM_TASK 12 字节、CRC、外层帧
   - /root/yolo_v11_send.py                              ← 主相机发送端（7 字节/目标、shape_id 还是 code）
   - /root/stage1_color_v6_send.py                       ← 旧的“颜色+形状”发送端（现在是否还用）
   - sorting_config.ini / calibration_config.ini          ← 现场真值（我们仓库里是过期副本）
4. 把设备真值回填仓库，重跑：
   python -m pytest tests/pick_strategy tests/rpi/... -q
5. 若接口有差异 ⇒ 先写进 docs/design/interface-contract 的变更记录，再改代码
```

## 四、常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: cv2` | 用的不是装了 cv2 的 Python | 换成你训练用的环境，或用 `--headless --no-image` |
| 副相机取数失败 `HTTPError` | Pi 上的快照服务没起 / 端口变了 | 先在浏览器打开 `http://172.20.10.8:8080/snap` 验证 |
| `Unexpected UTF-8 BOM` | 手工写的 json 带 BOM | 脚本已用 `utf-8-sig` 兼容 |
| 连 MaixCAM 超时 | 不同网段/防火墙/MaixCAM 脚本没在跑 | `ping` + 确认 `/root/yolo_v11_send.py` 在跑 |
| `ssh: command not found` | 本机没 OpenSSH | Windows 设置→可选功能→OpenSSH 客户端 |
| 快照里模型拉不下来 | 模型大/超时 | 先不加 `--with-models`，单独 scp |

## 五、边界声明（再强调一次）

- 两个脚本都**只读**：`three_way_view` 只连 8765 收流 + HTTP 取图；`collect_deployed_code` 只 `tar` 读 + `git rev-parse` 读
- **不改协议**：`--id-mode` 只是“怎么解读收到的字节”，不会改变发送端行为
- 三路视图里任何判决都**不写回设备**，不影响场上运行
