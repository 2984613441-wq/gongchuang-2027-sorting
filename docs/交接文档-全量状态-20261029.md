### 3.1 labelImg（标注工具）—— 本轮花最多时间的地方

#### 坑 A：打开后 File List 空、报 `AssertionError: cannot paint null image`

**根因**：labelimg 环境的 **Qt 不支持 JPEG**。
`qjpeg.dll` 存在但加载失败，因为它依赖 `Library\bin` 里的 libjpeg，而**没把 `Library\bin` 加进 PATH**。

**证据**（可直接复现）：
```python
# 缺 PATH 时：
formats = ['bmp','cur','gif','icns','ico','pbm','pgm','png','ppm','tga','tif','tiff','wbmp','webp','xbm','xpm']
'jpg' in formats  ⇒ False          # 16 种格式，没有 jpg/jpeg
# 加上 PATH 后：
formats 出现 'jpeg','jpg','svg','svgz'  ⇒ True
```
labelImg 的 `scan_all_images()` 用 `QImageReader.supportedImageFormats()` 过滤扩展名 ⇒ 扫到 0 张图 ⇒ 列表空。

**正确做法（必须 4 行，不能写成一行 `&&`）**：
```cmd
set PATH=D:\Anaconda\envs\labelimg;D:\Anaconda\envs\labelimg\Library\bin;D:\Anaconda\envs\labelimg\Scripts;%PATH%
set QT_PLUGIN_PATH=D:\Anaconda\envs\labelimg\Library\plugins
cd /d C:\Users\29845\Desktop\工创赛
"D:\Anaconda\envs\labelimg\Scripts\labelImg.exe" _review_20261028b\images _review_20261028b\predefined_classes.txt _review_20261028b\labels
```

**⚠️ 为什么不能写成一行**：cmd 在**解析整行时**就把 `%ENV%` 展开（此时还是空值）⇒ 路径变成 `\Scripts\labelImg.exe` ⇒ "系统找不到指定的路径"。

#### 坑 B：命令行传目录参数不生效 / 加载了错的目录

**根因**：`labelImg.py` 的 `open_dir_dialog()`（L1274-1290）有上游 bug：
```python
default_open_dir_path = dir_path if dir_path else '.'
if self.last_open_dir and os.path.exists(self.last_open_dir):
    default_open_dir_path = self.last_open_dir           # ← 用记住的旧目录覆盖命令行参数
else:
    default_open_dir_path = os.path.dirname(self.file_path) if self.file_path else '.'
                                                 # ↑ file_path 是目录时，dirname 拿到父目录（没图）
```
**对策**：
- 用**相对路径** + 先 `cd` 到项目根（这样连 dirname 兜底也能命中）
- 还不行就删掉 `C:\Users\29845\.labelImgSettings.pkl`（已备份为 `.bak-20261028`）
- **最稳的办法：GUI 里手动点 `Open Dir` 选 images，`Change Save Dir` 选 labels**

#### 坑 C：其他 labelImg 规矩
- 必须用 `Scripts\labelImg.exe`；**`python -m labelImg` 起不来**
- **`labels\` 目录里必须有 `classes.txt`**，否则保存时类别会写错
- **`classes.txt` 必须无 BOM**（有 BOM 时 labelImg 显示 `锘縞ube`）
- 环境位置：`D:\Anaconda\envs\labelimg`

### 3.2 PowerShell（本机 pwsh 实为 PS 5.1）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **`@"..."@` 会插值 `$变量`** | 写 shell/python 脚本时 `$ROOT` 被替换成空，脚本内容被破坏 | 用 **`@'...'@`**（单引号 here-string），或**直接写独立文件** |
| **没有 `<` 重定向** | `ssh host < file` 报 `RedirectionNotSupported` | `Get-Content x -Raw \| ssh host "sh -s"` |
| **中文 .ps1 必须带 UTF-8 BOM** | 否则中文乱码/解析错 | 用 `write` 工具写或带 BOM |
| **写 .sh 会带 CRLF** | bash 报 `syntax error near unexpected token $'do\r'` | 写完用 Python 规范化：`p.write_bytes(b.replace(b'\r\n', b'\n'))` |
| **`Select-Object -Last N` 管输出会干扰训练** | v8 训练莫名 exit 1（无 best.pt）| 后台任务用 **`Tee-Object -FilePath log`** 存全量日志 |

**通用铁律**：**长命令/含引号的命令/含变量的脚本 ⇒ 写文件再执行，不要内联。**

### 3.3 MaixPy / MaixCAM（代码里已固化，改前先看）

| 项 | 事实 |
|---|---|
| **`draw_rect`** | 真实签名 `draw_rect(x, y, w, h, color, thickness=1)`。**没有 `fill` 参数**；填充用 `thickness=-1`；**第 3、4 参是宽和高，不是 x2/y2** |
| **`draw_string`** | `font=` 必须传**注册时起的名字字符串**，不能传 `load_font` 的返回对象 |
| **`load_font`** | `load_font(name: str, path: str, size: int)`——**第 1 参是自己起的名字** |
| **中文字体** | `/usr/share/fonts/wqy-zenhei/wqy-zenhei.ttc`（设备自带）|
| **颜色常量只有 10 个** | `BLACK BLUE GRAY GREEN INVALID ORANGE PURPLE RED WHITE YELLOW`——**没有 CYAN**。用 `getattr(image, name, COLOR_WHITE)` 兜底 |
| **`dual_buff=True`** | **SIGSEGV**，必须 `False` |
| **加载顺序** | 相机 → 显示 → 模型（顺序错会崩）|
| **`detect()`** | 要传 maix 的 `image.Image`（frame），**不能传 numpy** |
| **内存 128 MB** | 720p 下**不要 `copy=True`**（会 SIGSEGV）|
| **相机打不开** | 通常是 `launcher_daemon` 占着 ⇒ `killall launcher_daemon` |
| **后台跑脚本看不到输出** | Python 缓冲 ⇒ 必须 **`python3 -u`** |
| **没有 `timeout` 命令** | busybox 环境；要限时就用 `cmd & PID=$!; sleep N; kill $PID` |
| **`image2cv`** | 用 `ensure_bgr=False` 得到 RGB；画框颜色按 RGB 给 |

| 10-28 下午批 | cuboid 162 / penta 75 / tetra **20** | cuboid **131** / penta 87 / tetra **42** | **tetra 漏了一半** |

**⇒ 结论：**
- **正方体 vs 长方体**（顶面正方形还是长方形）和**正四面体 vs 五棱柱**（三角面 vs 多边形面）是 AI 最容易错的
- 判据：**顶面 4 条边 → 立方体类；5 条边 → 五棱柱；三角形 → 正四面体；圆 → 圆柱/圆锥**
- **必须让用户复核**，复核一次能把 mAP50 拉 0.05~0.07

### 3.6 ToF（TOFSense-M S）

**协议（已破解并验证）**

```
UART 921600-8-N-1
帧格式：57 | 01 | reserved | id | system_time(4,LE) | zonemap | data[zonemap]×6 |
        reserved(6, 0xff) | SumCheck
🔴 手册没写的 6 字节保留块 ⇒ 8×8 = 400 字节（手册结构推算只有 394），4×4 = 112 字节（与手册一致，交叉验证了 +6）
每个 data = dis uint24(÷1000 = mm, LE) + dis_status uint8 + signal_strength uint16
FOV 45°×45°（对角 65°）
```

**状态码（datasheet 表 4，14 个）**

- **只有 `0`（可用）和 `10`（可用，无目标）可信**
- **`4` 目标一致性检查失败、`9` 大脉冲有效范围（可能多目标合并）、`13` 不一致（次目标）⇒ 必须排除**
- ⇒ 代码里 `VALID_STATUS = {0, 10}`

**高度图算法要点**

- 基线不能用中位数（桌面是最远的）⇒ 用 **80 百分位**
- 负高度**会被静默截断成 0** ⇒ 必须加**陈旧性自检**（中位偏移 >10mm 或 >20% 像素读得更远就告警）

**物理结论（决定它能不能用）**

| 物件 | 实测读数（托盘上方 237mm，像素 29.7mm）|
|---|---|
| 正方体 | **47 mm / 6 px**（真实 40~47mm）✅ |
| 圆柱 | **38 mm / 4 px** ✅ |
| **圆锥** | **15 mm / 1 px** = 高度/3（几何固定，降低安装高度也救不回）❌ |
| **正四面体** | **2 mm / 0 px（几乎不可见）** ❌ |

- 倾斜安装**失败**：像素 49.8mm、时抖 8.9mm、空托盘产生 3 个假区域、立方体测试 5 个假区域
- **⇒ ToF 只能做「平顶物件冗余校验」+ 答辩亮点，不能做存在检测（会漏圆锥/四面体 ⇒ 提前收工）**

**标定**：`读数 = 1.0214 × 实际 + 9.1`（4 点拟合，残差 +5.3/−4.4/−1.8/+0.9）；有效范围 **50~700 mm**；20mm 完全无效

**参考文件**：`E:\工创赛-tof\`（脚本、文档、NAssistant、基线 json）

```json
 "color": "yellow", "x": 505, "y": 122, "w": 174, "h": 203}
```

**gid = montage_no × 48 + 格内序号**（前 5 张各 48 格，第 6 张 20 格）。

## 12. STM32 上电实测：`FAULT_LOCK` 是**设计**，不是故障（2026-10-29 22:20 ~ 22:35）

### 12.1 板子活着，但停在初始态

### 12.2 INPUTS 逐位解码（位定义见 `电控/firmware/stm32f407_m144z/App/Inc/ec_inputs.h`）

| bit | 输入 | RAW | 判定 |
|---|---|---|---|
| 0 | X_HOME | 1 | 未触发 |
| 1 | X_END | 1 | 未触发 |
| 2 | Y_HOME | 1 | 未触发 |
| **3** | **Y_END** | 0→1 | **曾触发，随后恢复**（唯一动过的输入）|
| 4 | Z_UP | 1 | 未触发 |
| 5 | Z_DOWN | 1 | 未触发 |
| **6** | **ESTOP_FB** | **1** | **未触发 ⇒ 「急停极性/接线」假设被否决** |
| 7 | START | 1 | 未按 |
| 8 | MANUAL_RESET | 1 | 未按 |
| **9** | **POWER_PERMISSION** | **1** | **在位**（固件里未接 GPIO 时被硬置为有）|

### 12.3 真根因：初始态**就是** `FAULT_LOCK`（fail-closed 设计）

- `ec_app_init()`（`App/Src/ec_app.c:766-780`）里写着 `last_app_state = EC_STATE_FAULT_LOCK;`
- `EC_STATE_FAULT_LOCK = 0` 就是状态机枚举第一项（`电控/stm32_logic/include/ec_state_machine.h:10`）
- 离开 `FAULT_LOCK` **只有两条路**（`电控/stm32_logic/src/ec_state_machine.c:67-117`）：

| 路径 | 触发条件 | 后果 |
|---|---|---|
| ① **START 按键** | **PA4**（`main.h:68` `START_SIG_Pin`）拉低，且 ESTOP 未触发、MANUAL_RESET 未触发 ⇒ `MANUAL_NEW_ROUND_CONFIRMED`（`round_closed=true`、`round_id` 自增 1≠0）| → POWER_ON → POST(50 ms) → HOMING（**虚拟，无电机动作**）→ BARRIER（直接放行）→ **WAIT_TASK** |
| ② **合法 ITEM_TASK** | `danger_area_clear && estop_released` ⇒ 自学轮次、清 dedup | 同上，**之后会执行动作**（动电机，需 L4 授权）|

**⇒ 准确表述**：板子上电后处于 fail-closed 待命态，等一个「新轮次」信号；
「每次上电都被锁、所有运动指令被拒」的真相是 —— **这个信号一次都没到过板子**。

### 13.1 定位：不是"阈值触发的补救"，而是**每件双证据**

```
主相机：v11 → shape + color → code(1..30)，附 conf 与像素框
副相机：同一件、同一时刻一帧 → 独立验证；**副相机也可以单独训练 / 从 v11 微调出自己的分类器**（用户 22:58 确认）⇒ 训好后即为「**独立第二意见**」，证伪力最强
⇒ 每件产出证据等级：evidence = 2/2（双证）或 1/2（单证）
```

**为什么不做阈值复核**（三条理由，都指向"可证明"）：

| 理由 | 说明 |
|---|---|
| 阈值是工程妥协 | 阈值一改，判定结果就变，**无法对外证明**判据稳定 |
| 双证可复核 | 每件都有"两图 + 两个框 + 两个结论"，**错了能查、对了能证** |
| 答辩/争执可出示 | 裁判质疑"凭什么是正方体"⇒ 直接给两视角截图与一致性记录 |

### 13.2 安装：左右镜像

- 两台相机分置托盘**左右两侧**、镜像对称，各自俯视/内倾
- **A 的远端＝B 的偏近端** ⇒ 互补；左右镜像比对角 180° 更好施工与走线（用户定）
- DF200 **手动对焦**要对着"托盘远端"，对完点胶锁死

### 13.3 判定三态（fail-closed，不用阈值）

| 状态 | 条件 | 处理（**全程自动，无人介入**）|
|---|---|---|
| **CONFIRMED**（2/2） | 副相机在"预测区域"里确实有件，且**颜色一致**、**形状证据相容** | `PICK` 允许派件；证据入库 |
| **CONTRADICTED** | 副相机显示该区域**无件**，或颜色不符，或形状证据与主判**矛盾** | `RETRY` 先自动重试（重抓副相机帧/等稳定帧/移开夹爪清视线，上限 2 次）→ 仍冲突则 `ISOLATE`：**自动放进待定区**，不混入任何已分组，继续比其余件 |
| **UNPROVEN**（1/2） | 副相机没拍到/被遮挡/预测区域越界 | `RETRY` 同上 → 用尽后 `PICK_SINGLE`：以**主相机为权威**派件，记 `evidence=1/2` 供复盘 |

> 🔴 **为什么是"重试 + 隔离"而不是"交人工"**（用户 2026-10-30 明确）：**比赛不允许人工判断**。
> 所以任何"冲突"都必须在自动策略里被消化掉：
> ① 先给视觉再一次机会（换帧/等稳定/清视线，成本几毫秒）；
> ② 仍冲突 ⇒ 把该件**隔离**（牺牲这一件，保住其余所有组不被污染）；
> ③ 单证情形以主相机为权威放行，但留 `1/2` 标记，便于赛后复盘。
>
> ⚠️ 待用户拍板一件小事：**"待定区"物理上放哪儿**（现有方案：落料盘最边上一格 / 托盘一角固定位）。

> 「形状证据相容」分两阶段：
> **阶段 1（现在即可用）** 几何/颜色规则：轮廓边数、宽高比、面积占比、主色 HSV；
> **阶段 2（副相机模型训好后）** 副相机用**自己的模型**独立分类，要求与主判「同类 + 同色」。
>
> ⚠️ 为什么阶段 1 不能直接拿 v11 顶：DF200 与 MaixCAM 不同型号/不同视角，把 v11 权重喂副相机图是**域外推理**。
> **实测证据（2026-10-29 23:00）**：v11 在副相机 720p 帧上只检出 1 框、`conf 0.322`，且把**红色正四面体判成 `cube`** ⇒ 域外推理失效，副相机必须有自己的数据。

### 13.4 标定：主相机为主 + 副相机 4 点单应（**不是双目标定**）

| 步骤 | 做法 | 成本 |
|---|---|---|
| **S1** | 主相机标定（已有 `[CameraCalibration]`）⇒ **定义托盘 mm 坐标系，作为唯一权威系** | 已有 |
| **S2** | 副相机取 **4 个托盘栅格点** ⇒ 求自身 `homography` 映射到**同一个** mm 系 | **5 分钟/次** |
| **S3** | 镜像关系只用于**猜初值**（左右镜像 ⇒ 预期映射近似 `u' ≈ k·(W−u)+b`），精度由 4 点校正保证 | — |

**为什么这样就够**：两台相机都固定在**同一平面（托盘）上方**，平面到平面的映射是单应；
求单应只需 4 点，**不需要**两相机之间的 `R|t`（那才是"双目标定"，复杂且与"主相机为主"冲突）。

**托盘未定 ⇒ 参数占位（代码里不写死）**：

```ini
[CameraCalibration]    ; 主相机（已有）。动相机必须重标
[Camera2Homography]    ; 副相机 4 点表（新）；托盘/副相机位置定了填
[TableROI_mm]          ; 托盘范围（mm，新）
[RemoteROI_mm]         ; "远端"范围（mm，新）—— 用 mm 定义远端，不用像素
```
托盘到位后只重填这 3 组数（各 5 分钟），**代码不动**。托盘定之前可用 A3 白板 + 打印栅格当临时托盘先跑通流程。

### 13.5 副相机职能边界（明确不做）

| 能做 ✅ | 不做 ❌ |
|---|---|
| 远端件**存在性/颜色/形状相容**确证 | **不用它读二维码/文字**（归主相机，MaixPy 内置 `find_qrcodes()`，见 `省赛-改造设计-20260928.md:140`）|
| 遮挡/堆叠（两视角看是不是两件叠着）| **不拿它的图混训 v11**（域不同，必掉点）|
| 抓后确认（抓到了/没带两件）、放后确认（落格对不对）| **不做"深度测量"**（ToF 都测不准，单目/双像更不行）|
| 空台/清台计数、故障取证截图 | **未标定前不单独决策**（只作证据，不作判据）|

### 13.6 工程约束

1. **DF200 用法**：UVC 免驱；OpenCV `CAP_V4L2` + `FOURCC=MJPG`；建议 **1280×720**（1080p 软解吃 CPU，会与 `run_chain` 抢）
2. **按件抓帧**：不做常驻高帧率，主相机判完一件 → 抓副相机一帧 → 验证 → 下一件（Pi 负载可控）
3. **主相机别被读码拖慢**：当前 33 ms/帧（15.7 FPS）；`find_qrcodes()` 另算几十 ms ⇒ **等该件稳定帧再解码**，不每帧跑
4. **证据留存**：每件存 `主图 + 副图 + 两个框 + 判定 + 时间戳`，形成可回放证据链（复盘/答辩/争执都用得上）
5. **副相机模型跑在哪**：Pi 4 **没有 NPU** ⇒ 用 `onnxruntime` CPU 跑 yolo11n 448，预估 **100~200 ms/帧（待实测）**；
   每件一次完全够用；嫌慢就降到 `imgsz=320` 或 int8 量化。**绝不占用 MaixCAM 算力**
6. **设备实测（2026-10-29 23:00）**：`icspring camera`（USB `2993:0858`）→ `/dev/video0`；
   **仅 MJPG**，离散尺寸 1920×1080@30 / 1280×720@30 / 800×600 / 640×480 / **608×1024 / 640×1024（竖版）**；
   720p 实测 **30.5 fps**、1080p 实测 **16.5 fps**（Pi 软解上限）
7. **安装验收判据**：对焦在**远端**、画面里托盘占宽与主相机相当、清晰度 `laplacian_var` 越高越好
   （2026-10-29 首测 720p=218 / 1080p=128，属**失焦/位姿不对**，见 §13.9）

### 14.4 根因：旧标定是 **320×320 域**，而现在采集是 **1280×720**

| 项 | 值 | 出处 |
|---|---|---|
| 旧标定像素区间 | `[15,305] × [15,305]` | `pixel_to_device.py:76-77` |
| 旧标定帧尺寸 | `frame_width/height = 320/320` | `pixel_to_device.py:185-186`、`:240-241` |
| 仿射基准 | 「X: 像素 57↔−95mm、232↔+95mm；光轴 (160,160)」 | `calibration_config.ini` 注释 |
| 现在发送的坐标 | **1280×720 原始像素**（118~240, 459~480）| 本次实测 |

**不是"忘了缩放"这么简单** —— 按 1280×720 → 中心 720² 裁切 ÷2.25 换算成旧域：

```
(118,478) → (-72.0, 212.4)  域外
(239,459) → (-18.2, 204.0)  域外
旧域对应的新帧范围 = u∈[314,966] × v∈[34,686]
```

⇒ 探测到的件落在 **u≈115~240**，**根本不在旧标定覆盖的区域里**。
⇒ 说明这是**相机被移动（构图变了）+ 标定过期**，不是换算公式问题。

