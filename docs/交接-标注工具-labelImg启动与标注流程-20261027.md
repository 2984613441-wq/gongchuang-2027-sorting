## 1. 为什么不能直接双击 labelImg.exe（关键背景）

labelImg 是 PyQt5 程序，本项目用的是 **conda 环境 `labelimg`**。如果直接双击 `labelImg.exe` 或在错的 shell 里启动，会出两类致命问题：

| 故障 | 根因 | 表现 |
|---|---|---|
| **Open Dir 没反应 / 图片列表空** | Qt 的 `imageformats` 插件（jpeg.dll）找不到 | `Open Dir` 后 0 张图；控制台报 `Unsupported image format` |
| **点开图就闪退** | `libs\yolo_io.py` 的 `YoloReader` 要在**保存目录**里读 `classes.txt`，缺了就 `FileNotFoundError` → PyQt5 调 `qFatal` 直接杀进程 | 无报错窗口，进程消失 |

所以启动器必须做两件事：
1. 把 conda 环境的 `Library\bin` 等目录**加进 PATH**（jpeg 插件才能被 Qt 加载）
2. 每次启动**把 `classes.txt` 复制到保存目录**

### 3.2 cmd 等价命令（想自己写启动器时照抄）

```bat
setlocal
set "ENV=D:\Anaconda\envs\labelimg"
set "PATH=%ENV%;%ENV%\Library\mingw-w64\bin;%ENV%\Library\usr\bin;%ENV%\Library\bin;%ENV%\Scripts;%PATH%"

set "PYTHONIOENCODING=utf-8"

> `labelImg.exe` 的参数顺序是 **`<图片目录> <类别文件> <保存目录>`**，三者都给，才能保证
> ①自动打开图片目录 ②类别下拉框是正确顺序 ③保存到正确位置。

```

## 5. 类别定义（**顺序不可改**，改了编号全错）

`_label_kit\classes.txt` 当前 **7 类**：

| ID | 英文 | 中文 | 俯视判据 |
|---|---|---|---|
| 0 | `cube` | 正方体 | 顶面正方形，长=宽=高 |
| 1 | `cuboid` | 长方体 | 顶面长方形（明显长条） |
| 2 | `cylinder` | 圆柱 | 顶面正圆，无直边 |
| 3 | `hexagonal_prism` | 六棱柱 | 顶面 6 条边 |
| 4 | `pentagonal_prism` | 五棱柱 | 顶面 5 条边 |
| 5 | `triangular_prism` | 三棱柱 | 顶面三角形；侧放=长方形+斜棱 |
| 6 | `square_pyramid` | 四棱锥 | 顶面四边形 + 中心 **4 条**棱汇聚 |

**三组必混，按这个判**：
1. 正方体 vs 长方体 → 顶面**长宽比**
2. 圆柱 vs 六棱柱 → 顶面是**圆**还是有 **6 条直边**
3. 三棱柱 vs 四棱锥 → 顶面是三角形（3 条边）还是四边形（4 条边 + 中心 4 棱）

> ℹ️ **没有「正四面体」这个类**（2026-10-23 用户裁决「7 就是 6」，正四面体并入四棱锥）。
> ℹ️ **没有「球体」这个类**：数据里那个黑色圆是**矮圆柱俯视**，标 `cylinder`(2)。

配图：`_label_kit\形状对照表.png`（合成示意 + 俯视轮廓），根目录副本 `①形状对照表.png`。

## 6. 标注操作要点

| 操作 | 快捷键 / 位置 |

| 画框 | `W`，拖拽 |
| 上一张 / 下一张 | `A` / `D` |

**两个纪律**

2. **空标注 = 这张图不要**（本项目约定）：如果一张图里没有要识别的东西，就把它所有框删空并保存；后续会按"空标注清单"统一移入回收站。

## 7. 已知故障与处置（都是实际踩过的）

### 7.1 Open Dir 后列表为空 / 图片打不开
**根因**：Qt 找不到 jpeg 插件。
**验证**（在该环境 python 里跑）：
```python
from PyQt5.QtGui import QImageReader
print([bytes(f).decode() for f in QImageReader.supportedImageFormats()])   # 应包含 jpg/jpeg
```
**处置**：用 §3.1 的 bat，或 `conda activate labelimg` 后再启动。不要直接双击 exe。

### 7.2 点开某张图 / 保存时闪退
**根因**：保存目录缺 `classes.txt`（`YoloReader` 抛 `FileNotFoundError` → PyQt5 `qFatal`）。
**处置**：`copy /y _label_kit\classes.txt _dataset_yolo\labels\train\classes.txt`（val 同理），
或用 bat 启动（它每次都会复制）。

### 7.3 类别编号整体错乱
**根因**：labelImg 允许在 "Edit Label" 里手打类别名；一旦手打，它会把新名字**追加**到类别表，编号漂移。
**处置**：只用右侧列表点选；若已污染，用 `_label_kit\sync_back.py` 的校验（会拒绝 `class_id` 越界）拦下来，再人工修正。

### 7.4 ⚠️ labelImg 每次保存都会**整体重写** `classes.txt`
代码位置：`libs\yolo_io.py:52-75`，内容取自内存里的 `label_hist`。
- 若启动时没给类别文件 → `label_hist` 不完整 → 写出的 `classes.txt` **丢类**，后续读取会 `IndexError` 崩溃
- **所以：启动必须带类别文件；每次启动前用 bat 覆盖一份干净的 `classes.txt`**

### 7.5 崩溃但看不到报错
PyQt5 的 slot 异常会走 `qFatal` 直接杀进程，控制台什么都不留。用**留证启动器**：
```
双击 _label_kit\调试启动_记录崩溃.bat
```
它在前台控制台跑 labelImg，并把 stderr 写入 `_label_kit\labelimg_error.log`；崩了把该文件给支持方。

### 7.6 只在特定机器上崩：沙箱环境限制（如 DSH/受限容器）
- 某些沙箱**禁止创建命名管道**，GUI 子进程可能被回收 → 表现像"闪退"
- 本项目的 bat 用 `start ""` 拉起独立 GUI 进程，在普通 Windows 桌面上正常
- 如果必须从受限环境启动，请在**真实桌面**双击 bat，不要让受限进程托管 labelImg

## 8. 标完之后（写回数据集的标准链路）

> 本项目有「双目录」结构：`交付-标注数据集-20261018\`（权威真值源） → `_dataset_yolo\`（训练副本，由脚本重建）。
> **不要在 `_dataset_yolo` 里长期积累改动后直接重建**——重建会先 `rmtree`，必须先把标签写回权威源。

```powershell
cd C:\Users\29845\Desktop\工创赛
$py = "C:\Users\29845\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"

# ① 预演（只读，看有哪些改动/是否有非法行）
& $py _label_kit\sync_back.py

# ② 确认无误后写回权威源（自动备份到 _label_kit\_backup\<时间戳>\）
& $py _label_kit\sync_back.py --apply

# ③ 从权威源重建训练集（train/val 8:2，写 data.yaml）
& $py _turntable-edit\build_dataset.py
```

`sync_back.py` 的校验：5 列、`class_id` 在合法范围、坐标 0~1、文件名能反查到源图；不通过会拒绝写回。

## 9. 禁止事项

1. ❌ 不要手改 `交付-标注数据集-20261018\`（权威源）里的文件——一律通过 labelImg / `sync_back` 改
2. ❌ 不要在 labelImg 里按 `Ctrl+Shift+D`（Delete Image）：它 `os.remove` **真删图片文件**，不可恢复
3. ❌ 不要手打类别名（见 §7.3）
4. ❌ 不要用裸 `python`（会解析到 Unreal 的 3.7.7）
5. ❌ 不要改 `classes.txt` 的**顺序**（改顺序等于重编号，历史标签全部错位）
6. ❌ 不要在没有 `classes.txt` 的目录里保存标签（见 §7.2/§7.4）
