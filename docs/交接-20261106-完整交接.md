## 1. 一句话项目与当前阶段

**2027 工创赛 · 智能分拣装置**：MaixCAM 主相机看托盘 → 判形状+颜色 → 树莓派排顺序/分配货格 → STM32 控制 XYZ/夹爪/落料；副相机（DF200 接在 Pi）用于落料位复看；PC 负责训练、模型转换、调试观察。

当前阶段：**省赛（2026-11-23 ~ 12-06）**，按 24 件准备；赛规关键口径（`docs/references/赛题原文-提取文本/省赛规则.txt`）：

| 规则 | 行号 | 对策略的意义 |
|---|---|---|
| 同色同形同盒 **5 分/件** | L263-264 | 颜色必须进决策（这是 V1.0 code 的动机） |
| 单件单独一盒 **2 分** | L262 | 混盒 0 分，宁可单放 |
| 混色/混形盒 **0 分** | L265-266 | 一盒只能同色同形 |
| **掉件 = 本轮结束** | L267-268 | 宁可放弃难夹的件，也不能掉 |
| **15s 无动作 = 本轮结束** | L284 | 判不出/不敢抓也必须给链"动作"，不能僵住 |

## 4. 通信协议（红线区，改之前必须看这里）

### 4.1 已冻结（V0.9，`docs/design/interface-contract.md`）

| 项 | 值 |
|---|---|
| 外层帧 | `0xA5 0x5A` + `version=0x01` + `task_id` + `frame_seq` + `data_len`（大端）+ 载荷 + **CRC-16/MODBUS** |
| `ITEM_TASK` | **12 字节**：落料 X/Y + 抓取 X/Y 各为有符号 16 位 0.1mm；`angle=0xFF` 表示不用；`image_id == class_id` |
| 串口 | Pi↔STM32 **USART2 PA2/PA3**，115200 8N1；备用 USART3 PD8/PD9；MaixCAM↔Pi 文档写 UART 115200 |
| 现场实际 | **MaixCAM→Pi 走 TCP 8765 `BATCH_TARGETS`**（文档 UART 与实际不一致，以代码为准）|

### 4.2 `BATCH_TARGETS`（MaixCAM→Pi，现行）

```
头 3 字节：count(1B) + task_id(2B 大端)
每目标 7 字节：id_byte(1) + conf(1, 0..100) + x(2, 大端) + y(2, 大端) + angle(1)
```

- `id_byte` 两种语义：**shape_id(1..6)**（现状）或 **code(1..30)**（V1.0 草案）
- 解析权威：`电控/src/electrical_control/rpi/vision_ingest.py`
- 发送端权威：`_pi_tools/maixcam_scripts/yolo_v11_send.py`

### 4.3 V1.0 草案：颜色进链路（**未冻结，改动属 L4**）

```
code = (shape_id - 1) * 5 + color_id + 1      # 1..30；0 = 判不出
color_id：红/黄/绿/蓝/白 之一（HSV 判）
ITEM_TASK 仍 12 字节；每件 Z/夹爪参数走固件"按形状查表"，wire 不变
Pi 侧 class_id = code → (shape,color) → (box_id, 货格)
```

### 4.4 最容易踩的协议坑

| 坑 | 说明 | 出处 |
|---|---|---|
| `class_id` 当成 `box_id` | 转盘/滑台守卫曾用 `class_id` 判"货格号"，导致转错格；**必须用映射后的 `box_id`** | 2026-11-01 修 |
| `image_id == class_id` 假设 | 早期链路颜色不进决策，别在新代码里继续假设 | interface-contract § |
| 改协议 = 改多个子系统 | 属 L4，需要用户明确批准；改前先写"影响分析"（有先例 `docs/协议影响分析-20261101.md`）| CLAUDE.md 红线 |

## 5. 决策链与三套策略（怎么"选下一件"）

### 5.1 一帧的生命周期

```
socket 收帧 → 陈旧帧护栏(2.5s) → 首件稳定门(settle 3 帧) → 类别投票(A,默认关)
→ box_id 解析(code→货格) → skip_shapes 过滤 → 选"离当前位置最近的一件"（greedy TSP 首步）
→ 生成 ITEM_TASK → UART 下发 → 显示/台账 → 落料位复看(可选)
```

关键设计：**一帧只派一件**（不排队；排队会让第二件带旧坐标去抓）。

### 5.2 三套方案（预设文件，现场用覆盖方式切换）

| 方案 | 预设 | `order_mode` | `skip_shapes` | 思路 | 风险 |
|---|---|---|---|---|---|
| **A** | `presets/pick_strategy.planA_legacy.ini` | `group` | 0（全抓）| 回归基线：按货格分组顺序抓 | 最稳，但难件可能排前面 |
| **B** | `presets/pick_strategy.planB_weighted.ini` | `weighted` | 0（全抓）| **前端优先**加权评分 + 难件护栏 | 依赖 `[Tray] open_side`/前端轴正确 |
| **C** | `presets/pick_strategy.planC_skip.ini` | `weighted` | **3,5**（放弃圆柱/圆锥）| 掉件=本轮结束 ⇒ 主动放弃难夹件 | 直接丢分，但保命 |

### 5.3 加权排序（B/C 用的）

```
score = 0.70*front + 0.15*pick + 0.10*route + 0.05*isolation
```
- `front`：离无壁边越近越优先（**依赖 `[Tray] open_side` 实测值；未知时 fail-closed**）
- `pick`：难度层（圆柱/圆锥/四面体更难）+ 置信度
- `route`：空爪行程 + 到上次落点距离
- `isolation`：周围件越少越优先（`isolation_band_mm = 夹爪包络半宽 + 10mm`）
- **难件护栏** `weighted_guard_hard_first=true`：难件不得排首位（测评：首位率 10.33% → 0%，见 `docs/reports/测评-加权排序可行性-20261102.md`）

### 5.4 动态分配（2026-11-01 新增，默认关/需接线）

- `slot_allocator`：按 `(shape,color)` 组占货格，**派发时锁格**，落料/复看后释放
- 好处：不必预先固定"6 盒各放什么"，提高 5 分/件达成率
- 风险：与转盘两位置策略耦合，改动必须回归 `tests/rpi/test_slot_allocator.py`

### 5.5 落料位复看（`place_eye`，默认关）

| 模式 | 行为 |
|---|---|
| 关 | 不启用（现状）|
| `observe` | 只记录 MATCH/MISMATCH/UNKNOWN，不纠正 |
| `correct` | MISMATCH 时纠正台账（把颜色判错的那件挪到正确分组）|

限制：**只判颜色（HSV），不判形状**；需要 ROI 标定（`[PlaceEye]` 段）。

## 8. 我们的「技巧」在哪（设计要点，别当偶然）

1. **颜色不进 wire 也能判色**：主相机在**框内采样 RGB→HSV** 判 5 色，形状由模型给 ⇒ 一个 7 字节目标就能承载 `code=(shape-1)*5+color`（V1.0），不需要改 `ITEM_TASK`。
2. **一帧只派一件**：防"排队坐标过期"；代价是吞吐，换来定位准确。
3. **首件稳定门**：前 3 帧签名不变才派第一件，避免"相机还没稳就抓"。
4. **陈旧帧护栏**：>2.5s 的帧直接丢，防"视觉停了链还在用旧坐标"。
5. **难件护栏**（`weighted_guard_hard_first`）：加权排序会把前端好夹的件排前面，但必须禁止"难件（圆柱/圆锥）排首位"，否则第一件就掉件=本轮结束。
6. **放弃策略 C**：掉件=本轮结束 ⇒ 主动 `skip_shapes=3,5`，用 2 分/件换"不结束"。
7. **动态分配**：不预固定"6 盒各放什么"，按 (shape,color) 动态占格，提高 5 分/件达成率。
8. **落料位复看**：副相机在落料位只判颜色，MISMATCH 时纠正台账（`observe`/`correct` 两档），不改变运动。
9. **fail-closed 配置**：ini 里每个值带 `【固件常量】/【实测】/【待实测】/【演示】` 标签；**`【待实测】` 未填时相关功能拒绝启用**（如 `require_gap_geometry=true`）。
10. **两相机分工**：主相机"判形状+颜色出 code"，副相机"落料位颜色复核"——**不是**两个都跑模型（Pi 没推理运行时，也不该跑）。
11. **数据集合并去重**：多批数据用 sha1 去重再分层切分，避免同一张图跨 train/val 造成指标虚高。
12. **部署形态按设备能力分流**：MaixCAM→cvimodel+mud；Pi/PC→ONNX（PC 有 CUDA/ORT）。

## 12. 红线与风险（改之前先问自己）

| 红线 | 说明 |
|---|---|
| **通信协议** | 外层帧/CRC/ITEM_TASK 字节/波特率 = 冻结；改动属 **L4**，需用户批准 + 影响分析 |
| **I/O 映射 / 接线 / 烧录** | L4；固件 1278 个 C/H 文件，改错可能烧坏舵机/电机 |
| **机械结构** | 已加工件不可逆 |
| **删除/覆盖模型权重** | 属于"删除证据"，需先备份 |
| **现场实机运动** | 需用户在场授权；`FAULT_LOCK` 未解除时不要动 |

## 16. 术语表

| 术语 | 含义 |
|---|---|
| **code** | `(shape-1)*5 + color + 1`，1..30，V1.0 草案里替代 shape_id；0=判不出 |
| **class_id** | 视觉帧里目标 id 字节的语义值（可能是 shape_id 或 code，取决于 `--id-mode`）|
| **box_id** | 货格号（1..6 或动态分配后的格号）；**转盘/滑台守卫必须用它** |
| **BATCH_TARGETS** | MaixCAM→Pi 的 TCP 报文（8765）|
| **ITEM_TASK** | Pi→STM32 的 UART 报文（12 字节）|
| **稳定门** | 首件前要求连续 N 帧签名不变才放行 |
| **陈旧帧护栏** | 帧超过 2.5s 未用则丢弃 |
| **skip_shapes** | 主动放弃的形状（3=圆柱 5=圆锥）|
| **weighted** | 五键加权排序（front/pick/route/isolation）|
| **FAULT_LOCK** | STM32 故障锁存态，需复位 |
| **mud / cvimodel** | MaixCAM 模型包（元数据 + 编译后模型）|
| **PR 崩溃点** | 本仓无；`launcher_daemon` 占相机是主要 SIGSEGV 源 |
