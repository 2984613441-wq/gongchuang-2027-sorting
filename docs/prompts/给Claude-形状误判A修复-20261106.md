## 一、要修的 4 个问题（都是实测出来的，不是风格意见）

### 问题 1（最重要）：默认 2/3 多数票，对「两类互相误判」几乎无过滤

实测：类别在两类（如 cube↔cuboid）之间交替 12 帧，`class_vote_quorum=2, frames=3`：

```
stats {'accepted': 10, 'rejected_no_quorum': 2, 'timeout': 0}
```

窗口 `[2,3,2]` → 票数 `2:2, 3:1` ⇒ 判 class=2 通过。**我们要治的就是这种两类摇摆**。

**要求**：新增 `class_vote_mode: str = "unanimous"`（取值 `"majority" | "unanimous"`），**默认 `"unanimous"`**：
- `unanimous`：窗口内**所有** `class_id` 必须一致，且窗口已满（`len(hist) == class_vote_frames`）才采纳；
- `majority`：保持现有行为（`votes[best] >= quorum`）；
- 保留 `class_vote_quorum` 参数供 `majority` 使用；非法 mode 抛 `ValueError`（fail-closed）。

### 问题 2：默认参数下「超时保护」不可达

`class_vote_frames=3`，历史窗口封顶 3，而判据是 `len(hist) >= class_vote_max_wait_frames(6)` ⇒ 恒假，实测 `timeout` 永远 0。

**要求**：超时改成按「目标年龄」计，不再用被截断的 `len(hist)`：
- 新增 `_vote_seen: dict[key, int]`，每帧对该 key 自增 1；
- 判据：`_vote_seen[key] >= class_vote_max_wait_frames` 且仍未采纳 ⇒ `timeout` 计数 + WARNING（该 key 只警告一次）+ 丢弃该件 + 删除该 key 的历史与计数（避免下一帧重复计时）。

### 问题 3：跨轮历史不清空 ⇒ 新一轮被上一轮类别污染

实测（同一 source 实例）：

```
第一轮后 hist {('seq',1): [(2,…),(2,…)]}
新一轮后 hist {('seq',1): [(2,…),(5,…),(5,…)]}     ← 上一轮的 2 仍在
```

**要求**：
- `set_permitted(True)` 时清空 `_vote_history` 与 `_vote_seen`（新一轮/新一轮派发开始）；
- 每帧结束淘汰「连续 `class_vote_frames * 2` 帧没再出现」的 key（防内存增长），淘汰时同时清 `_vote_seen`。

### 问题 4：「位置匹配」是死代码 + 单位混用，且方向选错了

现状：键优先用 `("seq", target_seq)`；只有 `target_seq` 为 0/None 时才走位置分支——但生产 `target_seq` **恒非 0**，所以位置分支永不执行。
而真实场景里 `target_seq` 是**每帧按顺序重排**的：前面一件被抓走后，后面件的 seq 会整体前移 ⇒ **同一个物理件会换 seq**，这恰恰是 seq 键最不可靠的地方。

**要求（改为位置键，去掉 seq 键）**：
- 统一用**位置栅格键**：`grid = (round(px / class_vote_grid_px), round(py / class_vote_grid_px))`，默认 `class_vote_grid_px = 80`；
- 若相邻已有键的中心距 < `class_vote_match_radius_px`（默认 80 像素），复用它（处理跨格抖动）；
- 删除 `("seq", ...)` 键与对应死分支；注释里**写清单位是像素**，不要再说"约 40mm"；
- 保留「窗口内每帧最多记一次」：同一帧里若同一 key 出现多次，只记一次（防重复投票）。
