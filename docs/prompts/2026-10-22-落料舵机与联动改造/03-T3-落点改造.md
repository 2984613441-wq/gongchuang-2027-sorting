# 五、具体实现要求

## 5.1 目标数据结构（建议，可讨论）

**现状**：`[DropPoints]` 六盒 → 六份相同坐标

**建议改成**：

```ini
[Turntable]
# 转盘落点（方案B）。单位 mm，滑台记账坐标（不叠加 ToolOffset）。
# ⚠️ 必须在 ec_motion_plan.h 的 REACH_FAR 之内（X≤90.0, Y≤92.5）
x_mm = 90.0
y_mm = 92.0

# 转盘角度表（方案B 预留）：每个货格对应的转盘角度（度）
# 若为空 ⇒ 退化为"六盒全指向 [Turntable] 的单点"（兼容旧行为）
angles = 
```

**要求**：
1. **保留向后兼容**：旧 `[DropPoints]` 若存在且 `[Turntable]` 不存在 ⇒ 走旧逻辑并**打警告日志**
2. **新增校验**：落点必须在 `REACH_FAR` 之内，超了直接 `SystemExit`（**防止再撞限位**）
3. **明确注释**：哪个是"取料点"、哪个是"落料点"，中文写清楚

## 5.2 必须解决的矛盾

在报告里给出**证据链**：

```
grep -rn "load_drop_points\|drop_point_for_box\|\[Drop\]" 电控/src 电控/deploy
```

逐项说明：
- 谁读 `[DropPoints]`
- 谁读 `[Drop]`
- 两者是否是同一概念
- 如果是同一概念 ⇒ 统一成一个
- 如果不是 ⇒ 分别重命名，**消除歧义**

## 5.3 安全校验（必须加）

```python
# 落点必须落在可达域内，否则超程过堵转（实测已发生 3 次）
REACH_FAR_X_MM = 90.0    # = EC_MOTION_REACH_FAR_X_MM10 / 10
REACH_FAR_Y_MM = 92.5    # = EC_MOTION_REACH_FAR_Y_MM10 / 10

if not (0.0 <= x_mm <= REACH_FAR_X_MM):
    raise SystemExit("落点 X=%.1f 超出可达域 0~%.1f" % (x_mm, REACH_FAR_X_MM))
```

> ⚠️ 注意坐标是**滑台记账坐标**，取值范围要看 `load_drop_points` 里怎么解释的
> （是"相对原点"还是"绝对半程"？**先读代码确认，别照抄我这段**）。

## 5.4 预留方案B（转盘角度）

用户说"转盘也是这个固定落点" —— 意味着**转盘靠转动让不同货格对准同一个落料口**。
所以数据结构要能表达"落料口固定 + 转盘转角度"。

**先只留接口、不实现动作**（转盘控制是另一条链：`turntable.py` / `/dev/ttyAMA1`）。
