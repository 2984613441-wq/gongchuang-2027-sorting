## 任务 2：零位开关的输入遮罩审计（**这一项最危险**）

**已实测的输入基线**（`docs/design/stm32f407-实测确认引脚表-2026-08-14.md:5`，`main.c:704-708`）：

> **九路输入：板外 10k 上拉、低有效、MCU 配 `NOPULL`**

**意思**：这些输入脚**不能**在 MCU 内部开上拉，否则会和板外的 10k 分压打架。

**🔴 重大更正（2026-09-18，上一轮已核实）：PG7 不是「新增的第十根输入」，
它早就是九路输入之一，现在叫 `X_HOME`。**

| 证据 | 内容 |
|---|---|
| `Core/Inc/main.h:78` | `X_HOME_Pin = GPIO_PIN_7`，端口 GPIOG |
| `Core/Src/main.c:702-708` | PG7 已在 GPIOG 输入 mask 里 |
| `App/Inc/ec_inputs.h:6` | `#define EC_INPUT_X_HOME (UINT16_C(1) << 0U)` ← **bit0** |
| `App/Inc/ec_inputs.h:23-24` | `EC_INPUT_COUNT = 10`、`EC_INPUT_ALL_MASK = 0x03FF` |
| `App/Src/ec_board_stm32.c:75` | `EC_READ_HIGH(EC_INPUT_X_HOME, X_HOME);` |

**→ 正确做法是「把 bit0 的语义从 `X_HOME` 【改名】为 `TURNTABLE_HOME`」，
不是再加一个 bit10、把 mask 改成 `0x07FF`。**
（`docs/方案B固件侧清单-2026-09-17.md:33` 提议的正是后者 ——
**那会让同一物理引脚出现两个逻辑角色，不要采用**。）
