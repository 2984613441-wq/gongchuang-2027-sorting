# 任务：把 X/Y 限位从"一个宏"拆成"X、Y 各一个"（为实测行程铺路）

## 背景

STM32 固件现在用**一个宏**同时管 X 和 Y 的机械可达限位：

`电控/firmware/stm32f407_m144z/App/Inc/ec_motion_plan.h`
```
:57  #define EC_MOTION_WORKSPACE_LIMIT_MM10 1450   ← 协议合法域 ±145.0mm
:58  #define EC_MOTION_REACH_LIMIT_MM10      825   ← 机械可达域 ±82.5mm（165mm 全程的一半）
:63  #define EC_MOTION_HOME_X_MM10        (-800)
```

**问题**：用户实机实测，**X 和 Y 的可用行程不一样**（X 约 210mm、Y 约 190mm，**尚未定案**）。
一个宏塞不下两个不同的值。

## 你的任务

### 任务 A（**现在就能做，行为必须完全不变**）

把 `EC_MOTION_REACH_LIMIT_MM10` **拆成 X / Y 两个宏**：

```
EC_MOTION_REACH_LIMIT_X_MM10
EC_MOTION_REACH_LIMIT_Y_MM10
```

**本次两个值都填 825**，保证行为与改前一字不差。这样等实测值一到，只改两个数字。

### 任务 B（**不要现在做**，只写进交付的"待办"里）

实测值定案后：X 填 `实测X/2*10`、Y 填 `实测Y/2*10`。
**这一步需要用户确认，你不要自己填。**

## 硬约束

1. **`ec_motion_plan.c:55-69` 的双重域检查必须保留**（协议域 ∩ 机械域），只是把机械域那两次检查改成 X、Y 各查各的：
   ```c
   /* 现在 */  within_limit(x, y, EC_MOTION_REACH_LIMIT_MM10)
   /* 改成 */  x 在 ±REACH_X 内  &&  y 在 ±REACH_Y 内
   ```
   `within_limit()` 目前是"两个轴共用一个 limit"的写法，需要拆或加一个变体。
   **两个坐标（抓取点、落料点）都要查**——这是 2026-09-16 修过的 bug，别改回去。

2. **同步树莓派侧**：找出主机侧所有对坐标做域检查的地方（`电控/deploy/run_chain.py`、
   `电控/src/electrical_control/protocol/`），确认它们用的是同一个上限口径。
   如果主机侧也硬编码了 825 或 ±82.5，**列出来但先别改**，写进交付让你确认。

3. **`EC_AXIS_TRAVEL_TOTAL_MM`（`ec_axis_driver.h:37`，现 165）暂时不要动** ——
   它和 `EC_MOTION_REACH_LIMIT_MM10` 是**同一件事的两个副本**，实测定案后要一起改。
   在交付里明确写下"这两个值必须同时改"。
