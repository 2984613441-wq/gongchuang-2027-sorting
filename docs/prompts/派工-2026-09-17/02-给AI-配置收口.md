# 任务：配置文件收口（三份 ini 并存 + 硬编码超时）

## 背景

项目里现在**同时存在三份 ini**，各管一段，节名互不相同，谁都不知道哪份是权威：

| 文件 | 节 | 谁在读 |
|---|---|---|
| `电控/deploy/sorting_config.ini` | `[Vision]:1` `[Motion]:21` `[Timeout]:45` `[Safety]:60` `[Calibration]:89` `[Network]:110` | `run_chain.py`（**请复核**） |
| `电控/deployment/sorting_config.ini` | `[Vision]:30` `[Scheduler]:49` `[Network]:75` `[Debug]:86` | `deployment/apply_config.py` |
| `电控/calibration_config.ini` | `[CameraCalibration]:21` `[ObjectHeights]:47` `[WorkspaceLimits]:63` | `rpi/pixel_to_device.py` |

**三份都有 `[Vision]` 和 `[Network]`，但键不一样。** 改错一份 = 改了不生效。

## 已核实的三个具体毛病

### 毛病 1：`[Timeout]` 节写了，但代码根本不读

- `电控/deploy/sorting_config.ini:53,58` 定义了 `single_item_timeout_s = 13`、`total_round_timeout_s = 180`
- 而 `电控/deploy/run_chain.py:893` **硬编码** `task_timeout_s = 5.0`，用在 `:943`、`:946`、`:958`
- → **配置里那个 13 秒从来没生效过。** 谁是权威？现场调参的人会以为改 ini 有用。

### 毛病 2：`apply_config.py` 还在读废弃的键

`电控/deployment/apply_config.py:64`、`:66`、`:68`、`:104`、`:208` 都读 `[Vision] conf_threshold`。
请确认：这个键在 `deploy/sorting_config.ini` 的 `[Vision]` 里叫什么？
**如果名字不同，两份配置对同一个参数有两套名字。**

### 毛病 3：`[Safety] limit_switch_check = false` 与固件冲突（**这条可能是上电级故障**）

`电控/deploy/sorting_config.ini:73` 写 `limit_switch_check = false`（依据"X/Y 不装限位开关"的用户裁决），
但**同一份文件的 `:69-72` 注释自己就警告**：

> 固件 `ec_startup_sequence.c` 的 POST 自检与 HOMING 目前**仍依赖**
> X_HOME/X_END/Y_HOME/Y_END/Z_UP/Z_DOWN 六个输入（`:124-126`、`:158-171`）
> → 置 false 后若不同步改固件，**上电会 POST 失败进入 FAULT_LOCK**

**请到源码里核实这条注释是否仍然成立**（读 `ec_startup_sequence.c`）。
成立 → 这是一颗**上电就炸的雷**，必须报出来。
