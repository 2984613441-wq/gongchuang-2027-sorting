## 1. 🔍 复核重点 A：**"显示完才能下一件"门禁真的堵死了吗**

赛题评分细则第 5 条：

> **本次分拣信息没有显示前而分拣下一件货物不得分。**

**去看代码**（自己读，别信转述）：

| 要查的 | 位置 |
|---|---|
| `PendingRender` → `complete()` → `RenderReceipt` | `电控/src/electrical_control/rpi/__init__.py` |
| `scheduler` 怎么用 `RenderReceipt` 放行下一件 | `电控/src/electrical_control/scheduler/` |
| `run_chain.py` 的 `_render_and_ack(...)` | `电控/deploy/run_chain.py` |

**必须回答**：

1. **有没有任何路径能在没有 `RenderReceipt` 的情况下放行下一件？**
   （比如：显示抛异常被吞掉后仍然继续？调度器超时后强行推进？）
2. **`DISPLAY_ACK` 是谁发的、等的谁？** 是**树莓派自己确认自己**（假门禁）
   还是**等 STM32 回 ACK**（真门禁）？**这条很关键。**
3. **如果渲染失败（图片缺失 → `ImageLoadError`）会怎样？**
   `display_hdmi.py:41-42` 说 fail-closed。
   **但 fail-closed 之后整条链会卡住还是跳过？**
   卡住 = 比赛结束（15 秒无动作）；跳过 = 不得分。
   **哪个更糟？你应该建议哪个？**

## 2. 🔍 复核重点 B：**`success_count` 会不会虚增**

赛题要求显示"**分拣成功的总数量**"。
**先看 `06-屏幕显示.md` 的赛题原文**：夹空、未到位、落料异常**不能算成功**。

**必须回答**：

1. `success_count` **在哪里累加**？（文件:行号）
2. **什么情况下不累加？** 逐条列出：
   - 抓空（夹爪闭合但没夹到东西）
   - 货格未到位
   - 落料异常
   - `ITEM_RESULT` 报失败
3. ⚠️ **`ITEM_RESULT` 的结果码是"真实传感器反馈"还是"按流程走完就报成功"？**
   （去读 `ec_app.c` 里 `ec_app_inject_item_result` 的调用点）
   **如果结果是"流程走完就算成功"，那么抓空也会计数 —— 这是零分级的 bug。**
4. 结合 **P2**（抓取点写死会导致抓空）：**P2 没修之前，这里的计数肯定是错的**。
   **明确写出这个依赖关系。**

## 4. 🔍 复核重点 D：**对方的部署清单有没有隐患**

1. **`--frame-output auto`**：`auto` 在**没有 `/dev/fb0` 时静默变 `none`**。
   比赛时若真掉到 `none`，**屏幕什么都不显示 → 零分**。
   **这个静默降级合理吗？应该改成 fail-fast 吗？**（给判断）
2. **字体**：`font_path=None` → CJK 变方块。
   现在有没有**在启动时校验字体**的逻辑？还是**跑起来才发现**？
   （建议：启动时校验并**拒绝启动**，比比赛中途发现好）
3. **名称表缺项**：`build_display_view` 对未映射的 `class_id` 抛 `ValueError`（fail-closed）。
   **比赛时抽到没配的类别 = 整件不显示 = 不得分。**
   这个取舍对吗？还是该降级显示"未知"？**给判断。**
