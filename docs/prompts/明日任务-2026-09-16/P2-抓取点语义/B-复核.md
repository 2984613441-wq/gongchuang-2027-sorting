| 0 | MOVE_XY HOME → PICK | | |

**关键判定**：

## 2. 🔍 核实：**双重域检查覆盖了两组坐标吗**

`ec_motion_plan.c` 有**两个域**要查（`1450` 协议域 ∩ `825` 机械可达域）。

**执行者说"改后对两组坐标都查"** —— 你去数：

| | 抓取点 pick_x / pick_y | 落料点 place_x / place_y |
|---|---|---|
| 查了 1450 吗？ | | |
| 查了 825 吗？ | | |

**任何一格是空的，就是一个越界漏洞** ——
X/Y 已无限位开关，越界**没有任何硬件能发现**（会丢步、漂移、后续落点全错）。

## 3. 🔍 核实：**fail-closed 是不是真的 fail-closed**

这是本次改动**最重要的安全属性**。执行者说 `ec_gateway_item_pick()` 的桩返回 `false`，
让运动被拦住。你要确认：

1. **桩真的返回 false 吗？** 自己读代码。
2. **返回 false 后，`ec_app_start_motion()` 走向哪里？**
   是 `EC_RESULT_POSITION_UNREACHABLE`（正确，报失败）？
   还是**静默返回 / 继续用未初始化的栈变量**（❌ **最严重**）？
3. ⚠️ **重点查：`pick_x_mm10` / `pick_y_mm10` 有没有可能"未被赋值就被使用"？**
   C 里局部变量不初始化是 UB。
   如果执行者写的是
   ```c
   int16_t pick_x, pick_y;
   if (!ec_gateway_item_pick(&pick_x, &pick_y) || !ec_motion_plan_build(&p, pick_x, pick_y, ...))
   ```
   那么 `||` **短路**保证 `build` 不会被调用 —— 这是**对的**。
   但如果是**分开写的**（先调 build，再检查），就是 bug。**去看实际代码。**
4. **有没有路径能在"没有抓取点"的情况下仍然发出脉冲？**（追到 `ec_axis_driver_start_pick_place`）
