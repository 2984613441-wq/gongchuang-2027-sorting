## 1. 🔍 你必须自己重跑的事

**不要相信 对方的引用点清单。** 自己 grep：

```powershell
$fw = "电控\firmware\stm32f407_m144z"
# 限位引脚
Select-String -Path "$fw\Core\Inc\main.h","$fw\Core\Src\*.c","$fw\App\Src\*.c","$fw\App\Inc\*.h" `
  -Pattern 'X_HOME|X_END|Y_HOME|Y_END'
# Z 步进引脚
```

**然后回答**：

| 问题 | 你的答案 |
|---|---|
| 对方列全了吗？漏了哪些？ | |
| 有没有**活引用**（不只是定义）？ | |

## 2. 🔍 核实那条"一上电就启动失败"的风险

`docs/plans-2026-09-16/02-机构方案A-vs-B.md` 的 **X-5** 提出：

> `ec_startup_sequence.c:37, 194-210` 的 BARRIER 状态在取消挡板后，
> **会不会等不到挡板反馈而 5000 ms 超时判 FAILED？**

**去读 `App/Src/ec_startup_sequence.c`，自己判断。必须回答**：

1. BARRIER 状态**怎么算通过**？等的是什么信号？
2. 取消挡板后（不再有挡板反馈），这个状态**能不能通过**？
3. 有没有超时？超时后**走哪条路**（FAILED → 锁死？还是跳过？）
4. 🔴 **`ec_startup_sequence` 在主链路里到底被调用了吗？**
   （去 `ec_app.c` 找调用点；之前有一份方案说"未核实它在主链路中是否被调用"，**你去核实**）
5. **结论**：取消挡板后，按现状代码，装置**一上电会怎样**？

**把这一条标为最高优先级** —— 如果是"一上电就 FAILED"，那前面所有工作都白做。
