## 一、要解决的问题（有实测证据）

主相机 6 类模型（`_runs/main_6c_v2/weights/best.pt`，输入 448，YOLO11n）在**五棱柱 / 正方体 / 长方体**三类上互相误判。我刚在同一验证集（`_train_main_6c_v2/data.yaml`，94 张 / 270 实例）上跑出的结果：

| 类别 | Precision | Recall | mAP50 |
|---|---|---|---|
| cube 正方体 | 1.000 | **0.914** | 0.983 |
| cuboid 长方体 | 0.942 | 0.948 | **0.955** |
| cylinder 圆柱 | 0.896 | 1.000 | 0.993 |
| **pentagonal_prism 五棱柱** | **0.891** | 0.951 | 0.962 |
| cone 圆锥 | 0.994 | 0.932 | 0.984 |
| tetrahedron 四面体 | 1.000 | 0.975 | 0.995 |

归一化混淆矩阵（`runs/detect/_runs/val_main_v2/cls_report/confusion_matrix_normalized.png`）显示：
- cuboid 的预测里 **5% 判成 cube、5% 判成 penta、2% 判成 cone**
- penta 的预测里 **5% 判成 cube、5% 判成 cuboid**
- cube 的预测里 1% 判成 cuboid
- 另有 **25%/29%/17%**（cube/cuboid/penta）的预测落在 background（误检）

根因：俯视投影下这三类都是多边形，cube vs cuboid 只差长宽比，penta 的第五条边在小件/模糊/过曝时看不出；且训练集类别不均衡（cuboid 411 / penta 241 / cube 201 实例）。

## 二、任务：实现两档修复（A + B），默认全关、可一键回退

### A. 推理端「多帧类别投票」（Pi 侧）

文件：`电控/src/electrical_control/rpi/socket_vision_source.py`

现状：每个 `target_seq` 从 `BATCH_TARGETS` 拿一个 `class_id`（= shape_id 或 code）就直接派件。

要求：
1. 对同一目标维护最近 `N` 帧的 `(class_id, conf, 像素坐标)` 历史（默认 `N = 3`）。
2. 采纳规则：`class_id` 至少 `quorum` 票（默认 `2`，即 2/3）才采纳；未达 quorum 时**不派该件**（视为不可用），并在日志统计里计数。
3. 目标关联：优先用 `target_seq`；如果 `target_seq` 每帧会变（现状不保证唯一，代码注释里有说明），退化为**最近位置匹配**（阈值可配，默认 40 mm，使用现有坐标换算）。
4. 新增构造参数（全部有默认值、默认行为 = 关闭投票，保持现状）：
   - `class_vote_enabled: bool = False`
   - `class_vote_frames: int = 3`
   - `class_vote_quorum: int = 2`
   - `class_vote_max_wait_frames: int = 6`（等不到 quorum 的最长等待帧数，超时按不可用处理并记 WARNING 一次）
5. 不得破坏现有行为：`_resolve_box_ids`、`_filter_skipped`、`_visibility_signature`、`_expand`、`note_served`、首件稳定门、α 补尾语义都要保持；关闭投票时输出必须与现在逐字节等价。
6. 统计：新增 `vote_stats()`（accepted / rejected_no_quorum / timeout），在派件日志里可打印。

### B. 设备端「分类别置信度阈值」+ 低置信不抓

文件：`_pi_tools/maixcam_scripts/yolo_v11_send.py`（仓库版；设备上现在是 10-29 的旧版，**不要直接改设备**，只改仓库并在文档里写部署步骤）

要求：
1. 新增 `--min-conf-by-class "2:0.55,3:0.55"`（格式 `class_id(0-based):threshold`，逗号分隔；不写的类用 `--conf`）。
2. 未达阈值的检测**不加入 BATCH_TARGETS**；若整帧全被过滤，仍按现有逻辑发空批（保持链路心跳）。
3. 新增可选 `--unknown-as-code0`：开启 `--id-mode code` 时，若某件置信度介于 `--conf` 与分类阈值之间，可选择发 `code=0`（判不出）而不是丢掉——默认关闭，保持现状。
4. 打印每帧统计：`sent / dropped_low_conf / dropped_class`。
