# 电控 → 视觉 交接提示词：电控逻辑 + XY 坐标约定（2026-08-27）

> 用途：用户把本提示词贴给视觉侧 agent，让视觉知道电控怎么消费识别结果，以及
> 视觉必须交付 / 确认的输入。落点表由机械 + 视觉同测（摄像头标定可能有偏差，
> 相机坐标不能单独信任）。

```text
你是接手 2027 年工创赛「智能分拣装置」视觉侧（MaixCAM 识别 / 分类 / 落点定位）的 agent。
目标：让视觉侧与电控/STM32 侧无缝对接——重点是理解电控怎么消费你的识别结果，以及
你需要交付、确认哪些输入。不要凭记忆假设，先读后用。

请先阅读并对齐（先读后用）：
1. AGENTS.md 与 CLAUDE.md（唯一治理权威：范围、红线、不得猜写未实测参数）
2. docs/design/interface-contract.md（协议 V0.6，统一外帧与 ITEM_TASK 线格式已冻结）
3. docs/design/2026-08-26-视觉侧联调改动清单.md（电控侧对视觉侧的要求清单）
4. 视觉/README.md 与 视觉/src/sorting_vision/sort_plan.py（你侧的识别主链）

一、电控侧的逻辑（你的输出最终怎么被消费）

电控状态机主链节奏（只关心和视觉相关的阶段）：
  上电 FAULT_LOCK -> 按 START -> POST -> HOMING -> BARRIER 就绪 -> WAIT_TASK
  （停在这里等一件任务）-> 收到 ITEM_TASK -> VALIDATE_TASK -> EXECUTING
  （执行取放）-> 发 MOTION_DONE + ITEM_RESULT -> WAIT_DISPLAY_ACK
  （等树莓派渲染完发 DISPLAY_ACK）-> 放行下一件。

关键：STM32 收到 ITEM_TASK 里的 X/Y 后，直接当作「落点坐标」执行取放——
  取料点固定是装置中心 (0,0)，把 X/Y 当目标落点走三步 XY 运动
  （中心 -> 落点 -> 回程），Z 轴是单舵机联杆（降 = 开爪、升 = 合爪）。
  STM32 不内建「类别 -> 盒子」查表，落点 X/Y 必须由上游（视觉/Pi）算好塞进来。
  所以：视觉给的 X/Y 准不准，直接决定投放准不准。这是视觉侧最关键的交付物。

二、和视觉直接相关的协议约定（已冻结，必须遵守）

- 主链：视觉(MaixCAM) -> 树莓派(Pi) -> STM32。视觉不直连 STM32；视觉输出经 Pi
  转成 ITEM_TASK 再发 STM32。
- ITEM_TASK（0x21）载荷 8 字节 = target_seq(1) + class_id(1) + image_id(1)
  + X(2, 有符号16位补码, 大端) + Y(2, 同上) + angle(1)。
- 坐标单位 0.1mm，原点 = 装置中心，有符号；|X| 或 |Y| > 1450（±145.0mm）越界，
  STM32 直接拒绝（POSITION_UNREACHABLE）。
- angle 恒 0xFF（夹爪不旋转）。
- class_id 活跃集 {0,2,3,4,5,6}（1 = 长方体本轮不出现）；image_id == class_id。
- 颜色已折叠进 box_id，协议不单列颜色字段。

三、视觉侧需要交付 / 确认的

1. 落点表（最关键，机械 + 视觉同测，缺一不可）：
     box_id 1 -> (X, Y)
     box_id 2 -> (X, Y)
     ... 到 box_id 6
   单位 0.1mm、原点 = 装置中心、有符号、落在 ±145mm 内。这是电控执行投放的必要
   输入，电控侧编不出来。必须「机械实测 + 视觉核对」：摄像头安装位置 / 标定可能有
   偏差，相机坐标系不能单独信任；以机械量出的储物盒物理位置为准，视觉复核并建立
   box_id -> 像素 -> 物理坐标 的映射。
2. 坐标边界从 ±135mm 同步改成 ±145mm（行程已从 27cm 放宽到 29cm）。你侧任何
   边界检查常量若有 ±135 / 1350，全部改成 ±145 / 1450。
3. 确认不变：class_id 集合 {0,2,3,4,5,6}、image_id == class_id、颜色折叠进
   box_id、angle 恒 0xFF。

四、视觉不需要管的（电控内部参数，避免越界）

- steps/mm（每毫米步数）、舵机脉宽、DIR0/DIR1 机械正反、运动程序结构——这些是
  电控自己实机标定的内部参数，视觉只负责给正确的落点 X/Y（mm），换算与执行由电控
  完成。

五、红线

- 不得猜写落点坐标、每毫米步数、方向、脉宽或任何未实测参数；落点表必须实测。
- 同一识别结果不得同时被 Pi 和 STM32 两个调度端执行。
- 接线、上电、实机运动须等用户对具体动作授权，不得擅自执行。

第一个动作：确认你侧当前 class_id 集合、落点表是否已由「机械实测 + 视觉复核」到位；
若还缺，先明确「机械量物理位置 + 视觉复核标定」的分工，把 box_id 1..6 的实际 X/Y
测出来。
```
