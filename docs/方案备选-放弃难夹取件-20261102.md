| 两次机会 | 「每个参赛队可以有两次运行机会，取两次运行的最好成绩」 | L156 |

**三个关键推论**：

1. **掉件是最贵的错误**：不是扣 5 分，而是**整轮结束**（L268）——后面所有件全部归零。
2. **同组越多越划算**：2 件同组 = 10 分（5+5），1 件 = 2 分；所以「把同色同形凑一盒」比「什么都要抓一点」值钱。
3. **放弃不等于安全**：放弃的件留在托盘，可能挡住后续件的抓取路径/夹爪包络 ⇒ 需要在几何上确认它们不挡路（现有 `planner.check_exit` / `_carrying_path_blocked` 会把其他件当障碍，会因此**拒识**本来能抓的件）。

## 二、放弃的代价与收益（定量框架）

设一轮物料共 `N` 件，其中圆柱 `c` 件、圆锥 `o` 件；单件平均价值 5 分（同组多件时）。

### 方案 A：完全放弃圆柱 + 圆锥

```
得分变化   ≈ −5 × (c + o)            （这几件 0 分）
风险下降   = 消除「抓圆柱/圆锥失败 → 掉件 → 整轮结束」的概率
时间收益   ≈ +t_avg × (c + o)        （少抓的件时间，用来…但件是有限的，不产生更多分）
```

**关键判断**：如果「抓圆柱/圆锥」的成功率低于「它们占的分 / 掉件损失」，放弃就是赚的。

用期望值算：

```
抓：期望 = 5×(c+o)×p − P(掉件)×(剩余件数×5)
弃：期望 = 0，且 P(掉件)=0
```

举例（**假设**，需用你的实测替换）：

| 假设 | 抓的期望 | 弃的期望 | 结论 |
|---|---|---|---|
| 成功率 p=0.9，掉件概率 5%，后面还有 6 件 | 4.5(c+o) − 0.05×30 | 0 | 抓更划算 |
| p=0.5，掉件概率 30%，后面还有 6 件 | 2.5(c+o) − 9 | 0 | 弃更划算（掉件太贵）|

⇒ **决策完全取决于两个实测数字**：①圆柱/圆锥抓取成功率 ②失败时掉件（而非原地失败）的概率。

### 方案 B：只放弃圆锥（保留圆柱）

圆锥（tier2）判形有歧义 + 尖顶难吸；圆柱（tier1）只是俯视判形有歧义，抓取本身不一定难。
若圆柱实测成功率可接受（≥80%），只弃圆锥，收益/风险比更好。

### 方案 C：自适应放弃（推荐先做"能随时切"）

```
先抓简单件（cube / cuboid / 五棱柱 / 四面体）
每种"难件"（圆柱/圆锥）本轮最多尝试 K 次（K 可配，默认 1）
  成功 → 后续同形状继续抓
  失败（无 NACK 级别错误、但没夹住/掉回托盘）→ 本轮不再尝试该形状
```

- 需要失败反馈：`ITEM_RESULT` 的 `result_code` 是否能区分「成功/夹空/掉件」——**需查固件回传口径**（当前固件大概率只回 0x00 SUCCESS）
- 若固件只能回"成功"，则自适应退化为「N 个候选里试一个」的静态策略

## 三、三种方案的工程改动量

| 方案 | 改动 | 风险 | 建议 |
|---|---|---|---|
| A 完全放弃 | `[Strategy] skip_shapes = 3,5`；selector 过滤 + run_chain「无件」处理 + 日志计数 | 低 | 先做，作为保底 |
| B 只弃圆锥 | 同上，`skip_shapes = 5` | 低 | 先做，作为保底 |
| C 自适应 | 需失败反馈 + 每形状状态机 + 计数 | 中（依赖固件回传口径） | 第二步 |

**实现细节（A/B）**：
1. 在 `pick_strategy/selector.py` 加 `skip_shapes: tuple[int,...]`（从 `[Strategy]` 读），
   `usable_detections()` 里过滤；被过滤的件**保留在几何里**（作为障碍），只是不选它
2. `run_chain` 打印「本轮跳过 k 件（圆柱×a 圆锥×b）」
3. 若过滤后一帧无可用件 → 现有逻辑会走空帧/空闲钟，**不会**误判为"台面无件"？需确认：`empty_confirmation_frames` 会判空 ⇒ 可能提前结束本轮。**必须单独处理**：跳过件不算"空"，否则 15s 结束就白搭
4. 默认 `skip_shapes = 空`，行为与现在完全一致；一键回退

## 六、实现状态（2026-11-02 已落地，默认不跳过）

开关在 `pick_strategy.ini` 的 `[Strategy]`：

```ini
[Strategy]
skip_shapes = 0      # 0/none = 全抓（默认，行为与改动前一致）
#  A 方案（全弃圆柱+圆锥）： skip_shapes = 3,5
#  B 方案（只弃圆锥）      ： skip_shapes = 5
class_id_mode = box_id  # box_id=现状；协议 V1.0 生效（class_id=code）后改 code
```

**行为**：
- 被跳过的件**不派件**，但**仍留在帧里当障碍物**（路径/退出检查不会因“看不见”而放行）；
- 每帧日志：`主动放弃形状：本帧跳过 N 件（target_seq=[...]）`；
- 首件稳定门也用同一份过滤（不会因为“有件但全跳过”而卡在起轮）；
- 抛错/读配置失败 ⇒ 自动退回“不跳过任何形状”；
- 回退：`skip_shapes = 0`，无需改代码。

**已验证**：`skip_shapes` 配置解析（含全角逗号/去重/越界报错）、`shape_of_class_id` 两种口径、
选择器过滤（跳过件不算减少几何）、视觉源过滤（跳过件不派、其余正常、异常不崩）——
相关套件 **229 passed**。

**注意**：跳过改变的是“抓什么”，不改变“时序”。若跳过导致托盘上只剩被跳过的件，
链会走空闲钟正常收场（这是对的，不是 bug）。
