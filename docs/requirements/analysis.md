## 1. 赛题本质

本赛项的核心问题不是"设计分拣机"，而是：

> **在硬实时边界（15 秒无动作判负）和单电源约束下，让三个异构计算节点协同完成"识别→调度→执行→显示确认"的可靠闭环。**

四个关键的约束交叠：

- **安全不可妥协**：急停必须独立硬件切动力，重力轴必须断电自锁。
- **事件不可混淆**：`MOTION_DONE` ≠ `ITEM_RESULT` ≠ `DISPLAY_ACK`，累计成功数量只由成功 `ITEM_RESULT` 更新。
- **15 秒不可重置**：内部重传、重新识别、重复刷新都占用原预算，只有可观察动作进展和首次有效 `DISPLAY_ACK` 能更新时间基准。
- **单电源不可分割**：所有电压由一个电池分路转换，逻辑和动力必须分路布线但不允许第二电源。

## 2. 子系统依赖关系

```text
视觉(MaixCAM) ──结构化目标列表──► 调度(树莓派) ──单件高层任务──► 运动(STM32)
                                           │
                                           └──Micro-HDMI──► 显示屏
```

- MaixCAM → 树莓派：整批目标 + 逐件复核 → 树莓派只能发高层任务
- 树莓派 → STM32：单件任务 → STM32 独立执行 → 反馈 `MOTION_DONE` → `ITEM_RESULT`
- 树莓派 → 显示屏：类别 ID + 图片 ID + 序号 + 累计数量 → 收到 `DISPLAY_ACK` 后允许下一件
- STM32 → 执行器：步进脉冲/PWM/GPIO → 唯一底层运动与安全控制器

### 4.1 D-007 的事实、推断与未知

- **事实**：用户已于 2026-08-12 裁决采用方案 A；V0.3 的 `DISPLAY_ACK` CRC32 输入包含 `image_id` 与 `success_count`，但此前 STM32 缺少完整的期望值来源。
- **已冻结规则**：`image_id` 由树莓派随 `ITEM_TASK` 传给 STM32；每轮 `success_count` 初值为 0、范围为 0..255，只由首次有效的成功 `ITEM_RESULT` 使其加一，失败结果、重复帧、重传、心跳和重新渲染均不改变计数。
- **安全边界**：计数不得回绕。计数达到 255 后不得接受可能产生第 256 个成功结果的新件；若状态不同步或仍出现溢出条件，进入协议/轮次故障并等待人工复位，不自动清零。
- **轮次复位**：只有经验证的新轮次初始化才能将两端计数同时复位为 0；重连、重传、显示超时、普通通信恢复和同一轮软件重启不得自行复位。无法证明两端上下文一致时禁止续跑。
- **推断**：上述同步规则使 STM32 能独立重建当前本件 `DISPLAY_ACK` 的五字段期望内容，但仍须通过协议测试和未来的 Python↔STM32 C 跨语言向量验证。
- **已冻结（2026-08-25，见 D-011）**：统一外层帧头 `0xA5 0x5A`、外层 CRC=CRC-16/MODBUS（大端输出）、`task_id`/`frame_seq`/`data_len` 大端；正式 STM32 通信物理层 USART3 `PD8/PD9`、115200 8N1，USART2 `PA2/PA3` 仅作独立备用。
- **仍未知**：完整 `ITEM_TASK` 的 X/Y/角度线格式、超时/重传/心跳数值和真实硬件参数。

- **原始需求**：制作可制造的探索者 STM32F407 载板/接口 PCB；当前先关闭 Claude 回归复审的文档对账项，再进入 KiCad 候选原理图草图。

### 4.3 执行机构与末端方案任务认知（D-009）

- **原始需求**：根据机械结构和已确认执行器，生成可用于嘉立创 EDA 载板设计的正式方案及可交给 Codex 的完整提示词。
- **真实问题**：需要冻结电控通道数量和接口形式，同时避免把尚未确定的执行器型号、电源额定、机械尺寸和模块针序虚构成事实。
- **已确认事实**：X/Y/Z 各一台 `17HS4401` 步进电机（Z 与 X/Y 同型号）；四个挡板舵机分别使用独立 PWM 并同步动作；三指自定心夹爪由 `DS3120MG` 控制开合；比赛只要求抓起并投入固定储物盒，不要求投放姿态；六个储物盒不参与运动。
- **设计决定**：腕部旋转不进入比赛主链，但载板预留一路 `WRIST_PWM` 和连接器，默认 DNP、固件禁用；原理图候选保留 X/Y/Z 每轴两端共六路限位输入。
- **关键约束**：舵机动力、Z 轴驱动器、DC/DC 和急停主回路位于载板外；急停采用至少两组常闭触点，一组切危险动力正极，一组提供 `ESTOP_FB`；公共地不断，释放后不自动续跑。
- **未知**：Z 轴板外驱动器型号和断电防坠方案、挡板舵机型号及峰值电流、限位实物类型、电池和各 DC/DC 参数、A4988 实物针序、探索者排针物理位置、板框/排母/安装孔/连接器朝向。
- **最小验证行动**：固件按已固定的 GPIO/定时器/UART 功能映射实现并做主机测试；用户完成 CubeMX 配置后，再静态核对 `.ioc`、MSP、GPIO 默认态和定时器参数。机械尺寸未取得只阻塞 PCB 布局冻结，不阻塞软件适配。

### 4.4 STM32F407 首轮安全固件任务认知（D-010）

- **原始需求**：保留 `电控/stm32_logic` 决策内核，新增首轮安全启动、输入诊断、USART3 文本诊断和无功率单轴 STEP 测试代码。
- **真正问题**：在不使能真实电机、不自动启动任何执行器 PWM 的前提下，提供能被用户生成的 CubeMX/HAL 工程直接引用的薄适配层，并避免历史 test 工程中的内部上拉、ENABLE 低电平窗口和自动 PWM 启动残留。
- **必须目标**：三路 ENABLE 始终高电平禁能；九路输入按外部 10k 上拉、低有效、MCU `NOPULL` 解释；STEP 测试单轴互斥、10 Hz、5 秒自动停止；USART3 诊断使用固定缓冲区和逐字节中断接收。
- **非必须目标**：本轮不实现生产二进制协议、回零、真实运动参数、真实驱动使能、舵机动作、PCB 放行或投板结论。
- **分工与边界**：用户负责 CubeMX/Keil 配置和生成工程；Codex 只编写应用 C 代码、HAL 适配代码、主机测试与接入核对说明，不生成或改写 `.ioc`。
- **最小验收**：纯 C 决策内核保持 35/35；新增主机测试覆盖安全锁、20 ms 去抖、诊断解析、单轴互斥、5 秒停止和非法命令无副作用。目标 Keil 无警告构建与 `.ioc` 静态核对需等待用户生成工程后执行。
