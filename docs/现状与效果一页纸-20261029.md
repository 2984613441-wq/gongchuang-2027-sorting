## 5. 卡点与 25 天排法（省赛 11-23）

```
关键路径（卡死整条链的顺序，不能跳）：
① 相机装回 30° 俯视位姿（主方向≈0、托盘占宽 78~87%）
② MaixCAM 部署"生产发送器"并跑起来（往 Pi:8765 发）
③ 台上放件 → 按 Pi 启动键 → 板子收到首帧 ITEM_TASK 自愈 → 跑一件
④ 重标定（相机动过，像素→mm 必重来）
⑤ 颜色实机验 → 双相机复核 → 组盘/落点接通
```
**排期建议**：①②③ 是本周必须打通的最小闭环；④⑤ 下周；留最后 5~7 天做压力测试与预案。

## 6. 队长可能会问的 6 个问题（标准答案）

| 问 | 答 |
|---|---|
| 识别准确率多少？ | 6 类形状 **mAP50 0.972 / mAP50-95 0.593**，逐类最高 cube 0.991、tetra 0.995；**部署权重实测**，可复现 |
| 能实时吗？ | 能，MaixCAM 上 **15.7 FPS / 33 ms**，屏幕实时出框 + 中文名称 |
| 为什么有"测出来很好、现场不行"的风险？ | 因为**标签质量**：同一批数据 AI 自判时长方体精确率 0.621，人复核后 0.914 —— 模型上限由标注决定，所以我们做了三轮人工复核 |
| 现在为什么演示不了整机？ | 两处物理/链路问题：①相机被移动（+61°），训练分布外 ②设备上跑的是"只看不联网"脚本 ⇒ 树莓派收不到视觉 ⇒ 起链被"可见件数=0"挡住 |
| 还差多少工作量？ | 最小闭环（相机复位 + 推流 + 跑通一件）本周可期；颜色实机验、双相机复核、组盘接通需再加一周 |
| 失败了怎么办？ | 有退路：模型与部署已验证（15.7 FPS 落盘可复现）；颜色走 HSV 零训练；副相机方案保留但非必需；最坏情况按"形状+颜色"两维分拣，信息维度赛后补 |
