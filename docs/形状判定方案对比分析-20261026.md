## 一、背景与需求

### 1.1 赛规约束
- **6种形状**：正方体/长方体/圆柱/五棱柱/圆锥/正四面体
- **5种颜色**：白/红/蓝/绿/黄
- **"同类" = 形状相同 且 颜色相同**
- **混装惩罚**：该盒0分
- **掉件惩罚**：本轮比赛结束

### 1.2 技术挑战
- **俯视限制**：摄像头正上方，只看顶面
- **域偏移**：训练(木桌) vs 现场(白托盘)
- **圆柱/圆锥混淆**：俯视都是圆，只能靠尖顶判别
- **实时性**：需要在20秒内完成20件分拣

## 二、候选方案

### 方案A：纯YOLO（6类分类）

#### 技术路线
```
输入：448×448 RGB图
模型：YOLO11n（6类）
输出：[class_id, confidence, bbox]
```

#### 优势
- ✅ 端到端训练，无需手工特征
- ✅ 已有成熟工具链（ultralytics）
- ✅ MaixCAM NPU原生支持
- ✅ 5类模型已达 mAP50=0.9155

#### 劣势
- ❌ 圆锥数据缺失（当前0实例）
- ❌ 圆柱/圆锥俯视难区分
- ❌ 域偏移风险（白托盘 vs 木桌）
- ❌ 对训练数据质量依赖高

#### 性能预估
| 指标 | 预估值 | 依据 |
|------|--------|------|
| 准确率 | 85-90% | 5类模型已达91.5%，6类新增圆锥会拉低 |
| 推理速度 | 60-80ms/帧 | YOLO11n在MaixCAM实测（7类） |
| 开发周期 | 4-5天 | 需采集圆锥数据 + 白托盘数据 |
| 维护成本 | 低 | 标准YOLO流程 |

#### 风险点
1. **圆锥数据采集失败** → fallback到方案B
2. **圆柱/圆锥混淆率>10%** → 需几何特征辅助
3. **白托盘域偏移** → 需重新采集训练集

---

### 方案B：纯几何特征（OpenCV）

#### 技术路线
```
输入：448×448 RGB图
预处理：二值化 + 轮廓提取
特征：
  - 顶点数（3/4/5/多）
  - 长宽比
  - 轮廓面积/周长比
  - 顶部尖锐度（圆锥 vs 圆柱）
  - 对称性
分类器：决策树 / 规则引擎
```

#### 优势
- ✅ 无需训练数据（规则驱动）
- ✅ 可解释性强（便于调试）
- ✅ 对光照不敏感（阈值可调）
- ✅ 圆锥零数据也能识别（顶部尖锐度）

#### 劣势
- ❌ 手工特征设计复杂
- ❌ 对托盘背景敏感（白托盘 + 白物体 → 轮廓丢失）
- ❌ 俯视几何信息不足（3D→2D投影损失）
- ❌ 规则脆弱（边界case难处理）

#### 性能预估
| 指标 | 预估值 | 依据 |
|------|--------|------|
| 准确率 | 65-75% | 参考`archive/_B档金贵/stage1_contour_v3.py`历史实验 |
| 推理速度 | 20-30ms/帧 | OpenCV轮廓提取很快 |
| 开发周期 | 2-3天 | 需大量规则调试 |
| 维护成本 | 高 | 每个边界case都要手工处理 |

#### 风险点
1. **白托盘 + 白物体** → 轮廓提取失败
2. **五棱柱 vs 正方体** → 俯视都是多边形，顶点数不稳定
3. **圆锥 vs 圆柱** → 尖顶特征在俯视下不明显

### 方案C：YOLO + 几何融合（推荐）

#### 技术路线
```
阶段1：YOLO粗分类
  输入：448×448 RGB
  输出：6类 + confidence
  
阶段2：几何精修（仅对低置信度件）
  if confidence < 0.7 and class in [cylinder, cone]:
      提取轮廓 → 计算顶部尖锐度 → 修正为cone或cylinder
  
阶段3：输出最终结果
```

#### 优势
- ✅ 结合深度学习 + 可解释规则
- ✅ 几何特征只用于修正，降低误判风险
- ✅ 对圆锥数据不足有容错性
- ✅ 保留YOLO的高准确率，用几何补短板

#### 劣势
- ❌ 两阶段流程，代码复杂度上升
- ❌ 几何阶段仍需调参
- ❌ 推理速度略慢（+20ms）

#### 性能预估
| 指标 | 预估值 | 依据 |
|------|--------|------|
| 准确率 | 90-95% | YOLO基础90% + 几何修正提升5% |
| 推理速度 | 80-100ms/帧 | YOLO 70ms + 几何修正20ms（仅部分件） |
| 开发周期 | 5-6天 | YOLO训练 + 几何模块开发 |
| 维护成本 | 中 | 两个模块独立维护 |

#### 实现伪码
```python
def classify_shape(img, yolo_model):
    # 阶段1：YOLO推理
    results = yolo_model(img)
    class_id = results.class_id
    confidence = results.confidence
    
    # 阶段2：几何修正（仅对圆柱/圆锥低置信度）
    if class_id in [2, 4] and confidence < 0.7:
        # 提取轮廓
        gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
        contours = cv2.findContours(gray, ...)
        
        # 计算顶部尖锐度
        top_region = contours[0][:, :10]  # 取上方10%区域
        sharpness = compute_sharpness(top_region)
        
        # 修正
        if sharpness > 0.8:
            class_id = 4  # cone
        else:
            class_id = 2  # cylinder
    
    return class_id, confidence
```

#### 风险点
1. **几何阈值调参** → 需在实际白托盘上调试
2. **两阶段耦合** → YOLO错误可能被几何放大

### 方案D：YOLO + 斜视相机（最优但需硬件）

#### 技术路线
```
主相机（俯视）：颜色 + 大致形状
辅助相机（45°斜视）：侧壁斜率
  - 圆柱：侧壁垂直（斜率→∞）
  - 圆锥：侧壁斜向（斜率有限）

融合：
  if 俯视=圆形 and 斜视侧壁斜率<5:
      class_id = cone
  else:
      class_id = cylinder
```

#### 优势
- ✅ 物理特征明确，准确率最高（>95%）
- ✅ 对圆锥/圆柱混淆问题根本性解决
- ✅ YOLO只需5类（不需圆锥数据）

#### 劣势
- ❌ 需额外相机硬件（成本+300元）
- ❌ 标定复杂（两相机坐标系对齐）
- ❌ 开发周期长（7-10天）
- ❌ 机械结构需调整（安装位置）

#### 性能预估
| 指标 | 预估值 | 依据 |
|------|--------|------|
| 准确率 | 95-98% | 物理特征确定性高 |
| 推理速度 | 100-120ms/帧 | 双相机采集 + 融合 |
| 开发周期 | 7-10天 | 硬件采购 + 标定 + 代码 |
| 维护成本 | 中 | 相机标定漂移需定期校准 |

#### 风险点
1. **硬件预算超限** → 需申请额外资金
2. **机械结构改动** → 影响其他子系统
3. **省赛时间不够** → 只能赛后优化

## 四、推荐方案详细设计（方案C）

### 4.1 架构图
```
输入图像 (448×448)
    ↓
YOLO11n (6类分类)
    ↓
[class_id, confidence, bbox]
    ↓
   判断：是否需要几何修正？
    ├─ NO（confidence ≥ 0.7 或 非圆形类） → 输出结果
    └─ YES（confidence < 0.7 且 class in [2,4]）
        ↓
    几何特征提取
        ↓
    顶部尖锐度计算
        ↓
    修正class_id
        ↓
    输出最终结果
```

### 4.2 关键参数
```python
# YOLO阈段
CONFIDENCE_THRESHOLD = 0.7  # 低于此值触发几何修正

# 几何阶段
SHARPNESS_THRESHOLD = 0.8   # >0.8 → cone, <0.8 → cylinder
```

## 五、风险应对

### 5.1 圆锥数据采集失败
- **触发条件**：5天内无法采集150张圆锥照片
- **应对**：
  1. 降级为5类YOLO
  2. 圆锥/圆柱统一识别为"圆形"
  3. 用几何尖锐度100%依赖于几何判定

### 5.2 白托盘域偏移严重
- **触发条件**：新训练模型在白托盘上准确率<80%
- **应对**：
  1. 紧急采集200张白托盘数据
  2. fine-tune已有模型（不从头训练）
  3. 数据增强（颜色抖动/亮度调整）

### 5.3 圆柱/圆锥混淆率>10%
- **触发条件**：混淆矩阵 `confusion[2][4] + confusion[4][2] > 10%`
- **应对**：
  1. 增强几何修正权重
  2. 考虑引入深度相机（ToF）
  3. 最坏情况：启动方案D（斜视相机）

### 5.4 推理速度不达标（>150ms）
- **触发条件**：单帧推理>150ms，无法满足20秒/20件
- **应对**：
  1. 减少几何修正触发率（提高confidence阈值到0.8）
  2. 优化几何特征计算（只算ROI区域）
  3. 降级YOLO模型（yolo11n → yolo11-tiny）
