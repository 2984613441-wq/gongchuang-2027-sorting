## 2. 参数说明（`ec_step_profile_plan` 函数签名）

```c
bool ec_step_profile_plan(
    ec_step_profile_t *profile,
    uint32_t steps,              // 总步数
    uint32_t start_hz,           // 起步频率 = 200 Hz（不变）
    uint32_t cruise_hz,          // 巡航频率 = 5000 → 6250 Hz
    uint32_t end_hz,             // 末速频率 = 200 Hz（不变）
    uint32_t accel_hz_per_s,     // 加速率 = 10000 → 20000 Hz/s
    uint32_t decel_hz_per_s      // 减速率 = 10000 → 20000 Hz/s
);
```

### 为什么 6250 Hz？

| 理由 | 说明 |
|---|---|
| **整除档** | 100kHz ÷ 16 = 6250（ARR=15），定时器不会四舍五入 |
| **+25% 提速** | 5000 → 6250，单件耗时 13s → 10.4s（节省 2.6s） |
| **仍在安全域** | `EC_STEP_MAX_HZ = 10000`，6250 < 10000 |
| **80步/mm下** | 6250 Hz = 78.1 mm/s（vs 现 62.5 mm/s） |

### 为什么 20000 Hz/s？

| 理由 | 说明 |
|---|---|
| **+100% 加速** | 加减速段缩短一半 |
| **短距离收益大** | 夹取动作多为 50~100mm，加减速占比高 |
| **预期节省** | 单件再省 0.5~1s |
| **机械可承受** | GT2 皮带 + 铝型材龙门，20000 Hz/s 属常规 |

## 8. 注意事项（5 条铁律）

1. **分阶段改，不要一次改三个参数** —— 出问题时不知道是哪个参数的锅
2. **每次改完必须 `pi_square.py` 验证** —— 丢步无硬件检测（Phase 1 前）
3. **Phase 1（TMC2209）是 Phase 2 的前置** —— 否则丢步零可观测性
4. **改动前必须备份当前 hex** —— 回退比重新调试快 100 倍
5. **第一次跑实机前先跑空载测试** —— 带负载可能暴露新问题
