# 落料位复看（PlaceEye）标定与回退 — 2026-11-01

> 目标：放完件后，用**副相机在落料位**看一帧，确认「放下去的是不是我们以为的那件」，
> 不符时纠正货格分配台账。**默认关闭**，可一键回退。

## 一、它解决什么问题

动态分配（`slot_allocator`）按 code 分货格，且「同 code 复用同格」。一旦某件实际放错：

```
以为：格 3 = code 11（圆柱+红）
实际：格 3 里是 code 14（圆柱+蓝）
```

后续所有「圆柱+红」都会继续往格 3 放 ⇒ **整盒混料**。
复看能在**同一轮内**发现并纠正台账，止损。

## 二、为什么只判颜色

| 项 | 说明 |
|---|---|
| 形状 | 主相机抓取前已由 YOLO 判过（6 类，mAP50 0.978），抓的就是同一件 |
| 颜色 | **混料主要来源**；且判色是纯算法（HSV），Pi 本地 `cv2` 即可 |
| Pi 限制 | 无 YOLO 推理运行时（`cv2 4.5.1` DNN 不支持 YOLO11，无 onnxruntime）⇒ 落料位再判形状需另建通道、节拍也紧 |

## 三、配置（`sorting_config.ini`，缺节 = 禁用）

```ini
[PlaceEye]
enabled = true
device = /dev/video2        # 副相机设备节点（Pi 上 v4l2；用 `v4l2-ctl --list-devices` 确认）
width = 1280
height = 720
fps = 30
roi = x, y, w, h            # 落料位在**副相机画面**里的矩形（像素）
grid = 5                    # ROI 内 N×N 采样
min_votes = 3               # 至少这么多同类票才认
warmup_frames = 5           # 丢弃开流前几帧（曝光未稳定）
```

**解析策略**：文件缺失 / 缺节 / `enabled=false` / `roi` 缺失或越界 / 数值非法 ⇒
**禁用 + 告警**（fail-safe）。复看是增强功能，不能因配置写错把主链拖下来。

## 四、ROI 标定步骤（5 分钟）

1. 副相机装好、灯光固定（补光灯亮度固定，锁定曝光/AWB）
2. 在 Pi 上抓一张落料位图：
   ```bash
   python3 - <<'PY'
   import cv2
   cap = cv2.VideoCapture("/dev/video2")
   cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*"MJPG"))
   cap.set(cv2.CAP_PROP_FRAME_WIDTH, 1280); cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 720)
   for _ in range(5): cap.read()
   ok, frame = cap.read(); cap.release()
   cv2.imwrite("/home/pi/place_eye_frame.png", frame)
   print(ok, frame.shape)
   PY
   ```
3. 把图拷到电脑，量出**落料位区域**的 `x, y, w, h`（只框住会落料的那块，别框到背景）
4. 写进 `[PlaceEye] roi = x, y, w, h`
5. 五色阈值（`color_judge.THRESHOLDS`）在**同一光照**下用实物件验证；偏了就改阈值
   （全部标【待实测】）

## 五、开关与回退

| 开关 | 取值 | 说明 |
|---|---|---|
| `--verify-place`（环境变量 `VERIFY_PLACE`）| `off`（默认）/ `observe` / `correct` | off=完全不看；observe=只看只统计；correct=不符时纠正台账 |
| `--place-eye-config`（`PLACE_EYE_CONFIG`）| ini 路径 | 缺省用 `--config` 那份 `sorting_config.ini` |
| `--slot-mode`（`SLOT_MODE`）| `static`（默认）/ `dynamic` | 只有 dynamic 才会用到分配器与纠正 |

**回退**：`--verify-place off` 或把 `[PlaceEye] enabled` 改成 `false`，两者任一即可；无需改固件、无需回滚 wire。

## 六、判决与动作

| 观测 | 判决 | 动作 |
|---|---|---|
| 颜色与期望一致 | MATCH | 计数 |
| 颜色不一致（如期望 11，看到蓝）| MISMATCH | `observed_code` = **推断值**（形状不变、换颜色），标注"推断"；`correct` 模式下调 `SlotAllocator.correct()` |
| 判不出（遮挡/暗区/灰）| UNKNOWN | 只计数，不动台账 |
| 本件失败（`result_code != 0`）| 跳过 | 计入 skipped，不看 |

统计每 4 件打一条：`复看统计：检查 N（MATCH a / MISMATCH b / UNKNOWN c），跳过 d，纠正台账 e`。

## 七、界面/日志可见性

`run_chain` 的监控状态里新增 `place_check` 字段（最近一次的判决），
`tools/monitor_gui*.py` 可直接显示。

## 八、已知限制

1. **只判颜色**，不判形状 ⇒ 同色不同形的错放无法发现（可用"主相机多帧投票"补）
2. 落料位被夹爪/机身遮挡时只能 UNKNOWN（漏验优于错判）
3. 每次抓帧约 30~80 ms，12 件约 +0.4~1.0 s（未叠加转盘等待）
4. HSV 阈值与 ROI 都**未在实机标定**，出厂默认只是估计值
