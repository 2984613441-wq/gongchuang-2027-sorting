## 五、视觉实施清单（待 TinyF 到货后执行）

### 5.1 TinyF 多点测量算法

**目标**：一件测 2~3 个点（中心 + 偏 10mm 两侧），组合俯视轮廓（相机）和多点高度（TinyF）区分三组歧义。

**实施**：
1. **接线**：TinyF VDD/RX/TX/GND 接 STM32 某个 UART（§4.1 方案 A 用 UART4 PC10/PC11）
2. **固件侧**（或树莓派侧，待定）：
   - 读 TinyF 协议（UART 115200，输出帧包含距离值 mm）
   - 封装函数 `uint16_t tinyf_measure(void)`，返回距离（mm）
   - Z 轴移到件正上方 80~100mm 高度，调用 3 次：
     ```c
     uint16_t d_center = tinyf_measure();  // 中心
     // XY 偏移 +10mm
     uint16_t d_right = tinyf_measure();
     // XY 偏移 -10mm（从中心算）
     uint16_t d_left = tinyf_measure();
     ```
   - 判断逻辑：
     ```c
     bool is_flat_top = (abs(d_center - d_right) < 5 && abs(d_center - d_left) < 5);
     bool is_peaked = (d_center < d_right - 5 && d_center < d_left - 5);
     ```
3. **视觉侧**（MaixCAM）：
   - 俯视轮廓：圆/方/三角（模型 + HSV）
   - 发给树莓派：`(轮廓, is_flat_top, is_peaked, d_center)`
4. **树莓派查表**（§6 协议）：
   ```python
   if shape == "circle":
       if is_flat_top: class_id = 1  # 圆柱
       elif is_peaked: class_id = 2  # 圆锥
       else: class_id = 3  # 球
   elif shape == "square":
       if is_flat_top: class_id = 4  # 正方体
       else: class_id = 5  # 四棱锥
   elif shape == "triangle":
       class_id = 6  # 正四面体（三棱柱中心是平的，暂不区分）
   ```

### 5.3 Week1 验证实验（10-23~10-26，4 天）

**目标**：确认两个关键假设。

| 实验 | 目的 | 方法 | 通过标准 |
|---|---|---|---|
| ① 几何特征准确率 | 确认"特征点辅助"是否有用 | 用现有物料（6 类件各 10 个）测几何特征（面积/周长/凸包/矩）识别准确率 | **>70%** 才继续用特征辅助；否则只用模型 |
| ② 数据量对比 | 确认 1260 张是否够 | 标注 300/600/1260 张三组，训练后测 mAP@0.5 | 找到"再加数据收益 <5%"的拐点 |

**实验 ① 步骤**：
1. 用现有相机拍 60 张（6 类各 10 个，不同位置/角度/堆叠）
2. 跑 `stage1_color_v6_send.py` 的几何特征提取（面积/周长/凸包/矩）
3. 手工标注真值（每张标"这是什么"）
4. 统计准确率：`正确数 / 总数`
5. 若 **<70%**，则"特征点辅助"这条路不走，改为纯模型 + HSV 颜色

**实验 ② 步骤**：
1. 用 Roboflow 标注 1260 张（审核建议值）
2. 分三组：300/600/1260，训练 3 个模型
3. 用同一测试集（60 张，标注但不参与训练）测 mAP@0.5
4. 画曲线：数据量 vs mAP，找拐点
5. 若 600 张已达 mAP >0.85 且 1260 张只提升 <5%，则只标 600 张；否则按 1260 张

## 六、协议改动（L4，需你批准）

### 6.1 现状

| 段 | 当前格式 | 问题 |
|---|---|---|
| MaixCAM → 树莓派<br>`BATCH_TARGETS` | 7 字节：帧头 + **盒号**(1) + x(2) + y(2) + 校验 | **盒号是 MaixCAM 决定的**，但 6 类件现场才知道放哪个盒 ⇒ 改规则就得重刷 MaixCAM |
| 树莓派 → STM32<br>`ITEM_TASK` | 10 字节：帧头 + **class_id**(1) + x(2) + y(2) + z(2) + 校验 | `class_id` 对应夹爪张开脉宽（`ec_motion_plan.c:147`） |

### 6.2 推荐改法

| 段 | 改法 | 为什么 |
|---|---|---|
| MaixCAM → 树莓派 | 第 1 字节从"盒号"改成 **高 4 位颜色 + 低 4 位形状**<br>帧长不变 7 字节 | 不改帧长；高度等 ToF 数据以后再加字段 |
| 树莓派 | 新增配置节 `(颜色, 形状) → 盒号` | **6 类件现场才知道** ⇒ 改一个 ini 就行，**不用重刷 MaixCAM** |
| 树莓派 → STM32 | `class_id` 改为**形状号**<br>落点 X/Y 恒定（查表） | 固件按 `class_id` 选张爪脉宽，张多大取决于**形状**、不取决于颜色 |

**必须同步改**：
- `vision_ingest.py:52`（现在把 ID 字节当盒号）
- MaixCAM 发送端 `encode_target`（现在只接受 1..6）
- `interface-contract.md` 升版
- 端到端测试（MaixCAM 发 `0x12` = 红色圆 → 树莓派查表 → STM32 收到 `class_id=2` 圆锥）

**这条属跨子系统协议改动 = L4，等你批**。
