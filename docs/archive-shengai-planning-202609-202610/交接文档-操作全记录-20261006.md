### 2.1 🔴 固件主频真相：**跑在 16 MHz，而项目设计假设是 168 MHz**

| 证据 | 内容 |
|---|---|
| `Core/Src/main.c:162-181` | `OscillatorType=HSI\|LSI`、**`PLL.PLLState=RCC_PLL_NONE`**、**`SYSCLKSource=RCC_SYSCLKSOURCE_HSI`**、APB1/APB2 全 `DIV1`、`FLASH_LATENCY_0` ⇒ **SYSCLK = 16 MHz** |
| `system_stm32f4xx.c:137` | `SystemCoreClock = 16000000` |
| **项目自己的设计文档** | `docs/design/stm32f407-pin-timer-allocation.md:90` 原文"TIM8/TIM4/TIM9 时钟按 STM32F407 时钟树核算（**APB2 定时器 168 MHz 或 APB1 定时器 84 MHz**）" |
| **运动规划代码的设计假设** | `电控/stm32_logic/include/ec_step_profile.h:66-67` 原文"**sqrt is ~1 us on a 168 MHz M4**, negligible against the 100 us worst case" ⇒ 16 MHz 下同一开方约 **10.5 µs**，占 `EC_STEP_MAX_HZ=10000`（100 µs）预算的 **10%**，**且每拍在步进中断里都算** |
| **CubeMX 工程里 PLL 本来就配好的** | `diankongv1.0.ioc`：`RCC.HSE_VALUE=25000000`、`RCC.VCOInputFreq_Value=1000000`、`RCC.VCOOutputFreq_Value=192000000`、`RCC.PLLCLKFreq_Value=96000000`（目标是 96 MHz）⇒ **但生成代码是 `PLL_NONE`** ⇒ 疑"某次改动没改回去" |
| **F407 不需要 over-drive** | `stm32f407xx.h` **无** `PWR_CR_ODEN`；`stm32f4xx_hal_pwr_ex.c:404` 注释原文"can be used only for **STM32F42xx/STM32F43xx/STM32F446xx/STM32F469xx/STM32F479xx**" ⇒ **误调用会等永不置位的 ODRDY ⇒ 板子不启动** |

### 3.1 还踩了 2 个 **PowerShell 别名**陷阱（已修）

把删除函数命名为 **`Del`**、**`Kill`** —— 而这两个**都是别名**（`Del`→`Remove-Item`、`Kill`→`Stop-Process`），**别名优先级高于函数** ⇒ **函数从未被调用、前两次"删"实际没删掉**。
⇒ **教训**：脚本里不要用短名包装函数（`Del`/`Kill`/`Cd`/`Ls`/`Cat`/`Cp`/`Mv` 全是别名）；**删完必须回读现状**。
