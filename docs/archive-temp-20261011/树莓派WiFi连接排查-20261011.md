# 树莓派无法连接手机热点 - 排查指南（2026-10-13 修正版）

**原始版本**: 2026-10-11 ｜ **最后修正**: 2026-10-13 ｜ **修正人**: DSH (DeepSeek Harness)
**问题**: 树莓派4B 2GB，之前能连手机热点，**改成 GPIO 引脚供电后**突然连不上了。

> ⚠️ **本次修正了原文 3 处会导致误判的技术错误**，见文末「修正记录」。
> 旧版本备份在 `树莓派WiFi连接排查-20261011.md.bak-20261013`。

---

## 0. 先分类：你的系统是 Bullseye 还是 Bookworm？

**这一步决定后面所有命令是否有效**——两个版本的网络栈完全不同，用错方法会"改了没用"。

```bash
cat /etc/os-release | head -3      # VERSION_CODENAME=bullseye 或 bookworm
nmcli -v                           # 有输出 = 装了 NetworkManager（Bookworm 默认）
ip -br a                           # 看网卡（代替 ifconfig）
iw dev                             # 看无线网卡（代替 iwconfig）
```

| | Bullseye (11) 及更早 | Bookworm (12) 及更新 |
|---|---|---|
| 网络管理 | `wpa_supplicant` + `dhcpcd` | **NetworkManager** |
| 配置文件 | `/etc/wpa_supplicant/wpa_supplicant.conf` | `nmcli` / `raspi-config`（**不再读上面那个文件**） |
| 重启网络 | `sudo systemctl restart dhcpcd` | `sudo systemctl restart NetworkManager` |

> 📌 `ifconfig` / `iwconfig` / `iwlist` 属于 `net-tools`，Bookworm **默认不安装**。若提示 `command not found`，那是正常现象、**不是故障**，请改用 `ip` / `iw`。

## 1. 最可能的 5 个原因（按概率排序）

因为**唯一的改动是供电方式**，所以原因 1 的权重远高于其他。

### 原因 1（最高）｜欠压：GPIO 供电 + 线损，WiFi 发射瞬间电压跌落

**机制**：
- Pi 4B 官方要求 **5.1V / 3A**（不是 5.0V/2A）。这个"多出来的 0.1V"就是留给线损的。
- 从 **GPIO 物理引脚 4 (5V) / 6 (GND)** 供电会**绕过 USB-C 输入端的保护电路**（无过流保护、无极性保护、无反灌保护）。
- 杜邦线 + 接插件的接触电阻，在 1A 以上就会产生可观压降；WiFi 发射是**突发大电流**负载（峰值 >1A）。
- 一旦 PMIC 处跌到约 **4.6–4.7V** 以下 → 触发 under-voltage → brcmfmac 掉线 / 固件加载失败 / SDIO 复位。
- **典型表现**：WiFi 最先出问题（功耗突发最大），而桌面看起来还"正常"，很容易误判成"WiFi 坏了"。

**诊断命令**：
```bash
# ① 欠压标志（最权威的一条）
vcgencmd get_throttled

# ② 5V 轨"带载"实际电压（Pi 4B 有 PMIC ADC，固件较新时可用）
vcgencmd pmic_read_adc | grep -i EXT5V

# ③ 内核里有没有 WiFi/供电报错
dmesg | grep -iE "brcmfmac|sdio|under-voltage|voltage" | tail -30

# ④ 万用表：直接量 GPIO 物理引脚 4 与 6 之间
#    必须在"WiFi 正在尝试连接时"读数——空载读数会骗人
```

**`get_throttled` 位含义**：

| 值 | 含义 |
|---|---|
| `0x0` | 正常，从未发生 |
| `0x1` | **此刻**正在欠压 |
| `0x10000` | 自启动以来**发生过**欠压（历史位，断电才清） |
| `0x50000` | 历史欠压 + 历史降频 → **供电问题的铁证** |
| `0x50005` | 此刻欠压 + 此刻降频 + 历史欠压 + 历史降频 |

**解决方案**：
1. **最快**：改回原来的 USB-C 5V/3A 适配器 —— 如果 WiFi 立刻恢复，问题 100% 确认。
2. 若必须用 GPIO 供电：
   - 万用表先量 DCP3512 输出，**调到 5.1V**（切勿超过 **5.25V**，会烧板）；
   - 供电线加粗到 **20AWG 或更粗**、尽量短、用焊接或压接代替杜邦头；
   - 在引脚 4/6 就近并 **470–1000µF 电解电容 + 0.1µF 瓷片**（吸收 WiFi 突发电流）；
   - **GPIO 供电时 USB-C 必须拔掉**（同时接入会互相反灌，保护电路行为不可预期）；
   - DCP3512 不要与电机/舵机共用一个模块（电机换向的电流尖峰会直接打到 Pi 上）。
3. ⚠️ **安全警告**：GPIO 5V 引脚无极性和过流保护，**接反瞬间烧板**。接线前务必先量电压再插。

### 原因 2｜5GHz / 信道 / 管制域问题（**前提需纠正**）

> ❌ **原文错误**："树莓派4B的BCM43455芯片不支持5GHz" —— **这句话是错的**。
> Pi 4B 用的是 **CYW43455**，**支持 2.4GHz + 5GHz 双频 802.11ac**。
> 真正会踩的坑是下面这三条。

**真实的三种坑**：
1. **没设国家码（`country=CN`）** → regulatory 域未定义 → 大量 5GHz 信道被禁用。这种情况下"5GHz 连不上"看起来就像"不支持 5GHz"。
2. 手机热点开的是 **Wi-Fi 6E / 6GHz**（Pi 4B **确实不支持 6GHz**）或 **WPA3-SAE**（旧 wpa_supplicant 可能协商失败）。
3. 热点落在 **DFS 信道**（52–144），Pi 被动扫描可能长时间不发起连接。

**诊断命令**：
```bash
# ① 本机硬件/驱动到底支持几个频段（用事实代替猜测）
iw phy phy0 info | grep -E "Band [0-9]|MHz" | head -40

# ② 扫描结果里有没有 5GHz（出现 5xxx MHz 就是扫到了 5GHz）
iw dev wlan0 scan | grep -E "SSID:|freq:" | head -40

# ③ 当前管制域与国家码
iw reg get
```

**解决方案（手机侧改 2.4GHz）**：
- **Android**：`设置 → 网络和互联网 → 热点和网络共享 → 便携式热点 → 热点配置`
  → 把 **AP 频段 / Wi-Fi 频段** 选 **2.4GHz**；若有 **"Wi-Fi 6 / 6GHz"** 或"扩展兼容性"选项，一并关掉。
- **iPhone**：`设置 → 个人热点` → 打开 **"最大兼容性"**（顾名思义，强制 2.4GHz）。

**解决方案（Pi 侧补国家码）**：
- Bookworm：`sudo raspi-config` → `5 Localisation Options` → `L4 WLAN Country` → 选 `CN`
- 或：`sudo raspi-config` → `1 System Options` → `S1 Wireless LAN`（直接填 SSID/密码）
- Bullseye：在 `wpa_supplicant.conf` 顶部加一行 `country=CN`

### 原因 3｜WiFi 被 block，或驱动/固件没加载起来

**诊断命令**：
```bash
rfkill list                    # 看 Soft blocked / Hard blocked
nmcli radio wifi               # enabled / disabled
ip -br a                       # wlan0 到底存不存在
dmesg | grep -i brcmfmac | tail -30
```
- 有 `Soft blocked: yes` → `sudo rfkill unblock all`
- **`wlan0` 压根不存在** + `dmesg` 里有 brcmfmac 报错 → 大概率回到**原因 1（供电）**，而不是软件问题。

---

### 原因 4｜手机热点侧变了（不在 Pi 上）

- 热点 **SSID 或密码**改过（有些系统升级后会自动加后缀）；
- 开了 **"仅允许列表 / MAC 地址过滤"** → 用 `ip link show wlan0 | grep ether` 取 Pi 的 MAC 加入白名单；
- **客户端数量已满**（通常 8–10 台）；
- ⚠️ **Android 的"无设备连接时自动关闭热点"** → 会形成死循环：Pi 连不上 → 热点判定无设备自动关 → 更连不上。**排查期间请先关掉这个开关**；
- 系统升级后热点默认变成 **WPA3/SAE** 或 **5GHz/6GHz**。

**解决方案**：用**另一台设备**（笔记本/平板）连同一个热点 → 能连=热点正常，问题在 Pi；连不上=热点本身的问题。

---

### 原因 5｜配置/软件栈用错了方法（Bullseye vs Bookworm 混用）

**诊断命令**：
```bash
systemctl status wpa_supplicant dhcpcd NetworkManager --no-pager
journalctl -u wpa_supplicant -u NetworkManager -n 50 --no-pager
```

**解决（Bookworm 正确姿势）**：
```bash
nmcli device wifi list
nmcli device wifi connect "你的热点名称" password "你的密码"
nmcli connection show
```
**解决（Bullseye 正确姿势）**：
```bash
sudo cp /etc/wpa_supplicant/wpa_supplicant.conf{,.bak}
sudo nano /etc/wpa_supplicant/wpa_supplicant.conf
```
```conf
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=netdev
update_config=1
country=CN

network={
    ssid="你的热点名称"
    psk="你的密码"
    key_mgmt=WPA-PSK
    scan_ssid=1
}
```
```bash
sudo systemctl restart dhcpcd      # ⚠️ 仅 Bullseye！Bookworm 没有 dhcpcd 这个服务
```

## 2. 最快的二分法（比逐条排查更快）

**先做这两个实验，能省掉 80% 的时间**：

1. **换回原来的 USB-C 适配器再开机** → WiFi 恢复 ⟹ **确诊为供电问题**，直接按原因 1 处理，不用碰手机设置。
2. **用另一台设备连同一热点** → 能连 ⟹ 热点正常，问题在 Pi。

## 3. 三条命令定生死

```bash
vcgencmd get_throttled          # 有 0x10000/0x50000/0x1 → 供电问题
ip -br a; iw dev                # wlan0 在不在
dmesg | grep -i brcmfmac | tail -20   # 驱动有没有报错
```

| 结果 | 结论 |
|---|---|
| throttled 有欠压位 | **原因 1（供电）**，先别在手机设置上花时间 |
| 无 wlan0 + brcmfmac 报错 | 供电或驱动 → 先按原因 1 |
| wlan0 正常、扫不到热点 | 原因 2 / 4（频段或手机侧） |
| 扫得到热点、连不上 | 原因 2 / 3 / 5（认证方式、block、配置方法） |

## 4. 完整诊断包（一次性复制到树莓派终端，把输出发回）

```bash

echo "=== [2] 欠压标志 ==="; vcgencmd get_throttled

echo "=== [4] 网卡 ==="; ip -br a; iw dev
echo "=== [5] 频段支持 ==="; iw phy phy0 info | grep -E "Band [0-9]"

echo "=== [8] 管制域 ==="; iw reg get

```
