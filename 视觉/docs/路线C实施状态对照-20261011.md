## 🔍 逐项详细对照

### V1. 形状识别（P0）

#### 原方案要求

```
YOLO模型 + HSV颜色 + ToF深度 + 特征点辅助
- 形状：YOLO模型（MaixCAM跑.mud）
- 颜色：HSV像素统计（保留现有逻辑）
- 深度：TinyF测3点
- 特征点：置信度加权辅助（final = 0.3·特征 + 0.7·模型）
```

#### 当前实施

✅ **已实现**：
- YOLO模型：7类形状检测（`.onnx`存在，待转`.mud`）
- HSV颜色：MMCQ主色提取（62项测试通过）
- ToF深度：`depth_fusion.py`（28项测试通过）

❌ **未实现**：
- **特征点加权融合**（`final = 0.3·特征 + 0.7·模型`）
  - 现状：`shape_features.py`存在，但作为**降级预案**，不是加权融合
  - 逻辑：ToF失败时 → 切换到形状特征，**不是加权**

⚠️ **差异分析**：

**原方案意图**：
```python
# 原方案：加权融合
yolo_confidence = 0.85
feature_confidence = 0.60

final_confidence = 0.7 * yolo_confidence + 0.3 * feature_confidence
# = 0.7 * 0.85 + 0.3 * 0.60 = 0.595 + 0.18 = 0.775

if final_confidence > 0.7:
    return shape
```

**当前实现**：
```python
# 当前实现：if-else切换
if tof_sensor_available and requires_depth_disambiguation(yolo_shape):
    return depth_disambiguate(...)  # ToF深度判据
else:
    return yolo_shape  # 纯YOLO

# 降级预案（ToF完全失败时）
if tof_failed:
    return classify_shape_contour(...)  # 形状特征
```

**影响**：
- ✅ ToF方案更可靠（物理测量 > 像素特征）
- ❌ 未实现"置信度加权"机制
- ❌ 特征点和YOLO不能互补（只能二选一）

### V2. ToF深度测量（P1）

#### 原方案要求

```
TinyF测3个点（中心 + 偏10mm两侧）
- 为什么：区分"平顶vs尖顶"
  - 圆柱/圆锥
  - 正方体/四棱锥
  - 三棱柱/正四面体
```

#### 当前实施

✅ **已实现**：
- ToF深度融合架构（`depth_fusion.py`）
- 三组歧义判据（高宽比）
- 28项测试通过
- 实测指南完整

❌ **未实现**：
1. **未测3点**：
   - 当前：只读1个高度值（`DepthReading.height_mm`）
   - 原方案：测3点（中心 + 偏10mm两侧）

2. **未指定TinyF**：
   - 当前：支持VL53L1X/TF-Luna（通用接口）
   - 原方案：明确要求TinyF

3. **判据不同**：
   - 当前：**高宽比**判据（height/width > 1.2 → 圆柱）
   - 原方案：**3点差异**判据（中心高 > 边缘高 → 尖顶）

⚠️ **差异分析**：

**原方案逻辑**：
```python
# 3点测量
center_height = tof.read(center_position)
left_height = tof.read(center - 10mm)
right_height = tof.read(center + 10mm)

# 平顶vs尖顶判据
if abs(center_height - left_height) < 5mm:
    return "cylinder"  # 平顶
else:
    return "cone"      # 尖顶
```

**当前实现**：
```python
# 单点测量
height_mm = tof.read()

# 高宽比判据
if height_mm / width_mm > 1.2:
    return "cylinder"
elif height_mm / width_mm < 0.8:
    return "sphere"
```

**影响**：
- ✅ 高宽比判据更简单（易标定）
- ❌ 无法区分圆柱/圆锥（都是圆形俯视）
- ❌ 无法区分正方体/四棱锥的尖顶特征
- ⚠️ 省赛是否包含圆锥？需确认

### V4. 协议改动（P2）

#### 原方案要求

```
- 现状：MaixCAM→树莓派发"盒号"
- 改成：发"高4位颜色+低4位形状"
- 树莓派查表：(颜色,形状)→盒号
- 为什么：现场分配盒号只需改ini，不用重刷MaixCAM
```

#### 当前实施

❌ **未实现**：
- `ITEM_TASK`协议未改动
- 仍然直接发送`bin_id`
- 映射表在MaixCAM端（`stage1_color_v6_send.py:409`）

⚠️ **当前架构**：
```python
# MaixCAM端（stage1_color_v6_send.py）
shape, bin_id = COLOR_TO_MATERIAL[color]  # 查表在这里
send_to_raspberry({
    'image_id': class_id,
    'color': color,
    'shape': shape,
    'bin_id': bin_id  # 直接发盒号
})
```

**原方案架构**：
```python
# MaixCAM端
color_code = COLOR_TO_CODE[color]  # 0-15
shape_code = SHAPE_TO_CODE[shape]  # 0-15
combined = (color_code << 4) | shape_code  # 高4位+低4位

send_to_raspberry({
    'image_id': combined  # 只发组合码
})

# 树莓派端
color_code = (image_id >> 4) & 0x0F
shape_code = image_id & 0x0F
bin_id = CONFIG[(color_code, shape_code)]  # 查表在这里
```

**影响**：
- ❌ 现场分配盒号需要重刷MaixCAM
- ❌ 灵活性低
- ✅ 但协议简单，易调试

⚠️ **决策点**：**是否需要改？**
- 若省赛现场**不允许重刷MaixCAM** → 必须改
- 若**允许重刷** → 当前架构可用

```python
# depth_fusion.py 新增
def read_3point_tof(tof_sensor, bbox_center, px_to_mm):
    """测量3点：中心+左右偏移"""
    center = tof_sensor.read_height_mm()
    left = tof_sensor.read_height_mm()   # 移动传感器或多传感器
    right = tof_sensor.read_height_mm()
    
    # 平顶判据
    if abs(center - left) < 5 and abs(center - right) < 5:
        return "flat_top"  # 圆柱/正方体/三棱柱
    else:
        return "pointed_top"  # 圆锥/四棱锥/正四面体
```

# pipeline.py 新增
def weighted_shape_classification(yolo_result, shape_features, weights=(0.7, 0.3)):
    yolo_conf = yolo_result.confidence
    feature_conf = compute_feature_confidence(shape_features)
    
    final_conf = weights[0] * yolo_conf + weights[1] * feature_conf
    
    if final_conf > 0.7:
        return yolo_result.class_name
    else:
        return None  # Fail-closed
